# Steam 国际服汉化与翻译资源维护

## 使用

开发版先执行 `npm run localization:build` 构建自包含原生组件，再以 `npm run electron:dev` 启动。无需安装全局 .NET 运行时；开发构建需要 .NET 8 SDK 与 Visual Studio C++ x64 Build Tools。构建不生成助手安装程序。

切换到国际服，在侧边栏“游戏汉化”点击“切简体”或“切繁体”。切简体会自动检测游戏版本、检查翻译资源、按需下载变化内容并应用；切繁体直接使用同版本应用前备份中的官方繁体资源，不检查或下载服务器词库。只有一个 Steam 安装时会自动选择；有多个安装时先选择 Path of Exile 目录。无需分别扫描、下载、预览，也无需勾选或手动执行 Steam 完整性核对。切换与恢复要求游戏完全退出、Steam 不在更新中。

语言选择会跨游戏版本和助手重启保留，与“当前版本已经应用”分别显示。游戏更新后点击所需语言按钮，助手会按当前游戏资源重新生成补丁；无需仅因版本号或Steam Build改变重新上传相同译文。已有词库中稳定标识、英文原文、占位符和词缀结构仍匹配的内容可继续使用，不匹配或新增内容保留本版繁体／英文。成功恢复原版后清除已保存的语言选择。

助手自动检查资源结构与版本，并保存应用前备份；这个备份代表首次应用前的文件，不等于对 Steam 官方原版的证明。恢复原版同时恢复应用前保存的语言设置，只使用当前 Steam Build 的备份。游戏更新后，若索引仍引用旧汉化，助手只撤销能由原应用记录和有效备份核实的受管文件重定向，保留当前索引中的Steam更新和其它资源，再为当前Build建立备份并应用；点击恢复原版也可先完成这一步迁移，再恢复当前Build，不会用旧版完整索引覆盖新版。同版文件被外部修改、备份损坏、未知旧补丁或无法安全核实的残留会停止操作，按错误提示使用 Steam 校验游戏。游戏更新、外部修改和未完成事务会停用旧查价映射。启动助手、退出游戏、打开设置均不会自动联网检查资源或自动应用。

重复点击“切简体”会检查最新资源并复用未变化的缓存；重复点击“切繁体”保持本地处理。组件在事务中记录已应用模式，即使词库版本相同，从简体切到繁体或切回简体也会重新生成对应内容，同时保留最初的语言备份。切繁体可复用同游戏版本的本地验签词库作为查价映射，没有同版词库时仍可离线启用繁体。汉化任务进行中退出、重启、切服或安装更新时，助手会等待整条操作完成并保存状态，再清理退出；等待期间不接受新的汉化操作。

“切简体”遇到连接失败、超时或服务器暂时不可用时，可重新验证本地完整词库后继续应用，包括来自旧游戏版本的词库，并在页面提示缓存来源版本和资源检查失败原因。损坏或缺失对象的缓存不能使用，但可选择另一份完整、验签有效的本地缓存；没有任何完整有效缓存时仍需联网下载。收到新资源后发生签名、协议或对象完整性校验失败，以及权限错误时，直接停止，不使用缓存掩盖错误。

本轮资源入口为既有 SSH 测试隧道，保持以下命令运行：

```powershell
ssh -N -o ExitOnForwardFailure=yes -L 127.0.0.1:44317:127.0.0.1:8081 aliyun-kmio
```

`LOCALIZATION_RESOURCE_BASE_URL` 可单独配置资源入口。正式入口要求 HTTPS；HTTP 仅允许明确配置的本机回环地址。发布公钥固定在 `electron/assets/localization-public-key.pem`，可通过 `LOCALIZATION_PUBLIC_KEY_FILE` 指向维护者验证过的公钥。不要随资源包信任新公钥。

## 提取与发布

当需要补充游戏新增或修改的简体文本时，在维护者电脑更新游戏后从本机官方资源提取；普通游戏更新不要求重复导出上传已有兼容词条。目录由操作者明确提供，不以国服版本推断国际服版本：

```powershell
.\scripts\exportLocalizationData.ps1 -SteamGameDirectory '<Steam游戏目录>' -CnGameDirectory '<国服游戏目录>' -OutputPath '<导出JSON路径>'
```

如果国际服当前已应用汉化，额外传入 `-SteamLocalizationStorageRoot '<助手国际服localization缓存目录>'`。组件核对同版本应用前备份后只读提取，不需要恢复游戏；未指定可靠备份时会拒绝从受管补丁中导出，防止已汉化文本污染繁体回退。

导出命令只读游戏，不上传账号、会话或游戏存档。技能、宝石、装备基础与传奇名称、天赋、NPC、区域、剧情及界面等已确认的展示字段均参与提取，不限于装备词缀。游戏表通过稳定 Id／经校验的 HASH32 对应，英文原文和占位符必须一致，不按行号配对。国际服写入使用当前 `schema.json`；旧国服读取可使用固定 3.29.3 来源结构 `source-schema-cn.json`，该来源结构绝不用于国际服写入。未知结构或无法可靠对应时保留繁体／英文。

当前 `.datc64` 为 UTF-16LE、`.datcl64` 为 UTF-32LE；扩展名不能简单视为 UTF-8。词缀 `.csd` 采用 UTF-16LE，多语言描述必须按整组变体校验。国际服文件内已有的有效简体优先使用，缺失时才尝试经原文核验的国服内容。导出报告包含逐表简体覆盖和国服结构读取失败原因，避免整张名称表缺失简体却不易发现。

在反馈后台“翻译资源”导入 JSON，查看来源、条目及覆盖情况，确认后发布；导入候选不会改变当前频道。维护入口及回退命令见反馈后台 README。资源签名私钥仅保存在服务器私有目录，不进入助手、导出包或 Git。

公开路径为 `/resources/poe1/steam/stable.json`、`/resources/manifests/<hash>.json`、`/resources/objects/<hash>`。频道通过强 ETag 检查；不可变对象由 Nginx 缓存。资源按表隔离，每表固定16个稳定标识哈希桶，因此整张名称表更新不会重新传输未变化词缀表；缓存缺失或损坏仅重下相应对象，跳版本不依赖差分链。

## 验证与限制

原生自测覆盖编解码边界、真实字符串编码、DAT 文本指针和机制字段保护、词缀整组回退、包络和索引边界、自动备份及事务恢复。测试入口为 `node --test test/localizationNative.test.js test/localizationOneClick.test.js`，全量验证使用 `npm test` 与 `openspec validate add-steam-localization-hot-update --strict`。

国际服手动查价使用同代已应用词库，将混合语言文本还原到国际服目录。未知或歧义名称、条件会拒绝查询并提示，不使用国服价格、不静默删除条件。游戏内捕获和其他尚未完成国际服实测的自动操作保持原门禁。网页市集／商城不属于本地资源汉化范围。游戏原生市集的实例目录另由默认关闭的原生翻译组件处理，需在游戏启动前手动启用；停止或换简繁后完整重启游戏才能清除缓存。兼容版本、独立组件及实机验收见[原生市集翻译](native-market-localization.md)。

数据表没有稳定标识、官方文本本身缺失或新格式不受支持时会保留繁体／英文并报告，不能保证所有内容均为简体。引擎不通过数据通道升级；未来二进制格式变化仍可能需要更新助手。当前仅提供内部联调，未开放公网资源入口。

跨版本语言偏好、可信缓存回退和受管旧引用撤销的实现与验证以本变更任务第5节为准；旧版历史验收记录不代表新增跨Build路径已完成真实游戏验收。原生市集翻译有独立版本限制，不因语言词库可跨版本复用而自动获得兼容性。
