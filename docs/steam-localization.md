# Steam 国际服汉化与翻译资源维护

## 使用

开发版先执行 `npm run localization:build` 构建自包含原生组件，再以 `npm run electron:dev` 启动。无需安装全局 .NET 运行时；开发构建需要 .NET 8 SDK 与 Visual Studio C++ x64 Build Tools。构建不生成助手安装程序。

切换到国际服，在“设置 → 游戏汉化”选择 Steam 的 Path of Exile 目录，然后手动扫描、检查资源、下载变化资源、预览并应用。首次应用及 Steam 更新后先验证游戏完整性；勾选确认不会绕过真实验证记录。应用与恢复要求游戏完全退出、Steam 不在更新中。

恢复原版同时恢复应用前保存的语言设置。只允许同一个 Steam Build 恢复；跨版本重新从 Steam 校验后的原版生成。游戏更新、外部修改和未完成事务会停用旧查价映射。启动助手、退出游戏、打开设置均不会自动联网检查资源或自动应用。

已应用后的预览使用同版本原版基线；重复应用同版汉化会重新启用汉化语言，同时保留最初的语言备份。汉化任务进行中退出、重启、切服或安装更新时，助手会等待任务完成并保存词库状态，再清理退出；等待期间不接受新的汉化操作。

本轮资源入口为既有 SSH 测试隧道，保持以下命令运行：

```powershell
ssh -N -o ExitOnForwardFailure=yes -L 127.0.0.1:44317:127.0.0.1:8081 aliyun-kmio
```

`LOCALIZATION_RESOURCE_BASE_URL` 可单独配置资源入口。正式入口要求 HTTPS；HTTP 仅允许明确配置的本机回环地址。发布公钥固定在 `electron/assets/localization-public-key.pem`，可通过 `LOCALIZATION_PUBLIC_KEY_FILE` 指向维护者验证过的公钥。不要随资源包信任新公钥。

## 提取与发布

在维护者电脑更新游戏后，从本机官方资源提取。目录由操作者明确提供，不以国服版本推断国际服版本：

```powershell
.\scripts\exportLocalizationData.ps1 -SteamGameDirectory '<Steam游戏目录>' -CnGameDirectory '<国服游戏目录>' -OutputPath '<导出JSON路径>'
```

导出命令只读游戏，不上传账号、会话或游戏存档。游戏表通过稳定 Id／经校验的 HASH32 对应，旧版国服结构不兼容时保留国际服繁体；不按行号配对。当前 `.datc64` 为 UTF-16LE、`.datcl64` 为 UTF-32LE；扩展名不能简单视为 UTF-8。词缀 `.csd` 采用 UTF-16LE，多语言描述必须按整组变体校验。国际服文件内已有的有效简体优先使用，缺失时才尝试英文原文和结构一致的国服内容。

在反馈后台“翻译资源”导入 JSON，查看来源、条目及覆盖情况，确认后发布；导入候选不会改变当前频道。维护入口及回退命令见反馈后台 README。资源签名私钥仅保存在服务器私有目录，不进入助手、导出包或 Git。

公开路径为 `/resources/poe1/steam/stable.json`、`/resources/manifests/<hash>.json`、`/resources/objects/<hash>`。频道通过强 ETag 检查；不可变对象由 Nginx 缓存。资源按表隔离，每表固定16个稳定标识哈希桶，因此整张名称表更新不会重新传输未变化词缀表；缓存缺失或损坏仅重下相应对象，跳版本不依赖差分链。

## 验证与限制

原生自测覆盖编解码边界、真实字符串编码、DAT 文本指针和机制字段保护、词缀整组回退、包络和索引边界、Steam 验证证据及事务恢复。测试入口为 `node --test test/localizationNative.test.js`，全量验证使用 `npm test` 与 `openspec validate add-steam-localization-hot-update --strict`。

国际服手动查价使用同代已应用词库，将混合语言文本还原到国际服目录。未知或歧义名称、条件会拒绝查询并提示，不使用国服价格、不静默删除条件。游戏内捕获和其他尚未完成国际服实测的自动操作保持原门禁。网页市集／商城不属于本地资源汉化范围。

数据表没有稳定标识、官方文本本身缺失或新格式不受支持时会保留繁体／英文并报告，不能保证所有内容均为简体。引擎不通过数据通道升级；未来二进制格式变化仍可能需要更新助手。当前仅提供内部联调，未开放公网资源入口。
