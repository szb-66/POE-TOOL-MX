## 管理员启动连接超时回归

用户通过管理员开发版启用后，游戏正常进入，但市集组件报告控制连接超时。进程 PID `5288` 已加载本项目 DLL，故故障发生在注入后的控制连接阶段。针对同一 PID、同一 35,004 条完整词库，普通权限控制进程在 2,372 ms 内连接成功，排除了大词库配置及尚未启动游戏的解释。

根因是旧的 `PipeOptions.CurrentUserOnly` 使用提权进程 Owner SID 建立权限，并不等价于同一 User SID；管理员 Owner 通常为 Administrators，普通权限同账号的该 SID 为 deny-only。原原生自测只覆盖了相同提权状态，漏测“管理员助手＋普通权限游戏”。

修复增加 `MarketPipe`，原生创建 Owner 为当前 User SID、受保护且仅该 SID 可访问的 DACL，并显式包含 Medium／NoWriteUp 标签。保持首实例限制、本地客户端限制和客户端 PID 检查。创建后读回实际安全描述符验证全部条件；不使用会过滤 mandatory-label ACE 的 `PipeSecurity` 转换路径。

按用户后续要求，将独立市集卡片及逐会话启停按钮改为语言切换下方的一行“市集翻译”开关，常态不显示说明，只在失败或需要重启时显示提示。开关偏好保存至 `market-settings.json`，首次关闭；开启后助手启动会恢复监听，游戏退出后保持开启并等待下次游戏启动。关闭开关取消偏好，助手退出／切服仅清理当前会话。

## 游戏保留运行时重启助手恢复查询

用户反馈：市集已汉化，保持游戏开启，完全退出并重启助手后，查询显示 `An argument was invalid.`。根因是退出清理按设计停用查询转换，而游戏保留中文名称缓存；旧启动逻辑一律阻断已运行 PID，没有接回本项目已初始化的组件。回归先复现该断点：重建管理器后一直 waiting，没有任何恢复请求。

修复保留退出透传行为，并新增受限 `resume`：只连接已加载同路径组件的旧游戏，先核对原生状态和模式，再由已加载 DLL 的规范化配置身份校验保证完整词库相同。无组件、无初始化状态时不注入，等待重启；模式或词库不一致明确拒绝。同一个旧 PID 仅尝试一次，不在失败后回退到注入。无需修改已加载 DLL。
