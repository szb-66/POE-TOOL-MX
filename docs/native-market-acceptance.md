## 翻译用语复核

用户指出“伪词缀”不自然后，静态对照用户提供安装包中的 POE1 DLL 少量分类表，核实简体采用“综合、外延、基底、分裂的、工艺、影匿、附魔、异度天灾、古神熔炉”。没有运行第三方安装包或把其整套词库加入项目。

`pseudo` 简体表项为提取 DLL 文件偏移 `0x312698`，译文指针指向 `0x786e48` 的 UTF-8“综合”；繁体表项 `0x48d058` 为“偽屬性”。参考繁体 implicit 实际误写“固性屬性”（`0x48d028 → 0x895da0`），项目使用正确的“固定屬性”。最终固定译文和回归用例会避免再次出现“伪词缀／显式词缀”。

## 管理员启动连接超时回归

用户通过管理员开发版启用后，游戏正常进入，但市集组件报告控制连接超时。进程 PID `5288` 已加载本项目 DLL，故故障发生在注入后的控制连接阶段。针对同一 PID、同一 35,004 条完整词库，普通权限控制进程在 2,372 ms 内连接成功，排除了大词库配置及尚未启动游戏的解释。

根因是旧的 `PipeOptions.CurrentUserOnly` 使用提权进程 Owner SID 建立权限，并不等价于同一 User SID；管理员 Owner 通常为 Administrators，普通权限同账号的该 SID 为 deny-only。原原生自测只覆盖了相同提权状态，漏测“管理员助手＋普通权限游戏”。

修复增加 `MarketPipe`，原生创建 Owner 为当前 User SID、受保护且仅该 SID 可访问的 DACL，并显式包含 Medium／NoWriteUp 标签。保持首实例限制、本地客户端限制和客户端 PID 检查。创建后读回实际安全描述符验证全部条件；不使用会过滤 mandatory-label ACE 的 `PipeSecurity` 转换路径。

验证证据：

- 先在真实旧工厂创建的管道上增加安全策略断言，自测稳定拒绝旧策略；新增已构建 host 回归也先失败，再修复。
- 独立受限 token 差分将 Administrators 禁用为 deny-only，并使用 Medium 完整性：旧 BA-only DACL 的 `CreateFile` 返回错误 5，新 User SID-only／Medium 策略返回 0。
- 真实 .NET 8 构建与发布通过；host 自测现为 31 项，其中管道安全 8 项，覆盖实际 ACL／label 读回、原生客户端双向收发、peer PID、首实例及无效名称拒绝。
- 修复后的控制组件连接同一游戏 PID 5288，在 2,883 ms 内返回 active，随后已停止该临时验证连接。
- 20 项相关测试和 `runtime:verify` 通过；分发检查拒绝没有管道安全自测能力的旧 host。
- 用户已通过管理员开发版重新启用并启动新游戏进程，确认状态“已启用”，大部分市集内容正常显示，管理员控制链路问题已恢复。用户另指出下拉选择器存在数十项漏译，属于目录覆盖问题，后续单独补齐，不能据此宣称全部选择器验收完成。

## 市集翻译持久开关

按用户后续要求，将独立市集卡片及逐会话启停按钮改为语言切换下方的一行“市集翻译”开关，常态不显示说明，只在失败或需要重启时显示提示。开关偏好保存至 `market-settings.json`，首次关闭；开启后助手启动会恢复监听，游戏退出后保持开启并等待下次游戏启动。关闭开关取消偏好，助手退出／切服仅清理当前会话。

服务用例覆盖助手重建后读取开关、连续两次游戏启动、关闭后的下次启动不监听、运行中开关及启动助手时已有游戏不迟注入、探测失败恢复不迟注入、模式变更后跟随有效语言、国服不监听及并发退出清理。组件测试覆盖一行开关布局、后台偏好回显、状态订阅、提交期间防重和失败回显。上述最新专项 32 项通过；Vue 生产构建通过。新自动启用流程尚未通过重启管理员开发版及真实游戏复测，不将模拟进程／host 用例计作实机验收。

## 游戏保留运行时重启助手恢复查询

用户反馈：市集已汉化，保持游戏开启，完全退出并重启助手后，查询显示 `An argument was invalid.`。根因是退出清理按设计停用查询转换，而游戏保留中文名称缓存；旧启动逻辑一律阻断已运行 PID，没有接回本项目已初始化的组件。回归先复现该断点：重建管理器后一直 waiting，没有任何恢复请求。

修复保留退出透传行为，并新增受限 `resume`：只连接已加载同路径组件的旧游戏，先核对原生状态和模式，再由已加载 DLL 的规范化配置身份校验保证完整词库相同。无组件、无初始化状态时不注入，等待重启；模式或词库不一致明确拒绝。同一个旧 PID 仅尝试一次，不在失败后回退到注入。无需修改已加载 DLL。

实际验收使用原游戏 PID `46280`，Build `26673341`／`3.30.0b`，当前简体目录 `ca8f643d…`：

- 只读模块检查确认同路径 `MarketLocalizationHook.dll` 已加载，助手退出后的控制 host 不存在。
- 更新 host 后执行 `resume`，2,384 ms 返回 active／simplified／PID 46280。没有退出游戏或再次注入，DLL SHA-256 保持 `1bbb4581a93e7c8803ed420041abd92baf65de5c9575afa497fbcb4cb3d03f78`。
- 用户重复原查询后确认“可以正常查询，错误消失”。同一 PID 的 `builders/search` 由 `2/2` 增为 `3/3`，确认名称反向转换实际执行。
- 关闭临时验证 host 后，用户保持游戏开启，完全退出旧助手并手动重新启动管理员开发版，再次确认“已自动恢复，查询正常”。持久开关的启动接续链路已实测通过。
