## 注释规范（面向 AI 协作）

- 目的：让后续 AI / 开发者快速理解脚本意图、输入输出、外部依赖及边界条件，减少误改风险。
- 适用范围：`electron/`、`src/assets/scripts/` 及其子目录所有脚本。

### 文件级概要（置于文件顶部）
- 文件职责：一句话说明模块作用与主要场景。
- 主要入口：列出导出/注册的入口函数或事件。
- 关键依赖：注明外部资源（配置、环境变量、磁盘/网络 I/O、IPC 渠道、第三方库）。

### 函数/方法头注释
- 格式（可按需精简）：
  - `Purpose`：核心意图/业务结果。
  - `Inputs`：参数、类型/形态、约束（为空/缺省的处理）。
  - `Outputs`：返回值/副作用（状态更新、磁盘/网络/IPC 发送）。
  - `Preconditions`：必须满足的环境/状态（配置已加载、窗口已初始化等）。
  - `Edge cases`：异常/极值路径（空列表、权限不足、文件不存在、重复调用）。
  - `Errors`：抛出的错误或 Promise 拒绝原因，是否上抛/就地吞并。

### 数据与状态说明
- 复杂对象/配置结构：用简短注释或示例对象说明字段意义与可选值。
- 全局状态/缓存/单例：说明生命周期、谁负责初始化/销毁、并发安全假设。

### 流程/算法注释
- 对多步骤流程，使用步骤前置注释概述“做什么”而非逐行释义。
- 对关键分支/短路/早退，说明触发条件与原因，避免重复思考。

### TODO / NOTE 标记
- `TODO:` 明确下一步工作（缺失校验/错误处理/性能优化），可附责任或前置条件。
- `NOTE:` 对非直觉性选择/历史兼容/平台差异进行解释。

### 风格约定
- 语言：中文为主，可附简短英文关键词以利搜索；保持简洁，避免重复代码含义。
- 位置：以块级注释为主（JS/TS 使用 `//` 或 `/** */`，Python 使用 `#`）。
- 长度：优先描述意图、边界、依赖，避免逐行翻译代码。
- 一致性：同类函数使用相似字段顺序（Purpose → Inputs → Outputs → Preconditions → Edge cases → Errors）。

### 简短示例（Python）
```
# Purpose: 生成地图配方并写入目标文件
# Inputs: configs(list[dict]) 已校验；output_path(str) 可写路径
# Outputs: 写文件到 output_path；返回成功写入的行数
# Preconditions: 目标目录已存在
# Edge cases: configs 为空时写入空文件但返回 0
# Errors: IOError 上抛；数据校验错误应在调用前处理
```

### 简短示例（JS）
```js
// Purpose: 创建主窗口并挂载前端入口
// Inputs: ctx {app, BrowserWindow, preloadPath, entryUrl}
// Outputs: 赋值全局 win; 注册生命周期事件
// Preconditions: app.whenReady 已完成；preloadPath 存在
// Edge cases: 多实例时应提前退出（由上层保证）
// Errors: 窗口创建失败将抛出异常交由调用方处理
```
