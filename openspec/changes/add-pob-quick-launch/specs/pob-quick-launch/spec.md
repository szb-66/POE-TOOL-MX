## Purpose

为流放之路一代玩家在角色导出页面提供中文 PoB 快速启动入口，允许关联本地已有安装或从官方来源安装和更新两个必要组件，保留用户构筑与设置，并明确呈现失败和恢复状态。

## ADDED Requirements

### Requirement: 目录关联与检测
系统 SHALL 在导出页顶部提供启动卡片，默认目录空白，支持输入、选择、保存、清空及分别检测 PoeCharm 与 PoB Portable，未知版本如实显示。

#### Scenario: 本地安装关联
- **WHEN** 用户选择包含两个程序的目录并重启助手
- **THEN** 保存的目录和两个安装状态可见，可启动和更新

#### Scenario: 清空或取消
- **WHEN** 用户清空路径或取消目录选择
- **THEN** 清空只解除关联，取消不改变配置，均不删除安装文件

### Requirement: 安装及更新两个组件
系统 SHALL 根据用户操作从固定官方来源安装或更新两个组件，安装补齐缺失组件，更新选择最新稳定 PoB 和 PoeCharm main，显示进度，无版本变化时提示已是最新版本。

#### Scenario: 首次与部分安装
- **WHEN** 用户点击安装且路径为空或组件缺失
- **THEN** 先选择目录，再下载缺失组件并验证程序及官方目录结构

#### Scenario: 已完整安装
- **WHEN** 所选目录中的 PoeCharm 与 PoB Portable 均已安装
- **THEN** 安装按钮置灰且不可点击，无论版本是否已知；缺失任一组件时，在非忙碌且受支持的环境中恢复安装按钮以补齐组件

#### Scenario: 匿名 API 配额耗尽
- **WHEN** GitHub 匿名 API 配额耗尽但官方提交订阅和发布页面可访问
- **THEN** 系统仍可查询 PoeCharm 最新 main 提交及 PoB 最新稳定 Portable 版本，不要求用户配置 Token，下载来源仍为官方仓库

#### Scenario: 故障恢复和数据保留
- **WHEN** 下载、解压、替换失败或操作中断
- **THEN** 旧安装保持可用或在下次访问时恢复，BD、设置及用户新增文件保留，错误明确展示

#### Scenario: 非法归档
- **WHEN** 归档包含越界路径或链接
- **THEN** 拒绝归档，不写入目标目录以外位置

### Requirement: 互斥及启动
系统 SHALL 禁止管理操作期间切换目录或重复操作，运行中的程序不允许更新，不强制终止进程；启动 SHALL 使用 PoeCharm 安装目录为工作目录。

#### Scenario: 程序运行中
- **WHEN** 用户尝试更新运行中的目标安装
- **THEN** 提示先关闭程序，现有进程继续运行

#### Scenario: 启动失败
- **WHEN** 操作系统拒绝启动或程序不存在
- **THEN** 返回可见中文错误，不报告启动成功

### Requirement: 阶段进度与停止
系统 SHALL 分别报告下载、校验、解压的真实阶段进度及处理量；未知总量使用动态进度。安装或更新期间对应按钮 SHALL 变为停止，其他操作及目录编辑禁用。

#### Scenario: 取消操作
- **WHEN** 用户在安装或更新期间点击停止
- **THEN** 中止当前流并清理暂存，已开始替换则回滚，完成之前保持互斥，提交成功后不误报取消

#### Scenario: 进度与过期事件
- **WHEN** 操作进入新阶段或前端收到延迟的旧状态
- **THEN** 显示当前组件和阶段的真实处理量，仅阶段完成后显示 100%，忽略旧快照

### Requirement: 异常结果与通信恢复
系统 SHALL 隔离状态通知错误，保存脱敏阶段诊断，区分业务失败、取消和通信失败。

#### Scenario: 通信拒绝或窗口销毁
- **WHEN** 通知发送失败或操作 IPC 被拒绝
- **THEN** 通知失败不破坏事务，前端重新读取状态确认结果，仅通信仍不可用时提示重启

#### Scenario: 提交后清理失败
- **WHEN** 更新已成功提交但暂存清理失败
- **THEN** 保持成功结果并提示清理问题，不回滚或误报更新失败

### Requirement: 页面统一名称
系统 SHALL 将功能入口、模块管理名称及页面主标题统一显示为“POB”。

#### Scenario: 页面入口
- **WHEN** 用户查看侧栏、模块管理或进入该页面
- **THEN** 名称显示为“POB”，原有路由和导出功能保持可用
