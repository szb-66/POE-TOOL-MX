## Context

见 proposal.md。JavaScript 生成器无条件传递组合物等要求；Python 的单件准备和批量预检都消费这些要求。已有阶级算法与归档规范一致。

## Goals / Non-Goals

- Goals：在生成器统一限定校验范围，覆盖单件及批量。
- Non-Goals：不修改阶级算法、自动化输入或已有预设。

## Decisions

- 普通制作依据 moduleTwo.enabled 生成要求，精华和花园保留校验；停用时传空数组。无需在多个 Python 入口重复判断。
- 用生成后的 Python 校验函数验证停用模块后的行为，同时保留启用状态及最低阶级的回归用例。
- 四项失败来自测试绑定旧模板表达式或固定数量；更新为现有界面语义，保留目标预设、显示条件和响应式布局断言。

## Risks / Trade-offs

- 专用制作误跳过校验 → 覆盖精华、花园及普通制作场景。
- 放宽测试掩盖错误 → 保留具体条件及内容完整性检查。
