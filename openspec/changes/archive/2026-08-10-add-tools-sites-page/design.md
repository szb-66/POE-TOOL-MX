## Context

应用是 Vue 3、Pinia、Vue Router 和 Element Plus 构成的 Electron 桌面端。现有业务配置多使用 localStorage，侧栏路由支持悬停预加载，主进程已统一阻止应用内外部导航并用系统浏览器打开 HTTP/HTTPS 链接。

## Goals / Non-Goals

**Goals:**

- 让站点数据规则可独立单元测试，页面只负责交互与呈现。
- 保证用户删除或清空后的结果不会被默认数据覆盖。
- 在不增加依赖和 Electron 权限的前提下实现排序与外链打开。

**Non-Goals:**

- 不提供分类、搜索、同步、导入导出或本地图片导入。
- 不在应用内部嵌入第三方网页。

## Decisions

1. 新建纯 JavaScript 数据模块，导出默认站点、字段规范化、URL 校验、加载保存、增改删和移动操作。存储结构固定为 `{ version: 1, sites: [...] }`，以便后续迁移。相比把逻辑全部写入 Vue 页面，这能直接覆盖异常存储与排序边界测试。
2. 存储键缺失或数据损坏时以默认站点初始化；合法的 `{ version: 1, sites: [] }` 原样保留。默认项使用稳定 ID，用户项生成唯一 ID。
3. 页面使用原生 HTML5 Drag and Drop 与独立手柄，复用项目已有范式，避免引入拖拽依赖。拖动源索引到目标索引时采用“移除后插入”语义。
4. 新增和编辑复用一个 Element Plus 表单弹窗。保存前裁剪文本、验证必填字段、限定 HTTP/HTTPS，并按规范化后的 URL 检查重复。
5. 图片显示状态由卡片级回退索引控制：自定义地址（若有）、`new URL(site.url).origin + '/favicon.ico'`、文字占位。图片错误只推进当前卡片的回退状态。
6. 卡片主体和打开按钮使用标准外链行为，编辑、删除和拖拽控件停止事件冒泡；Electron 继续由既有 external-link-handling 策略接管。

## Risks / Trade-offs

- [部分站点不在根路径提供 favicon] → 显示稳定的文字占位，不把图片成功作为可用性前提。
- [第三方图片加载会产生网络请求] → 仅请求用户已配置站点的图标，不增加聚合代理服务。
- [原生拖拽不适合触摸设备] → 当前产品为 Windows 桌面端，保持实现轻量且与既有交互一致。

## Migration Plan

无需迁移已有数据。首次加载新页面时创建独立存储项；回滚代码不会影响其他设置。
