## Context

详见 proposal.md。当前物品解析器会把每个 `{ 传奇属性 }` 段写入 `modifiers`，查价模型再把 `unique` 映射到官方 `explicit` namespace；因此游戏同样标为“传奇属性”的橙色说明在官方目录查无结果后进入 `unknownStats`。属性头是否带标签并不可靠，现有样本包含无标签但合法的传奇属性。

项目已经随版本保存 PoEDB 传奇页与图片快照。该页面按物品身份列出真实 `.explicitMod`，而传奇说明不在这组真实属性中，因此可以复用现有离线来源建立可靠的物品级白名单，不增加应用运行时联网。

## Goals / Non-Goals

**Goals:**

- 在官方 stat 解析之外，以当前传奇的版本化真实属性集合完成第二层语义判定。
- 对官方暂不支持的真实属性、遗产物品和降级目录保持可解释且不丢数据的行为。
- 让内置目录和在线刷新目录使用同一份可信传奇元数据。

**Non-Goals:**

- 不改变剪贴板原始解析结构、渲染端模型编辑、IPC 或官方查询协议。
- 不在运行时请求 PoEDB，也不抓取每件物品的独立悬浮页。
- 不使用颜色 OCR、位置启发式、无标签启发式或特定说明文案黑名单。

## Decisions

### 1. 快照记录物品级 matcher，而不是说明文字黑名单

将传奇快照升级到 schema v2，每条记录增加 `modifierMatchers`。生成器遍历对应物品容器内不含 `.item_description` 的 `.explicitMod`，将 `.mod-value` 节点整体替换为 `#`，再压缩空白并去重。这样只参数化数据源明确标出的掷值，正文中的技能等级等固定数字不会被误替换。

选择真实属性白名单而非说明黑名单，是因为说明文字集合没有稳定公开契约，而真实属性已经存在于当前版本快照页。选择物品级 matcher 而非全局 matcher，是为了避免某件物品的合法属性错误证明另一件物品的说明文字合法。

### 2. 官方解析优先，快照只裁决完全未映射的 unique 行

查价模型先执行现有官方目录解析。存在唯一 match 或候选时保持原行为；仅在结果为 `not-found` 且无候选时检查物品级快照。命中 matcher 的行继续进入 `unknownStats`，未命中且身份具有完整覆盖的行才被排除。

这比在剪贴板解析阶段删除更安全：解析器没有交易目录或身份覆盖信息，也无法区分真正不受官方支持的属性。分类留在主进程模型构建阶段，渲染端提交的模型不能伪造可信快照覆盖。

### 3. 通过运行时目录增强携带可信覆盖信息

现有传奇快照增强逻辑从仅补充图片扩展为同时复制 `modifierMatchers` 和内部完整覆盖标记。应用在构造查价服务前读取并校验本地快照，用其增强内置目录；后台官方 items/stats 刷新继续调用同一增强函数，因此刷新失败不会回退到未增强目录。

若本地快照加载失败，仓库使用现有 fallback，物品不带完整覆盖标记，模型保持旧的未知词缀展示并在目录状态中合并警告。这样失败模式是多显示而不是误删。

### 4. 匹配使用与详细复制数值格式兼容的严格模板

快照 matcher 以 `#` 表示一个带可选正负号的整数或小数；运行时先移除详细复制附带的掷值范围，再对整行进行规范化和全量匹配。复合段按解析器产出的单行效果分别判断，不做子串或模糊匹配，防止相似说明误命中。

## Risks / Trade-offs

- [PoEDB 页面结构变化导致 matcher 为空或错位] → schema v2 校验每条记录的数组结构，并以“意志交锋”等正式哨兵检查真实属性；生成失败不得覆盖现有资产。
- [国服客户端与 PoEDB 简体文案存在差异] → 官方解析仍优先；只有完整快照且官方完全未映射时才裁决，并用真实客户端样本覆盖规范化边界。
- [同步读取本地快照增加启动耗时] → 只读取和校验 JSON 元数据，不读取图片文件内容；保留现有本地图片协议与后台网络刷新。
- [工作区已有查价和浮窗改动] → 实现只修改快照、目录增强和模型分类的窄路径，测试按语义定位，不回退或重写无关差异。

## Migration Plan

1. 更新解析器、校验器和固定夹具，离线使用已保存的当前补丁原始页生成 schema v2 目录。
2. 在主进程启动装配中先加载并增强内置目录，再启用查价服务和后台官方刷新。
3. 加入模型与服务回归测试，验证正常、降级和缺失覆盖路径。
4. 回滚时可恢复 schema v1 与旧增强函数；模型在没有覆盖标记时天然退回原有未知词缀行为，不需要用户数据迁移。
