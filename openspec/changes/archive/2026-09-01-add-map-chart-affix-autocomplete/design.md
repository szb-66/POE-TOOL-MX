## Context

参见 `proposal.md` 的 Why。当前 `MapRollingProfilePanel.vue` 直接用普通输入框编辑黑白名单字符串，异界地图与航海海图共用面板，但由 `MapView.vue` 提供各自独立的预设对象。运行时在 JavaScript 和 Python 中都使用“名单字符串包含于实际词缀”的规则，因此候选选中值必须是实际文本中连续且跨档位稳定的片段。

现有 `FRAGMENT_CHART_MODS` 提供 POEDB 海图碎片词缀数据，但同时包含多档位、奖励附加行、传奇条目和来源标签为空的条目。只有来源标签明确为前缀或后缀的条目属于本次联想范围。异界地图尚无专用的可洗词缀目录。项目当前游戏数据基线为国服 S30 / POE1 3.29，并优先使用随应用提供的离线快照。

## Goals / Non-Goals

**Goals:**

- 为共用面板提供纯前端、同步、离线的分类候选搜索。
- 将候选的展示文本与实际保存的稳定关键词分离，并用数据测试保证关键词可被现有匹配器使用。
- 在不改变预设 schema 和自动化运行时的前提下改善编辑体验。

**Non-Goals:**

- 不把黑白名单改为结构化词缀 ID，不增加数值阈值或档位筛选。
- 不在运行时下载 POEDB 数据，不将通用装备词缀或查价目录混入地图候选。
- 不修改黑名单优先于白名单的规则，也不改变命中统计。

## Decisions

### 使用显式候选契约

新增共用候选形状 `{ value, example, affixType, tags, variants }`：`value` 是保存到预设的稳定连续关键词，`example` 是完整的可读示例，`variants` 保存用于验证的同类实际档位文本。搜索工具仅依赖这一形状，按 `value`/`example`/`tags` 进行包含搜索并返回最多 50 项。

不在运行时通过通用正则“删除数字”自动产生 `value`：数字位于句子中部时，删除后的文本不再是实际词缀的连续子串。对此，候选目录显式指定已审核的稳定片段，并用每个 `variant.includes(value)` 的测试防止数据回归。

### 地图与海图分别构建候选

异界地图新增 POE1 3.29 国服 POEDB 可洗显式词缀快照，数据源覆盖 `Maps_low_tier`、`Maps_mid_tier`、`Maps_top_tier` 与 `Maps_uber_tier` 四个地图池，以语义家族去重并显式存储候选契约。Uber 地图与普通阶级共用 `atlas` 联想类型，专属词缀并入同一离线目录；同一语义在多个地图池出现时合并代表文本，避免重复候选。数据文件同时导出游戏版本、快照日期与四档来源元数据，便于赛季更新和审计。

海图候选由专用构建器基于 `FRAGMENT_CHART_MODS` 生成：以来源标签为准，只接受精确的 `prefix`/`suffix`，`legendary`、空值及任何未知类型在读取词缀文本前即被排除；再按语义家族映射到已审核的稳定关键词，合并档位并排除奖励行。输出候选的 `affixType` 也必须保持为 `prefix` 或 `suffix`，不得因跨类型合并产生 `mixed`。无法安全产生稳定关键词的条目不进入候选，由目录覆盖测试显示缺口，不产生可能误匹配的短词。

不直接使用国服查价目录：该目录混合装备、特殊基底和综合条件，无法仅通过 stat 文本可靠判断是否为普通通货可洗的地图词缀。

### 在共用面板内完成联想

`MapView.vue` 将当前 `activeKind` 显式传入共用面板。面板将黑白名单的普通输入框替换为 Element Plus 自动完成输入，根据 `targetKind` 调用同步本地搜索。选中项的 `value` 直接写回原数组当前索引；普通输入更新仍直接写回同一字符串，因此自由输入和旧预设不需要分支或迁移。

候选查询包在容错边界内：未知类型、空目录或查询异常都向组件回调空数组，不改变输入值，不把候选可用性纳入启动校验。

## Risks / Trade-offs

- [POEDB 词缀随赛季变化] → 候选快照带版本和来源元数据，并在测试中校验条目契约；目录滞后时用户仍可自由输入。
- [稳定关键词过短会误命中] → 显式审核每个关键词，保持类型内唯一并用代表档位测试命中范围；不能安全表达的条目不生成候选。
- [Uber 词缀强度与文本可能不同] → 将 Uber 代表文本纳入同一候选的 `variants` 契约；Uber 专属语义保留独立稳定关键词，并测试可被搜索和实际文本命中。
- [海图无标签条目可能看似可洗词缀] → 严格以 POEDB 来源标签为准，不根据文本内容推断前后缀；目录测试注入传奇、空值和未知类型，确保均被过滤。
- [数据量增加前端体积] → 仅保留四档地图可洗显式词缀及联想所需字段，不复制完整 POEDB 页面或查价目录。
- [下拉层在窄屏中过高] → 使用独立 popper class 限制视口高度并允许纵向滚动，保留 Element Plus 默认键盘导航和焦点行为。

## Migration Plan

1. 先引入且测试离线目录与搜索工具，再将共用面板接入候选。
2. 不变更本地存储键或数据形状；部署后旧预设按原数组直接加载。
3. 回滚时移除联想组件接入和新增目录即可，无需回滚用户数据。
