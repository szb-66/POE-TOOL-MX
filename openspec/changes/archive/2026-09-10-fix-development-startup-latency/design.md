## Context

见 proposal.md。现有客户端日志 start → recover → processProvider 与首次 pollProcess 串行重复探测，主窗口在日志及地图初始化完成后才创建。做装更新器和独特装备快照静态引入 Cheerio。

## Goals / Non-Goals

**Goals:** 减少启动关键路径，保持日志历史恢复、业务就绪、安全停止和现有 IPC 响应外形。

**Non-Goals:** 不调整系统或游戏资源策略，不清除缓存或修改业务设置，不掩盖并行启动游戏时的异常样本。

## Decisions

- 客户端服务保存共享初始化 Promise、进行中的探测 Promise，以及生命周期代次。一次启动显式传递探测结果给恢复与首次轮询，不设置跨轮询的长期缓存。
- 窗口创建前仅构建对象、注册 IPC；窗口创建后按日志 → 地图顺序运行共享就绪任务。状态增加初始化阶段；依赖操作通过就绪门禁等待。故障由各服务记录，不传递为整个应用启动失败。
- 客户端设置切换和 Tailer 异步边界检查代次，停止立即失效旧任务；地图关闭先取消初始化，等待其收尾后清理已创建资源。
- 独特装备 HTML 解析独立为数据生成模块，现有生成脚本/测试迁移引用。做装更新器保留原实例与取消控制器，在 update 内动态加载解析器，加载后检查取消。
- 启动计时增加固定白名单子阶段；前端各启用模块记录 started/succeeded/failed，不更改 interactive 的含义。

## Risks / Trade-offs

- 后台初始化与 IPC/退出竞态 → 共享就绪 Promise、操作门禁、代次检查及延迟 Promise 回归测试。
- 提前显示不代表业务就绪 → 保留运行时就绪等待、错误展示及快捷键注册顺序。
- 游戏同时启动造成系统资源竞争 → 分场景记录基准，不将当下低负载测量当作异常场景已修复的证据。
- 规范旧目标为外壳 3 秒、首页 8 秒，现行工具为窗口 10 秒、完整可操作 15 秒 → 不修改阈值，分别报告可观测指标差距。

## Migration Plan

无持久化迁移。开发版验证通过后保留变更待归档；回滚只撤销本次改动，不还原其他未提交内容。
