## Context

见 proposal.md。路线和控制浮窗每 250ms 同步；已隐藏窗口仍被反复 hide。路线浮窗纯展示却开启 forward，停止后窗口保留。原生脚本可能临时隐藏/移动浮窗，因此 JS 缓存不能作为实际状态的唯一依据。

## Goals / Non-Goals

目标：减少浮窗原生副作用，保留现有采集和停止语义。
非目标：重写主窗口拖动、改自动化输入和保护、升级 Electron、打包。

## Decisions

- 路线浮窗 setIgnoreMouseEvents(true, { forward: false })；无需用透明度或销毁重建规避。
- 通过 isVisible() 检查实际显隐，getBounds() 比较 x/y/width/height，避免仅缓存上次目标导致原生截图操作后无法恢复。
- 隐藏操作保持计数和 finally 恢复最新状态，销毁后不再恢复；不改变状态推送及过期检测定时器。
- 用窗口替身统计副作用次数并验证状态迁移；开发版三轮采集停止拖动验收用于判断用户症状是否消失。

## Risks / Trade-offs

- 重复窗口操作和转发是已确认问题，但与跳动的因果尚待实测 → 保留对照记录，未完成实机验收不宣称根因已证实。
- 实机游戏状态可能不满足校准条件 → 不绕过预检；明确记录无法完成的验收项。
- 新增实际窗口状态查询 → 仅在必要同步时查询，避免无意义原生写操作。
