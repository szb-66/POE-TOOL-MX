## Context

页面已能逐格修改类型和方向，Python 识别器也已统一服务普通识别与自动放入，但修正只保存在当前库存状态。基础识别依赖三个全局阈值预设；本变更必须保留现有前台、DPI、坐标和自动化失败关闭行为。

## Goals / Non-Goals

**Goals:**
- 复用现有逐格修正交互形成可管理的本机反馈闭环。
- 用同一匹配实现覆盖页面识别与自动放入仓库验证。
- 素材异常时无条件回退现有标准基础识别。

**Non-Goals:**
- 不训练或发布新的机器学习模型，不上传、导入或跨设备同步素材。
- 不改变 3×3 海图区、词缀 OCR、网格校准和自动化输入安全规则。

## Decisions

1. 新建独立 `PuzzleCalibrationRepository`，使用 Node 标准库在 `userData/puzzle-calibration` 保存 PNG 和 JSON 索引。图块内容哈希作为 ID，标签不参与 ID，确保重新标注覆盖而不是产生冲突副本。
2. Python 对每个仓库格生成固定长度、L2 归一化的绿色形状与灰度航线特征，同时返回 PNG data URL。素材向量由同一提取器产生并带版本；版本不符或长度错误直接跳过。
3. 相似度使用余弦积，门槛固定为 0.965。候选按 `similarity - threshold + epsilon` 加权投票；仅有一个标签或最高票至少为次高票 1.5 倍时覆盖。该规则保持简单并避免含糊素材污染自动化。
4. 校准在基础结果产生后覆盖最终方向掩码，因此同一标签同时修正占用、类型和方向。仓库空格也生成特征，使标签零可修正假阳性；非零标签可修正漏识别。
5. 截图图块仅保存在 Pinia 的易失映射，不进入 `localStorage`。人工修正继续按现有方式持久化；没有易失图块时可编辑但不能保存素材。
6. Electron 服务向普通分析和自动放置配置传入同一校准索引路径。Python 仅在 `regionType == inventory` 时加载，海图区完全隔离。

## Risks / Trade-offs

- [原始像素特征对较大显示变化敏感] → 先对固定图标区域缩放和归一化；低于高门槛时回退基础识别。
- [错误人工标签会影响相似图块] → 采用显式保存、冲突投票、命中标识和可删除管理。
- [素材数量增长导致线性匹配变慢] → 单页最多 60 格且个人素材规模有限，保持 NumPy 矩阵点积；出现可测性能问题后再引入索引。
- [IPC 图块体积增加] → 仅返回单格 PNG，且不持久化到渲染存储。

## Migration Plan

启动后忽略旧识别档位，不改写其他海图设置。新素材目录按需创建；删除新目录即可回滚到固定基础识别。开发版完成测试与手工验证，不执行安装包构建。
