## Context

见 proposal.md。用户提供的真实基线/悬停截图（2000×1088）已在离线回放中复现"未找到效果浮窗"：暗场景中浮窗体灰度约 31、周边背景 12–45、基线在浮窗下方约 33，三条定位路径的绝对阈值（透明度边 >12、深色轮廓 gray<85、delta>28 及边带 >8）同时失守。实测信号分离度：基线变暗（before−gray > 6..12）在浮窗内覆盖 0.69–0.77，浮窗外噪声仅 0.04。干净基线合成回放下，变暗掩码候选能精确复原 663×207 奖励浮窗且既有错误裁剪矩形仍被 changed_panel_boundary 拒绝；对两浮窗裁剪的 OCR 已验证可读出全部条目。

## Goals / Non-Goals

**Goals:** 暗场景状态栏浮窗定位成功且 OCR 分流正确；既有亮场景样本、错误小候选拒绝、多尺度选择语义不变；房间（map/decorated）定位路径不变。

**Non-Goals:** 不改图标入口检测（icon_candidates）、OCR 引擎、错误展示语义、证据存储 schema；不新增"定位失败保存诊断帧"能力；不触碰进行中的资源校准变更。

## Decisions

- 候选源改为基线变暗掩码：`before − gray > 6`（int16 差分），横向闭运算跨文字孔洞后取外轮廓。plain 模式下当 `gray<85` 掩码覆盖大半画面（整场景全暗、轮廓粘连）时不提供信息，仅作普通场景补充；变暗掩码成为主候选源。理由：它是唯一与场景亮度无关的信号；绝对深色轮廓在暗场景把全图连成一个巨型轮廓。
- 完整性门槛由 `delta>28` 均值 ≥.18 改为候选矩形内变暗覆盖率（≥.5 量级，以回放标定为准），保留尺寸、目标位置、垂直邻近与 changed_panel_boundary 结构校验。理由：delta>28 在半透明浮窗上覆盖率不稳定（实测 0.24–0.47），而变暗覆盖率分离度（0.69–0.77 vs 0.04）高一个数量级；结构校验是上次修复防"背景粘连"的关键，必须保留。
- changed_panel_boundary 边带判定放宽：对比阈值 8→5 或边带宽度随面板尺寸缩放（gap 由面板宽派生），支持边取"当前边缘"或"基线差分"任一（现语义），以回归矩阵标定。理由：实测真实浮窗边带 p75 差值 2–19，阈值 8 处于信号边缘；放宽只影响接受侧，拒绝侧由"静态区域无差分"继续保证。
- 回放样本入库：三张截图导出为 `test/fixtures/sanctum/status-dark-{base,rewards-hover,afflictions-hover}.png` + evidence md。断言两浮窗在 1920/2560/3072/3840 四宽度定位成功、OCR 分流正确（5 条次要痛苦 / 3 项本轮待领奖励）；icon_candidates 在基线裁剪上复现入口坐标。
- 现有用例全部保持：sanctumRewardTooltipLocation（合成背景错误裁剪拒绝）、sanctumEffectCrop、sanctumEffectRecognition、sanctumStatusRewards、sanctumDynamic。

## Risks / Trade-offs

- 手动截图间隔数秒、场景噪声大于现场 0.15s 基线 → 回放条件更苛刻，通过即覆盖现场；若实现中发现噪声合并导致干净浮窗候选丢失，优先在候选提取里要求矩形覆盖率而非依赖轮廓填充度，不为通过测试放宽结构校验。
- 阈值放宽可能重新接受背景粘连候选 → 以既有错误裁剪拒绝用例与全部旧样本四宽度回放作为硬门禁。
- 2000×1088 样本非原生 3840 宽 → 失效模式已在原尺度复现；四宽度回放覆盖尺度泛化，现场验收为最终确认。
- 变暗掩码对基线错位（窗口抖动）敏感 → 基线与悬停帧来自同一冻结流水线（共享内存、同帧尺寸校验），现有"提示框截图尺寸变化"守卫不变。

## Migration Plan

纯 Python 定位算法与测试改动，无持久化、无接口变更；回退本变更代码即可回滚。默认仅开发版验证。
