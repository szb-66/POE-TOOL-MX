## Why

地图制作与背包自动入库都依赖背包扫描提前结束逻辑，但当前阈值分别硬编码为一次复制失败和连续三个空格，无法适配不同背包摆放习惯。需要提供一个共享、持久化且可校验的设置，让两类自动化使用一致的连续空格终止数量。

## What Changes

- 在全局背包设置中新增 `inventory.emptySlotThreshold`，允许配置 1–60，默认值为 3。
- 地图制作与背包自动入库在各自扫描顺序中达到该连续空格数后正常提前结束。
- 旧设置缺少字段或包含非法值时补齐、取整并钳制到有效范围。
- 检测进程运行期间修改阈值时不重启检测器；当前入库轮次保持配置快照，后续轮次使用新值。
- 自动入库使用不包含固定数量语义的通用完成原因。

## Capabilities

### New Capabilities

- `inventory-empty-threshold`: 定义共享连续空格设置、地图扫描终止语义、持久化和运行时更新行为。

### Modified Capabilities

- `bag-auto-stash`: 将固定连续三个空格的提前结束规则改为使用共享可配置阈值。

## Impact

影响设置页面与 Pinia 设置存储、地图脚本生成器及 Python 模板、背包运行配置与 Electron IPC、自动入库 Python 模板、相关 OpenSpec 规范和 Node/Python 集成测试。无需新增第三方依赖。
