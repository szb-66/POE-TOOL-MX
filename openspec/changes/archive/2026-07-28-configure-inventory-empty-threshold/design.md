## Context

全局设置的 `inventory` 当前保存背包首格中心和格子间距。地图制作在生成 Python 脚本时读取该设置，背包自动入库则在启动检测器时生成一份运行配置，并在每次入库启动时复制为脚本配置。两套 Python 扫描逻辑对空格的识别方式不同，但都存在硬编码的提前结束数量。

## Goals / Non-Goals

**Goals:**

- 提供唯一、可持久化、可校验的连续空格阈值。
- 让地图制作和自动入库使用同一设置，同时保持各自已有的空格识别机制。
- 检测器运行期间允许更新下一轮入库配置，不影响当前轮次快照。

**Non-Goals:**

- 不统一地图与自动入库的复制命令、重试次数或安全门禁。
- 不改变背包扫描顺序、额外背包布局或地图制作策略。

## Decisions

- 将字段保存为 `inventory.emptySlotThreshold`，因为它描述共享背包扫描行为，并可随现有 `inventory` 配置同时传入地图生成器与自动入库配置构建器。
- 新增独立的规范化工具，统一采用默认值 3、整数化和 1–60 钳制，避免页面、Store、IPC 和脚本生成器各自解释边界。
- 地图脚本只把明确复制失败、序列号未变化或回退路径空内容计为空格候选；复制到新内容后立即清零，即使后续解析失败或类别不是地图。
- 自动入库继续冻结每轮配置。渲染进程通过 IPC 更新主进程保存的 `latestConfig`，因此新值仅影响下一次派生的入库脚本配置。
- 完成原因改为 `consecutive-empty-threshold`，避免阈值不为 3 时产生错误语义。

## Risks / Trade-offs

- [地图脚本现有回退路径无法区分陈旧的非空剪贴板] → 保留现有识别边界，不把该问题扩展到本次配置变更。
- [阈值设为较大值会弱化提前结束效果] → 页面明确说明语义，并将上限限制为完整原生背包的 60 格。
- [工作区存在其他未提交改动] → 只对重叠文件做局部补丁，不替换整文件。
