## Context

参见 `proposal.md`。当前 `PriceCheckOverlayManager` 在首次创建窗口时按鼠标所在显示器计算默认宽高，窗口实例存活期间复用 `getBounds()` 中的尺寸；窗口关闭或应用重启后没有尺寸来源。项目已有主进程 `window-state.json`，并通过合并写入保存主窗口及其他浮窗状态。

查价浮窗的位置与召唤时的鼠标和显示器绑定，因此不能把完整边界当作固定窗口布局恢复。Electron 的程序化 `setBounds()` 也可能产生尺寸相关事件，持久化路径必须只识别用户发起的缩放。

## Goals / Non-Goals

**Goals:**

- 在主进程保存并恢复用户明确调整的查价浮窗宽高。
- 让保存尺寸跨浮窗关闭和应用重启生效，同时保持当前的动态定位策略。
- 对损坏配置和不同显示器工作区进行安全归一化。
- 让程序化创建、定位和工作区钳制不会误改用户偏好。

**Non-Goals:**

- 不保存或恢复查价浮窗的 `x`、`y` 坐标。
- 不改变浮窗的失焦关闭、鼠标离开关闭、置顶或单实例行为。
- 不把窗口尺寸加入渲染端查价设置、查询模型、IPC 请求或官方交易请求。
- 不引入新的用户可见尺寸设置项，也不要求打包验证。

## Decisions

### 1. 复用主进程窗口状态文件并使用独立字段

在现有 `window-state.json` 中增加独立的 `priceCheckOverlaySize: { width, height }` 字段，通过窗口状态模块的合并写入保留其他窗口数据。尺寸属于 Electron 窗口生命周期状态，放在主进程可避免渲染端尚未加载、浮窗关闭过快或 `localStorage` 分散所有权的问题。

备选方案是写入查价 Pinia 设置或单独创建配置文件。前者会把窗口状态混入查询业务契约并需要额外 IPC 同步；后者会增加无必要的文件和迁移面，因此不采用。

### 2. 保存偏好尺寸，按当前显示器计算实际尺寸

持久化值只接受有限正数并归一为整数。创建浮窗时先读取偏好尺寸；没有合法值时沿用当前屏幕比例默认值。实际创建尺寸分别取偏好值与当前工作区宽高的较小值，再交给现有定位函数确保完整可见。

工作区钳制只影响本次实际尺寸，不回写偏好值。这样用户从大显示器临时切换到小显示器后，回到可容纳的显示器仍能恢复原始尺寸。除有效性和当前工作区限制外，不新增缩放下限，以免改变用户现有可手动调整的范围。

### 3. 以用户缩放意图区分程序化边界变化

在 Windows 支持的窗口用户缩放事件上标记一次用户缩放会话，只在该会话产生的尺寸稳定后读取最终 `getBounds()` 并保存宽高。连续拖动使用短防抖减少同步磁盘写入；窗口在待保存期间关闭时刷新最后一次有效尺寸。

程序创建、复用时的 `setBounds()`、显示器工作区钳制和自动重新定位没有用户缩放标记，因此不得进入保存路径。备选方案是监听所有 `resize` 后比较尺寸，但无法可靠区分自动边界变化，可能把小屏幕钳制结果永久覆盖用户偏好，因此不采用。

### 4. 将归一化与事件判定做成可单测边界

尺寸读取、有效性判断、工作区钳制以及“仅用户缩放可保存”的状态转换应与 Electron 事件绑定保持可分离，窗口状态读写通过现有模块或可注入回调接入。测试可使用窗口替身验证事件顺序，不依赖打包应用或真实拖动。

## Risks / Trade-offs

- [连续缩放触发大量事件和磁盘写入] → 使用短防抖，并在缩放结束或关闭前只提交最后尺寸。
- [程序化 `setBounds()` 被误判为用户缩放] → 保存必须具备用户缩放事件标记，自动定位路径不设置该标记。
- [保存尺寸大于当前显示器] → 仅对本次实际尺寸按工作区钳制，不覆盖偏好值。
- [窗口状态文件损坏或旧版本没有字段] → 沿用现有容错读取并回退到当前默认尺寸。
- [应用在防抖完成前异常退出] → 正常关闭路径刷新待保存值；进程被强制终止时可能丢失最后一次拖动，这是避免每帧同步写盘的可接受取舍。

## Migration Plan

1. 扩展现有窗口状态结构以读取和合并写入可选的查价浮窗尺寸字段；旧配置无需迁移。
2. 在查价浮窗创建和用户缩放生命周期中接入读取、钳制与防抖保存。
3. 通过主进程单元/集成测试、完整测试集和开发版手动拖动验证确认行为。
4. 回滚时移除读取和保存逻辑即可；遗留字段会被旧版本忽略，不阻塞启动。
