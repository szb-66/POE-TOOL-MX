## Context

参见 proposal.md。当前渲染页能接收 `puzzle-analysis-updated` 并显示词缀探测进度，但识别期间游戏位于前台，单屏用户看不到主窗口。既有海图区域遮罩会在词缀探测前关闭，以免覆盖鼠标目标或污染 OCR，因此不能承担持续状态提示。

## Goals / Non-Goals

**Goals:**

- 由主进程统一覆盖按钮、快捷键和自动触发的识别生命周期。
- 在不改变识别结果及 IPC 契约的前提下提供即时阶段进度和结束吐司。
- 保证提示不抢焦点、不截获输入、不进入识别截图，并能抵抗异步竞态。

**Non-Goals:**

- 不增加提示开关、声音、系统通知或持久化设置。
- 不改变词缀匹配算法、自动化门禁、停止机制及主页面现有反馈。
- 不打包或发布正式版本。

## Decisions

### 使用独立的预加载提示窗口

新增专用识别反馈窗口管理器和 Vue 路由，而不复用会在采集期间关闭的 `PuzzleOverlayManager`。管理器在应用服务初始化时预创建透明隐藏窗口，后续只更新边界和快照，避免首次识别时等待窗口加载。窗口固定为置顶、不可聚焦、鼠标穿透并启用内容保护，按框选元数据中的物理显示器边界换算为 DIP 后置于顶部居中。

替代方案是复用主窗口消息或现有区域遮罩；前者单屏不可见，后者与既有采集隐藏规则冲突，均不能满足要求。

### 主进程拥有反馈生命周期

`PuzzleAnalysisService` 接收独立的 feedback overlay 依赖。碎片识别在区域和页签校验后、首次分析子进程启动前开始状态会话；每页分析前更新页进度，进入复制阶段后根据已知占用格总数显示准备状态，并用既有 Python `EVENT` 更新逐格进度。独立边缘识别在区域与锁校验通过后开始会话，并用逐段 `EVENT` 更新 12 段进度。

服务在返回结构化结果前计算结束级别和摘要，直接切换为吐司。这样所有入口只调用同一服务，不会由页面和自动完成调用方重复显示。基础校验或锁失败时，如请求仍携带可用显示器元数据，则直接显示失败吐司而不显示运行状态。

### 采用会话代次隔离异步更新

管理器为每次 `showRunning` 生成单调递增会话 ID。`updateProgress`、`showResult`、自动关闭计时器和显隐回调都必须匹配当前 ID；新会话会取消旧计时器。应用退出使用无条件 `close` 销毁窗口，普通任务结束仅把当前会话切换为吐司或隐藏。

### 结果分级复用现有统计语义

碎片完整成功要求探测未跳过且 `unknown` 为 0；`unveiled` 作为有效业务结果计入已处理但使吐司采用黄色，以提醒用户该格没有可匹配词缀。边缘完整成功要求 `matched === attempted` 且未跳过。返回 `success: false` 为失败，`EMERGENCY_STOPPED` 单独映射为停止。失败文案只取既有错误 message 的短文本并限制长度，不展示 OCR 原文、路径或标准错误输出。

### 保持提示不进入采集内容

窗口启用 Electron 内容保护，视觉位置选择目标显示器顶部安全区，不覆盖框选网格。开发版验收必须使用实际屏幕采集确认提示未进入形状截图和 `mss` OCR 截图；若运行平台无法兑现内容保护，则该验收失败，不能以降低 OCR 准确率为代价继续交付。

## Risks / Trade-offs

- [不同 Windows 版本对内容保护行为存在差异] → 在项目支持的 Windows 10/11 开发环境以真实采集验证，并保持窗口远离框选区域。
- [预加载窗口在 Vite 尚未就绪时加载失败] → 复用现有开发/生产路由装载分支，窗口未就绪时缓存最新快照，在 `did-finish-load` 后只显示当前会话。
- [旧子进程事件晚到导致提示倒退或消失] → 所有管理器更新携带会话 ID并校验，启动新任务时清理旧计时器。
- [错误文案过长或泄露诊断细节] → 仅展示用户可见 message，去除换行并截断；完整诊断继续留在现有日志与主页面。

## Migration Plan

- 仅增加内部窗口、视图和服务依赖，无配置或数据迁移。
- 开发版验证失败时可整体移除新管理器注入和路由，现有识别及页面进度仍保持原行为。
