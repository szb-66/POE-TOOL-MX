## Context

当前应用已有共享界面检测进程、自动化锁、物理屏幕区域框选、无焦点游戏内按钮浮窗，以及由主进程管理Python取件脚本的模式。商城配方校准仍保存在自身设置内；旧金边方案已完全删除。

## Goals / Non-Goals

**Goals:**
- 用单格中央区域统计避免大型仓库轮廓合并。
- 正式扫描与预览共用同一检测实现。
- 不使用剪贴板，并用原格视觉变化确认转移。
- 保持仓库自动取件与账号、仓库API和商城配方开关独立。

**Non-Goals:**
- 不输入或清空游戏搜索词，不切换仓库页签。
- 不扫描背包剩余空间，不在背包满后暂停续跑。
- 不保证任意阈值都能区分自然发光物品；用户通过预览调参。
- 不判断游戏搜索高亮状态；高亮过滤作为后续能力叠加。

## Decisions

### 公共校准由界面检测设置持有

新增`stashGridCalibration { root, folder }`到公共界面检测存储，首次加载时从旧商城配方校准迁移。商城配方运行载荷改为读取公共值。相比让新功能依赖商城配方设置，此方式保持功能独立且只有一个校准来源。

### 检测核心放在可导入的Python脚本

脚本同时支持`--preview`和正式运行，纯函数负责布局评分、切格、统计量、候选生成和标注图。主进程只管理配置文件、子进程、事件与锁，便于用固定截图直接测试检测逻辑。

主窗口触发预览时不以“游戏当前已在前台”作为启动前置条件；Python脚本在截图前使用Win32查找中英文游戏窗口、恢复最小化并激活，确认前台成功后等待界面稳定再采集。无法激活时失败关闭，避免截取流放助手窗口。

### 布局按网格投影评分

对两个校准截图分别计算水平和垂直边缘投影。周期置信度在候选格距附近折叠投影并搜索相位，要求两个方向都存在稳定周期，因此少量框选边缘、缩放取整和格线起点偏移不会使有效仓库跌出阈值。12与24的判型使用低分位结构边缘在半格距处做两轴自相关：真实24格线会在约半个普通格的距离持续相关，而12格仓库中局部重复物品不会同时形成两轴贯穿结构。选择文件夹内外校准时，周期置信度负责有效性门槛，低分位结构格线对齐度参与排序，避免密集物品边缘压过格线后选择错位区域。低于最小置信度时停止，不按区域尺寸猜测布局。

### 初始候选冻结并局部复查

初始全屏截图生成候选格；鼠标移动并稳定后，每格操作前只重新计算该格。点击后轮询同一局部图像的归一化平均绝对差，首次没有变化时等待并重试同一格一次，两次均未变化才发出`inventory-full`。成功后比较点击前后的完整仓库图，将从点击格开始、发生变化且四向连通的候选格标记为同一件多格物品的已清空占位；后续直接跳过这些格，不再依赖彩色空背景必须降到阈值以下。未发生变化的相邻物品不会被合并。这避免游戏漏接和多格残留候选造成的错误停止，同时保持每件最多两次点击。

### 控制浮窗承载两个独立功能

保留现有浮窗窗口与拖动位置，由控制管理器合并商城配方状态和仓库取件状态。Vue视图按`recipeEnabled/stashPickupEnabled`渲染按钮，不创建第二个重叠浮窗。

## Risks / Trade-offs

- [固定阈值会受仓库背景和显示效果影响] → 普通/大型分别保存参数，并提供正式扫描同源的标注预览。
- [低纹理细长物品可能低于阈值] → 提供方差、亮度、饱和度模式和预览，由用户针对当前仓库调参。
- [游戏帧延迟可能被判断为背包满] → 在全局操作等待基础上进行短周期轮询，而不是单次截图。
- [子进程异常留下Ctrl] → Python与主进程停止路径都执行释放，主进程最终释放自动化锁。

## Migration Plan

首次加载公共界面检测设置时，公共校准存在则保留；否则复制旧`chaosRecipeSettings.calibration`。回滚时商城配方旧校准仍保留在本地设置，可恢复旧读取路径。
