## Context

全局快捷键由 `DEFAULT_GLOBAL_SHORTCUTS` 定义允许字段，经设置 Store 规范化和持久化，再由统一服务整组注册并按字段分发。当前设置页没有覆盖全部允许字段，战斗页单独维护三个入口，旧配置中的字段又会在未知字段不参与迁移判断时留存在本地数据中。

## Goals / Non-Goals

**Goals:**

- 让允许字段、设置汇总、运行时注册和动作分发使用同一受支持集合。
- 让旧字段在首次加载时被确定性清理，并保持其他配置不变。
- 让回城快捷键的两个入口共用现有事务式提交路径。
- 让配方只由页面控制开始与暂停，并复用全局紧急停止终止运行。

**Non-Goals:**

- 不改变战斗辅助、回城或海图按钮对应的业务服务和安全预检。
- 不修改业务预设、游戏动作按键或开发者固定快捷键。

## Decisions

- 以删除默认结构字段作为废弃快捷键的唯一运行时边界；规范化天然丢弃自动喝药、海图分析和配方专用快捷键字段，避免为已删除功能保留兼容分支。
- 设置加载迁移同时比较保存字段与允许字段集合，发现废弃字段即重新持久化；这比只在注册前过滤更彻底，可消除隐形配置。
- 回城模块直接读取 Store 中的 `portal` 并调用现有单键事务提交函数，不复制到战斗配置对象，避免双数据源。
- 海图保留公共分析函数供页面按钮调用，仅删除快捷键字段、分发映射和界面提示。
- 配方页面继续调用现有开始、暂停/继续操作；停止由既有全局紧急停止分发统一覆盖，不保留配方专用停止字段或动作分支。

## Risks / Trade-offs

- [旧用户依赖已保存快捷键] → 按已确认需求无条件清理六个字段，并通过设置迁移测试固定行为。
- [两个回城配置入口状态不同步] → 两处均渲染 Store 值且只通过同一提交函数更新。
- [规范或帮助仍宣传已取消入口] → 全局搜索相关字段和“海图识别快捷键”等文案，并增加静态集成断言。
- [配方专用停止移除后无法终止] → 验证全局紧急停止继续调用配方停止服务并释放输入状态。

## Migration Plan

1. 新版本加载设置时规范化到新的允许字段集合。
2. 发现任意未知/废弃快捷键字段时立即保存清理后的设置。
3. 初始化全局快捷键时使用清理后的集合，旧组合不再注册。
4. 回滚旧版本时不会恢复已删除值，用户如需要受支持快捷键须重新配置。
