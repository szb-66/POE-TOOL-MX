## Context

参见 [proposal.md](./proposal.md) 的动机。当前 Python 探测器在每个边缘移动鼠标前截取基准帧，随后将完整 1200×480 画面缩小为 32×32 二值签名，要求整框连续两帧完全相同。实际画面同时包含动态场景、发光碎片与仓库等级文字，因此目标词缀已经稳定时整框签名仍可能变化；等待超时后脚本直接 OCR 最后一帧。当前全帧 OCR 还会把紫色目标文字与白色 `L:83` 合并。

两张新样本验证了目标词缀完整位于现有捕获范围内，且用蓝紫色文字掩膜可分别得到「相邻区域包含」+「8个额外的海兽群」和「相邻区域的词缀数值提高」+「60%。」。因此无需扩大捕获范围，问题可以在目标文字提取与失败证据两个边界内解决。根据实际验证反馈，稳定性判定本身即根因：悬浮浮窗动画远短于固定等待窗口，整框或跨帧判定都只会增加耗时与复杂度，简化为「固定等待后单帧采样」即可。

## Goals / Non-Goals

**Goals:**

- 让边缘识别是否稳定只受目标词缀文字影响，不受捕获框内动态背景和仓库动画影响。
- 复用现有 65 条目录及 JavaScript 匹配器，避免 Python 与主进程产生两份匹配规则。
- 对 OCR 分段、等级粘连和轻微标点差异保持稳健，同时维持 0.82 阈值和唯一性约束。
- 让每个未知结果都尽可能携带本次运行的可读原文，下一次失败可直接定位层级。
- 让单段识别耗时接近「悬停→截图→OCR」的最简路径，不引入不必要的帧间判定。

**Non-Goals:**

- 不增加热点手动微调或多位置重试；热点沿对应方向按海图区物理宽度或高度的 6% 外移，且不重复乘 DPI，继续保留屏幕边缘钳制。捕获窗调整为以鼠标为中心的 800×800 逻辑正方形。
- 不更换 RapidOCR 模型、不降低目录阈值、不新增依赖。
- 不改变公开 IPC、`borderMods`、`fragmentMods` 或目录数据结构。
- 不在本变更中处理碎片剪贴板采集、形状识别和自动放入逻辑。

## Decisions

### 0. 热点按海图区物理尺寸同比缩放

以当前稳定工作的 825×828 物理像素海图区和 50 像素热点为标定，取 6% 作为外移比例。上下热点使用海图区高度，左右热点使用海图区宽度，分别四舍五入到物理像素；825×828 下均保持 50 像素。框选区域已经是物理像素，因此不再乘 `scaleFactor`；DPI 仍只参与捕获窗与文字字号换算。这样无需新增用户配置，即可随游戏分辨率和 UI 尺寸同比缩放。

### 1. 以鼠标为中心的正方形捕获 + 蓝紫色目标文字 ROI

探测器把捕获窗从 800×320 偏下矩形调整为以鼠标为中心的 800×800 逻辑正方形（DPI 换算后钳制在当前显示器内），覆盖浮窗渲染在光标任意一侧的情况（实测 W1/E1 浮窗比其它边缘更靠上，偏下矩形会漏掉）。对每次捕获生成蓝紫色优势像素掩膜，按词缀文字字号先验（逻辑高度约 25px，随 `scaleFactor` 换算物理高度）过滤噪点与大面积蓝紫背景（如海面），清理小噪点后按行带聚类目标文字连通域，取离鼠标锚点最近的行作为联合边界，并渲染为黑字白底的小 ROI；颜色提取失败时保留一次整帧 OCR 作为兼容回退和诊断证据。

选择颜色 ROI 是因为游戏用稳定的蓝紫色显示边缘词缀，而同框仓库等级使用白色，能够在不理解中文内容的前提下隔离目标；字号过滤与锚点行选择避免正方形内其它蓝字（如魔法地图名）与蓝色背景抢占 ROI。备选方案：继续扩大截图或延长等待。两者都会增加动态背景与仓库文字，无法消除整框稳定条件的根因。只缩小固定坐标区域也不可靠，因为东西南北浮窗方向和长文本宽度不同。

### 2. Python 固定等待后单帧采样，主进程判定目录语义

每个边缘移动鼠标后等待固定时间（300ms，浮窗动画约 200–400ms，可通过 `settleMs` 调整），抓取一帧并优先 OCR 小型目标 ROI；ROI 缺失时回退一次整帧 OCR。内部 Python `RESULT` 返回旧式单边缘 `texts` 文本行，服务向渲染进程返回的仍是现有 `{status, mod, confidence, rawTexts}`。Electron 主进程对文本执行唯一的 `matchBorderMods`，命中即成功，未命中标记未知并保留原文。

此决策避免把目录和相似度算法复制到 Python，也避免任何帧间稳定性状态机。备选方案（三帧采样 + 连续两次目录命中）曾纳入实现，实际验证表明动画窗口外的额外采样只是重复 OCR 同一文字，每段耗时约 3–5 秒且无识别收益，已按反馈简化删除。

### 3. 在共享匹配器生成有限的阅读顺序候选

`matchBorderMods` 在保留原始逐行候选的同时，增加相邻 2–3 段及完整短序列的阅读顺序拼接候选，用于颜色 ROI OCR 将一条词缀拆为多段的情况。所有候选仍依次经过精确、唯一完整包含、结构和 0.82 模糊匹配；多个完整目录命中或共享复合行不得提前成功。

只拼接相邻且数量有限的段，避免组合爆炸，也避免把整张全帧 OCR 的大量无关 UI 任意排列。测试必须覆盖局部文本、非相邻无关文本和多目录歧义。

### 4. 未知结果保留本次证据

若单帧文本未命中目录，服务将该帧非空文本写入现有 `rawTexts`；文本为空则 `rawTexts` 为空，不得覆盖已有非空原文。

边缘悬停在未知状态下显示「词缀：未知」并逐行附带 `rawTexts`。不新增持久化截图，也不把 OCR 原文写入通用诊断文件，避免磁盘增长和把游戏画面纳入长期诊断；真实回归夹具只保留经人工确认的最小游戏词缀区域。

### 5. 删除被替代的整框严格稳定路径

新流程稳定后删除不再使用的整框 `32×32` 完全相等判定及相关失败尝试代码；保留通用捕获、DPI、增强图像和兼容回退中仍有调用的部分。清理以引用搜索和 Python/Node 全量测试为准，避免两套稳定策略并存。

## Risks / Trade-offs

- [游戏颜色主题、HDR 或后处理使蓝紫色阈值漂移] → 使用通道相对优势而非单一固定 RGB，并保留全帧 OCR 回退；用多张 150% DPI 真实夹具覆盖亮暗背景。
- [颜色掩膜把蓝色游戏特效纳入 ROI] → 通过字符连通域尺寸、水平文本布局和目标区域联合边界过滤；最终仍须经过目录唯一性和既有阈值。
- [固定等待不足使浮窗动画未完成] → 单帧读到中间态时仅该段标记未知并保留原文，不阻断其余边缘；等待时长可通过 `settleMs` 调整。
- [同一词缀被拆分或粘连方式不同] → 阅读顺序拼接吸收空格、标点和分段差异，唯一包含吸收等级文字粘连。
- [严格要求唯一目录命中增加个别漏识别] → 掩膜失败时使用兼容回退；若仍未知则保留原文，不通过降低阈值制造误匹配。

## Migration Plan

1. 先以真实夹具建立颜色 ROI、阅读顺序拼接和等级粘连的失败测试。
2. 实现固定等待后单帧采样与兼容回退，接入服务匹配与未知原文展示。
3. 删除被新流程替代且无引用的整框严格稳定代码，运行受影响测试和 `npm test`。
4. 重启管理员权限开发版，识别 12 段并重点检查 E0/W0；若仍未知，直接读取悬停中的 `rawTexts` 定位。

回滚时恢复单样本全帧 OCR 路径即可；公开 IPC 与持久化数据未迁移，因此不需要数据回滚。不执行打包。
