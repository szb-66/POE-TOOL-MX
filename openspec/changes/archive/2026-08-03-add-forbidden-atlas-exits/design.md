## Context

海图求解当前以十二位边界掩码枚举候选，Pinia 仅保存 `requiredExits`，页面出口按钮只处理左键。两个区域配置已由同一组配置卡渲染，但对应框选按钮仍位于页面顶部。

## Goals / Non-Goals

**Goals:**
- 在现有边界掩码枚举中加入互斥的必选与禁止硬约束，不改变最优解计分规则。
- 以单一页面状态源驱动三态交互、样式、无解提示与清空操作。
- 复用现有配置卡数据，把区域入口与对应状态和预览放在一起。

**Non-Goals:**
- 不持久化出口选择，不修改识别、IPC 或自动放置负载。
- 不改变方案分数含义、同分方案顺序或 100 个展示上限。

## Decisions

1. 求解器接受 `forbiddenExits = []`，把它规范化为第二个十二位掩码。候选边界掩码先校验包含全部 required 位，再校验与 forbidden 位无交集；两组约束相交时直接返回 `NO_SOLUTION`。这比在生成布局后检查出口数组更直接，也保留现有稳定枚举顺序。
2. Store 继续使用两个数组而非单个三态对象。左键操作先从禁止数组移除再切换必选，右键操作反向处理，保证正常 UI 永远互斥。统一清空直接一次性置空两个数组并只重算一次。
3. 新识别沿用 `resetConstraints` 同时清空两组；`preserveSolution` 的库存同步路径不触碰约束。该边界与现有自动放置恢复流程一致。
4. 配置卡数据增加按钮文案，按钮放入卡片标题操作区。出口按钮用警示色描边表示必选、危险色和删除线表示禁止，已连接绿色仍作为方案结果状态。

## Risks / Trade-offs

- [右键缺少可发现性] → 在方案上方常驻说明左右键语义，并为按钮提供状态标题。
- [逐个切换导致重复求解] → 统一清空由独立 Store 操作一次性更新两组状态，只执行一次重算。
- [非法调用传入冲突约束] → 求解器明确返回结构化无解，避免静默选择其中一种约束。
