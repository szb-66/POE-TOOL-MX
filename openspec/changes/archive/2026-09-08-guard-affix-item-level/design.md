## Context

组合条件已经随目录候选保存阶级及 `requiredLevel`，但界面和 Python 自动化各自没有利用这些数据做组合级预检。共享编辑器同时服务普通、精华和花园制作，批量流程则会在正式制作前读取全部目标。

## Goals / Non-Goals

**Goals:**

- 用单一纯函数定义组合物等要求，避免界面与自动化计算漂移。
- 在所有制作路径的首次安全读取之后、任何制作输入之前拦截。
- 保持现有预设和 IPC 兼容。

**Non-Goals:**

- 不验证词缀与实际底材、势力或制作来源的完整可生成性。
- 不为自定义关键词猜测物等。
- 不改变组间 OR 匹配语义；物等预检按用户确认的保守规则检查每个启用组合。

## Decisions

### 共享派生函数，不持久化计算结果

在 `affixConfig` 中从规范化条件派生单条件和组合要求。最低 T 为 N 时纳入现有 `tier <= N` 的阶级，再取最低 `requiredLevel`；不限 T 时纳入全部阶级。组合取所有已知条件要求的最大值，并同时返回是否存在未知有效条件。

备选方案是把结果写入预设，但目录或规范化规则变化后会产生过期数据，因此不采用。

### 将预检元数据嵌入生成脚本

生成 Python 自动化脚本时从当前运行预设构建启用组合要求并嵌入只读数据。脚本用首次解析结果的 `level` 校验：单件流程在 `craft_one_item` 调用前检查，批量流程在扫描每个待制作目标时检查，从而覆盖普通和专项制作且不新增 IPC。

### 复用结构化异常停止通道

不足时调用既有运行停止函数并使用 `AFFIX_ITEM_LEVEL_INSUFFICIENT`，原因文本携带当前物等及所有失败组合。这样沿用现有错误音效、日志、主进程状态和悬浮窗提示。

## Risks / Trade-offs

- [保守检查会因一个备用组合要求过高而停止，即使其他组合可达] → 这是用户明确选择的规则；提示列出具体组合，便于调整或禁用。
- [自定义关键词可能实际需要更高物等] → 界面明确显示未知，运行时不做无法证实的拦截。
- [批量预检错误可能发生在批次中途] → 在现有全批目标预检阶段完成物等校验，保证正式制作前发现。
