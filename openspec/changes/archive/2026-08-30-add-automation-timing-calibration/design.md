## Context

现有自动化时序已经由 `operationDelayMs`、`adaptiveTiming`、`adaptiveTimeoutMs` 和 `fixedTiming` 组成完整全局协议，设置提交会先同步所有持续消费者，失败时回滚，离散脚本按启动快照运行。背包网格提供第一格中心和单格尺寸，现有 Python 自动化也已经具备游戏聚焦、逐次前台检查、剪贴板序列号和全局自动化互斥；本变更应在这些边界上增加探测，而不是建立第二套配置或输入通道。

## Goals / Non-Goals

**Goals:**

- 用五个不同物品的可验证复制结果测出本机最低稳定悬停和键盘输入时序。
- 对无法无副作用实测的字段给出来源透明、只增不减的保守推导。
- 任一安全检查、测量或运行时同步失败时不留下部分配置、按键状态、锁或物品文本。
- 让推荐算法、进程生命周期、设置应用和界面状态能够分别进行确定性测试。

**Non-Goals:**

- 不在启动时或后台自动运行校准，不根据 CPU 型号、跑分或网络延迟猜测游戏输入时序。
- 不点击、拿起、存取或移动游戏物品，不独立实测鼠标按钮和仓库动作。
- 不改变现有时序字段语义、默认值、持久化版本、自动化重试策略或自适应开关。
- 不保存检测历史、不上传测量或物品数据、不打包发布。

## Decisions

### 1. 独立校准服务持有安全生命周期

主进程增加一个校准服务，由它获取 `AutomationLock`、解析 Python 运行时、创建一次性配置、启动探测进程、转发脱敏进度并在所有结束路径释放资源。它接入全局紧急停止协调器；同一时刻只允许一个校准实例，重复停止返回同一个已停止状态。

探测进程使用 stdin 控制消息和可中断的短间隔等待。停止时先发送合作式取消，使 Python 在 `finally` 中释放 `C`、Ctrl 和鼠标按钮并恢复剪贴板；一秒内未退出才强制终止，并执行同一 Python 运行时中的输入释放兜底。每次移动、按下、释放和剪贴板轮询前后都检查取消信号、总时限和游戏前台。

备选方案是把校准并入背包入库模板，但该模板包含点击与转移路径，扩大误触风险且无法形成独立进度/停止契约，因此不采用。

### 2. Python 只输出测量证据，JavaScript 计算建议

Python 配置只包含规范化后的当前时序、背包第一格中心与单格尺寸、允许的游戏标题/进程名和校准标识。目标坐标固定为第一列五行中心；脚本只输出物品哈希、候选成败、最低稳定值、剪贴板 P95、可选画面稳定 P95、样本数和耗时，不输出原文。

共享 JavaScript 纯函数接收测量证据和校准前的完整时序，执行安全余量、取整、默认/当前值下限与实测/推导标注，再经 `normalizeAutomationTiming` 生成完整建议。这样推荐规则不散落在 Python、IPC 和界面中，也能用无游戏环境的单元测试覆盖。

备选方案是让 Python 直接返回最终配置，但会复制默认值和字段规范化规则，并使运行时升级更容易产生协议漂移，因此不采用。

### 3. 分阶段搜索并用最终组合确认

基线使用 500ms 悬停、100ms 修饰键稳定、50ms 按键保持、50ms 键盘释放稳定和 1000ms 剪贴板窗口依次读取五格；五个有效文本在内存中转为哈希且必须互不相同。之后按悬停、修饰键、按键保持、键盘释放稳定的顺序搜索，每次固定其他字段为保守值或已经得到的带余量值。探测脚本不点击鼠标，因此释放阈值只构成 `releaseSettleMs` 的键盘测量依据，不能证明鼠标右键选通货已经被游戏接收。

候选搜索以 10ms 为单位，先扩展得到失败/成功区间，再二分寻找最低 5/5 候选；候选在 15 次交替复制确认中失败时按 10ms 递增重试，直到通过、达到字段上限或总时限。最终组合再执行 15/15 确认，并从成功样本记录剪贴板更新 P95。

画面测量在目标切换后截取目标格邻域并轮询到连续帧差低于阈值；动画、遮挡或捕获失败导致无法形成稳定样本时，`visualP95` 为空而不是猜值。运行时需要 `pynput`、`pyperclip` 与 `mss`，均来自现有随附 Python 环境。

### 4. 推荐规则集中且来源可见

`guard(x)` 定义为 `ceil10(max(x * 1.25, x + 10))`。直接实测字段采用最低稳定值或剪贴板 P95的 `guard`；综合响应信号取带余量剪贴板 P95与可用画面 P95的最大值，缺少画面时只用剪贴板并降低置信度。

推导字段使用规范中的固定公式：按钮保持至少为当前值、20ms 和推荐按键保持的最大值；共享给键盘与鼠标的释放稳定至少为当前值、20ms 和键盘释放实测安全值的最大值；仓库页签/存仓分别至少为当前值、既有默认值和综合信号两倍；画面验证至少为当前值、550ms 和综合信号三倍；自适应上限取当前值、1000ms 和综合信号四倍后向上取整到 100ms。`releaseSettleMs` 与其他无法直接实测鼠标动作的字段标记为 `derived`，所有结果携带依据值和置信度。

### 5. 通过现有原子入口应用并维护易失撤销

渲染端开始校准前取得完整时序快照，但只有测量成功且 `updateAutomationTiming` 同步成功后才把该快照保存为 `lastCalibrationUndo`。撤销再次调用同一完整更新入口；手工更新成功、再次开始校准、重置设置或应用重启都会清空快照。撤销状态和检测结果只存 Pinia 内存，现有 localStorage 结构及 `operationTimingVersion` 不变。

IPC 使用 `start`、`stop` 和 `progress` 三个入口。`start` 返回 `{ success, calibrationId, recommendedTiming, fieldEvidence, sampleCount, durationMs, confidence }` 或 `{ success: false, error: { code, message } }`；进度只包含校准标识、阶段、完成数、总数和安全文案。渲染端通过既有序列化 helper 去除 Vue Proxy 后再跨 IPC。

### 6. 设置页用单个引导弹窗承载准备、进度和结果

“自动操作等待”旁增加“自动检测”按钮。弹窗依次显示准备清单和 12×5 示意图、正在检测阶段、结果对照表；缺少背包网格时禁用开始并提供跳转“界面识别”的入口。开始后主窗口不抢占焦点，主进程自动聚焦游戏；结束后先确认所有输入已释放再恢复设置窗口。用户始终可使用显示出的全局紧急停止快捷键。

## Risks / Trade-offs

- [游戏帧率或后台负载在校准后发生变化] → 采用 15/15 确认和 25%/10ms 余量，并提示改变显示器、帧率限制或渲染模式后重新检测。
- [五格物品布局不符合引导却产生看似有效的复制] → 以剪贴板序列号确认新鲜度并要求五个不同哈希；任何缺失或重复都整体失败。
- [画面捕获受动画或全屏模式影响] → 画面仅作为推导信号，无法稳定测量时回退剪贴板 P95并降低置信度，不阻断已经可靠的输入测量。
- [停止时 Python 正处于输入保持阶段] → 所有等待可中断，合作式取消优先，`finally` 和强制终止后的释放兜底双重清理。
- [推导字段可能比必要值更慢] → 明确标注推导且只增不减；稳定优先于无法验证的极限提速，用户仍可手工修改。
- [工作区另有海图边缘识别改动] → 实现时只精确编辑本变更文件和共享入口，不回退、不格式化或暂存无关内容。

## Migration Plan

1. 先增加纯推荐函数、测量协议和单元测试，不接入设置写入。
2. 增加校准 Python 脚本、主进程服务、资源路径、互斥和紧急停止，完成模拟输入与生命周期测试。
3. 接入 preload/API、Pinia 原子应用和会话撤销，再增加设置弹窗和脱敏进度。
4. 运行定向测试、全量测试、Vite 构建和 OpenSpec 严格校验；使用开发版完成手工安全场景。
5. 回滚时移除校准入口、IPC、服务和脚本即可；现有持久化字段未迁移，原时序值仍可直接读取。
