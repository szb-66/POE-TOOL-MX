## Why

不同电脑、显示器和游戏负载下，鼠标悬停、组合键采样与结果可见时间并不一致，当前只能由用户逐项手工试错，既难以得到稳定值，也容易把结果等待与物理输入时序混为一谈。设置页需要一个基于本机游戏实测的安全校准入口，自动给出现有全局时序字段的稳定优先推荐值。

## What Changes

- 在“设置 → 自动操作 → 操作延迟”增加人工启动的本机校准引导，要求背包第一列五格分别放置不同的 1×1 物品。
- 校准只移动鼠标并发送 `Ctrl+C`，通过五个物品的剪贴板新鲜度和画面变化测量本机时序；不得点击、转移物品或消耗通货。
- 直接实测悬停、组合键、按键保持、键盘释放稳定和剪贴板响应；共享给鼠标动作的 `releaseSettleMs` 以及无法无副作用实测的点击、仓库和画面结果等待使用明确标注、不得降低当前值或安全默认值的保守推导。
- 成功后通过现有完整时序更新入口原子写入全部数值字段，保留自适应开关，并提供本次会话内的一次撤销；失败或中止不修改设置。
- 接入现有自动化互斥、游戏前台门禁、紧急停止、输入释放和剪贴板恢复，返回不含物品原文的结构化进度、证据与错误。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `automation-operation-delay`: 增加设置页本机校准、推荐值计算、安全执行、原子应用与会话撤销要求。

## Impact

- 设置页、Pinia 设置状态与 Electron preload/IPC 增加校准入口、进度和停止协议。
- 主进程增加独立校准服务，随附 Python 探测脚本复用项目 Python 运行时和自动化安全边界。
- 继续使用现有 `operationDelayMs`、`adaptiveTimeoutMs`、`fixedTiming` 与 `operationTimingVersion`，不新增持久化迁移或外部网络依赖。
- 校准脚本需进入运行时资源清单；本次只进行开发版测试、构建和 Electron 手工验收，不打包发布。
