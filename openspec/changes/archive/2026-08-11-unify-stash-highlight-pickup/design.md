## Context

普通仓库 manager 当前调用独立的统计阈值脚本，高亮 manager 则调用 ONNX 分类脚本；后者的训练工作台已经覆盖 12×12 和 24×24 仓库素材。仓库还需要保留现有两套校准区域选择和布局判型。renderer 向仓库 IPC 传配置时没有经过公共的普通数据转换，响应式计时配置会触发 Electron structured clone 错误。

## Goals / Non-Goals

**Goals:**
- 让普通仓库和君锋镇共用一套基础模型、分类和安全转移实现。
- 保留普通仓库自动选择校准区域及 12/24 布局的能力。
- 在 renderer/preload 边界保证仓库运行配置可被 Electron 克隆。
- 保持旧配置可回退读取，但不再让阈值决定取件候选。

**Non-Goals:**
- 不自动读取、修改或清空游戏仓库搜索框。
- 不把君锋镇即时近邻纠正应用到普通仓库。
- 不执行打包或正式版验证。

## Decisions

### 扩展同一高亮脚本支持自动仓库布局
高亮脚本在存在 `calibration` 配置时复用仓库脚本的区域选择与布局判型，生成实际 `grid_region` 和正方形网格；君锋镇继续传固定区域和 12×11 网格。相比复制 ONNX 推理代码到旧脚本，这能保持分类、候选归并、重试、清空确认和错误语义只有一个实现。

### 仓库 manager 适配统一事件
仓库 manager 继续保留现有 IPC 和 renderer 状态字段，在接收高亮脚本事件时将 `candidateItems`/`remainingItems` 映射为 `candidateCells`/`remainingCells`，并保留布局、校准、模型版本和模糊格信息。这样无需同时迁移浮窗调用方。

### IPC 入口统一普通数据转换
仓库 `updateRuntime` 与其他复杂 IPC 一样在 renderer API 边界使用公共 payload 转换，回归测试直接向 API 传 Proxy 并断言 preload 收到的对象可 `structuredClone`。

### 普通仓库禁用即时近邻覆盖
仓库配置不给高亮脚本传校准索引。基础模型由三类网格训练数据共同训练，而即时纠正当前没有来源域门禁；禁用跨场景纠正比误用君锋镇近邻更安全。

### 按界面区分模糊格停止策略
君锋镇奖励候选数量少且误点风险高，继续沿用“存在模糊格即整轮停止”。普通仓库 24×24 一次包含 576 格，出现少量模糊格是常态；仓库模式只排除模糊格并继续处理高置信候选，避免安全门槛把整个功能变成零点击。

## Risks / Trade-offs

- [当前模型质量不足会漏取仓库物品] → 保留检测预览和 0.995 高置信门槛；模糊格自身始终零点击。
- [普通仓库模糊格可能漏取目标] → 模糊格保持零点击，但不阻塞同页其他高置信候选；用户可从预览观察数量并补充训练素材。
- [自动布局选中错误区域] → 沿用已覆盖夹内外校准和 12/24 判型的现有测试与置信门槛。
- [旧 UI 设置消失影响回退] → 不删除本地保存字段，只停止展示和运行时消费。
- [事件字段变化破坏既有界面] → 在 manager 边界兼容映射并增加集成测试。

## Migration Plan

先部署 IPC 克隆修复，再将仓库 manager 切换到统一高亮脚本，最后移除阈值 UI。回滚时恢复旧脚本路径即可继续读取保留的阈值配置。
