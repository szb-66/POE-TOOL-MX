## Context

沿用 .github/workflows/release.yml 和 .cnb.yml。GitHub 构建通过后发布五类资产并同步标签，CNB 下载并校验同一批资产后更新 latest。

## Goals / Non-Goals

目标是让版本号、更新说明、标签和公开资产对应同一份源码。此次不调整已有功能范围或发布流水线。

## Decisions

- 选择下一补丁版本 1.9.2，保留现有锁定依赖。
- 使用标签触发已有 CI 生成正式安装包，避免本地和 CI 重复构建发布产物。
- 更新说明按用户场景组织；本地测试在源码开发环境执行，安装包结构检查由发布 CI 执行。
- 推送前核对工作区和远端，提交当前已审查更改及版本文档；发布后用独立文档提交记录结果。

## Risks / Trade-offs

- 实际游戏操作人工验收尚未全部完成 → 原任务保持未勾选，发布记录明确列出限制。
- GitHub 发布成功但 CNB 镜像延迟或失败 → 检查工作流及 CNB latest 元数据，必要时使用仓库已有镜像恢复流程，不声称未核验的镜像已完成。
- CI 失败 → 分析失败日志，只修复发布阻塞根因并重新验证，不隐藏失败结果。
