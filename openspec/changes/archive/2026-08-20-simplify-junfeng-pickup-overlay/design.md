## Context

君锋镇复用混沌配方控制浮窗：主进程生成统一快照，Vue 组件按奖励界面状态切换到君锋镇按钮。目前统一模板始终渲染第二行状态，运行按钮通过再次点击调用停止 IPC；Python 进度事件已经携带 `currentIndex` 和归并后的 `candidateItems`，但君锋镇 manager 没有把处理序号保存在状态中。现有工作区还包含未提交的业务浮窗主题调整，实施必须在其共享 token 和组件改动上增量修改。

## Goals / Non-Goals

**Goals:**

- 让君锋镇模式使用与一键入库一致的“拖动柄 + 单按钮”结构，同时不影响同一组件中的商城配方和普通仓库模式。
- 让按钮进度按候选处理顺序稳定推进，包括成功取出和安全跳过。
- 保留自动化安全边界、主界面诊断和全局 End 停止能力。

**Non-Goals:**

- 不修改 Python 的候选识别、点击、重试、剪贴板确认或事件格式。
- 不简化商城配方、普通仓库取件或主界面“存取”页的状态展示。
- 不执行打包、发布或持久化数据迁移。

## Decisions

### 1. 在 manager 状态中保存语义化的已处理候选数

君锋镇初始状态增加 `processedItems: 0`。manager 接收 `progress` 事件时，将 `currentIndex` 规范化并钳制到 `0..candidateItems` 后写入 `processedItems`；`started` 阶段保持 0。控制浮窗使用 `processedItems/candidateItems` 生成运行文案。

这比使用 `pickedItems` 更准确，因为空来源格和已解析多格占位会被安全跳过，但仍已完成本轮候选处理；也比在渲染端根据剩余数反推更稳定，因为剩余数和成功取出数不覆盖所有跳过路径。

### 2. 主进程生成唯一的君锋镇按钮文案

控制快照继续提供 `junfengButtonLabel`：非运行状态固定为“取出高亮”，运行状态固定为 `进行中（processedItems/candidateItems）`。Vue 层只渲染该字段；本地启动等待期间直接使用“进行中（0/0）”，不引入“处理中”第三种文案。

备选方案是在 Vue 组件中拼接进度；这会把钳制和回退规则分散到渲染端，因此不采用。

### 3. 君锋镇运行按钮不可点击，停止交给全局 End

君锋镇按钮在运行或本地启动等待期间禁用，事件处理只允许调用启动 IPC，不再按运行状态切换到停止 IPC。停止能力由现有全局 End 协调器提供，主界面原有停止入口保持不变。

这与“一键入库”的单向触发模型一致，也避免进度文案同时隐含停止操作。

### 4. 只为君锋镇模式折叠浮窗布局

Vue 根容器按奖励模式添加专用类：隐藏状态行，将网格改为单行，并移除根容器的背景、边框和阴影；拖动柄与按钮使用现有业务浮窗 token。商城配方和普通仓库路径继续使用原双行面板。现有 ResizeObserver 在 DOM 收缩后上报新尺寸，不修改窗口定位、DPI 或拖动逻辑。

不可用、启动失败和结束原因不改变按钮文案；它们保留在 title、aria-label 和主界面状态中。

## Risks / Trade-offs

- [运行中不能用按钮停止] → 保留全局 End 和主界面停止入口，并用禁用态明确按钮不可操作。
- [启动到候选识别之间总数未知] → 统一显示“进行中（0/0）”，收到 started/progress 后更新。
- [异常事件携带越界或非数值序号] → manager 统一转为有限非负整数并按候选总数钳制。
- [共享组件样式影响其他模式] → 所有折叠规则限定在君锋镇专用类，并覆盖测试普通模式仍渲染状态行。
- [与未提交主题改动重叠] → 仅增量编辑相关模板和专用样式，不回退共享 token 或其他用户改动。

## Migration Plan

无需数据迁移。开发版验证通过后随常规代码提交生效；回滚时移除新增进度字段和君锋镇专用布局，恢复原运行按钮与状态行即可，Python 事件与持久化配置无需回滚。
