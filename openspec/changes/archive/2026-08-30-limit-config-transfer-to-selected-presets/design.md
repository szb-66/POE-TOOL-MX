## Context

现有配置传输以统一目录、区块描述器和事务服务支持 21 个区块，其中多数设置和设备区块需要运行时同步、紧急停止及跨进程回滚。新范围只保留四类预设和工具站点；这些内容都能在不改变当前预设、输入配置或主进程运行时的前提下完成持久数据合并。配置包主格式已经允许未知区块与兼容区块共存，因此无需升级 `formatVersion`。

## Goals / Non-Goals

**Goals:**

- 让目录、导出、导入预览和实际应用共享同一份五区块允许列表。
- 保持四类预设的逐项复制、安全 ID/重名语义及地图坐标双端确认。
- 保持工具站点按规范化 URL 合并且本地冲突项优先。
- 让旧配置包中的已移除区块安全降级为“不支持”，不影响五类兼容内容。
- 清理只为已移除区块存在的运行时、价格覆盖和设备迁移代码。

**Non-Goals:**

- 不删除或迁移用户本机已有的海图、商城或其他设置数据。
- 不改变配置包 kind、主格式版本、文件 IPC、安全大小限制和原子保存协议。
- 不为已移除区块提供隐藏开关、兼容导入或命令行入口。
- 不改变五类内容在各自页面中的日常编辑和启用行为。

## Decisions

### 1. 以五区块目录作为唯一能力边界

共享目录只保留 `preset.item`、`preset.map`、`preset.story`、`preset.storySkill`、`settings.toolSites`，区块描述器注册表与选择 UI 必须由该目录派生。解析器继续按目录判断兼容性，因此旧文件里的 `preset.chart`、`preset.shop`、`settings.*` 和 `device.*` 会自然变成不可选择的未知区块。

选择这一方案而不是只在 UI 隐藏区块，是为了避免程序化调用或旧预览状态仍能导入已移除配置。

### 2. 保持配置包格式版本不变

本次只减少应用支持的区块集合，不改变顶层 JSON 或保留区块 schema。导出只生成五个允许 ID；导入利用既有“未知区块隔离”协议处理旧文件。

选择保持 `formatVersion=1`，因为提升主版本会错误拒绝仍然兼容的旧预设文件，也无法带来额外安全收益。

### 3. UI 收敛为统一卡片层级

导出和导入弹窗不再使用“预设”“工具站点”等标题分区，而是在一个统一的大卡片容器中平铺五个内容小卡片。四类预设小卡片保留逐项选择、仅选当前预设和全选能力，选中后在卡片内部展开预设列表；工具站点使用同级小卡片。快捷操作保留“全部选择”和“清空”，删除“完整备份”、本机环境确认及设备风险提示。导入预览默认选择五类兼容内容，仍需用户确认后应用。

工具站点保留独立区块而不伪装成逐项预设，以继续使用 URL 级合并规则并准确报告冲突数量。

### 4. 事务只覆盖持久数据

保留“全量预校验 → 建立快照 → 串行持久化 → 失败逆序恢复”的原子语义，但删除紧急停止、候选运行时同步、强制关闭输入模块和主进程制作价格恢复分支。预设导入只新增非当前副本，工具站点只合并列表，因此不存在需要同步的输入运行时。

若制作价格批量替换 IPC、设备区块 normalizer 或运行时适配器没有其他调用方，实施时一并删除；若存在独立调用方则仅解除配置传输依赖并保留其公共用途。

### 5. 保留通用隐私防线

虽然五个描述器不会读取账号、路径或资产设置，导出 normalizer 和递归隐私字段检查仍保留，防止未来预设字段扩展意外带入敏感内容。地图 `deviceGrid` 继续是唯一可选设备字段，且需要导出端和导入端分别确认。

## Risks / Trade-offs

- [旧配置包显示更多“不支持”条目] → 预览按兼容与不支持分组，并明确兼容内容仍可导入。
- [只改 UI 会留下隐藏导入能力] → 同时收窄共享目录、描述器注册和事务计划创建入口，并测试直接构造旧区块请求也无法应用。
- [删除运行时路径可能误删其他功能复用接口] → 删除前检索所有调用点；有独立消费者的接口保留，只移除配置传输适配。
- [范围收窄后测试仍依赖 21 区块计数] → 将断言改为精确五区块集合，并增加旧包降级回归测试。

## Migration Plan

1. 先更新允许目录与兼容性测试，使已移除区块变为不支持。
2. 收窄描述器和 UI，移除不再可达的选择、警告及运行时事务分支。
3. 清理确认无其他调用方的价格覆盖/设备迁移接口和测试夹具。
4. 运行专项测试、整套测试、构建和开发版 Electron 验收。
5. 回滚时恢复原 21 区块目录及对应描述器/UI；用户本地数据和既有配置文件无需迁移或恢复。
