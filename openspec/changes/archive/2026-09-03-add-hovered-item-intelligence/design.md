## Context

现有国服查价由主进程负责激活并校验游戏窗口、发送普通 `Ctrl+C`、确认新鲜剪贴板、解析物品和管理独立浮窗；渲染层负责快捷键配置与查价状态。物品解析已经保留详细词缀的清洗文本和 `originalLines`，交易目录能够把中文词缀映射为稳定官方 stat ID，做装目录包含底材的词缀容量。当前文件监听器只服务 Python 临时通信，不适合作为游戏日志 tailer。

## Goals / Non-Goals

**Goals:**

- 让一次安全捕获可被查价、菜单和体检复用，同时保持主进程对原始文本和副作用的控制。
- 用现有目录构建确定性本地评估，不把目录缺口伪装成可靠评分。
- 为 Client.txt 提供可测试、可恢复、默认关闭的事件源。

**Non-Goals:**

- 不引入通用键鼠、任意文件读取、任意 URL 或任意窗口导航接口。
- 不把 Client.txt 事件接入剧情、地图或自动化。
- 不导入做装模拟器，不维护已装备快照，不实现高级复制。

## Decisions

### 共享捕获由主进程持有会话

从查价目录中抽出 `HoveredItemCaptureService`，由它持有单调递增请求序号和当前一次性捕获会话。服务调用既有前台校验和普通复制实现，解析后只向消费者提供结构化物品；原始文本只随内部会话保存。成功读取后，只在剪贴板仍等于本次复制结果时恢复旧值；若用户并发写入其他内容则保留用户新值。

相比让每个功能各自发送复制，这能消除重复输入和竞态；相比把原始文本交给渲染层，主进程会话可以对动作 ID、会话时效和外部副作用做统一校验。现有查价直达仍创建独立捕获请求，上下文菜单选择查价则调用接收可信结构化物品的查价入口。

### 体检模型在主进程构建

新增体检服务，输入解析后的物品、交易目录、做装目录和按类别偏好，输出无原始文本的快照。词缀身份复用交易目录解析，不另建中文文本身份；底材容量复用做装数据仓库的唯一底材解析。

数值范围从 `originalLines` 中按出现顺序提取 `current(min-max)`，百分位计算为 `(current-min)/(max-min)` 并限制为 0–100；上下界相等时标记固定值。每个值独立展示。T 级直接使用详细复制头信息；任一信息缺失均显式降级。

偏好仓库位于用户数据目录，结构为 `{ version: 1, byCategory: { [category]: { [statId]: "desired" | "avoid" } } }`。删除选择即恢复中性。写入使用临时文件加替换，读入时过滤未知层级、非法 ID 和非法状态。

### 菜单和体检使用两个轻量辅助窗口

新增菜单路由和体检浮窗路由，各由专用 manager 管理，并共享当前显示器工作区裁剪、加载感知发布和焦点转交规则。体检浮窗保持专用宽度并铺满鼠标所在显示器的工作区高度，与查价浮窗采用一致的纵向布局。上下文控制器保证菜单、体检与现有查价浮窗互斥。菜单窗口可聚焦以支持键盘；Esc、真实 blur 和确认指针离开均关闭当前会话。执行体检或查价动作时，菜单的程序隐藏及其派生 blur/mouseleave 不触发游戏焦点恢复，焦点直接交给目标业务浮窗。

菜单快照由主进程生成三个固定动作。渲染层只回传 `{ captureId, actionId }`：`inspect` 构建体检快照，`price-check` 检查查价运行时、认证和赛季后把已解析物品交给查价服务，`poedb` 在主进程用捕获物品的底材名称唯一匹配做装底材目录，并从受信任的 `sourceId` 生成 `https://poedb.tw/cn/<sourceId>` 直达页。随机物品名不参与地址拼接；缺失、歧义或不安全的目录标识会禁用动作，而不是退回 PoEDB 首页或失效的站内搜索路由。动作执行前再次校验捕获仍为当前会话。

“体检”作为可管理功能加入现有 feature catalog，拥有 `/item-inspection` 配置页和 `itemContextMenu` 快捷键；菜单功能随该模块启停。新快捷键默认空值，已有配置迁移由全局快捷键默认合并自动补齐。

### Client.txt 使用轮询增量读取而非 fs.watch

Windows 游戏持续持有日志文件时，`fs.watch` 可能合并或丢失通知。新增 `ClientLogEventService` 每 500ms 检查文件身份、大小和修改时间，仅在变化时按字节偏移读取追加区。服务用流式 UTF-8 解码器保留不完整字符，并单独保留未结束行；定时器 `unref`，关闭时立即释放句柄和缓冲。

首次绑定任一文件从 EOF 开始。若文件变小或文件身份变化，则清空解码缓冲、移动到新 EOF 并发布重同步状态，从而避免历史回放。文件暂时消失或不可读时进入等待/错误状态并按轮询重试，不执行广泛路径搜索。

路径解析顺序为已保存有效路径、从白名单游戏进程的可执行文件目录拼接 `logs/Client.txt`、用户文件选择。进程路径探测复用受控 Windows Python/Win32 能力，只返回推导后的候选文件，不暴露通用进程或文件 API。

解析器是纯函数并只输出三类白名单事件。区域行匹配 `Generating level <n> area "<id>"`，地图阶级仅在 PoE1 区域等级大于 67 时计算 `level - 67`；等级解析只接受明确的整数等级模式。所有其他行丢弃。环形队列只保留 50 个事件，原始行在解析后立即释放。

Client 设置仓库使用 `{ version: 1, enabled: false, logPath: "" }`，原子写入。状态与事件通过只读快照发布到设置页，不接入持久诊断事件。

### IPC 保持窄接口和发送方校验

preload 新增 `itemContext`、`itemInspection`、`clientEvents` 命名空间。IPC handler 对发送窗口、字符串长度、枚举、路径和对象深度进行验证；辅助浮窗只能读取自身状态和提交对应白名单动作。主窗口负责配置修改与文件选择，渲染层不能直接提供外部 URL 或任意文件读取目标。

## Risks / Trade-offs

- [国服普通复制格式再次变化] → 使用真实脱敏夹具覆盖解析；字段缺失只降级，不改用其他按键或近似评分。
- [交易目录 stat 与做装目录底材无法唯一关联] → 词缀偏好和容量分别独立降级，快照携带明确完整性原因。
- [多个辅助浮窗的焦点竞争] → 上下文控制器串行关闭旧窗口，显式区分程序隐藏与真实失焦，动作切换期间不恢复游戏焦点并由目标浮窗接管焦点。
- [日志轮转导致遗漏新文件开头] → 第一版优先避免历史重复，轮转后从新 EOF 继续并明确发布重同步状态；后续有真实国服样本再评估是否读取轮转间隙。
- [日志解析规则覆盖不足] → 解析器版本化、未知行静默丢弃，以真实国服开发版验证补充夹具，不把未知文本传到 UI。

## Migration Plan

1. 新增仓库和默认设置时保持菜单快捷键为空、Client 监听关闭，旧用户启动不产生新输入或文件读取。
2. 先切换现有查价到共享捕获并完成回归测试，再启用菜单和体检消费者。
3. 独立接入 Client 服务与设置 UI；任何阶段均可通过关闭新增 feature 或 Client 开关回退，不影响原查价数据。
4. 只在开发版完成真实普通复制、真实 Client.txt、多屏和 DPI 验证；不在本变更中打包。
