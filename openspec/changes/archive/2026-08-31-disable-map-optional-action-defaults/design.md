## Context

地图与海图配置由同一套 rolling profile 结构提供 `exalted.enabled`、`vaal.enabled` 与 `autoStash`，默认配置、Pinia 初始预设和新增预设都复用该结构。当前迁移逻辑先建立默认结构，再以已保存字段覆盖，因此显式用户选择可以与缺失字段的默认补齐区分。动机见 `proposal.md`，行为边界见 `specs/chart-rolling/spec.md`。

## Goals / Non-Goals

**Goals:**

- 在唯一共享默认源中关闭三项可选动作，避免地图与海图、初始与新建流程产生默认漂移。
- 保持逐字段迁移语义：只补齐缺失值，不覆盖已保存的布尔选择。
- 用迁移层测试覆盖所有配置入口，而不是仅验证页面复选框显示。

**Non-Goals:**

- 不修改复选框布局、文案、持久化字段名或预设格式版本。
- 不强制关闭既有预设中用户已明确启用的动作。
- 不改变用户启用后的通货顺序、条件复检、存仓或安全停止流程。

## Decisions

### 1. 修改共享 rolling profile 默认源

将共享默认结构中的三项布尔值统一设为 `false`，让异界地图与航海海图的初始、新建和缺失字段迁移自然得到相同结果。相比在页面挂载时重写复选框值，默认源修复可以覆盖 store、导入迁移和非页面调用，并避免 UI 状态与持久状态不一致。

### 2. 保留现有逐字段覆盖迁移

迁移继续采用“安全默认结构 + 已保存值覆盖”的顺序，嵌套的崇高石与瓦尔配置分别合并。这样缺失字段得到新的关闭默认，而显式 `true` 和 `false` 都保持不变。相比引入一次性版本迁移，这一方案不需要新增持久字段，且默认值变化本身不应重写明确的用户选择。

### 3. 地图与海图同步采用关闭默认

虽然反馈来自异界地图 Tab，但三个选项属于地图与海图共用的可选动作模型，且两类预设的创建和迁移共用默认源。保持一致的关闭默认可以避免用户切换 Tab 后遇到相反的隐式自动化行为；两类预设的已保存值仍完全独立。

### 4. 回归测试聚焦默认与兼容矩阵

扩展预设迁移测试，分别断言地图和海图的空配置、缺字段旧配置及显式启用配置。页面仅绑定活动预设字段，不需要为了默认值增加组件内逻辑；现有页面结构测试和开发构建用于确认绑定未回归。

## Risks / Trade-offs

- [旧预设从未保存某字段时，升级后该分支会从旧隐式开启变为关闭] → 这是本次安全默认的预期迁移；只有缺失字段受影响，显式选择不变。
- [只改部分创建入口会导致初始预设与新增预设不一致] → 只修改共享默认源，并用地图与海图两类测试同时覆盖。
- [测试只检查复选框可能遗漏运行时配置] → 直接测试规范化后的持久配置对象，并保留现有运行时顺序测试。

## Migration Plan

1. 更新共享 rolling profile 默认值，不改变结构或字段名。
2. 扩展迁移测试，先验证缺失字段默认关闭，再验证显式启用保留。
3. 在开发版运行目标测试、全量测试与 Vite 构建，并执行严格 OpenSpec 校验；不进行打包。
4. 如需回退，只恢复默认布尔值即可；既有持久数据无需回滚或转换。
