## Context

应用已经通过 Electron 主进程管理主窗口、覆盖层和调试红框窗口，并通过 preload 暴露窗口 IPC。主窗口 DevTools 目前仅能由全局快捷键切换，设置 store 不记录其状态。物品与地图共用主进程剪贴板解析器，但页面没有展示解析器所接受的文本结构。设置页则直接编辑通货、物品和背包首格坐标，自动化脚本对 DPI 和负坐标的处理并不完全一致。

本变更跨越 Vue、Pinia、Electron IPC/窗口生命周期与 Python 自动化脚本，需要建立明确的状态和坐标契约，同时保持现有预设及 localStorage 数据兼容。

## Goals / Non-Goals

**Goals:**

- 提供可持久化、可观察且与现有快捷键同步的 Console 调试模式。
- 让用户在物品和地图页面直接对照当前解析器支持的中文剪贴板结构。
- 通过覆盖所有显示器的取点层录入物理屏幕坐标，并安全处理确认、取消和异常退出。
- 统一所有自动化消费者对点位坐标的解释，并覆盖多显示器负坐标和 DPI 场景。

**Non-Goals:**

- 不构建新的应用内日志收集器，也不替换现有调试红框覆盖层。
- 不实时读取或上传用户剪贴板，不自动检测游戏版本和语言。
- 不为背包格子宽高、DPI、延迟等非点位数值提供取点。
- 不改变物品或地图的匹配算法和用户输入规则。

## Decisions

### 1. 调试模式以 DevTools 实际可见状态为准

设置 store 增加 `debugMode`，通过 localStorage 持久化。渲染进程通过 `setDevToolsVisible`、`getDevToolsVisible` 和 `onDevToolsVisibilityChanged` 与主进程同步；主进程监听 `devtools-opened`/`devtools-closed`，因此设置开关、F12、Ctrl+Shift+I 和用户手工关闭均收敛到同一状态。应用启动时由根组件应用已保存状态，避免只有访问设置页后才生效。

开启时使用停靠在右侧的 DevTools，并在打开事件后尝试切换到 Console。Console 切换依赖 Chromium DevTools 前端能力，失败时只降级为正常打开 DevTools，不影响开关或应用运行。

备选方案是仅在设置开关点击时调用 `openDevTools`，但这会让快捷键和手工关闭后的 UI 状态失真，因此不采用。

### 2. 格式说明使用共享、可解析的静态样例

建立纯 JavaScript 的支持格式定义，包含物品普通/详细复制样例，以及普通地图/高级地图样例。物品页和地图页通过共享展示组件渲染各自摘要、关键字段和可展开原文；同一批样例直接作为解析器回归测试输入。

样例只描述当前中文解析器能力，不在运行时读取剪贴板。与解析器代码完全自动推导相比，静态样例更易读；通过测试断言关键解析结果来防止其失真。

### 3. 每个显示器创建独立取点窗口

`pickScreenCoordinate()` 返回一个 Promise 结果：成功为 `{ canceled: false, x, y }`，取消为 `{ canceled: true }`。主进程为 `screen.getAllDisplays()` 中的每个显示器创建无边框、置顶、可聚焦的取点窗口，加载无主布局取点路由。取点页显示十字光标与“单击确认、Esc 取消”提示。

点击事件携带窗口内 DIP 坐标；主进程结合发送窗口的 bounds 计算全局 DIP，再使用 Electron `screen.dipToScreenPoint` 转为 Windows 物理像素。任一窗口确认、Esc、关闭或加载失败都会只结算一次 Promise，并统一关闭所有取点窗口及移除临时监听器。并发请求直接复用当前请求或返回明确错误，防止出现多组覆盖层。

相比倒计时读取鼠标位置，覆盖层点击提供明确的确认动作；相比单个横跨虚拟桌面的窗口，按显示器建窗能更稳定地处理不同缩放比例和负坐标原点。

### 4. 点位坐标统一为物理像素

通货、物品和背包首格坐标均定义为 Windows 虚拟桌面的物理像素坐标。现有保存值不做批量迁移，因为当前 Windows API 主路径已经按物理坐标使用；只移除 UI/校验/Python 中对负坐标的不合理限制，并修正背包脚本 Windows API 路径中重复乘以 DPI 的行为。pynput 回退路径继续在边界处完成其所需的 DPI 换算。

手工输入仍可用，点击取点成功后调用现有 store 更新方法立即保存；取消或失败不修改原值。格子宽高继续要求大于零。

### 5. 使用 Node 内置测试，不引入测试框架

增加 `npm test`，使用 `node --test` 验证所有展示样例能够被解析并产生预期字段，同时覆盖坐标转换中可抽离的纯函数。Electron 多窗口、DevTools 和真实鼠标位置通过开发环境集成测试验证。

## Risks / Trade-offs

- [Chromium 内部 Console 切换接口可能变化] → 将切换视为可降级步骤，DevTools 打开成功即保持调试模式有效。
- [多显示器混合 DPI 可能产生边界误差] → 按显示器建窗并使用 Electron 的 DIP/物理像素转换 API，在不同布局上执行人工验收。
- [负坐标暴露脚本中的旧限制] → 同步审计物品、地图和背包脚本的坐标校验及 Windows API 调用，使用回归场景验证。
- [取点窗口未清理会遮挡桌面] → 使用单一 settle/cleanup 路径处理确认、取消、关闭、加载失败和应用退出。
- [静态格式样例仍可能被更新遗漏] → 让展示和测试共享同一份样例，并对解析结果做明确断言。

## Migration Plan

1. 新字段使用默认值 `false` 合并加载，旧设置无需转换。
2. 保留现有坐标数值及手工输入；发布后新取点统一写入物理像素。
3. 调整背包脚本的 DPI 边界后，针对 100%、125%、150% 缩放执行坐标回归测试。
4. 回滚时可移除新增 UI、IPC 和路由；原有设置中的未知 `debugMode` 字段会被旧版本忽略。
