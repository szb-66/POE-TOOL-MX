## Context

见 proposal.md。现有 layout 手动枚举含 trap，正文解析跳过标题，实用推荐在路径结束时重新读取下一间布局，可能受后续隐藏效果影响。

## Goals / Non-Goals

目标是基于可核对属性排序；不预测耗时、受伤量或精确守卫数量，不更改键鼠流程。

## Decisions

- 共享静态目录按 floor:0–3 与标准名/别名索引；layout 表示目标，traps 表示已知陷阱，layoutPreferenceKey 保留 Exile-UI 穿越陷阱分类，roomProfile 记录来源。不会用任意陷阱存在覆盖出口偏好。
- 精确规范化匹配，候选属性求一致值而非猜测。实机标题可同时列出四层对应名称：要求所有候选有核实记录且包含当前楼层，跨层仅采用共同属性；独立数字装饰不是名称。别名依据四张 ocr 实机裁剪核对。目录无陷阱信息用未知而非空数组。标题只确认自身字段。
- 使用 knowledge 对新增属性统一门禁；路径逐房评估时保存偏好，避免后续效果反向覆盖之前证据。
- 新增 miniboss 默认 0；旧配置缺省仍为 0。保存字段增量兼容，旧结果重新采集才新增属性。

## Risks / Trade-offs

社区译名差异 → 通过中英页面共同房间位置及上游分类核对，保留来源；多候选仅取共同属性。
陷阱未列全 → 未列不代表没有，只在确认存在时应用相关规则。

## Migration Plan

开发版增量加载；保留现有手动 trap 与原有策略权重。回退可忽略新增字段，用户配置不重置。
