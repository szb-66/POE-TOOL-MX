## Context

见 `proposal.md` 的动机说明。当前 `ModuleTwo.vue` 在单个 `v-for` 区块内同时渲染组合标题栏和两列词缀配置；组合对象会经 `normalizeModuleTwo` 提交到 Pinia 预设，因此直接在组合对象上增加折叠字段会把纯展示状态混入预设及迁移路径。

## Goals / Non-Goals

**Goals:**

- 在现有组合标题栏提供明确、可访问的折叠控制，并让每个组合独立切换。
- 保证新增、复制的组合自然保持默认展开，同时保留其他组合当前的展开状态。
- 折叠后保留组合识别与管理所需的标题栏操作。

**Non-Goals:**

- 不持久化折叠状态，不修改 `affixConfig.js` 的业务数据结构或迁移逻辑。
- 不改变组合启停、条件编辑、匹配、复制和删除语义。
- 不引入全局“全部展开/全部收起”控制或折叠动画。

## Decisions

### 1. 以组件本地的“已收起 ID 集合”维护界面状态

使用响应式集合记录被用户收起的组合 ID，集合初始为空。渲染中以组合 ID 是否在集合内决定内容区显示，因此已有组合、新增组合和复制组合都无需额外初始化即可默认展开；切换一个 ID 也不会影响其他组合。

备选方案是在每个组合业务对象上增加 `collapsed` 或 `expanded`。该方案会进入 `commit()` 的规范化和预设保存边界，需要额外迁移并把临时界面偏好变成长期配置，不符合本次范围。

### 2. 标题栏始终渲染，只有条件内容区受折叠控制

折叠按钮放在组合标题栏操作区，使用可辨识的方向图标以及随状态变化的文本或无障碍标签。`affix-columns` 条件区按状态条件渲染；开关、名称、复制、删除和折叠按钮始终可用。

备选方案是点击整个标题栏切换。标题栏包含输入框、开关和按钮，整行点击容易与编辑、复制、删除操作冲突，因此采用独立控制。

### 3. 折叠操作不调用预设提交

折叠只更新本地集合，不调用 `commit()`。这样不会触发规范化、store 更新或持久化，也从实现边界上保证匹配逻辑只读取原有组合字段。

## Risks / Trade-offs

- [使用条件渲染会在展开时重新创建词缀行组件] → 条件值由 `form` 持有，不会丢失；测试覆盖收起后重新展开仍显示原配置。
- [集合保留已删除组合的 ID] → 删除时同步清理对应 ID，避免长会话积累无效状态。
- [图标含义不够明确] → 提供动态文字或无障碍标签，并以开发版页面交互验证可发现性。

## Migration Plan

无需数据迁移。发布后折叠集合从空状态开始；回滚只需移除组件本地折叠控制，不影响任何已保存预设。
