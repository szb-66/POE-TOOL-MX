# settings-tab-navigation Specification

## ADDED Requirements

### Requirement: 关于分类展示应用信息
系统 SHALL 在设置页提供"关于"分类内容：显示来自包元数据的当前版本号和有效的 GitHub 项目链接（遵循外部链接策略在系统浏览器打开），并 SHALL 展示版本与项目、数据来源与准确性、隐私许可与联系方式三个关于主题，内容与原帮助中心一致。

#### Scenario: 查看关于分类
- **WHEN** 用户选择设置页"关于"Tab
- **THEN** 页面显示当前包版本和项目链接卡片，以及三个关于主题

#### Scenario: 打开项目链接
- **WHEN** 用户在"关于"分类点击 GitHub 项目链接
- **THEN** 链接按应用外部链接策略在系统浏览器打开，不在应用内导航

## MODIFIED Requirements

### Requirement: 设置按任务分类展示
系统 SHALL 在设置页提供"通用、自动操作、界面识别、覆盖层、系统、问题反馈、关于"七个横向分类，并将现有设置、反馈入口、用户诊断操作与关于信息归入对应分类。

#### Scenario: 查看设置分类
- **WHEN** 用户打开设置页
- **THEN** 页面显示七个分类 Tab
- **AND** 全局“重置所有设置”操作显示在 Tab 导航之外

#### Scenario: 查看分类内容
- **WHEN** 用户选择任一分类 Tab
- **THEN** 页面只展示该分类对应的设置、反馈、诊断或关于内容
- **AND** 现有设置的保存和即时生效行为保持不变

#### Scenario: 查看反馈分类
- **WHEN** 用户选择“问题反馈”Tab
- **THEN** 页面显示问题反馈表单、本地诊断导出和诊断会话操作
- **AND** 隐藏与反馈和诊断无关的“重置所有设置”操作

### Requirement: 跨页面入口定位目标设置分类
系统 SHALL 接受设置页 `tab` 导航目标，并 SHALL 仅在目标为 `general`、`automation`、`detection`、`overlay`、`system`、`feedback` 或 `about` 时覆盖最后持久化分类；没有合法目标的普通入口 SHALL 继续恢复最后选中的有效分类。

#### Scenario: 明确入口打开对应分类
- **WHEN** 用户从带有明确设置目的的页面入口进入设置页
- **THEN** 设置页显示该入口指定的合法分类
- **AND** 将该分类保存为最后选中的有效分类

#### Scenario: 普通入口恢复持久化分类
- **WHEN** 用户从侧边栏或其他未指定目标分类的普通入口进入设置页
- **THEN** 设置页恢复最后选中的有效分类

#### Scenario: 非法目标不覆盖持久化分类
- **WHEN** 用户使用缺失、重复或不受支持的 `tab` 目标进入设置页
- **THEN** 设置页忽略该目标并恢复最后选中的有效分类

#### Scenario: 手动切换同步导航目标
- **WHEN** 用户在设置页手动切换到另一分类
- **THEN** 页面保存新的持久化分类
- **AND** 当前设置页路由反映新的合法 `tab` 目标且不增加额外历史记录
