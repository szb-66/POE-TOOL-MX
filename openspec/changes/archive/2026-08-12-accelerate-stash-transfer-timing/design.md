## Context

当前公共 `operationDelayMs` 默认 80ms，但多个 Electron 和 Python 入口仍直接写有同一字面量。取件的共享安全路径在每轮点击后重新执行完整 Ctrl+C，因而在默认 250ms 剪贴板无响应窗口之外还重复消耗 Ctrl 稳定与释放等待。设置没有统一版本字段，无法区分待迁移的旧默认与已迁移配置。

## Goals / Non-Goals

**Goals:**

- 用共享默认常量和 Python 对应兜底将悬停等待统一为 50ms。
- 减少同一取件候选内部的重复 Ctrl 输入，同时保持现有安全确认和清理语义。
- 让旧默认值只迁移一次，其他自定义值保持不变。
- 让用户直接决定所有时间配置，不再由 UI 或共享归一化层施加业务范围。

**Non-Goals:**

- 不改变剪贴板响应窗口的 250ms 默认值，不用图像确认替代剪贴板判空。
- 不增加独立的入库/取件速度设置，不追求两者总耗时完全相等。
- 不打包或发布安装版。

## Decisions

### 共享控制器持有已确认的 Ctrl

在现有输入控制器中复用已跟踪的按键集合：增加确保 Ctrl 按下、在 Ctrl 已持有时复制和点击的内部原语，现有公开动作作为负责获取和释放 Ctrl 的薄封装。取件转移函数在整个点击、确认和最多三次重试期间持有 Ctrl，并在唯一的 `finally` 中释放；入库仍使用单次点击封装。

相比降低固定时序，这一方案直接消除冗余等待而不缩短安全窗口；相比恢复图像确认，不依赖可能过期的模型结果。

### 使用单一时序版本迁移旧默认

设置增加 `operationTimingVersion = 2`。加载时先按现有旧字段优先级得到等待值；若版本低于 2 且结果恰为 80ms，则替换为 50ms，否则保留原值。随后写入版本并保存。已带版本的 80ms 被视为用户自定义值。

相比应用版本号判断，持久化字段能让迁移幂等且不依赖发布版本；相比无条件把 80ms 改为 50ms，不会在以后覆盖用户重新选择的 80ms。

### 默认值只保留一个 JavaScript 来源

JavaScript 模块和 Electron manager 复用 `OPERATION_DELAY.default`，Python 模板保留等值的 50ms 自包含兜底。测试扫描运行入口，阻止 80ms 默认字面量重新出现。

### 时间配置只校验有效性

设置页移除所有时间输入的 `min`、`max`，共享归一化只对缺失、非有限或负数值回退默认值。0ms、超过旧上限的数值和非步长整数原样保存并传入运行配置，避免界面看似接受但运行时静默裁剪。负数仍视为无效输入，因为底层等待 API 无法执行负时长。

## Risks / Trade-offs

- [旧配置中用户主动选择的 80ms 无法与旧默认区分] → 按已确认产品规则迁移一次；用户之后仍可重新设为 80ms，版本字段会保留该值。
- [持续持有 Ctrl 时发生异常可能造成修饰键粘连] → 所有退出路径复用已跟踪状态的 `release_all`，并用异常和失焦测试锁定鼠标先于 Ctrl 释放。
- [取件仍比入库慢] → 保留必要的剪贴板无响应窗口，以动作节奏一致和两边均快于当前基线作为验收标准。
- [用户可配置过短或过长等待导致识别失败或操作迟缓] → 保留安全默认值和说明文本，但不替用户裁剪合法的非负输入。

## Migration Plan

1. 先落地设置版本与默认值测试，再更新默认值和运行配置。
2. 先用假控制器锁定取件输入事件，再重构共享输入事务。
3. 运行受影响测试、全量测试和 OpenSpec 严格校验，并在开发版进行同组物品手工验证。
4. 回滚时恢复 80ms 默认与旧输入封装；已写入版本的 50ms 作为用户合法配置保留，不反向覆盖。
