## Context

项目是 Vue 3、Pinia、Element Plus 与 Electron 28 组成的 Windows 桌面应用。渲染进程目前通过 preload 白名单调用主进程 IPC，用户配置主要保存在 localStorage；现有“物品”页面负责游戏内自动制作，不具备赛季数据目录、外部价格、概率模型或离线策略计算能力。

规划器需要处理大量底材与词缀、易变化的第三方 HTML、长时间概率计算和国服 OCR 价格。数据和计算必须留在本机，不得阻塞 Electron 主线程，并且不能让一次失败更新破坏应用内置快照。

## Goals / Non-Goals

**Goals:**

- 为 POE1 国服当前赛季提供可离线启动、可手动更新的中文做装数据目录。
- 从合法起始底材和显式词缀目标生成可解释的普通通货、工艺台与花园策略。
- 在受支持的策略集合内按期望耗材成本排名，并同时暴露概率、波动和估算可信度。
- 通过稳定领域接口隔离 POEDB、价格 API、工艺动作与搜索算法，使后续工艺类型可插拔。
- 保持现有物品自动制作功能、预设和设置数据不变。

**Non-Goals:**

- 不证明游戏内所有动作组合的全局理论最优。
- 不在本期支持精髓、化石、隐匿混沌、征服者崇高、腐化、镜像和传奇做装。
- 不把追忆或异能固定词缀作为规划目标，也不计算底材购入价。
- 不支持国际服、历史赛季、账号登录、云同步或商业数据再分发。

## Decisions

### 1. 使用版本化规范数据，而不是让界面直接解析网页

新增 `DatasetManifest`、`BaseItem`、`ModifierFamily`、`ModifierTier` 和 `CraftDefinition` 等稳定 JSON 模型。底材、词缀与工艺使用来源稳定 ID 和 Mod Group 关联，中文名称只用于展示和搜索。构建脚本与运行时更新器复用同一套 POEDB 解析器，输出相同 schema。

选择该方式是因为 POEDB 没有承诺稳定 API，直接将页面 DOM 泄漏给规划器会使任何页面调整同时破坏 UI 和算法。替代方案是从网页实时查询每次选择，但其离线能力、性能和一致性均不可接受。

### 2. 主进程拥有数据与网络，Worker 拥有重计算

Electron 主进程负责快照路径、更新下载、图片缓存、价格缓存和规划任务生命周期；preload 只暴露具名 IPC。渲染进程通过分页/搜索接口取得需要的数据，不加载完整数据集。规划任务由 Node Worker Thread 执行，通过进度事件返回快速和精算结果，输入变化或页面卸载时可取消。

这保持了现有 context isolation 边界，也避免概率模拟冻结主窗口。浏览器模式的 mock API 返回明确的不可用状态和内置演示数据，而不尝试跨域抓取。

### 3. 数据更新采用暂存、验证、原子激活和单版本回滚

应用包内包含生成时快照。运行时数据存入 Electron `userData/crafting-data`，每次更新写入新的版本目录，完成 schema、记录数、外键、权重和 checksum 验证后再替换 `active.json` 指针；旧活动版本保留为 rollback。失败或取消只删除暂存版本，不修改活动数据。图片字段在更新快照中统一指向本地占位资源。

清单记录 schemaVersion、POE 版本、赛季、补丁、生成时间、来源 URL 与 checksum。POEDB 赛季与价格当前赛季不一致时继续允许使用旧快照，但界面必须显示陈旧警告和结果所用版本。

### 4. 运行时更新只同步文字数据

为避免 POEDB 图片 CDN 的 403 和大量串行下载拖慢更新，手动更新只请求底材、词缀和工艺文字页面，不请求任何远程图片。更新数据统一使用本地占位图引用，规划页不展示底材图片；已有私有图片协议仅为旧快照兼容保留。

### 5. 价格优先公开卖方均价，并允许买方回退和显式覆盖

价格 Provider 请求 `/api/summary?version=1`，不传 Token 和 season，缓存一小时。优先使用 `sell_avg` 作为买入成本；当卖方均价为零或缺失但 `buy_avg` 为正数时，回退使用买方均价并明确标识。记录按 `currency_unit` 通过对应基准通货价格换算为混沌石。API 的 `error`、买卖双方均缺失或非正数、未知单位或超过 24 小时记录均不可自动排名，用户必须设置本地覆盖后才能用于可估价策略。

本地覆盖按资源稳定 ID 保存并优先于远程值。所有结果显示来源、时间、异常状态和是否覆盖。底材成本固定为零。

### 6. 以领域状态机和 CraftActionProvider 表达工艺

`CraftState` 保存稀有度、前后缀、Mod Group、来源、破裂标记、势力和元工艺标记。`CraftActionProvider` 提供动作定义、适用性、成本、状态转移采样和候选模板。普通通货、工艺台与花园分别注册 Provider；新增工艺无需修改状态机或结果结构。

底材状态使用受约束的 variant 配置：普通；合法单/双势力；带一条已选破裂显式词缀；带已选追忆固定词缀；带异能固定词缀。非法组合在 UI 和领域校验器中双重拒绝。追忆/异能固定词缀不占显式槽位，破裂词缀占槽且不能被移除。

### 7. 用受限策略图搜索，而不是无限动作遍历

策略生成器从注册模板构建带成功、重试、回退和重启边的里程碑图，第一版包含改造-增幅-富豪、点金/混沌重洗、标签花园、抗性/伤害转换、移除并添加、势力重铸、工艺台/多大师收尾、锁前锁后，以及崇高/无效补救。明显无助于目标的动作由可达性和成本下界剪枝。

简单加权抽取使用精确概率；复杂状态转移使用固定种子 Monte Carlo。快速阶段每候选最多 10,000 次抽样；领先候选精算至少 100,000 次，直到 95% 置信区间相对宽度不高于 5% 或达到 500,000 次。最大样本仍无成功样本的策略标记为无法可靠估价，不参与前三名。

### 8. UI 使用三段输入和渐进结果

新增 `/craft-planner` 路由与独立侧栏项。页面依次收集底材/等级/特殊状态、目标词缀/最低 T 级/来源，随后启动计算。词缀搜索只返回当前底材、等级和状态下合法的词缀。所有目标采用 AND 关系。

结果区先显示快速排序，再原位更新精算结果。前三名按期望混沌成本排列，同时展示资源明细、单轮成功率、期望尝试次数、P50/P90、置信区间、步骤条件与失败分支，并明确标注“在当前支持的工艺与策略中最优”。

## Risks / Trade-offs

- [POEDB HTML 或语义变化导致解析失败] → 使用版本化 fixture、结构和数量验证、适配层及活动快照回滚；绝不激活部分更新。
- [POEDB 数据晚于游戏实际改动] → 显示来源版本与更新时间，对赛季不一致给出持续警告，不宣称实时准确。
- [公开价格来自 OCR，可能异常] → 拒绝自动使用异常/陈旧值，展示风险并允许按资源本地覆盖。
- [复杂稀有事件模拟耗时或无成功样本] → 分两阶段、可取消、固定最大样本，并将低可信结果从排名中移除。
- [策略模板遗漏更便宜路径] → 在产品文案中限定最优范围，通过 Provider 和模板注册表逐步扩展。
- [历史内置图片增大安装包] → 运行时不再下载或展示底材图片，后续构建可在不影响数据 schema 的前提下清理历史缩略图。
- [主进程 IPC 暴露文件或网络能力] → 仅接受稳定 ID 和结构化请求，校验所有参数，私有协议限定在活动数据目录。

## Migration Plan

1. 新增领域模型、内置快照与只读查询，不连接现有物品预设。
2. 接入更新器、价格 Provider 和受限 IPC，同时保留内置快照作为永久回退。
3. 接入 Worker 规划器和新页面，最后添加侧栏入口；现有 `/items` 路由和 localStorage 键不迁移。
4. 发布前用内置 fixture、黄金概率样例、完整测试和生产构建验证。
5. 若新模块异常，可移除侧栏入口并继续发布原功能；活动数据目录可被忽略，内置快照不影响旧模块。
