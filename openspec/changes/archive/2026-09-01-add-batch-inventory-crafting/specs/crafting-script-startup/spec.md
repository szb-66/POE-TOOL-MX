## ADDED Requirements

### Requirement: 批量物品制作具有独立启动门禁顺序
系统 MUST 在批量模式下依次完成账号与快照校验、候选及预设兼容校验、游戏内整批身份预检和固定通货预检，并且只有全部成功后才报告物品制作启动成功。任何阶段失败 MUST 通过现有结构化启动失败通道结束，且不得随后被运行中状态覆盖。

#### Scenario: 批量制作启动成功
- **WHEN** 账号、角色、快照、候选、预设兼容、整批身份和固定通货预检全部成功
- **THEN** 系统报告 `items` 制作启动成功并允许第一个候选正式制作

#### Scenario: 背包身份预检失败
- **WHEN** 后台进程已启动但任一冻结候选与游戏内背包不一致
- **THEN** 系统阻止固定通货预检和正式制作输入并发布具体失败原因
- **AND** 主界面和制作浮层不得显示虚假的运行中状态

### Requirement: 共享物品制作入口按批量开关一致分发
系统 MUST 让制作页面、首页和已注册制作快捷键继续调用同一个公共物品制作启动函数，并由该函数读取最新当前预设的批量开关来选择固定坐标单件流程或背包批量流程。

#### Scenario: 批量开关开启
- **WHEN** 当前物品预设开启批量制作且用户从任一共享入口启动
- **THEN** 系统只发起一次背包批量制作请求并执行相同门禁

#### Scenario: 批量开关关闭
- **WHEN** 当前物品预设关闭批量制作且用户从任一共享入口启动
- **THEN** 系统继续执行现有固定坐标单件制作且不要求角色背包快照
