## Context

现有物品制作由 `startCrafting` 收集当前物品预设和固定 `itemPosition`，生成单个 Python 脚本；脚本完成仓库页选择、固定通货预检、目标准备和一种或多种制作循环。地图脚本已经具备背包网格列优先遍历、逐格复制解析、进度检查点和异常恢复，但它按画面扫描发现对象，不能证明目标来自账号快照。

国服账号服务已经用隔离 Electron Session 管理网页登录、POESESSID 验证、限流和会话过期，并通过旧版仓库接口归一化物品尺寸、类别和坐标。新能力需要跨 renderer、账号 IPC、共享启动服务、Python 制作脚本和浮层，同时不得泄露账号或在身份不确定时继续使用通货。

## Goals / Non-Goals

**Goals:**

- 建立“账号快照给出候选身份、游戏内复制证明当前位置”的双证据门禁。
- 在一次 Python 进程内顺序复用现有单件制作事务，并保持通货记账、前台门禁和输入释放边界。
- 为异常停止保存足够但不含敏感文本的会话内恢复状态。

**Non-Goals:**

- 不支持按类别绑定不同预设，不把地图、技能宝石、通货或任务物品纳入通用批量制作。
- 不跨应用重启恢复批次，不持久化背包完整快照、剪贴板物品文本或账号凭据。
- 不新增网页抓取后备，不打包、发布或改变模拟器制作规则。

## Decisions

### 1. 新建角色背包客户端并复用账号会话

在 Electron 主进程增加专用角色客户端，使用现有 `requestPoeCnJson`、认证状态和限流错误模型调用 `/character-window/get-characters` 与 `/character-window/get-items`。角色列表先按全局赛季过滤并优先 `current`；背包响应只接受 `inventoryId === "MainInventory"` 的项目。

客户端输出最小归一化记录：`id`、`characterName`、`categoryId`、`categoryLabel`、`baseType`、`x/y/w/h`。类别解析共享和扩展已有物品类别/图标资源规则，并以显式可制作白名单过滤。相比把原始官网响应传给 renderer，这能固定 IPC 契约、减少隐私面并在主进程尽早拒绝不兼容结构。

### 2. 预设只持久化开关和类别，快照保持会话态

`batchCrafting` 随物品预设保存 `{ enabled, categoryIds }`，规范化器为旧值补 `enabled:false`。角色选择、快照、同步时间、请求状态和候选派生放入独立批量 Store；账号退出、赛季或角色变化通过现有订阅立即清空。

选择该边界是为了让“这套预设是否批量、处理哪些类别”可复用，同时避免下次启动误用旧角色或旧坐标。完整快照不写入 localStorage、诊断或日志。

### 3. 公共启动函数在 renderer 冻结批次

三个现有入口仍调用 `startCrafting`。该函数读取最新预设：关闭批量时沿用原配置；开启时要求有效账号/赛季/角色/快照和非空类别，按 `(x, y, id)` 的列优先稳定顺序派生候选，校验布局边界和预设类别兼容性后深拷贝为批次配置。

批次包含随机 `batchId`、快照指纹、角色摘要、候选最小身份、已完成 ID 和可选恢复检查点，不包含 Cookie 或原始响应。前端校验用于快速反馈，Python 仍执行权威游戏内门禁。

### 4. 单进程先全量预检再逐件制作

生成脚本新增 `batch_config`，但保留单件路径。批量路径先选择所需仓库页以确保背包可见，再遍历所有剩余候选，使用现有前台检查、鼠标移动、剪贴板新鲜度和三次读取链路取得解析结果，比较规范化类别、底材和可信尺寸。任何失败调用统一异常停止并释放按键鼠标；此阶段不调用 `apply_currency`、鉴定或任何改变物品的方法。

全部候选通过后才执行一次固定通货预检，然后为每个候选设置当前目标坐标，调用抽取后的单件准备与制作事务。完成事件只在目标真正达标或首次识别已达标后提交；失败不会前移索引。相比为每件物品重启 Python，这能避免重复仓库选择和通货预检，并让“整批预检早于任何通货”可验证。

### 5. 恢复以稳定 ID 集合而不是格子猜测

批量进度事件携带 `batchId`、总数、已完成 ID、当前 ID、格子和非敏感显示名；script Store 与浮层保存最近异常批次。点击重试时 renderer 重新加载最新预设与设置、重新获取同一角色快照，只从原成员 ID 重建剩余列表；新 ID 被忽略，缺失、重复或无法唯一匹配立即失败。

重启仍要求 Python 对全部剩余项重新做游戏内预检，并沿用原 `usageSessionId`。手动停止事件清除可续作资格，异常事件保留检查点。这里不以底材或坐标近似匹配，因为相同底材可能被替换并导致重复消耗。

### 6. 进度和错误通过现有制作事件通道传播

新增 `crafting-batch-started`、`crafting-batch-progress`、`crafting-batch-preflight-failed` 和 `crafting-batch-completed` 事件，字段使用白名单并复用当前 stdout → IPC → Store → 浮层链路。主页面显示同步与候选信息，浮层只显示运行进度、失败项和安全重试；完整物品文本、词缀、账号名和本机路径不进入操作日志。

## Risks / Trade-offs

- [国服旧版角色接口字段与国际服或仓库接口不同] → 使用固定夹具覆盖多种已知包裹结构，并在真实开发会话先做只读契约验证；未知结构返回 `API_INCOMPATIBLE`，不猜测。
- [官网快照在切图前仍旧] → 界面在批量模块启用时提示切换地图后点击重新同步，启动时用游戏内整批身份预检拦截陈旧坐标。
- [物品制作后官网 ID 发生变化] → 当前进程按冻结 ID 继续不受影响；异常续作无法唯一匹配时拒绝恢复并要求新批次。
- [一次性预检大量物品耗时] → 候选最多受配置背包布局限制，显示明确预检进度；不以抽样换取速度。
- [类别解析误判导致不适用通货] → 主进程白名单、renderer 预设兼容检查和 Python 实物类别检查三层失败关闭。
- [与工作区其他进行中功能冲突] → 只改本变更所需文件并精确检查 diff，不重置或覆盖现有未提交内容。

## Migration Plan

1. 先增加纯兼容的账号 IPC、批量配置规范化和 Store；旧预设默认关闭。
2. 接入页面同步与预览，再接入脚本批量门禁、逐件事务和浮层恢复。
3. 在开发版完成夹具测试、完整测试、构建与真实账号只读接口验证；受控实机验收只使用低价值物品。
4. 回滚时移除批量 UI 与分支即可恢复固定坐标单件路径；旧预设新增字段可被旧代码忽略，不迁移或删除账号数据。
