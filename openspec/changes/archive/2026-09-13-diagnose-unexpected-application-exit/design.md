## Context

见 proposal.md。日志已有同步落盘、轮转和脱敏；协调器仅在当前子进程 close 时记录异常，正常停止会清空引用。退出控制器清理后再次调用 quit。

## Goals / Non-Goals

保留退出首因和子进程完整时序，不改变窗口关闭策略、检测状态通知或自动操作。不以本变更宣称根因已修复。

## Decisions

- 在既有日志增加每次主进程启动唯一 sessionId 与 pid；保持既有字段和轮转路径。避免新增独立日志体系。
- 新增只观察、不控制退出的诊断对象；入口显式标记来源，监听 before-quit、will-quit、quit 和 process exit。窗口关闭候选先观察，确认未被托盘/选择框拦截后才设退出来源。未知来源不猜测。
- 包装共享清理函数记录开始/结束，因此退出、更新与重启均覆盖。首次来源不被清理后的 quit 覆盖。
- 每个检测 child 使用独立诊断实例，停止前设置原因，旧实例 close 仍记日志但不改变新实例状态。记录启动、ready、最后协议事件时间、有限消费者、error/exit/close，stderr 保持 4000 字符上限，启用 PYTHONFAULTHANDLER。
- 沿用现有 VM 测试方式，注入 child 创建函数和独立数据目录运行真实协调器，避免浅层源码字符串测试代替行为测试。隔离测试仅终止自己创建的进程。

## Risks / Trade-offs

- 强制终止可能没有 Python 堆栈 → 保留 code、signal 和请求来源；不猜测是安全软件或原生库故障。
- 诊断回调可能抛错 → 全部诊断入口吞掉自身失败，沿用同步有界日志。
- 原生窗口关闭不能证明是谁发起 → 记录为原生关闭候选，不声称用户点击。

## Migration Plan

无数据迁移；在开发版和隔离测试验证，部署后下一次发生时依据会话日志继续根因定位。回退仅移除新增诊断接线。
