## Context

背包模块把模板与黑名单保存在 `bagSettings`，而原生背包首格中心和格子间距来自全局设置。运行时由渲染进程组装配置，经 Electron 传给 Python；Python 当前固定以 12 列、5 行的列优先双循环扫描，并使用连续三个空格提前结束。

额外背包与原生背包共用格子尺寸，位于原生首列左侧。设计必须保持 `inventory.startPos` 的现有含义，避免影响地图制作等其他消费者。

## Goals / Non-Goals

**Goals:**

- 提供可视化布局并持久化额外列和逐格排除配置。
- 在一个明确的扫描计划中表达原生优先、额外次之、禁用格跳过和阶段终止规则。
- 保持旧设置、原生坐标和现有自动/手动入库入口兼容。

**Non-Goals:**

- 不自动识别用户购买了多少额外背包列。
- 不为额外背包配置独立格子尺寸或像素间隔。
- 不改变地图制作的背包遍历范围。

## Decisions

1. `bagSettings.inventoryLayout` 保存 `{ extraEnabled, extraColumns, excludedSlots }`。格子使用 `{ column, row }`，原生列为 `0..11`，额外列为 `-1..-6`。相对原生首列的负列编号使扩列、缩列后已有选择保持稳定；替代方案是使用扁平索引，但列数变化会改变格子身份。
2. 旧配置在归一化时补齐 `extraEnabled=false`、`extraColumns=1` 和空排除集合。归一化仅保留整数、合法范围并去重；隐藏额外列的排除项继续持久化，运行时按当前可见范围过滤。
3. 前端继续传递原生 `startPos`，Python 按 `x = startX + column * width` 统一计算正负列坐标。这样无需迁移全局坐标，也不会改变其他模块。
4. Python 生成两个阶段的显式格子计划。原生按 `0..11`，额外按 `-N..-1`，每列均从上到下；原生触发三空格即结束整轮，只有完整扫完原生才进入额外阶段，并在阶段边界重置空格计数。
5. 禁用格仍保留在遍历控制流中以中断空格连续性，但不执行门禁、鼠标、复制、点击或统计动作。进度分母只计算当前启用范围内未禁用格。
6. 布局编辑在模块启用时锁定，与黑名单策略一致，避免检测会话、下一轮配置和页面显示不一致。

## Risks / Trade-offs

- [原生背包提前结束会跳过额外背包] → 这是确认后的产品规则，并以规格和回归测试固定。
- [额外列实际存在间隔时坐标可能偏移] → 当前按同格宽连续排列；未来如游戏布局变化再增加独立偏移配置。
- [大量禁用格使三空格优化较少触发] → 禁用格必须中断未知区域两侧的连续性，优先保证不漏扫。
- [配置格式扩展导致旧数据异常] → 集中归一化并保证缺少新字段时使用关闭状态。

## Migration Plan

无需单独迁移。首次加载旧 `bagSettings` 时自动补齐默认布局，下一次保存写入新字段。回退时旧版本会忽略新增字段。
