## Context

剧情浮窗当前由剧情 store 生成快照，经既有 IPC 同步到一个自适应尺寸的透明 BrowserWindow；全局快捷键和游戏前台状态已有统一服务。计时需要跨剧情页面生命周期运行，同时不能建立第二套前台检测或独立浮窗。

## Goals / Non-Goals

**Goals:**
- 用单一状态源驱动页面、快捷键、前后台暂停和浮窗显示。
- 保持现有剧情浮窗宽度设置对剧情内容区域的含义。
- 保持现有浮窗拖动、穿透、分栏及几何收敛能力。

**Non-Goals:**
- 不按章节或步骤自动分段，不自动判断剧情完成。
- 不同步云端，不加入剧情预设导入导出。
- 不提供历史批量删除或打包验证。

## Decisions

- 新增剧情计时 Pinia store，并用纯函数模块负责状态规范化、时间累计、格式化和历史裁剪，便于用注入时钟测试。
- 本地数据保存累计毫秒、最后检查点、暂停原因、起始预设快照和历史；运行状态恢复时统一转换为重启暂停，避免计算离线时长。
- 计时 store 订阅设置 store 已有的前台状态；页面在后台触发开始或继续时保存待运行意图，恢复前台后执行，快捷键则继续被后台门禁阻止。监视器不可用时不应用后台暂停，只暴露降级警告。
- 剧情 store 的浮窗快照组合步骤、技能、模块开关和计时显示状态，继续使用现有 IPC。计时每秒仅更新渲染数据，几何上报层继续去重。
- 原生窗口将配置的剧情内容宽度与计时附加宽度分开计算；仅计时时采用紧凑宽度。分割线布局仍只描述剧情/技能内容区域。
- 模块设置保存在通用设置中；计时会话和历史保存在独立版本化存储键中。

## Risks / Trade-offs

- [频繁持久化影响性能] → 运行时按秒保存小型检查点，停止、重置、切换设置和卸载时立即保存。
- [计时栏改变分割线坐标] → 布局上报包含内容区域真实左偏移，复用现有原生抓手计算。
- [快捷键门禁关闭后后台仍可触发] → 动作分发层始终再次检查后台停止策略；页面按钮的待运行意图使用独立入口，不放宽快捷键。
- [旧设置缺少模块字段] → 规范化时明确补齐剧情和技能为开启、计时为关闭，并将缺失的后台停止设置补为开启。

## Migration Plan

- 读取旧设置时补齐三个模块默认值及默认开启的后台停止设置，无需修改剧情预设数据。
- 独立计时存储不存在或无效时创建空状态；版本不兼容时安全回退为空状态。
