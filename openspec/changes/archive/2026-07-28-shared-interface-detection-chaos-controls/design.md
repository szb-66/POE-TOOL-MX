## Context

自动入库 IPC 当前独占检测进程并在渲染端启动；混沌配方只在取件脚本内临时验证界面。两个功能共享同一组仓库/背包模板，但没有公共生命周期或鼠标自动化互斥。现有自动入库浮窗使用 `focusable: false` 和 CSS 原生拖动区域，在 Windows 无焦点窗口中抓手不能可靠拖动。

## Goals / Non-Goals

**Goals:**

- 一条检测进程服务多个功能消费者。
- 游戏内安全控制混沌配方刷新、高亮和取件。
- 相对窗口、跨 DPI 的可拖动定位，且不抢游戏焦点。
- 配置单一来源和自动化互斥。

**Non-Goals:**

- 不自动切换仓库页，不改变配方算法、认证或仓库接口。
- 不让检测器自动启动混沌取件。

## Decisions

1. 主进程新增检测协调器，保存消费者集合、最新配置和检测状态。自动入库保留自己的会话控制器，但从协调器订阅状态；混沌控制浮窗订阅同一状态。
2. 检测脚本只负责识别和上报状态，额外通过 Win32 `GetClientRect`/`ClientToScreen` 上报物理客户区；几何变化也触发事件。
3. 公共检测配置由独立 Pinia store 持久化，首次从 `bagSettings` 迁移。应用启动时根据自动入库与混沌配方开关注册消费者。
4. 使用主进程单例自动化锁协调自动入库和混沌取件；所有终止路径在 `finally` 等价路径释放。
5. 混沌控制浮窗与格子高亮浮窗分离。控制窗可交互且不聚焦，高亮窗保持点击穿透。
6. `(50,1550)` 和拖动后的偏移使用相对游戏客户区的物理像素保存，Electron 通过 `screenToDipPoint` 设置窗口 DIP 坐标并限制在客户区。
7. 两个控制浮窗均采用指针事件加受限 IPC 移动，不依赖 `-webkit-app-region: drag`。
8. 仓库布局由纯函数根据标签页尺寸和 `inFolder` 解析为 `normal`、`quad`、`folderNormal` 或 `folderQuad`；坐标、高亮、自动化和两个界面的校准完整性判断均复用该结果。

## Risks / Trade-offs

- [主渲染进程退出导致消费者状态丢失] → 主窗口生命周期统一初始化并在应用退出时清理。
- [检测重载造成短暂隐藏] → 配置变更时保留消费者，原子重启并广播 reloading 状态。
- [窗口坐标混用] → 检测和持久化统一物理像素，只在 BrowserWindow 边界转换为 DIP。
- [两个功能竞争输入] → 启动前获取自动化锁，失败时返回结构化禁用原因。
- [文件夹仓库沿用根目录坐标导致误点击] → 文件夹普通/大型校准默认留空，计划缺少对应校准时在主进程拒绝启动。

## Migration Plan

1. 引入公共配置和检测协调器，兼容读取旧自动入库配置。
2. 将自动入库接入协调器，再接入混沌控制浮窗。
3. 移除自动入库 IPC 对检测子进程的所有权和重复配置源。
4. 回滚时可恢复自动入库检测所有权；旧 `bagSettings` 在迁移期间保持可读。
5. 旧混沌配方 `normal` 和 `quad` 校准原样保留为根目录校准，不复制到新增的文件夹校准。
