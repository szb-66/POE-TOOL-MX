## Why

自动入库与混沌配方分别检测游戏界面会重复截图并缺少自动化互斥；混沌配方也只能从主页面启动，窗口模式下操作不便。需要把界面检测提升为公共能力，并提供不抢焦点的游戏内控制入口。

## What Changes

- 自动入库和混沌配方共用一条按消费者启停的界面检测进程。
- 将界面模板、搜索区域和匹配阈值迁移到设置页的公共检测配置。
- 混沌配方增加启用开关、独立操作等待和相对游戏窗口的可拖动控制浮窗。
- 游戏内提供刷新仓库、预览高亮和动态开始/停止/继续取件按钮。
- 增加跨自动入库与自动取件的主进程自动化互斥。
- 修复无焦点自动入库浮窗的拖动抓手。
- 将根目录和文件夹内的普通/大型仓库拆分为四套网格校准，并让主页面与游戏内控制共用布局判断。

## Capabilities

### New Capabilities

- `shared-game-interface-detection`: 公共仓库/背包检测、消费者生命周期、游戏客户区定位和自动化互斥。

### Modified Capabilities

- `cn-chaos-recipe-overlay`: 增加游戏内控制浮窗、启用状态、独立操作等待和动态取件控制。
- `screen-region-template-picker`: 分别保存根目录普通、根目录大型、文件夹普通和文件夹大型仓库校准。

## Impact

- 影响 Electron 检测进程编排、窗口管理、IPC/preload、自动入库服务和混沌配方服务。
- 影响设置页、自动入库页、混沌配方页及其持久化配置。
- Python 检测脚本增加游戏客户区几何信息，不改变仓库 API 和认证模型。
