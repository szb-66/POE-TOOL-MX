## Context

主窗口与所有透明浮窗加载同一个 Vue 入口，但每个 Electron `BrowserWindow` 拥有独立文档并通过路由 `meta.noLayout` 决定是否渲染主布局。现有浅色变量定义在 `:root`，Element Plus 弹层会传送到 `body`，因此只给组件子树添加主题类会漏掉弹层，而直接改写 `:root` 又会污染浮窗。

当前主界面已经具备统一的 `primary-page` 布局、Element Plus 覆盖层、首页模块卡片和设置页六标签结构。视觉重构应复用这些边界，不重写业务 Store、IPC 或自动化流程。

## Goals / Non-Goals

**Goals:**

- 为主布局窗口建立单一、可测试的深色主题作用域和语义令牌。
- 在不改变路由与业务行为的情况下完成壳层、首页和设置页的完整视觉试点。
- 让其余主窗口页面在深色主题下保持可读，并让所有无主布局窗口保持改版前视觉。
- 保持键盘可用性、状态可辨识性、启动性能和窄窗口布局。

**Non-Goals:**

- 不提供主题切换、系统主题同步或主题持久化。
- 不重构设置 Store、首页状态派生、路由、IPC、自动化或浮窗布局。
- 不在本变更中验证安装包、任务栏或安装器图标。
- 不引入新组件库、字体、动画库或装饰图片。

## Decisions

### 1. 在文档根节点切换主窗口主题类

`App.vue` 根据当前路由是否具有 `meta.noLayout`，在当前渲染文档的 `html` 根节点同步 `main-window-theme` 类，并在卸载时清理。主窗口根组件同时保留同名类，便于静态测试和局部样式限定。

主题变量写入 `html.main-window-theme`，现有 `:root` 浅色变量继续作为无主布局窗口的兼容基线。这样传送到 `body` 的 Element Plus 弹层仍能继承主窗口主题，而独立浮窗文档不会获得该类。

备选方案是仅在 `.app-root` 上挂载主题类，但传送弹层无法继承；直接替换 `:root` 则违反浮窗隔离要求，因此均不采用。

### 2. 使用语义令牌覆盖 Element Plus，而不是逐组件硬编码

主窗口令牌固定为：

| 角色 | 值 |
|---|---|
| 应用背景 | `#0E1013` |
| 导航背景 | `#111419` |
| 一级表面 | `#161A20` |
| 二级表面 | `#1C2129` |
| 悬停表面 | `#242B35` |
| 边框 | `#2C333D` |
| 主文字 | `#F2EFE8` |
| 次文字 | `#AEB4BD` |
| 弱文字 | `#7F8792` |
| 品牌金 | `#C5A46D` |
| 金色按钮文字 | `#15110A` |
| 成功 | `#6FAC7A` |
| 警告 | `#D29A50` |
| 危险 | `#D56C68` |
| 信息 | `#709CC6` |

Less 变量继续保留给既有编译期样式，新增 CSS 语义变量并在主题类下映射 Element Plus 的背景、填充、文字、边框、禁用、遮罩和状态色。所有主窗口页面优先消费语义变量；只对 POE 物品、稀有度、通货等领域视觉保留专用硬编码颜色。

正文使用 `"Segoe UI Variable", "Microsoft YaHei UI", "PingFang SC", sans-serif`，数字使用 `"Cascadia Mono", Consolas, monospace`。圆角规则为面板 8px、输入和按钮 6px、状态标签 4px。

### 3. 壳层保持结构，使用样式类形成分组

标题栏继续使用原有 DOM 与 Electron 调用，仅更新颜色、边框、按钮反馈和焦点样式。侧栏宽度从 68px 调整为 76px，不将入口改为折叠菜单。

侧栏保留现有显式入口和顺序，在制作、工具站、设置入口上添加区段起始类，以伪元素、顶部边框和额外间距形成四个非交互分组。这样不会引入新路由状态，也不会影响现有依赖源码结构的契约测试。

当前项使用左侧金色标记、金色低透明表面与浅色文字；悬停和键盘焦点分别使用表面变化与显式轮廓。导航仍在悬停或聚焦时预加载页面，并在低高度窗口纵向滚动。

### 4. 首页复用现有数据流并重组视觉容器

`useDashboard`、模块分组和所有动作保持不变。四项汇总仍使用相同数据，只把独立卡片视觉合并为单一紧凑状态带。系统健康区域保持一个可收起面板，业务模块继续使用现有 `ModuleStatusCard`。

首页和模块卡片通过图标、状态标题、说明与颜色共同表达状态。加载骨架匹配标题、状态带和模块卡片的最终几何；错误状态保留重试。模块卡仍最多三列，断点不足时自动降为单列。

不加入滚动动画、持续发光、玻璃材质或装饰数据。动效只允许 120-180ms 的颜色、透明度和最多 1px 位移，并在减少动态效果时关闭。

### 5. 设置页保留挂载与数据逻辑，仅统一内容层级

六个标签、`v-show` 持续挂载、`sessionStorage` 恢复、切换回顶和反馈页隐藏重置按钮保持原实现。现有 `el-card` 和设置区块统一为任务分组表面，避免拆分业务脚本或改变字段 DOM 顺序。

内容容器使用 `max-width: 1120px`。仅对互不依赖的短字段使用显式双列类；具有依赖、校准、说明、历史或提交顺序的区块保持单列。窄于布局断点时全部回到单列。危险按钮与错误反馈始终使用危险语义色。

### 6. 其余主窗口页面只做兼容审计

通过搜索浅色硬编码、白色表面、默认灰色文字和阴影，逐页修复在主窗口主题下不可读的样式。除通用令牌替换和对比度修正外，不调整页面结构。

无主布局组件不参加批量替换。每次修改共享样式时，必须同时检查主窗口和独立浮窗，避免透明背景、穿透区域或固定尺寸发生变化。

### 7. Logo 使用生成版临时资产

本期允许使用图像编辑工具生成的 `LOGO-dark.png` 作为临时深色资产。它保持原标志的主要几何轮廓与识别特征，使用深炭背景、品牌金主体和炭金阴影；精确像素换色及最终品牌资产由后续独立替换完成。

标题栏、窗口图标、favicon 与构建配置统一引用临时深色资产，原 `LOGO.png` 保留以便回退。开发版检查 18px 标题栏缩放；由于不允许打包，本变更不声称安装包图标已验证。

## Risks / Trade-offs

- [主窗口主题类挂载过晚导致首帧浅色闪烁] → 在应用挂载前即可依据当前路由同步根类，并增加静态契约测试。
- [Element Plus 传送弹层没有继承主题] → 主题类挂载到 `html` 而不是局部容器，并在下拉框、选择器、提示和确认框上验证。
- [共享 CSS 变量污染透明浮窗] → 保留浅色 `:root` 基线，所有深色覆盖必须以 `html.main-window-theme` 开头，并针对全部 `noLayout` 路由建立测试清单。
- [全局深色变量暴露其他页面硬编码浅色] → 实施兼容审计并将发现的问题限制为颜色和对比度修正，不扩大到结构重排。
- [设置页视觉调整意外改变字段行为] → 不移动脚本逻辑、不改变字段名称和挂载策略，运行现有设置与集成测试。
- [临时生成 Logo 体积与精确色值尚未最终优化] → 统一引用可替换的 `LOGO-dark.png`，保留原资产，本期只声明开发版视觉验证。
- [深色重绘增加启动或交互开销] → 不引入运行时主题计算、图片背景或动画库，并复跑既有启动性能测试。

## Migration Plan

1. 先落地主窗口主题类和令牌，在不改页面结构的情况下验证浮窗隔离。
2. 更新 Logo、标题栏、侧栏和路由加载反馈。
3. 完成首页与设置页完整试点。
4. 对其余主窗口页面执行深色兼容审计并修复对比度问题。
5. 运行针对性测试、完整测试、Vite 构建、严格 OpenSpec 校验和开发版多尺寸/DPI检查。

本变更没有数据迁移。回滚时移除主窗口主题类及其深色覆盖、恢复壳层/页面样式和原 Logo；业务状态与用户数据无需回退。
