## Context

数据快照已经为护甲基础属性保存最小/最大值，装备会话却通过 `rollBaseEntries` 独立重骰每一项。POE 的护甲基础防御来自同一个 Base Percentile；圣玉重骰的也是该百分比，而不是显式词缀或品质。当前状态没有保存百分比，因此无法显示、记录或准确重放这层数值。

## Goals / Non-Goals

**Goals:**

- 用单一基础防御百分比生成同一护甲上的护甲、闪避值、能量护盾和结界。
- 用快照已有整数范围实现可复现的圣玉重骰。
- 在装备卡和历史中明确区分基础防御、品质与显式词缀变化。
- 保持所有现有会话状态向后兼容。

**Non-Goals:**

- 不计算价格或圣玉掉率。
- 不模拟传奇物品专属防御或局部防御显式词缀的最终角色面板公式。
- 不改变非防御底材属性、品质或显式词缀的既有随机方式。

## Decisions

1. 状态新增可空的 `baseDefencePercentile`，对有可变基础防御的护甲保存 0–100 整数；其他装备保存 `null`。这与游戏高级描述和交易站的百分比表达一致，并能直接用于展示和事件历史。
2. 从跨度最大的基础防御整数范围中等权选择一个合法整数结果，再换算为共享百分比；其他防御项按同一相对位置映射并四舍五入到其整数范围。相比为每项独立调用 RNG，这能保持混合防具的一致 Base Percentile；相比直接等权抽 0–100，它不会人为制造超过底材整数范围的额外结果。
3. 新增纯函数识别基础防御项、生成共享防御结果和重骰已有基础防御。圣玉 provider 复用这些函数，且公共不可变门禁继续统一拒绝腐化和镜像。
4. 旧会话缺少百分比时，规范化层从首个可变基础防御的当前值反推近似百分比；没有可变防御则为 `null`。这样撤销、重做和历史快照不需要 schema 迁移。
5. 事件摘要同时比较百分比与基础防御数值，公开 `baseDefenceChange`；前端只在该字段存在时显示圣玉结果。

## Risks / Trade-offs

- [不同基础防御范围四舍五入后可能共享同一显示结果] → 百分比仍保存真实抽取位置；这是整数面板值的正常离散化。
- [旧会话反推百分比存在取整误差] → 约束为 0–100 且下一次圣玉会产生规范的新状态，不修改旧数值。
- [随机调用次数变化会改变同一种子新建装备的后续 RNG 起点] → 会话只承诺同一版本内可复现；更新测试锁定新规则，不伪装成旧错误序列。

## Migration Plan

新增字段由规范化函数提供默认和反推逻辑，不更新数据快照 schema。若需回滚，移除 provider 和展示字段即可，现有状态中的额外字段会被旧规范化逻辑忽略。
