## Context

AffixGoalEditor 和 AffixConditionRow 被三种制作共用；affixConfig 负责归一化与物等汇总，主进程 matchAffixes 负责达标及高亮来源。

## Goals / Non-Goals

**Goals:** UI、持久化、物等检查与实际匹配对词条启停使用一致语义。

**Non-Goals:** 不修改地图或古灵隐式匹配规则，不改变已有自动化预检。

## Decisions

- 使用 enabled !== false 兼容旧对象和字符串，归一化保留关闭词条而不删除；相比仅在 UI 过滤，能覆盖重载和自动化入口。
- 在 affixConfig 提供有效开启条件判断和数量计算；归一化与编辑器复用。主进程仅在组合词缀匹配入口过滤关闭条件，避免影响其他匹配调用者。
- 包含数按有效开启条数下调并持久化，零条保留 1；重新启用不恢复旧数量，遵循用户确认。
- 行首使用小型 el-switch，关闭状态淡化内容但允许编辑，选择联想保留 enabled。保持空白新增行，开关操作不能让尚未填写的行消失。

## Risks / Trade-offs

- 归一化可能丢失 enabled → 覆盖复制、预设归一化与配置传输回归。
- 仅 UI 过滤导致实际仍匹配 → 直接测试主进程原始配置和物等计算。
- 空白行在提交时被清理 → 编辑器保留空白行，仅输出配置时过滤无效条件。

## Migration Plan

无独立迁移；读取旧词缀默认开启，新字段随原预设保存。开发版验证，不打包。

## 审查收尾说明

`selectedCount` 采用单向钳制：例如包含数为 3 时关闭一条有效条件，数量下调并保存为 2；重新启用该条件后仍为 2，需要用户手动调高。此行为符合设计，并由“包含数下调持久化，重新开启不自动调高”测试覆盖。
