## Context

参见 `proposal.md`。现有采集元数据已保存显示器 id、缩放比例、物理尺寸和物理坐标选区，但启动校验只按 id 查找显示器。Electron 将 `Display.id` 定义为当前显示器的唯一标识，却未提供跨系统重启稳定性的契约；因此校验需要利用已有几何与显示参数完成安全回退。

当前 Electron IPC 显示器快照只有 id、缩放比例和物理尺寸，缺少用于判断采集区域落在哪块屏幕上的物理边界。选区模块已经使用 `screen.dipToScreenPoint` 生成 Windows 物理坐标，可以沿用相同换算规则。

## Goals / Non-Goals

**Goals:**

- 兼容单屏重启后 id 变化，以及多屏环境中 id 交换但屏幕布局未变化的情况。
- 只有在当前显示器可被唯一、安全解析且显示参数兼容时才放行。
- 不迁移、不重写现有采集配置。

**Non-Goals:**

- 不尝试在显示器布局、DPI 或分辨率确实变化后自动变换模板和搜索区域。
- 不引入操作系统专用的持久化硬件序列号或新依赖。

## Decisions

### 1. 将 id 视为优先提示，并按兼容性解析显示器

校验先检查同 id 显示器是否同时满足缩放比例与物理尺寸；若不满足或 id 不存在，再在所有当前显示器中查找参数兼容候选。这样也覆盖重启后 id 在两块屏幕间交换的情况。

未选择“只要存在同尺寸屏幕就放行”，因为相同型号的多显示器会产生歧义；也未直接删除 id 校验，因为同 id 且参数兼容仍是最便宜、最明确的正常路径。

### 2. 使用采集选区与当前物理边界消除多屏歧义

IPC 显示器快照增加物理边界。候选显示器必须完整包含采集时的 `selectedRegion`；唯一满足者才可作为 id 变化后的兼容显示器。若测试调用方或旧平台快照没有边界，仅在参数兼容候选只有一个时回退，以保持工具函数可复用且避免误放行。

### 3. 区分“显示参数变化”和“无法定位”错误

同 id 显示器仍存在、但没有任何参数兼容候选时，返回“显示环境已变化”；没有同 id 且无法找到唯一兼容候选时，保留“采集显示器已不存在”。这保持现有用户提示语义，同时修复误判。

## Risks / Trade-offs

- [两块完全相同且物理坐标重叠的虚拟显示器仍可能无法区分] → 拒绝启动并要求重新框选，优先保证自动操作安全。
- [显示器布局改变但采集区域仍恰好落在兼容屏幕内] → 本变更只保证标题搜索区域可在当前兼容屏幕使用；真实 DPI 或尺寸变化仍会被拦截。
- [不同平台的坐标语义不同] → Windows 使用与采集模块相同的 DIP 到物理坐标换算；其他平台沿用原边界坐标，且现有逻辑不被放宽到参数不兼容显示器。

## Migration Plan

无需配置迁移。发布后现有元数据在首次启动校验时直接使用新解析逻辑；回滚只需恢复旧校验代码，不改变已保存数据。
