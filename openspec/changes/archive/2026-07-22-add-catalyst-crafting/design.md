## Context

schema v6 会话只有通用 `quality` 数字，语义是武器/护甲品质。首饰底材的 `qualityType` 为 `none`，但 3.28 中戒指、项链和腰带可通过催化剂获得另一套带类型的品质。当前词缀实例已保存 `displayTags`、`affixType`、原始范围和实际掷值，足以计算催化后的派生显示值而无需重新解析中文文本。

## Goals / Non-Goals

**Goals:**

- 保存并校验独立的催化剂品质类型与数值。
- 支持 10 种标签催化剂、3.28 左右催化剂和污秽催化剂。
- 对匹配的普通/古灵固有词缀及显式词缀派生显示数值，保持原始掷值不变。
- 让催化剂动作参与确定性 RNG、历史、重置、分裂、拓印和希内科拉预见。

**Non-Goals:**

- 不支持传奇首饰、最高品质超过 20% 的特殊物品或商店配方。
- 不恢复 3.15 之前催化剂影响增幅/富豪/崇高等词缀权重及消耗品质的旧机制。
- 不在本阶段实现瓦尔宝珠或其他污秽通货。

## Decisions

### 1. 催化剂品质与装备品质分字段保存

状态新增 `catalystQuality: { type, amount }`，而不复用 `quality`。这样戒指等特殊有孔底材不会被误认为武器/护甲品质，也能明确表达“更换催化剂类型时品质归零后再增加”。

### 2. 催化数值始终作为派生显示值

规则函数接收词缀实例和催化剂状态，对匹配词缀的每个 `rolledValues` 按数值幅度增强后向下取整，再恢复正负号；例如 `79 → 94`、`-7 → -8`。带小数的属性保留原始值精度后向下取整。原始 `rolledValues` 与阶级保持不变，因此神圣石、撤销和品质切换不会累积舍入误差。

普通底材隐式与古灵隐式使用自身 `displayTags`；显式词缀使用保存于实例的标签。左右催化剂直接按 `affixType` 匹配，不要求额外标签。

### 3. 催化剂定义集中为版本化纯数据

规则模块保存 13 种定义、中文名称、匹配标签和适用模式。常规类型为攻击、速度、生命/魔力、施法、属性、物理/混沌、抗性、防御、元素伤害、暴击；特殊类型为前缀、后缀和污秽随机品质。

常规与左右催化剂复用品质通货的物品等级增量公式，封顶 20%。污秽催化剂只接受腐化首饰，并在全部 12 种非污秽品质类型中等权选择类型，同时随机 1–20 品质；其公开描述只承诺随机类型与数值，因此不伪造更细分权重。

### 4. 催化剂不改变词缀生成权重

3.15 已移除催化剂对增幅、富豪、崇高和势力崇高的匹配词缀概率提升以及制作时品质消耗。动作只改变 `catalystQuality`；所有现有词缀池逻辑保持不变，并用回归测试固定这一边界。

### 5. 只允许非传奇戒指、项链与腰带

当前模拟器不支持传奇稀有度，因此常规催化剂只需接受未腐化的 Ring、Amulet、Belt；污秽催化剂反向要求已腐化。镜像物品全部拒绝。使用相同类型且已达 20% 时禁用；不同类型即使旧品质为 20% 仍可使用并从 0 开始。

## Risks / Trade-offs

- [POEDB 标签与游戏催化标签粒度不同] → 定义显式标签集合并用真实首饰快照做哨兵测试；无法可靠匹配的词缀不增强，不从中文文案猜测。
- [负数词缀舍入方向容易错误] → 规则以游戏显示实例和边界值测试固定 `floor` 语义。
- [污秽催化剂的内部权重未公开] → 只声明并实现等权经验模型，在界面明确标注边界。
- [新增状态影响历史辅助结构] → 继续统一经过 `normalizeCraftState` 和深克隆路径，并覆盖分裂、拓印、预见与重置。

## Migration Plan

1. 旧会话缺少字段时规范化为 `{ type: null, amount: 0 }`。
2. 添加规则纯函数和状态测试，再注册 12 种动作。
3. 接入装备卡派生显示与事件摘要。
4. 运行完整测试、构建和 OpenSpec strict 校验；失败时无需迁移已保存数据，可回退为默认空品质。

## Open Questions

- 污秽催化剂若未来公开准确类型或数值权重，只替换版本化随机模型，不改变状态结构。
