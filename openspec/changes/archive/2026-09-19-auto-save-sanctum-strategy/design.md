## Context

组件持有本地策略，按钮调用 saveStrategy；store.action 会替换整体状态，服务保存前会 stop 并发布中间状态。直接深度监听草稿会因初始化和回传重复提交，也可能让中间状态覆盖新编辑。

## Goals / Non-Goals

**Goals:** 自动保存、跨页签保留草稿、串行合并请求和失败重试。

**Non-Goals:** 不修改 IPC、配置结构、采集停止和路线计算语义，不增加依赖。

## Decisions

- store 持有策略草稿、保存状态、独立错误和编辑版本；组件仅由控件 change 和添加操作触发提交，不使用深度监听自动保存。
- store 接收后台策略时仅在无未保存编辑、无在途请求时同步草稿；展示补齐默认字段沿用现有逻辑。
- 每次提交复制草稿快照，单个异步循环串行执行；期间编辑只保留最新待提交快照。完成版本与当前编辑版本一致才清除待保存状态。
- 请求失败停止队列，保留最新草稿及错误；重试或下一次用户编辑提交最新值。只读期间不发请求，未提交内容标记保存失败并在重新启用后允许重试。
- 保存请求通过现有 action 调用；watch 同步采用同步时机以保护 stop/persist 推送及 action 响应期间草稿。切换页签不终止 store 保存循环。

## Risks / Trade-offs

- 连续编辑重复停止采集及计算 → 串行合并在途请求期间的新编辑，保留既有安全行为。
- 保存失败后其他操作清除全局错误 → 策略保存保留独立错误展示。
- 应用异常退出时未成功提交的草稿会丢失 → 仅成功响应显示已保存，不将内存草稿伪装为持久化结果。

## Migration Plan

无数据迁移；使用现有配置和接口，回退前端即可恢复手动保存。
