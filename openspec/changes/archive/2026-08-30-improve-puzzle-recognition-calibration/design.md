## Context

见 [proposal.md](./proposal.md) 的动机。现有 Python 图像分析器把占用、类型和方向一次性写入格结果，Electron 服务随后只对这些“已占用”格复制词缀；v1 校准按图块相似度投票整个方向掩码，因此也会覆盖占用与类型。双页结果由 Pinia 持久化，自动放入又独立调用同一分析器验证仓库来源。

本次改造跨 Electron、Python、Pinia 和 Vue，且自动放入属于安全敏感输入链路。当前工作树还包含另一项边缘词缀顺时针扫描改动，实施必须逐文件精确合并，不能回退这些差异。

## Goals / Non-Goals

**Goals:**

- 建立“图像找候选、复制定类型、同类型判断方向”的单向真值链。
- 让单格未知可被人工逐项修正、立即保存并反馈到求解，而不污染其他类型。
- 在自动放入每个来源产生危险输入前重新确认复制类型。
- 保持校准 IPC 名称和双页原子提交等现有外部契约兼容。

**Non-Goals:**

- 不扫描两页全部 120 格，只处理明确与疑似视觉候选。
- 不保留或迁移 v1 校准素材，也不建立云端同步。
- 不改变 3×3 海图区的识别算法，不执行安装包构建或发布。
- 不为 Python 再维护一套独立中文形状常量。

## Decisions

### 1. 将复制类型解析放在共享 JS 契约中

国服五类形状及别名继续以现有查价形状表为唯一来源，并给每个形状关联内部 puzzle type。初扫服务与自动放入配置都从该表生成解析数据；Python 只消费配置中的归一化别名到内部类型映射。

选择这一方案是为了避免初扫与自动放入对中文名称产生漂移。替代方案是在 Python 写同名正则常量，但会形成第二套业务真值，因此不采用。

### 2. 图像分析结果拆成候选状态与按类型方向候选

图像分析器保留严格占用门槛，并把已通过最小绿色连通域、但未达到严格占用门槛的格标记为疑似候选。每个候选计算五种类型合法掩码集合中的最佳方向及置信度，返回 `directionCandidates`；不再把某个图像类型作为最终类型。

Electron 复制后才组装最终格：有效复制类型选择同名方向候选；复制失败保持 `candidate: true`、`type: null`、`uncertain: true`；明确空格保持非候选。这样既避免扫描 120 格，也让疑似漏检有机会被复制晋升。

### 3. v2 校准记录显式区分空格与“类型 + 方向”

v2 记录保存 `kind`、内部 `type`、合法方向掩码、图块、特征版本和来源。匹配器先按用途过滤：有复制类型时只读取同类型非空样本并只输出方向；无有效复制文本时才允许空格样本消除假阳性。任何校准结果都不能改写成功复制类型。

仓储首次发现 schema v1、feature v1 或混合旧记录时，在本机校准根目录内删除旧索引与样本图，随后原子写入空 v2 索引，不备份。选择清空而不是迁移，是因为 v1 标签无法证明其类型来自复制文本，迁移会保留污染源。

### 4. 临时证据与可持久化格状态分层

双页格状态增加 `candidate`、`typeSource`、`shapeLabel` 和 `directionConfidence`。`directionCandidates`、原图 Data URL 与特征仅放在本轮 capture map；持久化序列化器显式丢弃这些字段。只有用户确认后，原图与特征才能经校准 IPC 写到 v2 仓储。

这避免 localStorage 体积膨胀和隐式素材留存，同时允许引导弹窗在当前识别轮次内展示与修正。

### 5. 引导队列由证据状态和人工修正共同派生

队列按页、行、列稳定排序，包含所有 `uncertain` 格以及用户对高置信结果做出的手动修正。复制已成功的格锁定类型，只允许选择该类型的合法方向；复制失败格允许选择空格或五种类型，再选择对应合法方向。

「下一个」执行单条 IPC 保存，成功后才从队列移除、更新格状态并触发求解；失败保持当前项目。弹窗关闭不清空 capture map 或已保存进度。素材列表/删除/重置继续作为独立入口。

### 6. 自动放入在每来源输入边界执行复制检查

每次切到计划来源页并完成页面稳定后，脚本把鼠标移到该来源、用哨兵剪贴板执行一次复制并解析形状。检查发生在该来源任何右键或左键前；失败直接返回稳定错误码。确认类型同时作为仓库方向分析的 type hint，旋转验证不会重新猜类型。

整个执行保存原剪贴板并在成功、错误、异常和停止的共同清理路径恢复。替代方案是在一轮开始时批量复制九格，但它无法证明切页后的当前来源仍是计划对象，因此不采用。

## Risks / Trade-offs

- [疑似门槛过低会增加复制次数] → 只复用现有最小绿色连通域作为低门槛，不扫描无视觉证据格，并以测试约束候选数量行为。
- [复制文本偶发未刷新] → 使用哨兵和值变化校验；单格初扫继续其余格，自动放入则在危险输入前失败关闭。
- [v1 清空会丢失用户素材] → UI/仓储将升级视作一次性迁移，明确采用用户已确认的“不保留备份”策略；基础识别仍可工作。
- [方向低置信会增加人工队列] → 已复制类型保持只读，用户只需在合法方向中选择；已保存结果立即影响剩余队列和求解。
- [与现有边缘识别改动冲突] → 只触碰碎片复制分支，合并 `puzzleIntegration` 测试时保留当前 N0 顺时针场景并在最终 diff 中复核。

## Migration Plan

1. 先发布支持 v2 的代码；仓储首次访问时在校准根目录执行幂等的 v1 清空并建立 v2 索引。
2. 双页旧持久化格经过兼容归一化：缺失新字段时使用安全默认值，但不会据此产生新的复制类型真值。
3. 开发版验证识别、逐项校准、重启复用和自动放入失败边界；不构建安装包。
4. 若开发验证失败，代码可回退到上一版本；v1 素材已按明确策略清空，不能恢复且不尝试伪造迁移。
