## Context

现有身份只接受 map/chart/mercenary_warrant；宝石与魔法物品共用后缀底材恢复。日志行尾 implicit 路径没有统一清理范围，区域被当成 explicit。前端回传模型必须经主进程可信模型校验。

## Goals / Non-Goals

以八个真实样本验证最终请求；沿用现有 IPC、勾选交互和来源弹层。不新增职业需求筛选、不清除已支持的地图碎片。

## Decisions

- 通用任务速度与职业专用速度是独立词缀，不依据工具职业自动替换。零结果不能作为替换词缀身份的依据。

- 专门解析日志分区元数据，复用统一词缀清理；查询层按目录 pseudo 映射派系和区域，合并前保留原区域来源。日志综合项不能被通用 pseudo 重算清除。
- 宝石先精确匹配显示名称再生成 type/discriminator；菌潮按区域与目录 text 唯一匹配内部编号。扩展 discriminator 白名单并在可信模型校验中保持身份。
- 退化传奇提供独立的宽泛查询选择，主进程保留可信身份限制，阻止未经确认的自动底材移除。UI 通过已有 query/model 更新通道提交明确选择。
- 日志沿用平铺列表，同 ID 数值相加。默认选项遵从 initialSelection；来源说明显示区域、派系和原始文本。

## Risks / Trade-offs

- 跨区域求和不是单一区域数值 → 按用户确认的参考行为展示，并保留来源。
- 国服目录和实际接口可能不同步 → 未知特殊身份阻止误查，在线失败保留具体原因。
- 共用解析器可能影响制作模块 → 使用完整测试回归，开发版验证，不打包。

## Migration Plan

无持久化迁移；新元数据只存在于本次解析模型，旧物品与设置继续兼容。回滚只需撤销本变更代码。
