## Context

见 `proposal.md`。当前装备脚本会把各阶段的局部 `iteration` 覆盖写入同一个结果文件，文件监听收到变化后延迟读取并只发布最新内容；词缀标准输出只报告第 1 次和每 10 次，孔连颜色阶段每 20 次报告一次。最小回放连续写入 1–20 时稳定只发布 20，证明该通道只能表达快照，不能表达逐次消耗。制作恢复已经区分新任务、完成态重新开始和异常重试，并为地图保存恢复检查点；新账单必须沿用这些安全边界且不得改变键鼠输入行为。

## Goals / Non-Goals

**Goals:**

- 让每次已经作用到目标的通货操作产生不可由文件监听合并的结构化事件。
- 由主进程维护当前逻辑制作会话的规范化累计账单，并可靠发布给浮窗和终止快照。
- 让异常重试延续账单，同时让重新开始和新任务明确清零。
- 使用静态、本地、可审计的通货图标目录呈现账单。

**Non-Goals:**

- 不读取或比较仓库堆叠数量，不承诺库存差值精确核对。
- 不计算混沌石价格、期望成本或制作历史，不跨应用重启持久化。
- 不新增通货自动化类型，不改变预检、前台门禁、点击时序、补读、停止和地图恢复语义。

## Decisions

### 1. 在目标点击成功后发出增量事件

脚本提供统一的 `record_currency_usage(currency)`，在 `apply_currency` 完成目标左键点击之后调用；开孔、连线和改色等分离右键/左键流程也只在目标左键成功后调用。事件形状为 `{ event: "crafting-currency-used", mode, currency, amount: 1 }`。

选择增量事件而不是继续写结果文件，是因为结构化 stdout 已有逐行解析和进程归属，事件不会因 20ms 文件读取窗口合并。选择目标点击后而不是右键选择后计数，是因为右键后移动失败尚未把通货作用到物品；目标点击后解析失败则通常已经消耗，因此应立即计入。补读函数不调用计数器。

### 2. 主进程维护单一活动逻辑会话账本

启动服务为每个正常启动或完成态重新开始生成新的 `usageSessionId`；异常重试显式传回当前浮窗保存的会话 ID 并标记 continuation。主进程只维护当前活动会话 `{ id, mode, totals }`：新 ID 初始化空账本，同一 ID 且模式一致时延续，模式或 ID 不匹配时不得继承旧账本。

主进程解析事件后使用固定目录校验 `currency` 和 `amount`，累加后通过既有 `update-overlay` 通道发布 `{ usageSessionId, currencyUsage }`。`prepareCraftingOverlay` 即使重置其他视觉状态，也随首次快照发回延续后的账本；`script-stopped` 同样携带最终账本，使停止和重试启动失败都能恢复显示。

选择主进程聚合而不是让浮窗直接解析日志，是为了在浮窗重载、stdout 分块和终止事件竞争时保持单一事实来源；也避免把旧的结果文件快照变成新的计数依赖。

### 3. 固定通货展示目录并校验脚本覆盖

新增共享 JavaScript 目录，记录当前自动化可用通货键、中文名、稳定显示顺序和本地图标导入。目录覆盖基础词缀通货、知识卷轴、孔连颜色通货、瓦尔宝珠及八类古灵通货；地图和海图只会产生其中自身使用的子集。主进程仅接受目录中的键，测试同时校验 Python 模板的通货名称集合与展示目录一致。

图标在开发期通过项目既有 PoEDB/Path of Exile 物品美术快照方式获取，固定为仓库内静态资源并补充 `THIRD_PARTY_NOTICES.md`。浮窗只引用构建资源，不接受事件提供的路径或 URL。

### 4. 账单组件替代旧循环次数

浮窗状态保存 `usageSessionId` 和规范化 `currencyUsage`，向内容组件传递按目录排序且数量大于零的条目。物品与地图布局均在主要概览附近显示紧凑、可换行的图标条；终态无条目时显示“本次未消耗通货”，运行中无条目不展示误导性数量。

删除 `scriptIteration`、`iteration` prop、`[进度]` 正则提取和黄色“已循环次数”。脚本中只为刷新旧次数而覆盖写回结果文件的代码一并移除；物品解析结果和地图恢复统计仍沿用现有文件/结构化事件链。

### 5. 重试与失败状态保留账本

异常停止快照包含会话 ID 和账本。重试调用把该上下文传给最新配置启动链；启动成功后继续累计，校验或启动失败时恢复原快照。完成态“重新开始”不传 continuation，因此清零。关闭浮窗结束可见会话；下一次主界面启动总是创建新 ID。

## Risks / Trade-offs

- [目标点击成功不等于已读取仓库堆叠减少] → UI 使用“本次消耗”并在帮助/规范中限定为脚本已执行次数，不提供库存核对承诺。
- [主进程和 Python 通货目录漂移] → 用覆盖全部支持键的回归测试锁定集合，未知事件失败关闭为忽略而非展示。
- [当前未提交恢复与浮窗位置改动重叠] → 实施前逐文件检查现有 diff，仅叠加最小修改，不重置、清理或覆盖用户工作。
- [图标增加构建体积和权利说明维护] → 仅收录当前自动化可产生的压缩小图，沿用既有物品美术来源与第三方声明。

## Migration Plan

不迁移持久化数据。开发版更新后，新账本仅存在于当前逻辑制作会话和主进程内存中；回滚代码即可恢复旧浮窗。先完成结构化计数与聚合测试，再接入浮窗和图标，最后清理旧 iteration 通道并执行完整开发版验证；不进行安装包构建。
