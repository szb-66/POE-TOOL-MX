## Context

背包黑名单规则当前数据结构为 `{ field, keyword }`，JavaScript 与 Python 都直接执行不区分大小写的包含匹配。配置保存在 localStorage，并由 JavaScript 规范化后传给独立 Python 入库进程，因此匹配模式必须贯穿界面、持久化、运行配置和脚本。

## Goals / Non-Goals

**Goals:**

- 每条规则可独立选择模糊或精确匹配。
- JavaScript 与 Python 具有完全一致的匹配结果。
- 不含新字段的旧规则无损迁移并保持原行为。

**Non-Goals:**

- 不增加正则表达式、通配符或字段组合条件。
- 不改变物品头解析方式和黑名单命中后的入库行为。

## Decisions

1. 规则新增 `matchMode`，有效值为 `contains` 和 `exact`。使用稳定的英文枚举避免把界面文案写入配置；相比全局开关，逐条模式允许用户同时保留宽泛规则与严格规则。
2. 缺失或非法的 `matchMode` 统一规范化为 `contains`。这保证旧配置继续执行此前的包含匹配，不会在升级后静默改变用户已有规则的覆盖范围。
3. 两种模式都先对字段值和关键词去除首尾空白并执行不区分大小写比较；`contains` 使用包含关系，`exact` 使用完整字符串相等。JavaScript 与 Python 分别实现相同的小型判定分支，避免运行端依赖 UI 行为。
4. 编辑器默认选择模糊匹配，并在列表中明确显示模式。默认值延续现有用户心智，同时让“地图”等有歧义的规则可显式改为精确匹配。

## Risks / Trade-offs

- [不同运行端的枚举处理不一致] → 两端共享相同枚举值、非法值回退规则，并分别增加回归测试。
- [旧规则保存后数据结构变化] → 规范化只补充 `matchMode: contains`，不改变字段和关键词。
- [精确匹配受复制文本空白影响] → 比较前继续清理首尾空白，但不改写字符串内部内容。

## Migration Plan

加载旧配置时自动为每条规则补充 `contains`；下一次持久化写回新结构。回滚到旧版本时，多余字段会被旧规范化逻辑忽略，因此无需独立迁移脚本。
