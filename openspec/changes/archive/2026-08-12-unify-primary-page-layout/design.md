## Context

主窗口已经由 `TitleBar` 和 `MainLayout` 统一标题栏及侧栏，但各路由页面仍自行决定根容器高度、20/22/24px 间距和滚动元素。存取、地图、商城、设置使用顶层分类 Tab，其中前三者将 Tab 与业务内容放在同一页面结构中，设置页则把 Tab 放在滚动容器内。当前工作区还包含设置页和应用更新相关的未提交改动，实施必须增量保留。

## Goals / Non-Goals

**Goals:**

- 用公共布局样式统一页面外层约束，不新增应用状态或路由层。
- 让四个顶层分类 Tab 独立于内容滚动，并保持现有选中状态和面板生命周期。
- 兼容全宽工作台、居中表单页和内部多滚动区页面。

**Non-Goals:**

- 不统一各业务页面的卡片、标题、网格或最大内容宽度。
- 不把帮助分类、做装模拟内部 Tab 等局部导航提升为一级 Tab。
- 不调整浮层、窗口标题、侧栏、数据状态、IPC 或持久化。

## Decisions

1. 在公共 Less 中增加少量一级页面布局类，统一全高、最小高度、背景、固定 Tab 条、内容滚动区和 20px 边距。相比引入带多个模式参数的新 Vue 容器组件，CSS 约定能覆盖当前差异且更少侵入现有模板。
2. 存取页让 `el-tabs` 占满页面剩余高度，并由其内容区承担滚动；地图和商城在 Tab 后增加独立内容滚动容器；设置页把 Tab 与重置按钮移到滚动条之前。四页继续使用原有 `activeTab`/`activeKind`/`activeTool` 状态，不上移到路由或全局 store。
3. 无顶层分类的页面只统一外层高度、滚动归属和 20px 边距。现有 980/1100/1200px 居中宽度、全宽工作台、帮助左右分栏和剧情内部滚动保持不变。
4. 首页路由骨架采用与真实首页相同的 20px 间距；开发版模型训练页纳入普通一级页面契约，但不改变训练数据、标签或筛选逻辑。
5. 使用源码契约测试枚举正常布局路由并断言只有四个页面声明顶层 Tab 布局，再通过既有业务测试和 Vite 开发转换覆盖结构调整。

## Risks / Trade-offs

- [调整滚动所有者可能影响定位和回顶] → 保留设置页现有滚动引用与回顶调用，并在开发版逐页验证长内容滚动。
- [Scoped Less 与公共类叠加造成优先级冲突] → 删除或收窄重复的根容器声明，避免使用 `!important`。
- [设置页存在重叠未提交修改] → 只移动现有模板块并检查最终差异，不重写脚本或业务设置。
- [特殊工作区需要内部滚动] → 统一的是整页滚动所有者；剧情、帮助等内部面板滚动仍由页面自身管理。

## Migration Plan

无需数据迁移。开发版按页面逐步切换到公共布局类并验证；如需回退，可恢复各页面原有根容器样式，业务状态与数据格式不受影响。
