## Why

应用当前虽然提供全局自动化时序设置，但不同游戏输入链路只消费其中一部分字段，仓库取件等实际脚本仍使用固定等待或隐藏下限，商城配方还保留独立延迟来源，导致相同设置在各模块表现不一致。需要把时间来源统一到现有全局协议，同时保留输入安全门禁和业务节奏配置。

## What Changes

- 将制作、地图洗练、背包入库、普通仓库取件、君锋取件、商城配方取件、海图自动放置、仓库页签选择和战斗辅助的游戏输入统一接入完整自动化时序。
- 明确鼠标悬停、物理输入时序、固定结果等待和自适应结果等待的统一语义，并让正在运行的持续功能从下一轮安全边界使用最新设置。
- 删除商城配方独立操作延迟来源；旧字段继续允许加载但不再影响执行，也不覆盖全局设置。
- 为渲染端和 Python 配置提供唯一规范化/序列化入口，保留现有字段和 snake_case 线协议。
- 清除输入动作边界的裸数字等待与隐藏下限；业务冷却、轮询频率、网络限流、进程生命周期和 UI 防抖不纳入全局时序。
- 调整设置页，使始终生效的物理输入时序始终可见，只在固定模式展示固定结果等待。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `automation-operation-delay`: 扩大统一时序覆盖范围，定义完整配置协议、自适应/固定模式语义、运行时同步和硬编码等待边界。
- `atlas-auto-placement`: 海图输入、页签切换和识别验证改用统一时序，不再使用隐藏最小等待。
- `combat-assist`: 药剂、主动循环和回城的物理键鼠输入接入全局时序，同时保留战斗业务间隔。
- `enabled-feature-runtime-configuration`: 全局时序修改按配置事务同步到已启用消费者，并从下一轮操作生效。

## Impact

- 影响全局设置 store、设置页、Electron IPC/preload/API、各自动化管理器与 Python 游戏输入脚本。
- 新增完整时序运行时更新 IPC；旧背包延迟 IPC 保留为兼容转发入口。
- 不新增依赖，不改变现有坐标、DPI、前台、模板、识别、停止和输入释放安全规则。
- 验证仅在开发版执行受影响测试、完整测试和 Vite 转换，不进行打包。
