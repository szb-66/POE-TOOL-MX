## Context

公共检测进程持续匹配仓库、背包和君锋镇奖励标题，并向多个功能发布就绪状态。标题检测适合确定空闲态入口和启动场景，但自动化将鼠标悬浮到物品后，属性弹窗可能覆盖标题区域；若 manager 或点击脚本继续消费就绪状态，会把自动化自身造成的遮挡误判为界面丢失。

三个执行路径具有不同的候选识别方式，但共享游戏前台检查、自动化互斥和结构化状态。设计需统一标题生命周期，同时保留各路径现有的转移安全机制。

## Goals / Non-Goals

**Goals:**

- 明确区分空闲检测/启动门禁与执行态安全门禁。
- 让三个执行路径都不再受自动化自身产生的标题遮挡影响。
- 让浮窗在运行期间稳定提供当前进度和停止入口。
- 删除因逐件标题复检产生的额外停车与等待。

**Non-Goals:**

- 不停止或移除公共标题检测进程。
- 不放宽游戏前台、坐标、网格、候选、转移确认和互斥锁检查。
- 不改变标题模板、搜索区域、匹配阈值或高亮模型门槛。

## Decisions

### 标题状态只在启动边界消费

空闲态按钮和 manager 的启动方法继续读取公共检测状态。子进程进入运行态后，manager 只因游戏失焦等运行安全条件停止，Python 执行配置不再携带标题模板，点击循环也不构造标题匹配器。

备选方案是在每次匹配前将鼠标停到网格外。该方案每件物品都会增加移动和等待，而且仍依赖弹窗消失时序，因此不采用。

### 运行中的浮窗模式由自动化状态锁定

浮窗计算显示模式时，正在运行的普通仓库或君锋镇自动化优先于实时标题检测。这样标题暂时失配不会隐藏停止入口，也不会把普通仓库与君锋镇按钮相互切换；自动化结束后重新采用实时标题状态。

### 执行安全使用动作相关信号

背包入库在每格输入前验证游戏前台和复制结果；普通仓库及君锋镇取件验证前台、当前格仍为高亮及点击后来源清空。所有路径继续受自动化互斥和用户停止控制。标题像素不再作为执行安全信号，因为它会被正常悬浮行为改变。

### 自动入库会话不因执行期标题波动解锁

自动入库轮次启动后，会话锁定状态不消费标题就绪切换，避免属性弹窗造成假关闭并在标题恢复后重复自动启动。轮次结束后再根据稳定的空闲检测确认是否形成新会话。

## Risks / Trade-offs

- [执行期间用户真正关闭仓库但游戏仍在前台] → 背包入库依靠复制结果安全跳过，视觉取件依靠候选复检和转移确认停止；不使用不可靠的被遮挡标题代替动作验证。
- [公共检测与运行态显示短暂不一致] → 运行状态仅覆盖当前操作模式，自动化结束后立即恢复实时检测结果。
- [会话锁定过久] → 仅在自动化运行期间忽略标题波动，结束后由稳定空闲检测重新建立会话边界。

## Migration Plan

1. 添加三份能力 delta 和回归契约，锁定统一标题生命周期。
2. 删除执行配置及脚本中的标题匹配，调整 manager 停止条件和浮窗运行态优先级。
3. 核对自动入库会话锁在执行期标题波动下不会提前解锁或重复启动。
4. 在开发版运行受影响测试、全量测试和 OpenSpec 严格校验。
5. 回滚时恢复执行态标题门禁、浮窗实时标题优先级和会话原行为；不涉及数据迁移。
