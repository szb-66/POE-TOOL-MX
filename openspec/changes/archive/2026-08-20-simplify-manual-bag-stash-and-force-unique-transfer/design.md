## Context

当前背包设置在前端、Pinia、运行配置和 Electron IPC 中同时携带 `immediateStash` 与 `showStashButtonOnlyWhenReady`，检测订阅还会通过会话锁自动启动 Python 入库。Python 入库已经在点击前复制物品、解析名称/基底/类别并对普通入库执行一次 Ctrl+左键，但其契约明确禁止点击后确认，也没有保留稀有度或 Shift 输入路径。

工作区包含与本变更无关的未提交布局和主题改动，实施时必须只修改目标逻辑并保留现有差异。

## Goals / Non-Goals

**Goals:**

- 将背包检测与入库执行彻底解耦，唯一执行入口为就绪浮层的用户点击。
- 将传奇强制入库限制为默认关闭、一次确认、一次强制点击的窄路径。
- 让输入清理和失败策略覆盖 Ctrl+Shift 组合键。
- 兼容合法旧布局配置，并清理不再消费的旧触发字段。

**Non-Goals:**

- 不改变模板检测、前台聚焦、DPI 坐标、黑名单、占位推断、空格阈值或自动化互斥。
- 不为强制点击增加第二次结果确认或重试。
- 不执行打包、部署或发布。

## Decisions

### 1. 从配置模型和 IPC 根部删除旧触发策略

规范化结果、store、运行配置和 IPC 不再读写 `immediateStash`、`showStashButtonOnlyWhenReady`。旧持久化对象经过规范化后丢弃这两个字段，下一次保存写回干净结构。检测订阅只更新会话就绪状态和浮层，不调用入库进程。

选择彻底删除而不是将两个字段固定为 `false/true`，避免死配置继续影响分支、测试和后续维护。

### 2. 会话控制器只维护门禁，不再返回自动启动信号

`setReady` 只同步 ready/foreground 并处理会话解锁；入库仅通过手动 `beginManual` 进入。浮层可见性固定为 `moduleEnabled && (ready && foreground || stashing)`。

保留 `stashing` 时可见，确保执行状态和停止反馈不会因标题短暂变化消失。

### 3. 强制入库配置随每轮快照进入 Python

新增布尔字段 `forceUniqueStash`，默认关闭。与黑名单和布局一样，由前端规范化、IPC 转换并冻结进当前 Python 配置；运行中修改只影响下一轮，但页面不再显示额外提示文案。

### 4. 解析稀有度并复用清空剪贴板判空

Python 的物品头解析返回规范化稀有度；中文 `传奇` 与英文 `Unique` 都映射为传奇。仅当点击前对象是传奇且开关开启时，首次普通点击后调用现有 `copy_item_text(clear_first=True)` 确认：空表示成功，复制到物品表示需要强制点击，其他结果按 `transfer-unconfirmed` 停止。

复用现有剪贴板确认而不引入截图识别，保持来源格判空契约一致。

### 5. InputController 显式追踪 Shift

强制动作先确认 Ctrl，再按下 Shift，随后发送一次左键。`pressed_keys` 继续作为唯一所有权来源，统一清理按鼠标按钮、Shift、Ctrl 的顺序释放当前控制器持有的输入。强制点击完成后不再复制确认，并按已处理物品的占位尺寸继续扫描。

不模拟按键字符串组合，避免异常路径无法知道哪些修饰键实际处于按下状态。

### 6. UI 说明使用现有 QuestionFilled 模式

“启用模块”行和“物品黑名单”标题使用现有 Element Plus tooltip + `QuestionFilled` 图标；删除三处冗余说明。存取页面所有 `el-switch` 移除 active/inactive 文案、`inline-prompt` 和行内开关文字，但保留表单标签与无障碍说明。

## Risks / Trade-offs

- [首次点击后复制会增加传奇处理耗时] → 仅在用户开启强制功能且物品为传奇时执行。
- [强制点击后不确认可能把失败动作计为已处理] → 这是用户明确选择的流程；不增加隐式重试，并在动作前保留完整门禁。
- [点击后复制失败可能中断整轮] → 使用 `transfer-unconfirmed` 安全停止，避免在无法判断占位时继续误扫。
- [工作区已有同文件改动产生覆盖风险] → 使用局部补丁，实施前后检查目标文件 diff，不重置或格式化无关内容。

## Migration Plan

1. 先更新配置规范化和测试，使旧触发字段被忽略、新字段默认关闭、默认列数为 6。
2. 删除 Electron 自动启动和可选显示策略，再更新浮层测试。
3. 实现 Python 传奇确认与强制点击，并用脚本夹具验证输入顺序和失败清理。
4. 完成页面精简和静态 UI 测试。
5. 运行定向测试、全量测试、Vite 构建、diff check 与严格 OpenSpec 校验。

回滚时整体撤销本变更；旧持久化文件中的两个字段即使已被清理也不会影响旧版本，因为旧版本对缺失字段有默认值。
