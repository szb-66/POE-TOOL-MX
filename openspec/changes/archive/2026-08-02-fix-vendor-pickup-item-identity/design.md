## Context

预览高亮和点击坐标来自同一仓库快照计划。第三方价格补丁会改变复制文本，但同一件物品在点击前后会产生相同的完整文本。用户要求取件不再依赖屏幕、标题模板或字段身份，只判断计划坐标上的原物品在 Ctrl+左键后是否仍能复制到相同文本。

## Goals / Non-Goals

**Goals:**

- 只执行计划坐标上的移动、复制、Ctrl+左键和再次复制。
- 只用点击前后完整复制文本是否相同判断原物品是否仍在原位。
- 保留一次重试和背包满断点。
- 删除被最终方案取代的屏幕与身份校验代码。

**Non-Goals:**

- 不重新计算或改变仓库计划坐标。
- 不解析名称、底材、稀有度、物等、插槽或价格补丁字段。
- 不使用截图或仓库、背包标题模板确认取件。

## Decisions

1. **只比较剪贴板整体文本，不解析身份字段。** 移动到计划坐标后先 Ctrl+C 保存完整文本，Ctrl+左键后再次 Ctrl+C；无文本或文本变化表示原物品已离开，相同文本表示原物品仍在。
2. **复制结果是唯一成功条件。** 第一次点击后文本仍相同则重试一次，第二次仍相同才保持当前游标并报告背包满。
3. **每次复制先清空剪贴板。** 脚本等待游戏写入新的非空文本，避免当前位置为空时误读上一次复制内容。
4. **删除屏幕与旧身份链路。** 移除 cv2、mss、numpy、界面模板匹配、源格截图差异、文本字段解析及严格/模糊身份匹配。
5. **只在启动时尝试聚焦游戏。** 之后不做逐件屏幕、标题模板或前台门禁；用户停止信号仍会终止后续输入。
6. **重新生成打包资源。** 打包模式只从 process.resourcesPath 加载脚本，因此实现验证后重建 Windows 包并对比资源脚本与源码。

## Risks / Trade-offs

- [计划坐标处物品被用户手动替换] → 脚本会取走该坐标当前物品；这是用户明确选择不做身份字段校验的结果。
- [其他程序抢走前台] → 启动后不再逐件检查前台；用户需保持游戏前台或使用紧急停止。
- [复制快捷键响应延迟] → 每次 Ctrl+C 先清空剪贴板并在受控等待窗口内轮询新文本。
- [旧打包副本继续被启动] → 本次重新生成打包产物并验证 resources 脚本与源码哈希一致。

## Migration Plan

无需配置或数据迁移。关闭旧应用，使用本次重新生成的打包版本；回滚时恢复旧取件脚本即可。
