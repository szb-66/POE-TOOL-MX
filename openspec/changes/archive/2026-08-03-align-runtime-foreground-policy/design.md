## Context

自动化由多个独立 Python 模板和 Electron 管理器组成，且工作区正在引入可热更新的游戏窗口名称文件。现有代码已有启动聚焦与部分前台检查，但门禁位置和失焦状态语义不统一。

## Goals / Non-Goals

**Goals:**
- 将前台检查放到每个截图或输入的紧邻位置，关闭检查与动作之间的明显竞态窗口。
- 让持续检测暂停、一次性检测聚焦、自动执行停止三种策略可独立验证。
- 复用现有窗口名称文件、结构化事件和运行状态。

**Non-Goals:**
- 不新增后台窗口截图能力，不改变游戏窗口尺寸或位置。
- 不为物品制作、地图洗练、背包入库或当前页仓库取件增加通用断点系统。
- 不改变网络查询、剧情浮窗和离线手动做装行为。

## Decisions

1. Python 自动化模板各自在输入边界调用前台门禁。模板作为独立资源运行，复用小型约定比引入新的运行时 Python 包更可靠；代价是少量重复代码。
2. 自动执行只在启动或用户明确继续时调用聚焦函数。运行中门禁失败只停止，避免用户切到其他应用后被反复抢回游戏。
3. 共享检测循环先检查前台，再调用截图匹配；进入后台时清空滞回计数并发布未就绪，防止恢复后沿用旧画面状态。
4. 配方取件把 `GAME_NOT_FOREGROUND` 映射为可继续暂停，其他无断点扫描以安全停止结束并在下次重新扫描现场。
5. 查价把窗口标题校验放进发送复制键的 Windows 子进程，使校验失败发生在剪贴板 sentinel 写入前，并对高级复制和回退复制都执行门禁。

## Risks / Trade-offs

- [检查后极短时间内仍可能发生系统级失焦] → 在每个按下动作紧邻前重复检查，并确保所有结束路径释放修饰键。
- [后台/前台快速切换造成检测抖动] → 后台清空稳定计数，恢复后沿用既有连续命中阈值。
- [现有未提交窗口标题改动被覆盖] → 仅做增量补丁并在验证前检查相关 diff。
