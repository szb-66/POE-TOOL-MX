## Context

参见 `proposal.md`。当前应用只有 5 个 Vue 页面使用 Element Plus Tab，但状态策略分散：地图通过预设 store 持久化，商城直接使用 `localStorage`，设置使用 `sessionStorage`，存取和制作的部分 Tab 没有受控状态；制作页还包含按业务分组重复渲染的前缀/后缀 Tab。存取页共享校准素材表当前通过固定最大高度产生内部滚动。

## Goals / Non-Goals

**Goals:**

- 让当前及后续用户可切换 Tab 采用一致的合法恢复、独立存储和失败回退规则。
- 保留地图 Tab 与运行目标绑定、商城既有选择等当前有效状态，不破坏已有本机数据。
- 在一个页面内完成存取说明收纳、共享素材标题操作层级和客户端分页。

**Non-Goals:**

- 不改变路由、页面层级、Tab 的业务内容或自动化执行逻辑。
- 不将 Tab 选择同步到云端、预设文件或不同设备。
- 不引入服务端分页，也不改变校准素材 IPC 或磁盘格式。

## Decisions

### 1. 使用共享的容错持久化工具统一 Tab 状态

提供一个小型前端工具，接收独立存储键、合法选项集合和默认值，负责从 `localStorage` 读取、校验、回退和写入，并捕获存储不可用异常。页面仍持有自己的响应式 Tab 状态，工具只统一边界行为。

选择这一方式而不是让每个页面继续直接读写存储，是为了让非法值回退和异常容错可集中测试，也让新 Tab 能明确遵循同一契约。地图 Tab 继续由预设 store 保存，因为它同时决定自动洗图运行目标；共享工具不取代业务状态，只覆盖纯界面 Tab。

### 2. 保留现有持久化键兼容，新增状态使用命名空间键

商城继续兼容 `shopActiveTool`，地图继续兼容 `mapRollingKind`。设置从 `sessionStorage` 切换到独立的本机持久化键；存取、制作动作目录使用各自独立键。所有新键使用稳定页面与分组标识，避免不同 Tab 组互相覆盖。

制作动作目录的各 Tab 补充稳定名称。按目录业务组重复出现的“前缀/后缀”Tab 使用业务组 ID 隔离选择，并将选择映射作为一个容错持久化记录保存；恢复时逐组校验，只接受 `prefix` 或 `suffix`。

### 3. 共享校准素材采用纯前端分页

保留一次加载全部本机素材的现有数据流，用计算属性按当前页和固定每页 10 条切片供表格展示，并用总素材数驱动分页组件。素材集合变化后将当前页收敛到 `1..总页数`；空列表使用第 1 页作为内部安全值但不显示分页。

选择客户端分页是因为数据已完整加载且规模为本机校准素材量，不需要扩大 IPC 或存储契约。移除表格 `max-height` 后，页面只保留外层页面滚动，避免嵌套滚动区域。

### 4. 标题行承载说明、数量和操作

仓库自动取件与君锋镇取出高亮复用现有标题问号视觉，将截图中两段说明原文分别作为可悬停、可聚焦的提示内容，删除卡片内对应整行提示。

共享本机校准素材标题行使用左侧标题加括号数量、右侧操作区的两端布局；“重建特征”和“全部重置”使用两个带间距的独立普通按钮，不采用连体按钮组，避免呈现出类似 Tab 的视觉。重建与重置继续沿用原禁用条件、危险语义和确认流程，不改变操作含义。

## Risks / Trade-offs

- [浏览器存储可能被禁用或写满] → 共享工具捕获读写异常，使用默认值或当前内存值继续渲染。
- [Tab 选项后续改名导致旧记录无效] → 每次恢复都以当前合法集合校验，并安全回退默认项。
- [动态业务组被删除后留下旧映射] → 读取时只使用当前存在的业务组 ID；写入时可仅保留当前目录分组，旧值不影响页面。
- [素材删除使最后一页为空] → 对素材总数做响应式页码收敛，并对删除最后一条的场景添加测试。
- [统一工具误覆盖地图的业务状态] → 地图继续使用预设 store 的既有持久化路径，仅验证其满足统一行为，不迁移到纯界面状态。

## Migration Plan

1. 引入并测试共享 Tab 状态工具，随后逐页接入设置、存取和制作；保留商城与地图既有键和行为。
2. 设置页不读取旧 `sessionStorage` 作为跨重启来源；没有新持久化值时按“通用”回退，用户下一次选择后写入新记录。
3. 完成存取页布局与分页调整并运行页面契约、Vite 转换和全量测试。
4. 回滚时可撤回界面与工具代码；原有商城、地图数据以及全部业务数据保持可用。
