## Why

四项并行功能虽然已有测试覆盖，但审查发现运行时反馈、更新清理失败、古灵隐式来源判断和启动后页面加载失败仍存在用户可见的状态错误。需要在进入发布流程前修复这些根因，并用跨进程与真实数据回归用例覆盖此前遗漏的边界。

## What Changes

- 将物品制作运行结果同时路由到主窗口和浮层，使古灵循环次数、成功目标与停止原因保持一致。
- 让更新安装前的不可回滚清理进入终止态；失败或超时后不允许已拆除资源的应用继续作为健康实例运行。
- 区分天然基底隐式与目标来源的古灵隐式，避免同文案效果导致零消耗误判成功。
- 区分启动期和运行期页面加载失败；取消导航及启动完成后的刷新失败不再触发“启动失败”退出。
- 为底层更新安装拒绝结果提供明确原因，避免防御性调用得到错误的清理失败文案。

## Capabilities

### New Capabilities

- `application-update-safety`: 定义安装前清理开始后的终止语义、超时协调和明确失败原因。

### Modified Capabilities

- `eldritch-implicit-automation`: 要求主窗口可见运行反馈，并保证天然基底隐式不能冒充所选来源的古灵隐式。
- `startup-crash-diagnostics`: 将致命页面加载诊断限制在真实启动失败，运行期加载失败只记录且允许恢复。

## Impact

涉及 Electron 更新服务与退出控制器、物品解析 IPC、古灵目标规范化和匹配器、启动崩溃保护、设置页错误提示，以及对应的开发版单元/集成测试。无新增依赖，无对外 API 破坏性变更。
