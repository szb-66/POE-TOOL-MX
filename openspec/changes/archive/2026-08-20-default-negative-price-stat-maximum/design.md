## Context

见 `proposal.md`。查价模型已经用 `valueMultiplier` 保存交易目录声明的数值方向，并在官方请求序列化时对负向显示边界取负和交换两端；当前偏差只来自默认边界函数始终返回 `min=绝对值`。该函数同时被初始模型、词缀合并、综合词缀和候选消歧使用。

## Goals / Non-Goals

**Goals:**

- 在统一模型边界按现有数值方向选择默认最小值或最大值。
- 保留显示坐标为正数、官方坐标为有符号数值以及手动双边范围转换。

**Non-Goals:**

- 不改变 matcher 方向识别、目录 schema、浮窗布局、IPC 或持久化格式。
- 不增加中文负向词语判断或负向词缀专用 UI。

## Decisions

### 1. 根据标准化后的有符号 values 选择默认边界

默认边界函数先过滤有限数值，再以现有合并方向规则确定符号。非负方向返回最小绝对值作为 `min`；负向返回最小绝对值作为 `max`。这样所有现有调用点自动一致，无需在 UI、服务或候选路径分别增加分支。

相比读取中文文案或给调用方新增方向参数，该方案复用目录已经转换完成的官方坐标值，并覆盖综合词缀合并后的实际方向。

### 2. 保留负向查询序列化的交换规则

官方查询构造继续把负向显示 `min/max` 映射为官方 `-max/-min`。因此默认 `max=45` 自然得到官方 `min=-45`，而用户手动输入 `min=40,max=50` 仍得到 `min=-50,max=-40`，无需增加特殊情况。

## Risks / Trade-offs

- [只更新初始创建会遗漏合并或消歧路径] → 修改共享默认边界函数并覆盖初始、清理、真实目录、通用负向和消歧回归。
- [错误改变手动双边范围语义] → 保留序列化实现并断言双边范围的官方查询 JSON。
- [无数值词缀被错误赋值] → 显式测试无有限 values 时两端都为空。
