## Context

参见 `proposal.md` 的问题背景。当前主入口只显式引入 Message 和 Notification 样式，升级后弹窗则从挂载后动态载入的运行时模块中调用 MessageBox。Vite 将 MessageBox CSS 分离到其他懒加载页面的资源中，但启动运行时的依赖列表不包含该 CSS。发布说明来自远程更新元数据，不能通过直接 HTML 注入换取 Markdown 格式。

## Goals / Non-Goals

**Goals:**

- 使 MessageBox 基础样式成为主窗口初始样式的显式依赖。
- 以一套可测试的受限解析规则向三个展示入口输出一致的 Vue 节点。
- 原始 HTML 和非 HTTP(S) 链接始终无法获得可执行语义。

**Non-Goals:**

- 不实现表格、引用、围栏代码块、图片或原始 HTML。
- 不改变更新数据结构、网络来源、安装确认、已读确认或发布流水线。
- 不引入通用 Markdown 包或 HTML 净化包。

## Decisions

### 主入口显式引入 MessageBox CSS

在渲染入口与现有 Message/Notification 样式并列引入 MessageBox CSS。这使样式在启动运行时动态模块执行前已经就绪，并让构建产物的首页样式或其初始依赖固定包含 `.el-message-box` 规则。

备选方案是在每个调用 MessageBox 的页面就近引入，但仍会让首次启动弹窗受懒加载顺序影响，无法修复根因。

### 使用受限解析模型而非 HTML 字符串

新增无 DOM 依赖的纯函数，将输入分为标题、段落和列表块，再将行内内容分为文字、强调、行内代码与链接节点。解析结果仅包含固定节点类型和文字字段，Vue 组件使用模板/渲染函数创建元素，不使用 `v-html` 或 `innerHTML`。

链接只在通过 URL 解析确认为 `http:` 或 `https:` 后才输出锚点，并带 `target="_blank"` 与 `rel="noopener noreferrer"`；实际导航继续由现有主窗口外链策略拦截并交给系统浏览器。危险或无效链接仅保留可见文字。

备选方案是引入完整 Markdown 解析器并将产物通过 `v-html` 展示，但这会增加依赖、扩大语法范围与注入攻击面，不符合已确认的安全子集。

### 三处入口共用单一组件

复用组件只接收 `source` 字符串，并为标题、列表、代码和链接提供局部 scoped Less 样式。升级后弹窗和标题栏确认弹窗传入该组件的 VNode，设置页直接声明组件。空值由调用方继续使用现有“本版本暂无更新说明”文案。

备选方案是在三个入口分别转换 Markdown，但会导致安全规则和样式逐步分叉。

## Risks / Trade-offs

- [自实现受限解析器不覆盖完整 Markdown] → 对支持语法建立精确测试，未支持或畸形输入保留可读原文。
- [内联标记组合可能引入边界歧义] → 限定简单、非嵌套语法，并用实际 1.2.2 发布说明与恶意样例固定行为。
- [已有未提交工作同时修改标题栏和设置页] → 只在更新说明相关区域进行精确补丁，完成后分别核对该文件的用户原有差异。

## Migration Plan

1. 先引入解析测试和展示集成契约，确认当前三处纯文本实现与首页样式依赖不满足新契约。
2. 实现受限解析器、共享组件与显式 MessageBox CSS 依赖，再替换三处入口。
3. 运行定向测试、完整测试、Vite 构建和严格 OpenSpec 校验；检查构建首页 CSS 依赖确实包含 MessageBox 核心规则。
4. 仅在开发版用 1.2.2 说明验证三处展示；不执行 Electron 打包。

回滚时可移除共享组件并恢复原纯文本节点，MessageBox 全局样式引入可独立保留，因其修复了已确认的启动弹窗缺样式根因。
