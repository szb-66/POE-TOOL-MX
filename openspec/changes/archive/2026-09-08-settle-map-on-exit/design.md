## Context
现有状态机回城仍保留活动局，服务异步处理事件未串行，摘要有独立实例合并逻辑。客户端监听 started 与游戏在线混淆。

## Goals / Non-Goals
实现已确认的即时结算与连接门禁；不修改其他自动化模块，不回放历史日志，不批量迁移旧记录。

## Decisions
- game-state 使用 unknown/loading/in-game/disconnected；日志监听状态独立。只接受系统消息开头的断线和加载特征。进程检测失败返回未知，不推断退出。
- 状态机保存已结算实例索引，按角色与区域/seed复用记录ID；无角色仅连续上下文内复用，有角色可由历史恢复。无 seed 不合并。
- 服务使用串行事件/写入队列；输入任务独立且使用 AbortController 与代次失效，避免输入或网络等待阻塞断线结算。采样绑定本次进入区间，回城终值可补写原记录。
- 快照增加历史修订号与入库归属ID；历史表随修订刷新。活动草稿与历史按ID合并只取最新累计值。
- 保留最近结算地图供正常回城入库，断线清除入库上下文，进入新地图后旧批次不得写入。

## Risks / Trade-offs
- 没有命令请求ID的日志响应无法绝对关联任意延迟：仅接受有效请求窗口中的响应，切换区间撤销请求并设超时隔离。
- 正常退出未找到可信日志特征时，依靠白名单游戏进程消失补充。
- 区域生成代表加载开始：连接实例日志暂停计时，区域生成事件携带 loading，直到真实系统“你已进入”行才恢复计时和采样；INFO 与 DEBUG 日志头均支持，自动输入仍保留现有画面预检。

## Migration Plan
字段采用兼容默认值，旧历史不重写。开发版测试和真实日志回放验证，无打包。
