## Context

快捷键空值目前在捕获、校验和主进程全量初始化中被部分接受，但设置页、业务页、查价模块启停和 Python 脚本各自存在不同回退或拒绝逻辑。该变更跨越公共组件、持久化、注册事务和安全停止路径，需要建立单一空值语义。

## Goals / Non-Goals

**Goals:**

- 用空字符串作为普通应用快捷键“未设置”的唯一持久化表示，并确保所有显示和注册入口一致。
- 保持全量注册失败回滚和全局紧急停止始终可用。
- 让清空查价快捷键只影响触发入口，不修改模块启用状态。

**Non-Goals:**

- 不改变 Electron IPC 形状、快捷键作用域门禁、动作分发标识或默认快捷键集合。
- 不允许游戏动作键序列以本变更的全局快捷键规则清空。
- 不执行打包或发布验证。

## Decisions

1. **在共享配置层规范化持久化值。** 普通字段把空白字符串归一化为 `''`；`end` 的空白历史值迁移为默认值。相比在每个页面处理，这能同时覆盖首次加载、重启和手工损坏的本地存储。
2. **在提交服务强制紧急停止必填。** 完整候选集合先规范化、再验证和注册，成功后才写入 store；这保留现有事务边界，并阻止任何绕过 UI 的空值提交。
3. **空值由全量注册协议自然省略。** Electron IPC 继续过滤空 accelerator；清空时全量替换注册集合，从而注销旧组合而无需新增单独 IPC。
4. **组件用 `allow-empty` 表达交互策略。** 默认允许清空并在非空时展示按钮；紧急停止入口显式关闭，Delete/Backspace 也不会提交空值。相比按字段名硬编码，组件仍可复用和测试。
5. **模块状态与快捷键状态解耦。** 查价启用流程允许空快捷键；启用且为空时只启动模块运行态，不注册触发入口，后续设置非空值时由统一提交恢复注册。
6. **移除普通字段的显示回退。** 页面直接展示 store 中的规范化值，以“未设置”表达空值；仅加载迁移负责紧急停止兜底，Python 生成器要求收到已规范化的有效停止键。

## Risks / Trade-offs

- [模块显示已启用但无快捷键入口] → 明确显示“未设置”，保留配置，并在重新设置后立即恢复注册。
- [清空过程中注册其他快捷键失败] → 沿用主进程全量回滚，且失败时不持久化空值。
- [旧空紧急停止曾依赖脚本内隐式 Alt+3] → 加载阶段统一迁移并持久化，测试确保 Electron 与 Python 使用同一值。
- [工作区已有未提交改动] → 只修改本功能涉及的局部行，验证最终 diff 不包含回退或覆盖。

## Migration Plan

加载设置时检测 `globalShortcuts.end`；若为缺失字段继续使用默认合并逻辑，若为显式空或纯空白则恢复 `Alt+3` 并保存规范化设置。普通字段的显式空字符串原样保留。回滚代码后旧版本仍会通过默认合并读取非空值，普通空值则可能恢复旧页面回退行为，但不会破坏存储结构。
