## Context

见 `proposal.md`。当前交易目录把 matcher 保存为纯字符串；固定 Awakened PoE Trade 与 Sidekick 数据都能为负向 matcher 提供 `negate` 标记，但生成器只保留字符串。运行时因此能匹配“回复速度减慢 45%”，却把捕获值解释成 `+45`。默认范围函数还会对数值应用 10% 或 20% 下浮。

未鉴定传奇解析已经按官方物品目录的“名称 + 底材”工作，运行时目录也包含“卡鲁之血 / 圣化生命药剂”，但现有测试只覆盖通用珠宝候选，未锁定药剂类别与未鉴定过滤。

当前工作区存在多项与查价模块重叠的未提交改动；实施必须在现有内容上做最小增量修改，并与 `add-map-and-chart-price-check` 保持独立。

## Goals / Non-Goals

**Goals:**

- 从上游元数据而非中文关键词确定 matcher 的数值方向。
- 让展示文案、解析数值和官方查询边界各自表达正确语义。
- 删除无实际使用场景的全局宽松范围策略，同时保留逐条手动编辑。
- 以真实药剂语料锁定通用未鉴定传奇流程。

**Non-Goals:**

- 不重写词缀消歧、综合规则或官方请求协议。
- 不新增药剂专用候选 UI 或公开 IPC。
- 不改变初始词缀勾选、认证、快捷键、分页和价格分布。
- 不打包或发布应用。

## Decisions

### 1. 保持 matcher 字符串兼容并增加稀疏负向集合

交易目录 schema 升级一版，继续使用 `matchers: string[]`，并在 stat 记录上增加可选 `negatedMatchers: string[]`。校验器要求每个负向 matcher 都是 `matchers` 的成员、非空且不重复。未列入该集合的 matcher 隐式使用乘数 `+1`，列入者使用 `-1`。

这比把所有 matcher 改成对象更小，能减少大型内置目录和现有索引、审计、测试的迁移面；也比维护中文负向词库可靠，因为方向直接来自固定上游 `negate` 字段。

### 2. 在生成和合并边界保留负向元数据

初始目录生成读取 Awakened matcher 对象的 `string` 与 `negate`；中文 matcher 合并同时读取 Sidekick 定义的 `negate`，OpenCC 转换只改变字符串，不改变方向。按 stat ID 合并、官方本地化别名扩展和在线刷新时同时并集 `matchers` 与 `negatedMatchers`，并在最终验证前移除不再存在的负向键。

官方实时响应自身没有方向元数据时只新增普通 matcher，不覆盖内置负向集合。旧 schema 目录不作为可信活动目录加载；应用随版本携带重建后的新 schema 目录，在线刷新从该可信基线开始。

### 3. 匹配成功后保留官方数值与查询方向

运行时索引仍按 matcher 文本定位候选。正则提取数字后，根据实际命中的 matcher 是否属于 `negatedMatchers`，将该 matcher 的全部捕获值乘以 `-1`，把转换后的 `values` 传给模型、候选、综合规则和清理；同时为词缀模型保留只允许 `+1` 或 `-1` 的查询方向乘数。候选选择、模型清理、综合刷新和重跑都不得丢失该乘数。

内部 `values` 继续处于官方坐标系，确保综合规则等现有消费者不需要药剂、装备或中文文案分支。`stat.text` 与 source text 始终保留剪贴板原文；浮窗的 `min/max` 则处于该原文的显示坐标系，负向词条显示正数。

### 4. 显示边界使用文案坐标，提交时转换到官方坐标

删除 `valueRange` 枚举及所有函数参数。默认显示边界从转换后的 values 和查询方向计算：没有数值时不设边界；正向词条设置 `min=原值`；负向词条设置 `min=绝对值`。既有多来源合并完成后重新按合计值计算同样的显示边界，不再乘以 0.9 或 0.8。

浮窗继续呈现每条属性和词缀的 min/max 输入，且数值始终按当前展示文案解释。官方请求序列化时，正向词条直接使用显示边界；负向词条把两端乘以 `-1` 并交换上下界，例如浮窗 `min=40,max=50` 转为官方 `min=-50,max=-40`，默认 `min=45` 转为官方 `max=-45`。用户编辑值由现有模型清理白名单保护。旧持久化设置中的 `valueRange` 不进入规范化结果，因此下一次保存自然移除。

### 5. 未鉴定传奇药剂复用现有身份解析

不增加药剂专用解析器。真实未鉴定药剂文本先由共享物品解析器得到 `rarity=传奇`、药剂 category、底材名称和未鉴定事实，再由通用传奇解析按底材筛选官方目录候选。唯一候选自动应用；多候选走现有图片选择；零候选返回既有可诊断错误。查询构造继续从可信 category 映射 `flask` 并发送 `identified=false`。

## Risks / Trade-offs

- [大型目录 schema 升级可能遗漏合并路径] → 对生成、简繁转换、在线刷新、降级和序列化分别增加负向哨兵测试，并运行全部负向 matcher 回放审计。
- [负向显示边界转换时未交换上下界会改变筛选语义] → 同时断言单值与双边范围的浮窗正数、乘负号和上下界交换，并用开发版官方查询核对网页条件。
- [移除设置后旧字段继续从某个同步路径泄漏] → 覆盖默认值、规范化、store、IPC 快照、主页面和浮窗的静态及行为测试。
- [未鉴定药剂测试只验证合成目录] → 使用当前内置目录和真实“圣化生命药剂”剪贴板格式回放，断言“卡鲁之血”及完整请求。
- [与正在进行的地图/海图改动冲突] → 只追加独立 delta 与最小代码差异，实施完成后逐文件检查并删除失败尝试遗留代码。

## Migration Plan

随应用发布新 schema 的确定性内置目录；用户无需执行迁移。运行时设置规范化忽略旧 `valueRange`，后续保存自动清除。若回滚代码，应同时回滚内置目录 schema；用户设置中的已清除字段不需要恢复。
