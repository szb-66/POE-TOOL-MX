## Context

设备相关默认值目前分散在设置 Store、共享战斗配置、背包配置归一化和商城配方浮窗定位中。仅修改初始对象会被下游归一化或运行时构建重新补回旧值，因此需要统一空白表示并贯穿加载、重置、校验与 IPC 边界。

## Goals / Non-Goals

**Goals:**

- 用稳定、可校验的空值表示未配置状态。
- 保持已有本地数据及现有预设结构兼容。
- 保持自动化失败关闭和紧急停止能力。

**Non-Goals:**

- 不删除默认预设记录或改变制作业务规则。
- 不清理已有用户数据，不增加向导或云端迁移。
- 不修改时间、阈值和窗口识别默认值。

## Decisions

- 点坐标统一使用 `{ x: 0, y: 0 }`，背包格子尺寸使用 `{ w: 0, h: 0 }`，矩形区域使用四边均为 `0`。这些形态兼容现有输入组件和持久化结构，并可由现有预检判定无效。
- `DEFAULT_GLOBAL_SHORTCUTS` 保留全部稳定字段，但除 `end: 'Alt+3'` 外值均为空，避免破坏注册、合并和诊断使用的字段清单。
- 战斗配置保留启用开关、阈值和所有时间参数，仅清空检测点、药剂按键、回城按键及点击点；归一化必须保留显式空字符串和空数组。
- 背包和模板归一化的缺失回退改为空白配置，运行时构建不得再使用旧坐标常量。已有非零存储值按原结构加载。
- 浮窗偏移以 `null` 表示未手动定位，Electron 在显示时根据游戏窗口尺寸计算左下方安全位置；只有拖动事件写入具体偏移对象。现有偏移对象继续走原有约束逻辑。
- 界面中的快捷键说明从配置状态派生；帮助中的操作说明改为要求用户先设置快捷键，不再陈述固定绑定。

## Risks / Trade-offs

- [新用户看到更多“需配置”状态] → 使用现有校准入口和明确缺失项提示，不以危险的通用坐标换取开箱即用。
- [零值也可能是虚拟桌面的合法边界坐标] → 延续项目现有的 `(0, 0)` 未配置约定，用户通过坐标选择器保存实际有效点。
- [旧版部分存储字段缺失] → 缺失字段采用新空白默认，已存在字段绝不按数值猜测或清理。
- [浮窗动态位置在极小窗口中受限] → 复用现有边界裁剪，确保浮窗始终位于游戏窗口可见范围内。

## Migration Plan

- 不执行数据迁移；加载时只读取并归一化已有字段。
- 发布回滚时旧版本仍能读取已保存的坐标对象；`null` 浮窗偏移会被旧版本解释为其旧默认位置，不损坏存储。
