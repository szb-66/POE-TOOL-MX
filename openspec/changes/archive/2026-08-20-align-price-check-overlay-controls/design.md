## Context

见 `proposal.md`。当前查价浮窗直接渲染原生 `<select>` 与 `input[type="number"]`，虽然外围 CSS 已引用全局颜色变量，但原生选择器的选项弹层仍由 Chromium/系统绘制，无法完整继承 Element Plus 的全局暗色主题。状态过滤则使用标题与右侧文字按钮分离的结构，实际热区小于视觉标题区。

实现必须叠加在当前工作区已有的浮窗主题调整上，保留用户未提交改动，不回退或重写无关样式。

## Goals / Non-Goals

**Goals:**

- 从控件实现层消除原生弹层与全局主题不一致的根因。
- 在紧凑浮窗布局内复用既有全局控件状态和设计令牌。
- 保持状态过滤和表单字段的现有数据流、空值语义与事件隔离。
- 让正常就绪状态保持静默，并让加载与错误反馈和实际结果共享稳定位置。

**Non-Goals:**

- 不重新设计查价浮窗的信息层级、查询模型或结果区域。
- 不修改主窗口其他页面的控件样式，也不增加新的全局主题规则，除非开发验证证明现有规则缺少浮窗所需的通用状态。
- 不更改总过滤器按钮、设置齿轮、窗口尺寸或折叠状态持久化规则。
- 不修改加载、错误、限流文案的内容和触发条件，只调整正常提示及反馈位置。

## Decisions

### 使用现有 Element Plus 表单控件替换浮窗原生控件

选择器使用 `el-select` / `el-option`，数字字段使用适合紧凑布局的 `el-input-number` 并隐藏增减控制器。弹层保持传送到主题覆盖可达的文档层级，从而复用项目已经维护的暗色变量、选项状态和键盘行为。

备选方案是继续为原生控件补 CSS，但原生 `<select>` 的系统选项弹层无法可靠覆盖颜色与交互状态，不能解决截图中的根因，因此不采用。

### 显式保留字段语义和事件边界

替换控件时逐类映射现有 `v-model`、`change` 同步、`min`/`max`、placeholder 和 disabled 行为。数字控件必须允许既有空边界，并确认组件输出的 `null`/number 不改变查询清理结果。嵌在可选择属性行和词缀行中的控件继续阻止点击及键盘事件冒泡，避免编辑数值或枚举时切换整行启用状态。

备选方案是统一抽象新的查价表单组件；本次字段种类有限，抽象会扩大变更面且无新的跨页面复用需求，因此直接复用现有组件。

### 标题区域采用单一语义按钮

将状态过滤标题行整体实现为一个带 `aria-expanded` 和 `aria-controls` 的按钮语义热区，内部保留标题文本并使用现有 `ArrowDown` 图标按状态旋转。这样点击文字、空白处和图标均经过同一路径，浏览器原生按钮键盘行为也覆盖 Enter/Space。

备选方案是在标题容器上添加 click 与 keydown；这需要手工复制按钮语义和键盘规则，且更容易产生嵌套交互热区，因此不采用。

### 仅增加领域级尺寸适配

颜色、边框、弹层和交互状态由全局主题提供；查价浮窗 scoped 样式只负责宽度、高度、栅格占位和紧凑字号等领域布局。若 Element Plus 内部结构需要穿透，仅添加最小的 `:deep()` 尺寸规则，不复制全局颜色常量。

### 状态反馈与结果共享固定区域

删除身份栏右侧 `ready-to-query` 正常提示。将查询加载、查询错误和限流反馈移动到操作按钮之后、结果内容之前，使查询过程、失败原因和成功结果在同一视觉位置切换；身份栏只保留物品状态标签。这样搜索按钮已经表达操作入口，用户注意力不会在筛选区和结果区之间跳转。

备选方案是保留身份栏提示并只移动错误，但会继续产生正常态冗余信息，也使同一查询流程的状态分散在两个区域，因此不采用。

## Risks / Trade-offs

- [Element Plus 数字控件将空字符串标准化为 `null`] → 在实现测试中覆盖空最小值/最大值，并确认提交前清理逻辑产生与现状相同的查询。
- [传送弹层可能超出浮窗边界或被错误层级遮挡] → 在开发版实际打开设置、状态与属性三类弹层，核对定位、z-index、主题类和窗口边缘翻转。
- [紧凑栅格中的组件默认宽度可能挤压标签] → 为组件容器设置 `min-width: 0` 和现有列宽约束，并覆盖典型双列属性与五列词缀行。
- [标题整行按钮扩大热区后可能与内部交互冲突] → 标题行只包含文本与状态图标，不放置第二个按钮或其他可交互子元素。
- [错误移动后可能与结果同时出现造成歧义] → 由互斥的查询状态控制加载、错误与结果展示，并用回归测试固定它们都位于操作按钮之后。

## Migration Plan

这是渲染层局部替换，不需要数据迁移。实现后先运行查价浮窗定向测试和 Vite 开发转换，再在开发版核对鼠标、键盘、弹层和数字空值；若回滚，只需恢复该浮窗的控件模板与领域尺寸样式，不影响已保存设置或查询契约。
