## Context

当前开发版已经具备国服 PoE1 悬停物品解析、基础体检浮窗、交易 Stat 目录和做装数据，但现有体检只覆盖少量词缀展示，缺少 Exile-UI Item info 的核心解释能力、偏好交互、装备比较和制作刷新。目标基线固定为 Exile-UI `3152d169dbbc3dc19308b42ac4b3f45538713070`；复刻其公开功能与行为，不直接移植 AHK UI 代码。

实现横跨 Electron 主进程、preload/IPC、Vue 浮窗与配置页、离线数据生成、用户设置迁移和 Windows 输入状态观察。运行时必须完全离线，只支持国服 PoE1，并继续使用 460px 宽、当前显示器工作区全高的既有窗口形态。

现有解析器已经提供品质、物品等级、防御、武器伤害、暴击、攻速、底材百分位以及详细词缀来源等字段；`electron/assets/crafting-data/dataset.json` 已包含底材、词缀族、权重、阶级和需求等级。新增设计应复用这些稳定输入，避免再维护一套并行解析器。

## Goals / Non-Goals

### Goals

- 对魔法、稀有、传奇装备、药剂、普通/深渊/星团珠宝提供完整、可降级的离线体检快照。
- 在一个统一模型中表达底材质量、词缀范围、需求物等、权重、特殊隐式、涂油、传奇 roll-power 和装备比较。
- 提供五档配置、原项目四种偏好手势、稳定反转规则、全局规则、颜色及显示选项，并安全迁移版本 1 偏好。
- 以最小权限实现快捷键短按/长按/按住模式和 Shift 制作刷新；任何门禁失败均不得发送复制按键。
- 保持中文可读性、键盘可达性和多屏/DPI 下的全高紧凑布局。

### Non-Goals

- 不支持 PoE2 的阶级重排、铁符文或品质缩放。
- 不逐像素复刻 Exile-UI，也不逐行移植 AHK 实现。
- 不提供主观价值、战力或价格评分，不为传奇推导前后缀空位。
- 不在运行时联网，不保存原始剪贴板，不暴露任意键盘输入或任意文件访问。
- 不在本变更中构建安装包；规范同步和归档也不属于本次实现自动步骤。

## Decisions

### 1. 固定来源版本并生成单一离线目录

新增版本化目录生成器，将现有做装底材/词缀数据、交易 Stat、特殊隐式、传奇快照与固定提交中的涂油配方和传奇掉落档位合并为紧凑的 `item-inspection-catalog.json`。目录包含 schema 版本、游戏范围、生成时间、上游提交和来源清单，并在构建时进行引用完整性与哨兵数据校验。

选择生成目录而非运行时读取多份来源，是为了让匹配和降级行为可测试、避免网络依赖，并把上游许可与版本固定在可审查的构建步骤。来自 MIT 数据或其行为派生的内容记录到 `THIRD_PARTY_NOTICES.md`。

运行时加载器按分区验证目录。某一分区缺失或版本不兼容时，仅把相关能力标记为未知并写入 `warnings`，不能使整个体检失败。

### 2. 使用纯计算评估管线和统一不可变快照

评估器以解析后的结构化物品为输入，依次执行身份归一化、目录匹配、词缀评估、底材指标、特殊物品评估和装备比较，输出：

`identity`、`baseMetrics`、`comparison`、`implicitSections`、`modifiers`、`cluster`、`uniqueSummary`、`affixCapacity` 和 `warnings`。

各子评估器保持纯函数，UI 不重复做数值推导。稳定词缀身份优先使用交易 Stat ID；没有可信 Stat ID 时使用规范化文本、来源、数值位置和适用标签组成的签名。存在多个可信候选且无法唯一判定时明确降级，不按模糊相似度猜测。

当前阶级区间取已匹配阶级的数值范围；完整区间由物品标签和词缀族下全部可用阶级合并得到。单值和多值词缀逐位置归一化，反转方向按稳定身份持久化，右键删除反转规则恢复默认。

### 3. 底材与传奇只做可证明的计算

武器按每种伤害区间均值乘攻击速度计算物理、元素、混沌和总 DPS，并从离线底材索引计算同类别最优百分比。防具展示单项与组合防御，并优先使用复制文本中的可信底材百分位；只有底材区间、品质及局部增减词缀能唯一反解时才反算，否则显示未知。

普通和深渊珠宝的生成权重只表示相对稀有度，以灰度编码，不能复用质量色。星团珠宝由独立评估器展示规模、天赋数量、最优数量提示、附魔和普通词缀。

传奇每个可变数值单独归一化。整体 roll-power 使用所有非固定数值的归一化分子之和除以分母之和；固定值不参与。掉落档位只在离线目录有可信映射时展示，否则输出“掉落档位未知”。

### 4. 偏好设置升级为版本 2，装备快照独立存储

设置仓库版本 2 包含一个活动档案 ID、固定五个可命名档案，以及每档的全局/类别/隐式偏好、数值反转规则、自动偏好规则、显示选项和颜色。类别规则优先于全局规则；隐式规则与显式规则使用独立命名空间。

版本 1 的 `byCategory` 偏好迁入默认档案的类别偏好。迁移通过临时文件和替换实现原子写入；失败时保留旧文件并继续以安全默认值读取。未知旧 Stat ID 原样保留，以便目录将来恢复识别。

装备仓库使用独立版本和原子写入，只允许 `mainhand`、`offhand`、`helmet`、`body`、`amulet`、`ring1`、`ring2`、`belt`、`gloves`、`boots`，只保存归一化结构属性，不保存原始剪贴板。

### 5. 比较按候选槽独立计算

武器比较优先展示 DPS、攻击速度等同类指标；当前装备有同类值时给百分比差异，否则给绝对差异。防具与首饰按固定顺序汇总生命和抗性，再列出更换后丢失的其他“想要”词缀，已在 DPS 或抗性摘要出现的属性不重复。

戒指候选分别与 `ring1`、`ring2` 比较，单手武器分别与主手、副手比较，禁止先合并双槽属性再给出一个结果。这样可以保留真实换装决策语义，并避免把两个独立装备槽误当作一个基准。

### 6. 输入观察只输出语义事件

Electron `globalShortcut` 无法可靠提供按键释放事件，因此使用受限的 Windows 辅助进程观察用户已配置的“物品菜单”组合键以及 Shift/Esc。辅助进程只接收通过白名单语法验证的组合键，只在模块需要且游戏前台时运行，并输出 `pressed`、`longPressed`、`released`、`shiftReleased`、`escape` 等语义事件；不输出键名、字符流或其他键盘状态。

优先复用项目现有 Python/Win32 运行方式，不新增常驻 npm 原生依赖。辅助进程异常、配置非法或前台校验失败时按 fail-closed 处理：关闭体检联动且不发送输入。

快捷键状态机在 350ms 前释放时打开物品菜单；达到阈值时直接体检。切换模式下再次短按体检下一件，Esc、关闭按钮或点击回游戏关闭；按住模式在长按后显示并在释放时关闭。

### 7. Shift 制作刷新采用一次性门禁状态机

状态依次为 `idle`、`currencySelected`、`pendingCopy`、`refreshed`。只有游戏前台、背包识别成功、Shift 按下、用户右键选择通货并随后主动点击有效物品时才进入 `pendingCopy`；350ms 后再次验证全部条件，最多发送一次普通 `Ctrl+C`。500ms 内重复事件去抖，不创建循环。

Shift 期间右键添加的“不要出售”标记由独立覆盖层管理。Shift 释放、Esc、游戏失焦、背包识别失败或物品校验失败都会清除状态和标记。任何失败都必须在发送复制按键之前终止。

### 8. UI 采用固定摘要与独立滚动表格

浮窗继续使用 460px 宽和当前显示器工作区全高，以 flex 布局实现固定头部、固定摘要和唯一滚动内容区。表格使用固定列、来源分区、文字标签、色块与数值条；所有仅靠颜色表达的状态同时提供文字或数字。

词缀行实现左键全局想要、右键全局排除、长按左键类别想要、长按右键类别排除，并提供中文手势提示、状态图例、焦点样式和键盘等价操作。配置页按常规、档案、规则、颜色和装备组织，支持搜索、筛选、稳定 Stat ID 查看及恢复中性。

颜色输入只接受规范化的六位十六进制值，并始终提供默认恢复。需求物等默认关闭；默认启用底材信息，使用当前阶级区间和切换显示模式；装备比较与 Shift 刷新默认关闭。

### 9. IPC 使用窄类型接口并修正广播契约

preload 只暴露读取/更新设置、更新偏好、切换数值反转、捕获/清除白名单装备槽、读取/关闭浮窗等显式方法。主进程对枚举、字符串长度、对象深度、颜色和槽位进行验证，渲染层不能读取任意文件、任意剪贴板或任意按键。

偏好更新统一返回 `{ settings, inspection }`。只有 `inspection` 存在时才广播体检浮窗状态，防止把设置对象误发为体检快照。原始复制文本只在主进程短暂处理并立即转成结构化模型。

## Risks / Trade-offs

- 上游数据和国服文本可能漂移：目录固定来源与生成版本，匹配失败按分区降级，并以多类真实/脱敏夹具覆盖变化。
- 稳定 Stat ID 不总是可得：使用确定性的复合签名作为后备，但遇到歧义不猜测，因此部分物品会显示未知警告。
- Windows 按键观察增加安全敏感面：协议只允许一个配置组合键和 Shift/Esc，输出语义事件并在异常时关闭功能；代价是暂不支持非 Windows 平台。
- 多屏、DPI 和装备槽定位可能不稳定：使用当前显示器工作区与现有界面识别/校准，不在识别失败时继续捕获或发送输入。
- 全量评估可能增加浮窗延迟：构建期预计算底材最优索引和词缀查询表，运行时只做确定性查找与纯计算。
- 五档配置和迁移扩大持久化复杂度：设置与装备仓库分离、版本化、原子写入，并以损坏文件和未知 ID 测试覆盖回退。

## Migration Plan

1. 保留现有版本 1 文件，读取并验证后生成版本 2 临时文件；成功替换后才切换活动仓库。
2. 将旧类别偏好迁入默认档案，其余四档使用默认值；未知 ID 不丢弃。
3. 新功能以兼容默认值上线：切换显示、当前阶级区间、底材信息开启；需求物等、装备比较和 Shift 刷新关闭。
4. 装备仓库首次使用时创建，不从剪贴板或旧设置推断装备。
5. 在开发版以真实国服夹具、完整测试和 Electron 手工流程验证。若迁移或目录加载失败，回退到旧设置读取与基础体检，并通过 `warnings` 明示降级。
6. 本变更不执行安装包构建。实现和验证完成后，规范同步及归档必须再次取得用户确认。

回滚时停用版本 2 写入和新输入观察，继续读取保留的版本 1 设置；独立装备仓库可安全忽略，不影响基础体检。
