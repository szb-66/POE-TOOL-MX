## Context

现有两份 Python 模板的通货入口只检查坐标和鼠标移动是否成功，随后直接右键。脚本输出已经同时转发给主窗口和置顶浮窗，首页也已有 `scriptStore.lastError`，因此可以在不扩展预加载 API 的情况下传递失败原因。地图模板当前存在未提交的游戏窗口前台聚焦修复，必须在该版本上增量修改。

## Goals / Non-Goals

**Goals:**

- 让当前预设所有可能执行分支的通货在首次正式点击前完成一次无点击验证。
- 让条件分支无法绕过预检集合执行通货点击。
- 将同一结构化失败原因可靠同步到进程状态、首页和浮窗。

**Non-Goals:**

- 不在每次使用通货时重复复制验证。
- 不检测运行中通货移动或耗尽，不自动切换仓库页或寻找其他通货堆。

## Decisions

### 清单在 JavaScript 生成阶段确定

在 `python.js` 根据预设生成有序、去重的通货 ID 数组并注入模板。该层拥有完整预设信息，并枚举该预设下所有可达分支：物品词缀模式包含起始稀有度预处理通货，地图模式包含未鉴定地图使用的知识卷轴。相比在 Python 中重新解释预设，这可避免两套策略漂移。

### 预检使用剪贴板序列号和头部完整行

每项预检记录 Win32 剪贴板序列号，发送复制命令后要求序列号变化，再只检查第一个分隔线之前是否存在目标中文名称完整行。无序列号、无变化或名称不符均失败关闭，不能回退到旧剪贴板。

### 已验证集合是正式通货入口的唯一门禁

预检成功后保存 `verified_currency_types`。`right_click_currency` 在移动或点击前检查成员关系；未预检通货触发同一失败事件。这样正式路径没有额外剪贴板等待，同时所有现有调用者自动受保护。

### 使用结构化标准输出承载失败

Python 输出单行 `EVENT` JSON，包含 `event=currency-preflight-failed`、`reason`、目标/实际通货与坐标，并以非零退出结束。主进程使用按行缓冲解析事件，保存最终运行错误；浮窗从同一输出解析 `stopReason`。相比新增 IPC 通道，此方案复用现有进程输出生命周期且无需扩展公开 API。

### 失败状态与完成状态互斥

模板顶层记录退出结果，只有所有制作阶段成功时输出完成标记和完成音。预检失败只播放一次系统错误音并退出；地图循环也不得在失败后落入无条件“地图洗练结束”分支。

## Risks / Trade-offs

- [国服物品文本头部格式变化] → 仅依赖分隔线与完整目标名称行，并以失败关闭保护输入。
- [Node stdout 数据块拆分 JSON 行] → 主进程和浮窗均保留跨数据块行缓冲。
- [新增制作分支后遗漏通货] → 清单生成测试枚举模板中的全部通货调用，正式入口门禁继续作为最后保护。
- [现有地图前台修复被覆盖] → 只在当前工作树版本上打补丁并保留对应回归测试。

## Migration Plan

1. 注入固定清单并加入 Python 预检/门禁。
2. 接入结构化错误状态和浮窗展示。
3. 增加运行时与界面回归测试后启用；无需设置迁移。
4. 回滚时移除预检注入与事件解析即可，原坐标配置保持兼容。
