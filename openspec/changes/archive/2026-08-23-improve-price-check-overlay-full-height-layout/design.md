## Context

参见 `proposal.md`。当前主进程将查价浮窗的宽高作为一个偏好保存，默认高度上限为 760；浮窗复用时沿用当前边界重新靠近鼠标定位。渲染端内容区可滚动，但词缀和佣兵区域还分别设置了固定最大高度与 `overflow-y`，形成多层滚动。属性虽然已经是两列网格，每个未启用属性行却没有稳定可见的容器边界。

## Goals / Non-Goals

**Goals:**

- 让窗口高度、纵向位置和可调整方向共同表达“始终铺满当前工作区”的单一规则。
- 保留用户宽度偏好与现有横向鼠标锚定策略，并安全兼容旧窗口状态。
- 让真实浮窗只有内容区一层纵向滚动，预览仍受设置页固定高度约束。
- 只加强属性项的容器关系，不改变现有查价主题和筛选语义。

**Non-Goals:**

- 不读取或跟随游戏客户区边界，窗口化游戏也以当前显示器工作区为准。
- 不增加满高模式开关、宽度设置项或新的渲染端持久化状态。
- 不改变词缀行、顶栏、透明度、结果布局、查询模型、IPC 或官方接口。
- 不执行安装包构建或正式游戏自动化验收。

## Decisions

### 1. 尺寸控制器只拥有宽度偏好

将尺寸归一化与持久化语义收窄为宽度：读取时同时接受旧对象中的 `width`，不再依赖 `height`；保存时写入仅含 `width` 的对象。实际布局每次由“偏好宽度钳制到当前工作区 + 当前工作区完整高度”组成。

相比保留高度但每次覆盖，这种模型不会向用户暴露一个永远不生效的高度偏好，也能让测试直接表达真实所有权。旧 `height` 无需迁移或删除，首次宽度保存后自然被新结构替换。

### 2. 创建和复用路径统一重新应用工作区纵向边界

窗口首次创建、重复查价和跨显示器复用都使用同一个布局解析结果：`y = workArea.y`、`height = workArea.height`，横向仍由现有鼠标邻近与翻转算法计算。程序化边界更新不进入用户宽度保存路径。

窗口保持可缩放，但将最小高度与最大高度同步锁定为当前工作区高度，因此平台只允许横向变化。切换显示器前先更新高度约束，再设置新边界；工作区宽度继续作为实际最大宽度，小屏钳制不回写偏好。

### 3. 内容区成为唯一滚动所有者

保留 `.content` 的视口高度和 `overflow: auto`，移除词缀列表与佣兵面板的 `max-height` 和纵向 overflow。这样普通物品可以直接连续展示全部词缀，极长物品、佣兵凭证和查询结果仍可通过一条主滚动浏览。

设置页预览继续通过 `.overlay-shell.preview` 的固定高度覆盖真实窗口的 `100vh`，但其内部同样只由 `.content` 滚动，不恢复子区域滚动。

### 4. 属性行获得始终可见的卡片表面

保持现有两列 `.property-grid` 和属性行内部的标题/输入列。为所有 `.property-row` 提供中性背景与基础边框，启用、悬浮和焦点继续使用现有整行状态规则覆盖。输入控件仍阻止点击和键盘事件冒泡，避免编辑数值时切换筛选。

相比重构模板或引入新组件，局部样式能准确形成一个视觉整体，同时避免影响词缀、地图、海图和佣兵属性的数据结构。

## Risks / Trade-offs

- [满高浮窗在窗口化游戏中可能高于游戏客户区] → 明确以当前显示器工作区为产品边界，保持无需额外窗口识别的稳定行为。
- [锁定高度的系统缩放约束在切换显示器时短暂冲突] → 在程序化设置新边界前同步目标工作区的最小/最大高度，并用单元测试覆盖切换顺序和结果。
- [去掉子滚动后查询结果离首屏更远] → 保留吸底操作栏和总过滤器折叠，用户仍可快速搜索或折叠过滤条件。
- [保存文件仍可能存在历史 `height`] → 读取时只提取合法宽度，写入新宽度时替换为宽度单字段，损坏值回退默认宽度。
- [属性卡片在窄宽度下更紧凑] → 保留现有标题省略提示、两列布局和输入宽度，不额外增加字号或间距。

## Migration Plan

1. 扩展尺寸与状态回归测试，使旧宽高配置只恢复宽度，实际高度始终来自工作区。
2. 更新主进程创建、复用和用户缩放路径，再调整渲染端滚动与属性卡片样式。
3. 运行定向测试、完整测试、Vite 构建、严格 OpenSpec 校验和开发版手动验证。
4. 回滚时恢复宽高偏好与内部最大高度；已写入的宽度单字段会由旧版无效配置回退逻辑安全处理。
