## Context

现有查价链路已能从详细复制文本获得真实词缀类型、匹配活动交易目录、清理渲染进程模型并构造腾讯国服官方查询。当前模型把物品状态事实直接转成固定布尔查询，目录只保留 matcher 与官方 ID，因而既无法编辑状态，也缺少从多个 stat 来源生成综合条件所需的稳定语义引用。

工作区存在两个独立 OpenSpec 变更和未提交实现，本变更必须在当前工作树上增量修改，不能清理或还原无关文件。实现仅在开发版验证，不构建安装包。

## Goals / Non-Goals

**Goals:**

- 让状态事实、用户查询意图和官方请求字段三层分离并可安全往返。
- 以固定、可审计规则从已唯一映射的 stat 生成真实可查询的 `pseudo.*` 条件。
- 在目录在线刷新、内置降级、模型清理和浮窗展示之间保持 stat 类型、引用和 ID 一致。
- 保持每个综合值对原始词缀来源可追踪，并避免默认查询重复约束。

**Non-Goals:**

- 不实现官方全部约 298 个 pseudo 条目的推测公式，只实现固定上游规则明确可由物品 stat 推导的集合。
- 不增加任意自定义状态字段、自由输入 stat ID、手动添加官方过滤器或新的持久化查询预设。
- 不改变账号认证、IPC 权限、快捷键捕获、挂单抓取、价格统计和官方外链生命周期。
- 不执行 Windows 安装包或发布验证。

## Decisions

### 1. 物品事实与三态查询条件使用独立字段

解析器继续产生可信布尔事实；查价模型新增 `stateFilters`，每个白名单键只允许 `any | true | false`。创建模型时除 `mirrored=any` 外按事实初始化，`identified` 使用正向语义。模型清理先验证三态字段；旧模型缺失字段时从旧事实迁移，避免已打开浮窗或旧调用路径失效。

查询构造器只读取清理后的 `stateFilters`：`any` 省略字段，其余写入 `misc_filters.filters.<official-key>.option`。选择不写入全局 settings，因此新物品始终重新初始化。

选择该方案而不是直接允许修改 `item`/`flags`，因为后者会丢失“物品实际是什么”和“用户想搜索什么”的区别，并扩大渲染进程伪造模型的影响面。

### 2. 目录 schema 升级并以稳定 ref 连接本地文本、官方 ID和综合规则

目录 schema 升级一版。stat 记录增加去重且受校验的 `refs`；顶层增加 `pseudoRuleVersion` 和 `pseudoRules`。规则结构包含目标 ref、来源 ref 列表、倍率、required、group/replaces 和默认启用语义。目录生成时从固定版本 Awakened PoE Trade 英文 NDJSON 按 trade ID关联 ref；对该精简 NDJSON 未保留、但固定综合规则直接引用的 ref，再以国际服官方 matcher 与规则 ref 的精确相等关系补齐，禁止模糊关联。随后从国际服与腾讯国服官方目录保留 namespace、ID和中文 matcher，再由 Sidekick 当前游戏描述补充国服剪贴板 matcher；在线刷新重新按 ref/ID建立索引但不改变固定规则内容。

采用 ref 而不是中文文本作为规则键，因为中文 matcher 会随翻译和赛季更新，而 ref 是固定上游规则使用的语义身份。采用目录内版本化规则而不是运行时抓取上游，保证离线可重复、降级目录自洽和发布可审计。

### 3. 固定采用 Awakened PoE Trade 3.29.102 综合规则语义

以提交 `91b5a05b14cda3a632a306b5f606ca1cced8b4a9` 的 `filters/pseudo/index.ts` 为来源，将数据规则转换为本项目的纯数据结构，保留抗性和属性贡献矩阵、倍率、required、group/replaces 与默认选择行为。第三方声明记录新提交、文件和 MIT 许可。

不直接移植其完整解析器和 UI：本项目已经拥有国服详细文本、目录消歧和查询模型，只复用综合规则语义并接入既有模型。这样避免引入第二套物品模型和大型依赖。

### 4. 先匹配原始 stat，再由来源集合派生综合 stat

目录匹配结果增加 ref；每条标准 stat 的 `sources` 保留 ref、真实类型、文本和数值。所有唯一映射来源完成合并后，综合引擎遍历规则：

1. 按来源 ref 收集贡献并应用倍率；
2. 检查 required 来源与 replacement/group 规则；
3. 通过目标 ref 在活动目录唯一查找 `pseudo.*` ID；
4. 使用既有数值范围策略创建 `type=pseudo` 的 stat，并保存贡献明细；
5. 目标无效时省略并计入审计，不产生未知项或猜测 ID。

原始 stat 仍保留在模型和界面。若综合规则默认启用，则取消被吸收来源的自动启用；用户之后仍可独立选择任意组合。查询序列化继续走统一 stat 白名单和 `query.stats[0].filters`，无需增加旁路协议。

### 5. 状态和类型展示使用集中元数据

主模型共享白名单状态定义（模型键、官方键、中文标签、默认策略）和 stat 类型定义（namespace、中文标签、CSS token）。浮窗按白名单顺序渲染状态下拉，按真实 namespace 渲染标签；未知类型使用中性回退且不改变查询类型。

集中定义可避免解析器、清理器、查询构造和 Vue 模板各自维护不一致映射。颜色只承担辅助区分，文本标签和焦点样式仍满足可访问性。

### 6. 审计与兼容验证作为目录边界

目录校验除现有 ID/matcher 唯一性外，增加 refs、规则结构、目标 namespace、来源存在性和规则身份检查。在线刷新状态报告规则总数、可用/缺失目标和来源；缺失规则不会使整个官方目录不可用，但会被明确审计并在运行时安全省略。结构损坏仍使目录加载失败并回退可信内置目录。

## Risks / Trade-offs

- [上游 ref 或规则随赛季变化] → 固定提交和规则版本；刷新时做覆盖审计，新版本通过显式目录更新引入。
- [同一 stat ID关联多个 ref导致错误汇总] → refs 去重并按当前已匹配的唯一语义 ref贡献；无法唯一关联的来源不进入综合计算。
- [综合与原始词缀同时启用过度收窄] → 默认综合规则吸收的来源取消自动启用，同时保留用户手动覆盖能力。
- [本地防御词缀与全局属性混淆] → 综合规则只消费指定 ref，继续沿用现有 local/category 消歧结果，不按显示文本模糊求和。
- [目录 schema 升级导致旧快照不可读] → 同一次变更重建并提交内置目录；加载器拒绝旧 schema并显示明确目录错误，不在运行时猜测迁移大体量快照。
- [状态过滤项使浮窗增高] → 使用紧凑、可换行的状态区域并保持内容内部滚动，不扩大窗口生命周期权限。

## Migration Plan

1. 扩展生成器和校验器，生成新 schema 内置目录及综合覆盖报告。
2. 扩展解析事实、三态模型、旧模型迁移、综合引擎和官方查询序列化。
3. 更新浮窗状态控件与来源标签，保持现有手动/立即查询流程。
4. 运行目录、解析、查询、IPC/模型清理、Vue 开发转换和完整测试；仅在开发版完成官方 query JSON/网页市集等价验证。
5. 若需回滚，回退本变更的目录 schema、模型和浮窗改动并恢复上一份内置目录；不涉及用户数据库或云端迁移。
