## Context

当前主界面路由均通过动态 `import()` 懒加载，首次访问会等待开发服务器编译和传输页面模块。Vue Router 在目标异步组件解析完成前保留旧路由，根布局和侧栏没有可观察的导航状态，因此点击后的等待看起来像界面冻结。现有代码没有统一的路由加载状态，也没有复用路由组件加载器进行预取。

## Goals / Non-Goals

**Goals:**
- 将路由等待状态限制在主内容区，不影响窗口操作和继续选择其他 Tab。
- 用单一导航状态源处理成功、错误和重叠导航。
- 复用同一个动态导入函数进行按意图预加载，避免重复下载或维护第二套路由映射。

**Non-Goals:**
- 不缓存所有已挂载页面组件，不改变各页面自身的数据加载语义。
- 不一次性预加载所有页面，以免拖慢应用启动。
- 不修改覆盖层窗口的无布局路由表现。

## Decisions

1. 在路由模块导出可复用的主页面加载器，并由路由定义和预加载函数共同引用。动态 `import()` Promise 由模块加载系统缓存，侧栏无需维护重复组件映射。相比在侧栏复制 import 路径，此方案消除配置漂移。
2. 使用独立的响应式路由切换状态，由全局导航守卫开始和结束导航。状态带递增令牌，只有最新导航可以结束加载，避免连续点击时旧导航关闭新导航的遮罩。
3. 加载层延迟短暂显示，以避免已预加载页面切换时闪烁；一旦显示则维持最短可感知时间，减少视觉跳动。导航异常路径显式清理状态。
4. 侧栏在 `pointerenter` 与 `focusin` 时调用预加载函数并吞掉预加载错误。正常点击仍由 Router 处理，预加载只是性能优化，不成为导航前置条件。

## Risks / Trade-offs

- [页面同步挂载工作阻塞主线程，加载层可能来不及绘制] → 导航开始后先建立延迟加载反馈；预加载主要消除异步模块等待，各页面内部重计算仍应单独优化。
- [最短展示时间会略微延后加载层消失] → 只在加载层实际显示后应用很短的最短时长，快速导航完全不展示。
- [动态导入预加载消耗额外资源] → 仅根据悬停或键盘焦点触发，不在启动时批量加载。

## Migration Plan

该变更仅涉及渲染进程，可直接在开发版启用。回滚时移除路由状态、加载层与预加载事件即可，路由地址和业务状态不受影响。
