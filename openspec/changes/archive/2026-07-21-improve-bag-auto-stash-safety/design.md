## Context

背包模块当前由一个常驻检测进程和一个按需入库进程组成，但检测脚本只加载仓库模板，入库脚本则不读取物品信息，直接点击全部 60 个格子。检测事件还依赖 `BagView` 挂载后的监听器，模块离开页面后无法可靠维护状态。项目已经具备 `mss`/OpenCV 模板匹配、`pyperclip`、Windows 剪贴板序列号检测、DPI 感知鼠标控制、游戏前台窗口检查和统一全局快捷键，可在不新增依赖的情况下重构。

## Goals / Non-Goals

**Goals:**

- 仅在仓库与背包同时稳定打开且游戏位于前台时自动入库。
- 每个连续打开会话自动执行一次，避免检测持续命中导致循环运行。
- 识别每格物品的名称、基底和类别，并让黑名单物品留在背包。
- 对空格、复制失败、界面丢失和停止操作采取不误点的失败关闭策略。
- 让检测、自动触发和运行状态独立于背包设置页面生命周期。

**Non-Goals:**

- 不使用 OCR、图标识别或在线物品数据库。
- 不在本次变更中支持词缀、稀有度、插槽或正则表达式黑名单。
- 不推断多格物品的占用尺寸，统计单位保持为扫描格数。

## Decisions

### Electron 主进程负责会话编排

保留“检测进程 + 单次入库进程”的边界，但把最新配置、匹配状态、入库进程和 `sessionLocked` 会话锁统一放在背包 IPC 模块。检测进程连续三次同时命中两个模板后发送 ready 事件，主进程在未锁定时设置锁并启动入库；连续三次未同时命中后解除锁。这样自动触发不依赖 Vue 页面，且不会因持续匹配反复启动。

手动按钮和 `stashStart` 快捷键调用同一个入库启动函数，只在当前 ready 且没有入库进程时有效；手动补扫可以绕过当前会话已执行锁，但不能绕过界面和前台校验。

替代方案是把检测、状态机和入库合并成单个 Python 进程，但这会增加进程内命令通信、重启和错误恢复复杂度，且不利于复用现有 IPC 生命周期。

### 模板匹配只负责界面门禁，剪贴板负责物品判定

检测进程必须加载仓库和背包模板，并分别在配置区域匹配。入库进程启动前及每个格子执行动作前再次检查游戏前台和两个界面，避免检测与点击之间的竞态。

每格移动鼠标后记录 Windows 剪贴板序列号，发送普通 `Ctrl+C`，在全局 `clipboardRead` 延迟范围内轮询新内容。只有序列号变化且文本包含合法物品头时才继续；否则将该格记为 empty 或 unreadable 并跳过。相比 OCR，该方案能直接获得稳定的语义字段，不受图标皮肤和画面缩放影响。

### 黑名单使用显式字段规则

持久化结构为 `blacklist: Array<{ field: 'name' | 'baseName' | 'category', keyword: string }>`。匹配前对规则值和物品字段执行 Unicode 字符串首尾去空白及不区分大小写的包含比较；任一有效规则命中即跳过 Ctrl+点击。空关键词不保存，未知字段在加载和 IPC 边界被丢弃。

物品头解析只移植现有解析器中类别、稀有度后的名称/基底提取规则，不解析词缀。无法得到合法类别及名称的文本视为 unreadable，不采用全文兜底，以防词缀误命中。

### 使用逐行结构化事件

Python 进程以 `EVENT {json}` 单行输出 `detection-state`、`stash-progress`、`stash-completed`、`stash-aborted` 和 `stash-error`。Electron 对 stdout 做跨 chunk 行缓冲后解析，前端事件包含 `scannedSlots`、`stashedSlots`、`blacklistedSlots`、`emptySlots`、`unreadableSlots`、`progress` 和可选 `reason`。普通日志不能驱动状态。

所有退出路径通过统一清理逻辑释放 Ctrl、Alt、Shift 和鼠标按键。对已发送的 Ctrl+点击不自动重试，以避免重复或错误转移。

### 配置与生命周期迁移

`bagSettings` 增加空黑名单默认值；读取旧设置时规范化规则。旧 `buttonPosition` 数据可以留在 localStorage 中但不再读取或写回，页面移除对应无效配置。应用初始化时由应用级服务读取持久化设置：若模块已启用且模板、区域和网格有效，则恢复检测；页面只负责编辑配置和展示 store 状态。

## Risks / Trade-offs

- [游戏复制快捷键失效或剪贴板被其他程序抢占] → 使用序列号和合法头校验，失败格一律不点击并在摘要中报告。
- [模板区域或阈值配置不正确] → 要求双模板连续命中，并保留红框调试与等待状态，不自动降低阈值。
- [逐格复制比盲点更慢] → 复用用户延迟配置；正确性优先，空格在一次超时后继续。
- [黑名单多格物品被重复统计] → 明确统计为格数，不宣称唯一物品数。
- [用户在运行中切换窗口或关闭界面] → 每格动作前校验并立即安全终止，不等到整轮结束。

## Migration Plan

1. 先引入黑名单规范化、结构化事件解析和纯函数测试，再切换 Python 输出协议。
2. 接通双模板检测及会话锁后启用自动触发，同时保留手动入口作为回退。
3. 接通逐格复制与安全停止后移除盲点逻辑、页面级运行监听和按钮位置配置。
4. 若新流程出现问题，可关闭模块；旧设置除被忽略的按钮位置外保持可读取，回滚代码不需要数据迁移。
