## Context

当前装备模板 `src/assets/scripts/crafting_template.py` 与地图/海图模板 `src/assets/scripts/map_rolling_template.py` 各自实现了一套剪贴板复制、`allow_unchanged_text`、`verify_freshness`、全文历史和解析等待逻辑。通货后读取先在 `wait_for_clipboard_change` 中为“序列号已变化、文本仍相同”消耗完整自适应超时，再固定退避 200ms 复核；外层 `read_current_*` 又最多执行三次补读。默认时序下，这把持续旧文本路径从约 3.33s/3 次 Ctrl+C 扩张到约 7.26s/6 次 Ctrl+C，而现有测试把退避覆写为 0，未锁定真实调度成本。

解析链路由 Python 写入带 requestId 的请求，`electron/modules/watcher/fileWatcher.js` 读取后交给 `electron/modules/ipc/file.js` 解析。后者既会立即发送解析结果，结果文件监听器也会再次发送，所以脚本尚未验证目标身份和动作后置条件时，候选结果已经可能更新面板。另一方面，`src/utils/python.js` 中富豪石和崇高石收尾只执行 `apply_currency`，未重新读取，完成提示与面板因此可能必然落后于游戏内实物。

本变更继续消费已有的自动操作时序与 `adaptiveTimeoutMs`，结果观察、确认和发布仍与校准服务解耦；但通货选择必须增加独立的鼠标安全下限，避免无点击校准得到的键盘释放阈值降低右键选通货的可靠性。现有前台窗口、DPI、坐标、通货预检、紧急停止与异常恢复门禁继续保留。

## Goals / Non-Goals

**Goals:**

- 把每次“通货输入 -> 当前目标观察 -> 解析 -> 后置条件验证 -> 面板提交”收束为一个不可拆分事务。
- 让装备、插槽、古灵、地图和海图共享同一生成期观察协议，消除两套漂移实现与嵌套重试。
- 在有剪贴板事件证据时缩短同文本判断路径，并用虚拟时钟锁定复制次数与调度上界。
- 让候选解析仅供 Python 验证，验证通过后才以同一 requestId 发布；陈旧候选永不进入面板。
- 保持“三次串行补读”、请求隔离、异常停止和恢复上下文，同时保证补读不重复消耗通货。
- 只在开发版输出可用于 p50/p95 分析的脱敏指标。

**Non-Goals:**

- 不改变手工制作模拟器、用户可见配置、持久化数据或公开 Electron API。
- 不新增用户可调的通货选择时序，不改变鼠标坐标、DPI 或游戏窗口识别策略。
- 不打包或发布生产版本；本变更只在开发版验证。
- 不把物品全文、文本哈希、路径或账号信息持久化或输出。

## Decisions

### 1. 使用生成期共享片段，而不是运行时 Python 模块

新增一份共享 Python 观察协议片段，由 `src/utils/python.js` 以 `?raw` 方式加载，并注入装备与地图/海图模板中的明确占位符。最终生成的 Python 脚本仍然自包含，不需要修改安装包的 Python 模块搜索路径或额外资源列表。

共享片段拥有剪贴板证据、目标历史、候选分发、解析重放和确认调度；模板只保留领域动作、目标定位、结果匹配及终态逻辑。与目标领域相关的身份提取和通货后置条件通过小型策略函数传给共享协议，避免共享层认识所有 UI 配置。

采用这一方式是因为两个模板当前都由同一个 JS 生成入口加载，生成期注入能在不引入运行时依赖的前提下保证实现只有一个来源。直接让两个模板互相复制新函数仍会保留漂移风险；运行时 `import` 新 Python 文件则会扩大开发、打包和脚本落盘契约。

### 2. 用显式观察上下文替代布尔放行与嵌套重试

共享协议使用三种明确操作：

- `initial`：为当前固定装备或新地图/海图格位建立目标身份与初始已提交结果。只要非空复制有剪贴板序列号证据，即可接受与调用前剪贴板相同的文本。
- `post-action`：携带 `actionType`、`actionCompletedAt`、`targetId`、动作前已提交结果和后置条件策略。结果确认前不得推进任何制作状态。
- `parse-replay`：对已经捕获的同一候选重新分发解析，最多三次；不再复制、不产生键鼠输入且不改变动作计数。

一次 `post-action` 最多产生三次 Ctrl+C 复制观察。若已经捕获可解析候选，传输失败只进入 `parse-replay`，不会再回到外层复制；只有没有候选或候选被身份/动作条件否决时，才消费下一次复制观察。这样把“最多三次”从嵌套的 3×复核改为单一复制预算。

观察结果使用有限枚举，例如 `confirmed-change`、`confirmed-stable`、`copy-timeout`、`parse-timeout`、`identity-mismatch`、`postcondition-failed` 与 `cancelled`。异常结果保留现有恢复检查点并由现有异常停止路径终止，不新增自动继续分支。

### 3. 剪贴板事件、提交宽限和动作确认窗口各自只有一个职责

复制前记录 Windows 剪贴板序列号与文本。发送 Ctrl+C 后：

1. 若在 `adaptiveTimeoutMs` 内没有任何序列号变化，该次观察以 `copy-timeout` 失败；`adaptiveTimeoutMs` 仅用于这一分支。
2. 若序列号已变化而文本仍相同，只继续轮询约 30ms 的提交宽限，吸收“序列号先变、文本稍后提交”的系统时序；宽限结束后立即产出同文本证据，不再等待完整自适应超时。
3. 第一次动作后证据与动作前相同，或命中当前目标历史时，将下一次复制安排在 `actionCompletedAt + 约 200ms`。如果当前时间已经越过该窗口，则立即复制，不再固定睡眠 200ms。
4. 新文本首次就满足身份与后置条件时直接确认，不增加固定等待。

虚拟时钟测试以调度时间而非外部解析耗时为准：正常新文本 1 次 Ctrl+C；旧文本后变新和允许无变化的稳定同文本最多 2 次 Ctrl+C，前者默认调度不超过 500ms；没有剪贴板事件时才允许三次各自受 `adaptiveTimeoutMs` 限制的观察。

### 4. 最近历史只存目标内哈希

共享协议为每个 `targetId` 保存 `deque(maxlen=8)` 的 SHA-256 文本哈希，不保存物品全文。装备任务使用固定目标 ID；地图和海图以目标类型与格位索引组成 ID，换格即切换并清理不再需要的历史。因此相同地图文本出现在相邻格位时不会被前一格误判为回放。

哈希只存在于 Python 进程内存中，只参与候选可疑性判断，不进入日志、错误、指标、结果文件或 IPC。目标身份验证仍基于结构化解析结果和当前目标上下文：装备使用固定光标目标及稳定的类别/基底字段，地图/海图使用当前格位、目标类型与结构化类别。会因重滚而变化的名称不作为唯一身份字段。

### 5. 后置条件采用“确定变化”和“允许稳定”两类策略

事务建立时保存动作前已提交的结构化结果，并对最终候选执行目标身份验证，再执行通货策略：

- 知识卷轴：`isUnidentified` 变为 false。
- 蜕变石：稀有度为魔法。
- 点金石：稀有度为稀有。
- 重铸石：稀有度为普通且显式词缀为空。
- 增幅石：显式词缀计数比动作前增加。
- 富豪石：稀有度为稀有，且显式词缀计数增加。
- 崇高石：显式词缀计数增加。
- 瓦尔宝珠：`isCorrupted` 为 true。

改造石、混沌石、工匠石、链接石、幻色石与古灵直接通货存在合法可见结果不变的可能。它们在取得新且合法的结构化结果时可直接确认；若结果与动作前相同，则必须由两次具有序列号证据、相隔动作确认窗口且文本一致的复制证明稳定，随后只解析选定的最终候选并验证目标身份。任何解析字段不足、身份冲突或确定变化缺失都 fail closed，不能通过“看起来合理”继续消耗通货。

显式词缀计数使用解析结果中已支持的结构化显式词缀集合，并统一过滤非词缀展示字段；不从原始文本重新实现第二套词缀解析。若现有解析器标记词缀格式不支持，则需要确定变化的动作无法确认并安全停止。

### 6. 候选解析与面板发布使用同一 requestId 的两阶段协议

解析请求 JSON 增加可选 `publish`：缺省视为 `true`，保持既有调用兼容。确认事务发送 `{ clipboard, requestId, publish: false }`。`fileWatcher` 解码并把 requestId/publish 一起传给解析器，解析结果原样携带这两个字段写回。Python 可读取 `publish: false` 候选，但该候选不能触发任何渲染进程更新。

`electron/modules/ipc/file.js` 将即时解析发送和 `resultFileChanged` 发送收束到同一个内部发布门。门禁执行以下检查：

- `publish !== false`；
- requestId 仍是当前有效解析请求；
- 结果结构完整；
- 同一已提交 requestId 的相同物品结果不会因即时路径与文件监听路径重复发布。

Python 完成身份与后置条件验证后，把同一候选、同一 requestId 原子地改写为 `publish: true`；结果文件监听器再通过同一门禁提交。后续新请求会使旧 requestId 失效，因此晚到候选即使被改写也无法覆盖面板。地图统计的既有结果文件更新继续使用现有语义，但必须与候选物品发布分开判断，不能借统计更新泄漏 `publish: false` 的物品字段。

Windows 会合并快速连续的候选、提交与确认文件事件，因此 `fs.watch` 只负责低延迟通知，不能成为提交交付的唯一依据。当前 requestId 尚未确认时，结果监听器同时每 10ms 读取一次最新结果；读取到该 requestId 的 `publicationAcknowledged: true` 后停止本次轮询，新请求则重置轮询。该内部间隔不读取或修改全局 `operationDelayMs`，也不参与自动时序校准，10ms 的自动操作推荐语义保持不变。

结果读取按成功解析后的完整文件内容去重，不再以 `mtimeMs` 决定是否跳过变化。空文件、写入中间态和损坏 JSON 仅等待下一次读取；只有完整 JSON 才进入发布门禁并成为去重基线。停止或重启监听时清除文件事件防抖与轮询定时器，并递增监听会话标识；所有异步读取和延迟回调在发布前校验该标识，防止旧会话污染新 requestId。

选择可选字段而不是新增 IPC 通道，是为了保持公开 Electron API 和现有文件协议调用方不变；选择同一 requestId 提交则避免重新解析或把“验证对象”和“展示对象”分裂为两份结果。

### 7. 通货输入先通过共享选择门禁，再进入确认事务

装备与地图/海图模板由生成器注入同一通货动作协议。协议先移动到已通过启动预检的通货坐标，复核前台与物理像素位置，再将右键保持 `max(buttonHoldMs, 50ms)`；右键无论成功、停止或异常都在 `finally` 中释放。释放后以 10ms 短轮询等待 `max(100ms, operationDelayMs × 2, releaseSettleMs)`，每轮检查任务仍在运行且游戏仍在前台。等待结束后复核右键未按下、鼠标仍在通货坐标，随后才移动到目标并再次复核前台与位置。

任一门禁失败返回结构化 `CURRENCY_SELECTION_UNSAFE`，调用事务直接停止且不把结构化错误误判为动作成功。协议只在全部门禁通过后发送一次目标左键并记录一次通货使用。若左键后结果证据失败，不发送自动放回或补偿点击，因为脚本无法确认通货是否已经作用，补点可能再次消耗通货或拿起物品。

该等待是通货动作内部安全下限，不新增持久化字段或 IPC，也不由校准建议直接覆盖。正常机器通常增加约 100ms；若本机悬停等待更高，则按 `operationDelayMs × 2` 自动放大。

### 8. 所有通货调用点只通过事务辅助函数推进

生成逻辑提供单一的 `apply_currency_and_confirm` 领域入口：记录动作前结果，调用现有 `apply_currency` 一次，随后调用共享观察协议并在提交成功后返回新结果。预处理、主循环、增幅、词缀命中后的富豪/崇高收尾、插槽、古灵、地图/海图重滚和瓦尔收尾均改用该入口；不得在业务分支中保留“使用通货后直接完成”或“未变化直接下一轮”的旁路。

富豪石和每颗崇高石分别建立事务。若计划连续使用多颗崇高石，第 N 颗已提交结果成为第 N+1 颗的动作前结果。地图/海图只有当前格最后一个事务提交后，才能提交统计和移动；失败格仍沿用既有恢复检查点。

### 9. 开发指标与测试不暴露物品内容

生成器把构建模式固化为 Python 常量。仅开发模式在每个事务结束时输出一条结构化指标，字段限定为动作类型、复制观察次数、解析重放次数、结果枚举与耗时毫秒；生产构建常量关闭该输出。指标函数不接受文本、哈希、路径或账号参数，降低调用点误传敏感信息的可能。

测试使用现有 Node 驱动 Python 片段的方式增加可注入单调时钟、sleep 和复制结果序列。除逐类后置条件外，测试还覆盖候选不显示、提交才显示、陈旧 requestId、跨格历史、最终富豪/崇高同步，以及失败后不存在下一条通货记录。现有把 `STALE_COPY_BACKOFF_SECONDS` 改为 0 的测试将被替换或改写，避免继续掩盖真实调度回退。

## Risks / Trade-offs

- **30ms 提交宽限在极端系统负载下仍可能不足。** 宽限只把同文本标为证据，不会直接把必须变化动作确认成功；最多三次观察与 fail-closed 后置条件仍阻止继续消耗通货。该常量由虚拟时钟和开发指标观察，但不自动接入全局时序校准。
- **合法无变化与旧 tooltip 在文本层不可区分。** 仅为语义上允许无变化的通货开放“两次相隔窗口稳定”策略；富豪、崇高等必须变化动作绝不使用此兜底。
- **解析器字段不足会增加安全停止。** 这是有意的安全取舍。优先复用并补齐结构化解析字段，不回退到未经验证地继续制作。
- **两阶段文件写入增加监听时序。** Windows 可能合并或遗漏快速连续事件，因此使用 `fs.watch` 与当前请求 10ms 轮询互补；当前 requestId 门禁、成功解析内容去重、会话隔离和幂等发布共同限制竞态。测试需覆盖遗漏提交事件、损坏中间态、提交快速改写和旧会话回调晚到。
- **共享片段注入会改变模板测试定位方式。** 测试应针对生成后的脚本和共享协议公开的语义片段，逐步删除依赖旧函数源码边界的脆弱字符串截取。

## Migration Plan

1. 先扩展文件协议测试与发布门禁测试，确认缺省 `publish: true` 兼容、候选被抑制、提交可见及陈旧请求被拒绝。
2. 引入共享观察协议和模板占位符，以虚拟时钟测试独立锁定 30ms/200ms/三次预算，不接入通货路径。
3. 先接入装备预处理与单次主循环，再依次接入增幅、富豪/崇高、插槽、古灵、地图与海图；每组迁移后删除对应旧旁路。
4. 删除两模板中的全文历史、哨兵、`allow_unchanged_text`/`verify_freshness` 分支、嵌套复核、失效注释及失败方案日志，只保留共享协议和 requestId 安全门禁。
5. 对结果文件协议增加确定性遗漏事件测试、停止/重启会话隔离测试，以及真实临时目录与子进程的 10ms 连续事务压力测试；确认至少 100 次全部发布确认且无重复。
6. 运行定向测试、完整 `npm test`、`npm run build`、`git diff --check` 与 OpenSpec 严格校验。构建仅用于开发代码静态验证，不进行打包。
7. 在用户确认测试窗口和低价值通货后，用开发版分别抽样装备与地图/海图，核对每次游戏实物/面板及最终富豪/崇高结果，并从脱敏指标计算 p50/p95。

若接入阶段需要回退，候选协议的 `publish` 缺省仍为 true，因此可按调用路径逐组撤回事务接入；不得只撤回发布门禁而保留 `publish: false` 请求。任何回退均保留异常停止和 requestId 隔离。
