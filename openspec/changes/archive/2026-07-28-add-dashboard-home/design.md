## Context

应用是 Vue 3、Pinia 和 Electron 构成的单窗口桌面应用。现有业务状态分散在预设、设置、脚本、背包、战斗、剧情和做装 Store 中；物品与地图共用一个 Python 进程，但当前进程状态不记录运行模块，且自然退出不会同步主界面。看板必须复用这些状态源并避免产生第二份业务真相。

## Goals / Non-Goals

**Goals:**

- 提供统一首页，可靠汇总七个业务模块和三项全局环境健康状态。
- 用纯状态评估函数把各模块现有数据映射为统一、可测试的状态模型。
- 让安全的常用操作复用现有业务服务，并保持所有入口行为一致。
- 补齐共享 Python 脚本的运行模式与全生命周期同步。

**Non-Goals:**

- 不在首页编辑预设、坐标、阈值或其他详细配置。
- 不提供卡片排序、隐藏、数据更新、重置或一键回城。
- 不迁移现有持久化数据，也不引入新依赖。

## Decisions

### 使用派生状态而不是集中复制业务状态

新增 dashboard 领域的纯评估器和页面编排层。评估器接收普通数据，输出统一的模块描述；页面从现有 Store 构造输入。这样保留各模块 Store 为唯一状态源，也能使用 Node 测试覆盖状态优先级。没有采用独立持久化 Dashboard Store，因为会造成同步和迁移负担。

### 统一四种互斥主状态

主状态固定为 `error`、`running`、`attention`、`ready`，判定优先级依次降低。每个模块还可提供指标、问题列表和操作，但顶部计数只统计主状态，避免重复计数。

### 操作复用现有服务

物品、地图、背包、战斗和剧情的快捷操作直接调用已有公共服务或 Store 方法；商城复制复用统一剪贴板接口。页面只管理按钮 pending 状态和错误呈现，不重写业务启停逻辑。

### 主进程拥有共享脚本运行模式

renderer 启动共享脚本时显式传入 `mode`。Electron 主进程随当前子进程保存该模式，状态查询返回它，并在启动、停止、退出和错误时发布结构化事件。renderer 的脚本 Store 从查询和事件统一应用快照，从而覆盖刷新、自然退出和异常退出场景。

### 系统健康按需刷新

首页加载和用户手动刷新时检测 Python、刷新共享脚本及已有运行服务状态；DPI 使用设置 Store 已有结果并允许手动刷新。快捷键初始化结果进入内存中的可观察状态。运行时主要依赖事件，不增加轮询。

## Risks / Trade-offs

- [不同模块的“可用”语义不同] → 为每个模块建立独立评估器，但统一主状态和问题格式。
- [首页调用启停可能与模块页同时操作] → 复用幂等服务，并以每卡 pending 状态阻止重复提交。
- [旧调用未传脚本 mode] → 主进程规范化未知值为 `null`，但新的物品和地图入口必须传入明确值。
- [全局环境状态可能短暂过期] → 提供手动刷新并消费生命周期事件，不采用高频轮询。
- [侧栏项目增加后低窗口截断] → 侧栏菜单启用纵向滚动并保持固定宽度。
