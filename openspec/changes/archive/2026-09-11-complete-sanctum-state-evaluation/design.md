## Context

见 proposal。目录123个效果含次数变体；名称匹配、版本核验、规则解析与两套规划器分离。图片当前共用20张/64MB FIFO，引用未同步失效。

## Goals / Non-Goals

统一规则语义与可解释排序，确认空列表必须有完整扫描证据。不增加受击次数或耗时假设配置，不恢复圣物编辑功能。

## Decisions

- 共享规则注册表按精确规范文本与参数解析，记录评估模式、事件、持续与消耗；沿用审核指纹，新增规则不能绕过版本核验。每个现行目录条目由覆盖测试约束。
- 共用路径效果评估器，持有坚毅、上限、启迪、金币及剩余效果。实际起点资源已含获取时变化；仅路径新增效果触发获取事件。条件影响输出风险/机会及依据，参与原排序或用户权重。
- 识别缺口保存 category/targetId/stage/reason，与条件评估分开。扫描结束才将剩余未确认类别转为失败；页面、浮窗、保存路线复用共享展示函数。
- 截图使用用户数据目录独立子目录和UUID文件名，内存上限只淘汰buffer。先写候选图片，再将图片元数据与结果原子写入存档，成功后回收旧文件；失败保留旧图及其结果，显示上次采集，旧结果不冒充本次识别。重启加载图片索引，退出不删除持久图片，重置清理；IPC不暴露磁盘路径。
- 保留目标身份检查，按采集版本过滤异步事件，确保保存后才发布evidenceId。旧存档没有截图时给出明确说明。

## Risks / Trade-offs

- 随机和战斗条件无法精确预测 → 条件收益或风险参与排序，不伪造数值；缺少资源明确报告。
- 当前资源重复扣减 → 分离已持有效果与路径获取事件，测试对照。
- 临时文件残留或错绑 → 目录与文件由应用生成，清理验证限定根目录；仅返回图片元数据。

## Migration Plan

内部字段兼容增加，旧状态保持未确认或历史展示，原无图存档明确标注未保存截图。开发版验证，现场不可用如实记录。按子系统回退本次代码即可回滚。
