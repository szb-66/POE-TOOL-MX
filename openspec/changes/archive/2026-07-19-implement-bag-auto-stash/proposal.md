# Proposal: 实现背包自动入库功能

## 概述

实现完整的背包自动入库功能，包括模板匹配检测和一键入库操作。用户在背包页面启用模块后，系统实时检测屏幕中的仓库和道具标题是否匹配，匹配成功时在页面显示"开始入库"按钮，用户点击后系统自动将背包12×5格子中的物品逐个存入仓库。

## 动机

当前背包自动入库功能的UI和配置已完成，但核心功能未实现：
- IPC处理器使用内联生成的Python脚本，未使用已有的模板文件
- 前端API封装缺失（electronApi.bag）
- 检测状态和入库进度的事件通信未完全连接
- 一键入库按钮的显示逻辑未实现

这导致用户无法使用该功能，需要完成剩余的实现工作。

## 目标

1. **使用Python模板文件**：IPC处理器应使用 `bag_auto_stash_template.py` 而不是内联生成脚本
2. **完善前端API**：在 `electronApi` 中添加 `bag` 模块的完整封装
3. **实现检测逻辑**：启动Python检测进程，实时监听匹配结果
4. **实现入库逻辑**：点击按钮后启动Python入库进程，显示进度
5. **完善事件通信**：前后端通过IPC事件同步检测状态和入库进度
6. **集成设置参数**：从全局设置中读取背包首格位置和格子尺寸

## 范围

### 包含
- 修改 `electron/modules/ipc/bag.js` 使用模板文件
- 添加 `electronApi.bag` API封装
- 在 `BagView.vue` 中实现"开始入库"按钮和状态显示
- 完善事件监听和状态同步
- 从 `settingsStore` 读取背包参数

### 不包含

- 添加快捷键支持（后续功能）
- 创建独立的覆盖层窗口（不需要）

## 设计考虑

### 技术方案

1. **Python脚本管理**
   - 检测模式：持续运行，定期检查屏幕匹配
   - 入库模式：一次性执行，完成后自动退出
   - 使用模板文件替换，通过命令行参数传递配置

2. **状态管理**
   - 检测状态：未启用、检测中、匹配成功、匹配失败
   - 入库状态：未开始、进行中、已完成、失败
   - 使用 Pinia store 管理状态

3. **事件通信**
   - `bag-detection-match`: 检测匹配结果
   - `bag-stash-progress`: 入库进度更新
   - `bag-stash-completed`: 入库完成
   - `bag-stash-stopped`: 入库停止

4. **配置传递**
   - 模板路径：从 bagStore 读取
   - 匹配区域：从 bagStore 读取
   - 背包参数：从 settingsStore 读取
   - 合并配置后传递给Python脚本

### 用户体验

1. **启用检测**
   - 用户上传模板图片并配置匹配区域
   - 点击"启用模块"开关
   - 系统启动检测进程，显示"检测中"状态

2. **匹配成功**
   - 检测到仓库和道具标题都匹配时
   - 状态显示"匹配成功"
   - "开始入库"按钮显示在页面上（仅在匹配成功时显示）

3. **执行入库**
   - 用户点击"开始入库"按钮
   - 系统启动入库进程
   - 按从左到右、每列从上到下的顺序处理背包12列×5行格子
   - 显示进度条（0-100%）
   - 完成后显示成功提示

4. **停止功能**
   - 用户关闭"启用模块"开关
   - 系统停止检测和入库进程
   - 清理所有状态

## 风险和缓解

### 风险
1. **Python依赖缺失**：用户未安装 opencv-python、mss 等依赖
2. **模板匹配失败**：用户上传的模板图片不准确
3. **坐标不准确**：不同分辨率下坐标可能偏移
4. **进程管理**：Python进程可能无法正常终止

### 缓解措施
1. 在启动时检测Python依赖，提示用户安装
2. 提供匹配阈值配置，允许用户调整
3. 提供DPI缩放配置（已在设置中）
4. 使用 SIGTERM 和 SIGKILL 确保进程终止

## 成功标准

1. 用户可以上传模板图片并配置匹配区域
2. 启用模块后，系统能正确检测匹配状态
3. 匹配成功时，"开始入库"按钮可用
4. 点击按钮后，系统能自动完成60格物品的入库
5. 入库过程中显示实时进度
6. 用户可以随时停止检测和入库
7. 所有配置能正确保存和加载
