## Context

当前做装模块已经有 POEDB schema v3 快照、词缀合法性过滤、加权抽取和一组 `CraftActionRegistry` 动作，但这些能力只被自动路径 Worker 间接调用。`CraftState` 仅保存阶级 ID，没有保存实际骰出的数值，神圣石目前是空操作；页面则强依赖目标、价格和规划任务。内置快照虽然有 951 个底材和 5535 个词缀效果，却只区分 `natural`/`crafted`，势力及地心、穿越、隐匿、精华来源仍需补全。

## Goals / Non-Goals

**Goals:**

- 把状态机提升为可直接驱动 UI 的手动制作会话。
- 每次通货操作都返回可用性、前后状态、具体随机结果和中文解释。
- 在装备卡片中展示实际词缀等阶、名称、效果和已骰数值。
- 用同一份合法词缀池驱动随机制作和三级词缀目录，避免展示与模拟不一致。
- 主流程不请求价格、不启动 Worker，并支持撤销、重做和固定种子复现。
- 明确标记数据快照中尚未覆盖的来源，不能把缺失数据伪装成零权重的完整支持。

**Non-Goals:**

- 本阶段不恢复自动路径推荐或比较期望价格。
- 不在第一阶段实现化石、精华、花园、野兽、赛季专属或腐化的全部复杂组合。
- 不模拟装备插槽、品质、护甲/伤害派生数值和传奇物品。
- 不承诺复刻参考网站的品牌、素材或源代码，只复刻适合桌面应用的交互结构与信息层级。

## Decisions

### 1. 在 Electron 主进程维护无状态的手动动作接口

新增 `manualCrafting` 领域服务，接口接收完整会话状态、动作 ID 和随机种子，返回新的规范化状态与事件。状态仍由渲染进程 Pinia 保存，因此无需引入持久服务器会话，也不会出现跨窗口任务串线。相比复用规划 Worker，这个接口延迟更低且不依赖价格。

### 2. 扩展 CraftState，而不是建立第二套装备模型

每条显式词缀新增 `rolledValues`、`text`、`name`、`affixType` 和来源快照。抽到阶级时立即按各数值区间独立生成整数；神圣石只重骰已有显式词缀的数值，不改变阶级；祝福石预留给基底词缀。旧规划代码只读取 ID 和分组字段，因此可向后兼容。

### 3. Provider 同时提供执行规则和用户说明

通货 Provider 增加 `description`、`requirements`、`consequences` 和 `destructive` 元数据，并提供只读 `inspect` 结果。UI 只显示服务返回的动作目录和当前 `canApply/reason`，不复制一份易漂移的规则表。

### 4. 加权抽取按 Mod Family 后再按阶级

继续沿用现有“合法阶级权重汇总为 family 权重，再在 family 内抽取”的模型，并在每次抽取前应用物品等级、底材标签、来源、势力、互斥组和容量过滤。前后缀类型在剩余容量之间选择；稀有词缀数量沿用可测试的 4/5/6 分布，后续如获得权威分布数据可独立替换。

### 5. 三级目录使用稳定的来源 × 前后缀分区

一级固定为基础、六种势力、地心探险、穿越、隐匿、工艺台、精华，每项各含前缀和后缀。二级为 Mod Family，显示复选框、小项数、当前合法总权重及标签。三级弹窗按阶级行展示 T 级、词缀名、需求等级、效果、标签与单项权重。父项选择等于选择当前可见且可用的全部子项；子项变化实时计算父项的全选/半选状态。

### 6. 来源覆盖必须显式可审计

解析器为每条记录保存规范化 `sourceDomain`。如果活动快照缺少某来源，一级分区仍可见但显示“当前数据未覆盖”，不得用基础词缀替代。数据版本以官方当前 PoE1 补丁与 POEDB 生成时间共同展示；在线更新仍由用户手动触发并原子切换。

## Risks / Trade-offs

- [POEDB HTML 结构及中文字段可能变化] → 保留 fixture、schema 校验和原子回退，并让未知来源更新失败而不是静默归类。
- [现有数据快照缺少势力来源] → 第一阶段把缺口明确展示并补解析测试，只有经数据验证的来源才进入随机池。
- [随机结果与游戏内部未公开细节可能存在差异] → 固定种子、记录每步候选池总权重，并为未经权威证实的分布显示范围声明。
- [大词缀表导致渲染卡顿] → 一级/二级按需展开，三级仅在弹窗中渲染当前 family，并复用服务端分页查询。
- [旧规划测试与新页面断言冲突] → 保留底层优化器兼容测试，重写 UI 测试以新主流程为准，删除不再成立的价格/推荐路径页面断言。

## Migration Plan

1. 先补动作元数据、实际数值和手动会话单元测试，不改变现有 IPC。
2. 增加手动会话 IPC 与 Pinia 状态，保留旧规划接口供兼容测试使用。
3. 用手动模拟工作台替换 `CraftPlannerView`，移除页面价格初始化和 Worker 生命周期。
4. 补三级目录联动及来源缺口提示，再扩展 POEDB 解析器的来源分类。
5. 运行全量测试与生产构建，清理旧页面专用代码和此前失败实现留下的死分支。

回滚时可恢复旧 `CraftPlannerView` 和 store 入口；新增状态字段及 IPC 均为增量，不需要迁移用户持久数据。

## Open Questions

- POE1 3.28 后各稀有度的精确词缀数量分布是否有可引用的官方数据；未确认前在 UI 标明为模拟分布。
- 精华、化石及特殊崇高石应在后续按 Provider 分阶段加入，不能仅靠通用“重铸并保证标签”近似。
