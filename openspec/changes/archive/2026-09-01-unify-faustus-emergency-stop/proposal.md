## Why

浮士德页面当前同时提供模块内“停止”和全局紧急停止，造成同一自动化存在两个用户停止入口，增加操作认知与安全提示的不一致。应将浮士德统一纳入全局紧急停止契约，并让页面只保留启动与运行状态展示。

## What Changes

- 从浮士德页面移除独立“停止”按钮，不再把模块内停止作为用户可见操作。
- 在浮士德运行控制区明确提示使用已配置的全局紧急停止快捷键终止运行。
- 保留主进程内部幂等停止能力，供全局紧急停止、应用退出和安全失败路径调用。
- 将浮士德明确加入“全局紧急停止全部游戏自动化”的规范范围，并验证一次触发会终止浮士德运行、释放输入和自动化锁。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `faustus-market-repricing`: 将用户主动停止入口从页面独立按钮改为统一的全局紧急停止，并保留内部安全停止能力。
- `captured-key-input`: 将浮士德市集分段改价明确纳入全局紧急停止覆盖的游戏自动化集合。

## Impact

- 浮士德页面运行控制区及其 UI 测试。
- 全局紧急停止协调器、快捷键契约和相关集成测试。
- 浮士德 renderer API 可继续保留内部停止封装，但页面不再直接调用；主进程停止 IPC 与 manager 停止能力继续作为安全基础设施存在。
- 不改变浮士德配置、改价算法、识别流程、权限边界或自动化锁模型。
