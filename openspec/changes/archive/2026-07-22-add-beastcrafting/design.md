## Context

手动模拟器以一个可序列化会话保存当前装备、确定性随机数状态和撤销/重做历史。现有动作大多只产生一个装备状态；野兽分裂会同时产生多个物品，拓印绑定特定原物品，希内科拉之锁则要求在不消耗随机状态的前提下稳定预览下一枚通货，因此需要扩展会话级状态而不能只新增普通 Action Provider。

本变更以 PoE Wiki 当前 Beastcrafting、Split、Imprint、Hinekora's Lock 规则和 POEDB 势技能文本为依据。当前数据集中没有势技能或综合隐式池，静态定义只用于规则固定且没有随机数值的势技能和配方元数据。

## Goals / Non-Goals

**Goals:**

- 准确执行当前装备模型可表达的常用野兽工艺，并让每个不可执行条件可见。
- 保证兽级、词缀锁、不能骰出标签、Mod Group、词缀位和势力条件参与正确阶段。
- 把分裂多产物、绑定物品的拓印和确定性通货预览建模为可撤销的会话状态。
- 兼容缺少新字段的旧会话，并保持全部入口返回一致的最新目录。

**Non-Goals:**

- 不模拟兽园捕捉、战斗或野兽库存价格。
- 不伪造综合隐式池、护符底材转换、守望之眼专用池、传奇转换和物品插槽系统。
- 希内科拉之锁不预览工艺台、庄园、重组、野兽工艺或其他非通货设备结果。

## Decisions

### 1. 独立规则模块与静态版本目录

新增 `beastcraftRules` 模块保存配方 ID、中文名称、3.28 规则说明、主要野兽、类别和支持状态。执行时仍从活动词缀数据集求合法池；只有无随机数值的八条势技能使用受版本控制的静态 affix 定义。

选择此方案而不是抓取 POEDB HTML 运行时执行，因为兽谱配方表不是稳定的机器接口，且势技能不在当前规范化显式词缀集中。静态定义必须带来源说明和测试，未知池的配方只展示禁用状态。

### 2. 增删词缀使用两阶段原子结果枚举

“加前删后/加后删前”先判断目标词缀位和兽级合法新增池，再按元工艺决定删除侧：位置锁存在时只新增，否则从对应侧可移除词缀中等概率删除。新增池使用兽级代替物品等级，并受不能骰出攻击/施法影响；删除随机选择忽略这两个标签限制。若不存在任何完整合法结果则禁用动作。

这避免先删除后发现无法添加导致的半完成状态，也明确区分位置锁与标签锁。

### 3. 分裂进入“待选择产物”状态

分裂动作生成带独立 `itemId` 的全部结果并写入 `pendingSplitResults`，在用户选择前阻止其他制作动作。原物品结果保留原 `itemId`，复制品获得确定性新 ID；所有结果带 Split 属性。二分随机洗牌后按数量均分显式词缀，三分要求恰好六条显式并分成每份两条。结果按自身词缀组成重新判定魔法/稀有度；古灵双方隐式在二分时分别归属不同结果。

不自动选择第一份，因为这会悄悄丢失用户决策；也不建立完整仓库系统，因为当前页面一次只制作一件装备。

### 4. 拓印绑定稳定物品身份

会话新增 `activeItemId` 与可选 `imprint`。创建拓印只允许魔法物品，保存当前 state、variant 和 itemId；恢复要求当前 `activeItemId` 相同且物品未破裂，成功后消费拓印。分裂复制品因此不能错误使用原物品拓印。

### 5. 预见状态通过同一通货执行器进行纯模拟

会话新增可选 `foreseeing` 标志。目录预览对会话深拷贝并使用当前 `rngState` 调用与真实应用相同的通货核心执行器，但不提交状态、历史或随机数。相同通货重复查看得到相同结果，真正使用任意受支持通货时得到该结果并清除预见；其他会修改装备的已支持动作也清除预见但不提供预览。

不缓存所有预览结果，因为当前确定性 RNG 已是更小且不易失配的事实来源。

### 6. 会话辅助状态随历史一起保存

历史记录在装备 state 和 variant 之外保存 `activeItemId`、`pendingSplitResults`、`imprint`、`foreseeing` 的 before/after 快照。撤销、重做和重置统一恢复这些字段；读取旧会话时缺省为空。

## Risks / Trade-offs

- [配方规则随版本更新] → 静态目录标注 3.28，并用来源与精确数量测试使更新差异可审计。
- [分裂的游戏内隐藏分配细节变化] → 只实现文档可验证的均分、限制、稀有度和古灵隐式规则，避免推断插槽等当前模型没有的属性。
- [希内科拉预览发生执行路径漂移] → 预览和实际使用共享同一个通货核心函数，并以“预览结果等于应用结果”回归测试约束。
- [辅助状态遗漏于某一动作历史] → 使用统一捕获/恢复辅助状态的帮助函数，覆盖每类动作的撤销、重做和重置测试。
