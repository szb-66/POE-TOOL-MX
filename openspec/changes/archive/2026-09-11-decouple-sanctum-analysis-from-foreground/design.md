## Context

服务层 setForeground 调用 stop；采集层 captureSignal 与分析 signal 相同，安全事件取消两者。房间及效果图片已经通过独立进程处理，但取消边界仍覆盖整轮。

## Goals / Non-Goals

分离实时输入与冻结图片分析的生命周期。保留原生前台预检、全局紧急停止、日志身份校验及现有图片处理超时。不增加自动恢复或并发采集。

## Decisions

- 每轮独立输入控制器和总任务控制器；失焦仅取消输入，总任务取消同时传播到输入。服务层和原生失焦汇入同一入口，其他身份失效继续取消整轮。
- 采集结束幂等关闭输入进程并释放锁；OCR、图片后处理及补充图标识别在独立分析信号下收尾。状态截图中断也等待已排队任务后汇总。
- 输入中断不再抛出导致跳过所有分析收尾；未获取截图的目标标记 skipped 和具体原因。完成快照是否不完整按实际房间、效果缺口判断。
- 已冻结结果继续绑定原日志会话；日志失效、主动停止或重置保留现有代次隔离。页面进度保持运行至分析完成，浮窗沿用前台门禁。
- 不采用只忽略服务层失焦的局部修补，因为原生通知和采集 guard 仍可取消分析。
- startLive 等待任务和驱动关闭、清理 startTask 后再构造返回快照；不将清理前生成的返回值交给页面覆盖已推送状态。停止后重启同样在等待完成后读取最新状态。保留真实清理期间的禁用，不增加前台条件或轮询。

## Risks / Trade-offs

- 最后一帧返回与失焦竞态 → 图片成功返回后转移给分析任务，不再因输入信号丢弃；尚未返回的请求仍可取消。
- 重复关闭与锁释放 → 幂等的采集收尾 Promise，最终清理只释放仍持有的锁。
- 部分状态扫描被误当作完整 → 未截取目标及覆盖缺口保持显式未知。

## Migration Plan

无迁移，保留旧存档读取。先跑针对性回归，再运行全套测试与开发版验证；不打包。
