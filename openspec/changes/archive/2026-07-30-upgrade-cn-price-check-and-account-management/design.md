## Context

主进程已经用单一 `persist:poe-cn-auth` Session 同时服务商城配方和查价，但渲染端账号入口、赛季与状态分散在两个 Store。查价快捷键总是注册，浮层只展示最小词缀列表，查询模型缺少属性、状态、T 级和分页。现有 Awakened 查询适配与腾讯官方 stat 目录必须继续复用，且不得把 Cookie 或令牌持久化到渲染端。

## Goals / Non-Goals

**Goals:**

- 建立中立的账号/赛季 Store 与 IPC，保持现有 Session 和登录态。
- 让查价开关同时控制快捷键、服务门禁和浮层。
- 用高级复制得到真实 T 级，补齐安全、可解释的属性与词缀查询。
- 提供接近参考界面的游戏内浮层、分页挂单与失焦关闭。

**Non-Goals:**

- 不引入第三方价格历史、价格预测或自动交易。
- 不用做装目录猜测缺失的 T 级。
- 不完整移植 Awakened 的全部专项物品、伪属性与多语言体系。

## Decisions

1. **认证仍由单一主进程服务持有。** 新增中立账号 IPC 和 `usePoeCnAccountStore`，商城与查价 Store 只消费共享状态；Cookie 继续留在原分区，避免重新登录和敏感数据迁移。
2. **全局赛季保存在账号设置。** 首次迁移优先商城赛季、其次查价赛季。切换赛季先安全关闭商城控制和查价请求，再清理功能缓存与旧仓库选择。
3. **查价开关采取双重门禁。** 渲染端事务式重注册快捷键，主进程运行态再次拒绝禁用请求；关闭会 abort 查询并关闭窗口。
4. **高级复制优先且不猜测。** `Ctrl+D` 先发送 `Ctrl+Alt+C`，无结果才发送 `Ctrl+C`。高级头直接提供 T 级；回退文本显示 `T?`，自动选择不会启用未知级别。
5. **筛选使用白名单领域模型。** 属性和状态先标准化为有限 ID，再由 Awakened 查询适配写入对应官方过滤组；渲染端不能传任意查询路径或结果 ID。
6. **分页状态归主进程所有。** 服务保存当前 query ID、结果 ID 和 offset，每次只追加 10 条并限制 50 条，避免渲染端伪造 fetch 请求。
7. **失焦在 BrowserWindow 层关闭。** `blur` 直接销毁浮层并发布空状态；查询迟到只更新服务数据，不重建窗口。官方市集 URL 在调用外部打开前完成构造。

## Risks / Trade-offs

- [高级复制在部分客户端不可用] → 超时后自动回退普通复制并显示 `T?`。
- [赛季统一会改变旧查价赛季] → 迁移优先保留商城赛季并清除不再合法的旧仓库选择。
- [自动 T1/T2 仍可能过度筛选] → 用户可选“全部/无”并逐项编辑，默认数值下浮 20%。
- [腾讯接口字段变化] → 延续严格响应校验、白名单和明确不兼容错误。

## Migration Plan

1. 新增共享账号 Store/IPC，复用原 Session，并迁移赛季。
2. 接入默认关闭的查价运行态和快捷键事务。
3. 扩展解析、查询、分页与浮层，再删除手动文本入口和重复账号 UI。
4. 回滚时保留原 Session；禁用新查价开关即可停止快捷键与请求。
