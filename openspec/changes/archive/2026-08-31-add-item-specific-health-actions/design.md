## Context

首页健康项由渲染进程派生状态与 Electron 启动健康检查共同组成。当前设置导航工具先选择首个非正常项，首页标题栏再用单一按钮跳转；首页帮助抽屉位于动态加载容器中，只能由自身浮动按钮打开。相关页面与帮助文件已有未提交改动，实施必须采用小范围补丁并保留这些工作。

## Goals / Non-Goals

**Goals:**

- 用一个纯映射把健康项的状态和 ID 转换为明确的设置操作或帮助主题操作。
- 让动态加载的首页内容能够请求外层帮助抽屉打开指定主题。
- 保持健康判定、刷新、诊断记录和帮助浮动入口不变。

**Non-Goals:**

- 不增加 Python 路径、提权、网络或系统配置能力。
- 不改变启动健康检查、自动化门禁、IPC 或持久化格式。
- 不打包或发布。

## Decisions

### 使用显式健康操作映射

新增纯函数按 `status` 和 `id` 返回 `{ type, label, target }`，仅 `attention` 与 `error` 状态参与映射。快捷键映射到 `general`，DPI 映射到 `system`；Python、显示器、配置目录以及系统/权限/网络分别映射到帮助主题。未知 ID 返回空值。

选择显式白名单而不是把所有非快捷键项目默认映射到“系统”，避免未来新增健康检查时自动产生错误入口。

### 通过组件事件连接动态首页和帮助抽屉

首页内容对设置操作直接使用路由，对帮助操作向动态容器发出主题 ID。容器持有帮助抽屉引用并调用其公开的 `open(topicId)` 接口。帮助主题列表接受当前目标主题并同步展开状态。

选择组件事件而不是全局事件总线或 Store，因为该通信只存在于首页内容与其直接容器之间，不需要持久化或跨页面共享。

### 复用并补充现有帮助主题

Python 使用现有运行时 FAQ，显示器使用现有 DPI FAQ，配置目录使用现有配置目录 FAQ；新增系统环境 FAQ，覆盖系统版本、权限级别和网络接口。首页帮助主题集合加入这些 FAQ，使卡片入口和右下角帮助入口共享同一内容。

## Risks / Trade-offs

- [帮助主题通过 ID 连接，重命名可能导致入口失效] → 将 ID 集中在健康操作映射并用单元测试覆盖所有目标。
- [卡片增加操作后窄宽度可能挤压状态文字] → 文本容器允许收缩并保持省略，按钮固定不收缩，窄窗口验证布局。
- [已有未提交帮助与首页改动可能重叠] → 实施前重新读取文件，只做上下文补丁并检查最终差异，不覆盖无关内容。

## Migration Plan

无需数据迁移。开发版通过受影响测试、完整测试、Vite 构建和浏览器交互验证后即可随后续正常发布交付；回滚时删除逐项操作映射与帮助抽屉接口并恢复原页面结构。
