# Design: 装备制作的剪贴板证据链修复

## Context

假匹配成功的完整链路（改造+增幅、固定延迟）：增幅补读在 tooltip 重渲染窗口内复制到增幅前文本 → 重试旁路（`allow_unchanged_text or attempt > 0`）以序列号变化为证据接受了同文本 → 旧文本（roll-A）被当作当前状态写入 `before_text` 证据链 → 下一轮改造后的重渲染窗口内复制到"增幅已完成"的旧 tooltip（roll-A'，恰含目标词缀）→ 与被污染的 `before_text` 不同 → 立即被接受 → 词缀匹配成功，而实际物品已被改造重滚。旁路由 70909a1 引入，本意是解析管线失败后重发同一文本。

关键洞察：`clipboard_changed` 的"同文本拒收"本来就足以挡住旧 tooltip——只要 `before_text` 恒为"上次真实状态"。旁路误用是唯一让假文本进入证据链的洞。

## Goals / Non-Goals

**Goals:**

- 恢复不变量"被接受的文本 = 复制时刻 tooltip 真实状态"。
- 零额外复制次数与延迟（不做双重复制确认）。
- 同文本重发的合法用途（解析管线失败后补发）保留。

**Non-Goals:**

- 不引入成功前二次复核（读入口修复后无必要）。
- 不改显式 `allow_unchanged_text=True` 调用方（首次读取/插槽/古灵/地图初始扫描）的行为。

## Decisions

### 1. 三态化复制等待结果

`clipboard_changed`/`wait_for_clipboard_change` 引入哨兵 `CLIPBOARD_TEXT_UNCHANGED`：有序列号变化证据但文本相同 → 哨兵；无序列号证据 → 维持现有 False/None 失败语义；文本变化 → 文本。哨兵沿 `send_copy_command` → `read_clipboard_to_file`（返回字符串 `"unchanged"`，与整数 requestId 天然可区分）向上传播。选择字符串哨兵而非异常/元组：生成模板内保持最简契约，测试可直接断言。

### 2. 旁路条件从 `attempt > 0` 收紧为 `attempt > 0 and last_dispatched`

`last_dispatched` 记录上一轮是否走到了分发解析：分发过 → 重试放行同文本（重发语义）；复制阶段就失败/未变化 → 重试保持严格。这样修复后：

- 增幅补读的旧 tooltip：同文本被拒 → 重试拿到渲染后的新文本 → 在正确的物品上匹配（假匹配链路在源头断裂）。
- 残余代价：竞态发生的轮次里增幅效果被下一轮改造覆盖，浪费一次增幅——这是竞态本身的固有损耗，不属于判定错误。

### 3. "全部尝试未变化"返回 `{"unchanged": True}` 而非错误

同文本意味着匹配结论不变：词缀主循环跳过本轮增幅/匹配直接下一轮；增幅补读沿用增幅前结果；预处理沿用上次状态但消耗一次尝试（防死循环，收敛于既有 preprocess_limit）。日志打印中文提示，`last_error` 用中文短语承载哨兵语义。

### 4. 显式放行调用方零改动

`allow_unchanged_text=True` 的调用（首次读取/插槽/古灵/地图初始扫描）在首次尝试即接受有序列号证据的同文本，哨兵对其不可达（无序列号 API 时维持超时失败路径），不需要新增分支。

### 5. 地图洗练的未变化语义

`read_current_rolling_target` 与装备侧同构：旁路收紧 + 全部尝试未变化返回 `{"unchanged": True}`（优先于空格判定，且仅在从未分发解析时返回）。通货后未变化的结果流入 `process_single_map` 循环时按字段默认值处理（稀有度回落"普通"）→ 循环继续使用通货重滚——语义即"无新信息，再滚一次"，下一轮读取取得渲染后的真实文本后自愈；最坏情况多消耗一次通货点击，不产生误存仓。地图初始扫描（allow=True）与存图/统计决策只消费真实分发结果，不受影响。

## Risks / Trade-offs

- [同文本重滚（改造后词缀文本完全相同）会被拒收到尝试耗尽，返回未变化结果] → 语义正确（同文本=同结论，主循环继续下一轮），仅多耗约两个重试窗口的时间；不产生停止或误判。
- [哨兵字符串与游戏文本碰撞] → 使用含双下划线的固定标记，物品文本不可能出现。
- [三个消费点遗漏 unchanged 处理] → 用测试钉住每个消费点行为；其余调用方（古灵/插槽）因 allow=True 语义不可达哨兵，设计文档留痕。

## Migration Plan

纯模板与生成逻辑改动，无数据迁移。回滚即还原三个文件与测试。
