## Context

见 `proposal.md` 的 Why。价格窗口测试目前横跨 Vue/Pinia、renderer API、preload、IPC、主进程 manager 和 Python 自动化脚本；前端和主进程各有一层强制门禁。正式改价已在每件物品上读取价格、识别通货、提交前复核，并在单件失败时安全跳过。

## Goals / Non-Goals

**Goals:**

- 从所有对外和内部层级完整删除价格窗口测试与临时通过状态。
- 让正式改价在价格配置和网格校准有效时直接启动。
- 保持现有安全预检、逐件识别、失败跳过和全局停止行为。

**Non-Goals:**

- 不修改价格读取、通货 OCR、价格计算或提交算法。
- 不引入隐藏诊断入口或兼容空实现。
- 不打包或发布，不在本变更中同步主规范或归档。

## Decisions

### 1. 纵向删除整条测试能力

同时删除 UI、store、renderer API、preload、IPC、schema、manager 和 Python 模式，不保留无法达到的兼容分支。这比只隐藏按钮更能防止旧门禁或未维护的 IPC 继续影响启动。

### 2. 不用自动测试替代手动测试

正式运行已使用相同的价格窗口解析路径，并且单件不可编辑时会跳过。额外在启动前打开某个物品的价格窗口仍然会受锁定状态影响，不能代表整页其他物品，因此不保留等价门禁。

### 3. 只删除测试独占的辅助代码

主进程的一次性子进程封装、测试结果浮层和等待参数在无其他调用者时删除。正式改价仍使用的进度浮层、事件解析、子进程终止和配置清理保留。

## Risks / Trade-offs

- [用户失去手动 OCR 诊断入口] → 该入口本就不能保证整批成功；逐件日志继续返回具体失败原因。
- [删除 IPC 会影响仍调用旧方法的代码] → 同一 Electron 应用内没有独立外部客户端，并在同一变更内删除所有调用者与契约测试。
- [清理过度误删正式运行能力] → 以引用搜索和浮士德全量测试确认只删除 `price-window-test` 专属路径。

## Migration Plan

1. 先移除前端门禁与入口，再自上而下删除 API/IPC/manager/Python 死路径。
2. 更新各层契约测试，运行浮士德聚焦测试、全量测试和 OpenSpec 严格校验。
3. 回滚时整体恢复本变更的垂直切片，避免只恢复门禁却没有可用 IPC 的不一致状态。
