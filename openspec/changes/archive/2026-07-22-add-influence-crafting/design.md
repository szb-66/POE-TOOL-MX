## Context

手动做装引擎已经用 `ManualSession` 表示单件装备，并通过固定随机种子、统一候选池解析、不可并存 ModGroup、工艺台元属性与历史记录实现可重复的状态转换。数据快照已包含六类势力词缀以及权重为零的尊崇 T1，因此本次不抓取新词缀表，重点是把势力通货的状态规则正确接到现有引擎。

觉醒者之石是首个同时消费两件装备的动作。它必须保留受体的底材属性、消费供体，并忽略两件装备上的元属性重骰其余词缀；这不能简单复用只处理当前装备的普通通货入口。

## Goals / Non-Goals

**Goals:**

- 完整实现当前版本六种势力崇高石、统御宝珠和觉醒者之石的前置条件、随机过程与结果。
- 继续复用统一词缀池、物品等级、生成标签、ModGroup 与固定种子，保证相同输入得到相同结果。
- 提供一个明确的觉醒者供体配置区，配置结果本身必须是一件合法装备，而不是绕过规则的临时词缀列表。
- 所有动作给出可操作的中文失败原因，并写入可撤销历史。

**Non-Goals:**

- 不获取通货价格、不恢复自动制作路径规划。
- 不模拟势力装备的掉落概率、市场库存或供体购买成本。
- 不在本阶段实现辛迪加势力圣甲虫、预兆、镜子或重组器。
- 不实现预知类效果对觉醒者随机选择的特殊展示。

## Decisions

### 1. 势力规则使用独立模块并复用现有候选解析器

新增 `influenceRules` 模块，定义八类通货及纯规则函数。六种势力崇高石用已有 `sources: [influence]` 候选解析和 `addRandomAffix`，先验证稀有度、装备变体、空词缀槽与至少一个合法候选。这样自动继承物品等级、标签权重、ModGroup 和“无法骰出攻击/施法”限制，不复制一套筛选逻辑。

势力崇高石原子地为装备添加势力与对应词缀；失败时不得先改变 `variant` 或 `influences`。

### 2. 尊崇阶直接使用快照中权重为零的 T1

普通随机生成继续排除零权重阶级。统御宝珠则按同一 modifier family 的 tier 数字查找更高一阶，允许命中零权重的 T1。当前词缀已是 T1 时保留该 tier 并重骰数值。只有具备可解析升级目标的势力显式词缀进入可影响集合。

前缀/后缀保护会从可影响集合排除对应词缀。为避免在候选不足时猜测游戏端失败细节，模拟器只有在至少两条可影响势力词缀时启用统御宝珠。

### 3. 觉醒者之石 API 接收两份完整会话

核心规则以 receiver 与 donor 两份 `ManualSession` 做校验和转换；会话信封用可选的 `awakenerDonor` 保存供体，但供体不嵌入 receiver 的装备 state，以免污染通用装备模型。成功结果将该字段置空并记录 `donorConsumed: true`；历史快照同时保存 `donorBefore` 与 `donorAfter`，因此撤销可以恢复供体。旧存档缺省为 null。

UI 首版通过“供体配置”创建同装备类型、单势力、包含一条用户所选合法势力词缀的魔法供体。选择的 modifier tier 必须满足供体底材、物品等级和势力标签；因此配置出来的是一件可被核心 API 验证的真实装备状态。核心 API 仍支持包含多条势力词缀的完整供体会话，并按随机种子随机选择一条，为以后加入双工作台编辑保留能力。

### 4. 觉醒重骰从干净受体状态开始

校验通过后先分别从供体和受体的势力显式词缀中随机选择一条。若两条属于同一 ModGroup，再用随机种子决定仅保留其中一条，并记录被丢弃项。随后创建保留受体底材、物品等级、品质效果、孔洞等已建模非显式属性的干净稀有状态，设置双势力，清除元属性与原显式词缀，再把保留项作为 guaranteed affixes 交给 `rollItem` 重骰数值并补满稀有词缀。

觉醒者之石明确忽略“前缀/后缀无法改变”和“无法骰出攻击/施法”等元属性；补骰来源为基础词缀加两种目标势力词缀，仍遵守物品等级、标签权重和 ModGroup。

### 5. 合法性在动作前统一计算

服务层返回每种通货的 `enabled`、失败原因和候选摘要。界面只消费该结果，不在 Vue 组件内重写规则。失败动作不消耗种子、不产生历史快照；成功动作保存通货名、势力变化、移除/升级/继承词缀及供体是否销毁。

## Risks / Trade-offs

- [快照中个别势力词缀缺少尊崇对应阶] → 仅把能解析到升级目标的词缀列为统御候选，并用数据审计测试明确数量与异常样本。
- [供体配置比完整双工作台编辑能力弱] → 核心采用完整双会话 API；首版 UI 生成合法单词缀供体，后续可无损升级为第二工作台。
- [同 ModGroup 的两条继承词缀只能保留一条] → 用固定种子显式随机决定并在历史中展示，避免静默丢失。
- [旧存档没有供体字段] → 读取时迁移为空供体；写出时沿用当前 schema 版本的向后兼容可选字段。

## Migration Plan

1. 增加纯规则与单元测试，不改变现有会话格式。
2. 扩展服务/API/store，并将缺失供体字段归一为 null。
3. 接入页面势力制作区和供体配置区。
4. 运行完整测试、OpenSpec 校验与生产构建；若需回滚，移除新增入口即可，既有单装备存档仍可读取。

## Open Questions

无。供体首版采用合法单词缀装备配置，完整双工作台编辑留作后续增强。
