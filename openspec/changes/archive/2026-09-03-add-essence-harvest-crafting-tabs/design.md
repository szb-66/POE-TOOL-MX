## Context

现有制作页将通用预设、页面坐标、启动校验和单一 Python 通货流程紧密连接。词缀匹配数据已经能独立表达多组必选/挑选目标，但编辑 UI 和执行动作仍绑定通用通货模式。当前工作区在相关文件存在其他未提交修改，实施必须增量合并。

## Goals / Non-Goals

**Goals:**
- 用稳定制作类型贯穿页面选择、预设、校验、脚本生成、运行事件和重试。
- 复用同一词缀目标模型，避免三套匹配语义分叉。
- 在任何可能消耗材料的鼠标输入前完成可执行的安全预检。

**Non-Goals:**
- 不让精华或花园支持批量、插槽、古灵或固定通货仓库选择。
- 不识别或选择具体花园工艺名称；用户负责把目标工艺准备在按钮位置。
- 不执行安装包构建。

## Decisions

1. 使用 `general | essence | harvest` 作为稳定制作类型并持久化当前值。单一快捷键和首页入口读取该值，避免增加快捷键冲突。
2. 保留 `itemPresets` 作为通用集合，新增 `essencePresets` 与 `harvestPresets`。专用预设直接保存规范化 `affixGroups`；启动时适配为解析器需要的 `moduleTwo`，不把通用通货模式字段泄漏进专用预设。
3. 通用坐标继续兼容原 `itemPosition`，设置 Store 新增精华物品、花园物品和花园按钮坐标。首次识别使用独立的类型映射；首次迁移读取当前通用预设旧值，然后预设规范化不再写回该字段。
4. 抽取无制作方式的词缀目标编辑组件，通用模块在外层保留改造/混沌/点金选项，专用页面只使用目标编辑部分。
5. 启动服务按制作类型构造统一执行快照并选择校验分支。通用继续走原通货及仓库预检；精华和花园绕过固定通货预检，但仍使用前台、DPI、坐标、解析和进程保护。
6. Python 模板新增专用分支。精华在首次鼠标输入前复制验证目标坐标为精华；两个分支每轮动作后使用现有新鲜度机制读取物品，`unchanged` 立即作为异常终止，循环上限为 1000。

## Risks / Trade-offs

- [精华位置只能验证为精华，无法自动理解用户想要的精华名称] → 坐标随预设保存，并在每次启动时重新验证精华身份。
- [花园按钮无法通过物品文本预先确认] → 输入前验证物品，输入后强制要求文本变化，第一次异常立即停止。
- [旧预设可能保存不同首次识别值] → 只迁移当前通用预设的值，符合页面级单一设置语义，其余旧字段保留读取兼容但不再生效。
- [共享文件存在未提交改动] → 使用局部补丁并在完成后检查差异，不覆盖或回滚无关修改。

## Migration Plan

加载时创建缺失的专用默认预设和页面设置。首次识别映射缺失时从当前通用预设迁移；新增坐标默认为未配置。回滚版本会忽略新增存储键，原通用预设与坐标仍可使用。
