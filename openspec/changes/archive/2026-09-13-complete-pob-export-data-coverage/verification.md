## XML 与实际 PoB 导入

使用本机 PoeCharm 中 PoB 2.67.2 的 Lua 运行时执行实际 `ImportTab` 导入码解析和导入按钮逻辑，
验证 harness 禁用设置/构筑写入及网络调用，只输出合成样本的数量摘要。

合成构筑验证：5 个物品、3 颗技能、2 个连线组、角色 90 级；所有物品底材、技能身份、装备栏位、
等级品质与 XML 一致。包括腐母之叛/珠光项链、刺客印记、弹幕辅助、闪回传奇、嫁接和腰带内深渊珠宝。
本次合成构筑不包含已配置天赋；天赋、专精、普通珠宝与星团缺失检查由 Node 回归单独覆盖。
这些结果不是实战伤害计算一致性的证明。

导入器验证实际发现并修复了两处仅检查 XML 数量不能发现的问题：

1. 稀有名称为空会让 PoB 错认底材行；统一补稀有占位名称。
2. PoB 读回 XML 根据词缀重建深渊插槽，只写 `Sockets: A` 可能让镶嵌珠宝失去栏位；
   缺少对应英文插槽词缀时，根据官网明确给出的 A 插槽数量补齐，不重复已有的数量词缀。

## 真实角色现场验收

当前开发版每次导出创建新 worker，会加载更新后的数据和转换器。直接匿名读取官网接口返回 401；随后通过开发版一次临时诊断取得技能属性名、数值和显示字段，
没有包含账号、角色名、物品 ID 或认证信息。定位真实等级格式后，诊断代码和临时数据文件均已删除，worker 文件恢复原状。
用户确认实际角色导出成功。随后从本地剪贴板读取此次导入码，只在本机 PoB 中解压和导入，没有上传。
核对角色为 100 级追猎者：26 个物品、15 颗技能、8 个原始连线组、131 个已配置节点、12 个天赋珠宝；
装备栏位、技能英文身份、等级品质、所有节点与珠宝位置均和导出 XML 一致。
PoB 另生成 3 个带 `source` 的装备/效果技能组，单独计数，未将它们误认为源技能重复。
验证后删除本次临时导入码文件，文档仅保留数量摘要。

现场验证 harness 也做了两处必要修正：永恒珠宝查找表超过最初 16 MiB 解压缓冲区，需要动态扩大；
PoB 自动生成的装备/效果技能组应与无 `source` 的原始镶嵌技能组分别核验。
这两处属于验证器限制，没有通过修改角色 XML 来绕过失败。

真实角色导入通过不代表实战伤害或所有未来赛季内容已验证；覆盖报告中的模板冲突与上游限制仍保留，未称为 100% 全游戏数据覆盖。
