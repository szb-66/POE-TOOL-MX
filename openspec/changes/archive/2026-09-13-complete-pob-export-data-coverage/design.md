## Context

参见 proposal.md。当前 cn-poe-utils 0.0.9 在创建翻译器时构建分类索引；兼容数据只追加 gemSkills/stats。生成器按中文去重并静默丢弃歧义模板；装备翻译将未匹配传奇视为随机稀有名称。

## Goals / Non-Goals

**Goals:** 可复现生成全类别补充数据，保留基线关联信息；按国服别名解析确定身份；在序列化前后检查完整性。

**Non-Goals:** 不编写 PoB 伤害计算器，不推断官网未提供的战斗配置，不通过运行时网络翻译弥补数据。

## Decisions

- 保留固定转换依赖，补齐本地分类数据和有来源的覆盖项；不直接改 node_modules，也不使用模糊字符串匹配猜测身份。
- 以固定 PoeCharm 快照与项目已有国服数据快照按稳定英文标识关联，记录输入哈希；生成器提供只读检查模式及完整排除报告，替代只输出新增条数。
- 覆盖明细按解压后的生成内容判断一致性；内容相同则复用已有 gzip 字节及哈希，避免 Python 压缩元数据差异产生误报或无意义重写。报告仍核验实际文件哈希，内容过期或压缩损坏仍拒绝通过只读检查。
- 保留旧基线映射；同名按类别、底材、传奇名匹配，无法确定则报告而不覆盖。模板引用采用已验证引用元数据，无法安全解析则保留并报告。
- 在转换器独立校验传奇、底材、技能和必要结构；收集完所有问题再失败。检查转换前后物品、技能、词缀和天赋信息，必要时修复序列化适配。
- 保持 code/warnings 接口；词缀未知保留警告，关键身份未知阻止输出。数据生成元数据不带账号或完整本地路径。

## Risks / Trade-offs

- 上游显示译名与国服官网不同 → 关联现有国服目录并保存有依据的别名。
- 上游数据有歧义和非角色词缀 → 明确报告冲突或不支持，不用虚假 100% 覆盖率。
- 数据变大、翻译索引耗时 → 只保存必要映射，复用 worker 内索引并验证耗时。

## Migration Plan

无需用户数据迁移；数据与转换适配一起更新，回滚时一起恢复。仅在开发版运行自动测试和导入验证。
