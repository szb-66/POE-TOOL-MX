## Context

边缘热点由共享几何函数生成，Electron 服务将其原样放入 `border` 探测配置，Python 脚本按数组顺序逐项悬停。`BORDER_EDGE_IDS` 同时用于状态初始化、规范化和持久化完整性检查，因此不能把存储 ID 顺序直接改成扫描顺序。

## Goals / Non-Goals

**Goals:**

- 让所有边缘词缀识别入口从 N0 开始沿外圈连续顺时针扫描。
- 保持边缘 ID、坐标、结果映射和持久化兼容。

**Non-Goals:**

- 不调整 OCR 捕获范围、等待时间、置信度或匹配算法。
- 不改变自动化安全预检、停止机制、错误码或进度事件结构。

## Decisions

1. 保留 `BORDER_EDGE_IDS` 作为稳定的边缘身份集合顺序，新增模块内部的显式顺时针扫描序列。相比直接重排 `BORDER_EDGE_IDS`，这避免改变状态对象的键插入顺序及持久化输出。
2. 几何函数先按原有 ID 计算 12 个目标坐标，再按扫描序列返回目标数组。相比仅反转两个循环，显式序列能直接对应规格和测试中的完整路径，后续更容易审查与防回归。
3. 服务层和 Python 探测脚本不增加排序逻辑。它们继续透传并按输入数组枚举，以保持唯一排序来源并覆盖手动及完成后自动识别两个入口。

## Risks / Trade-offs

- [身份集合与扫描序列出现不一致] → 几何测试同时校验 12 个 ID 完整唯一及精确扫描顺序。
- [后续调用层重新排序目标] → 集成测试锁定服务原样传递数组且 Python 按输入顺序枚举。
