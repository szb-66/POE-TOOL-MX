## Context

参见 `proposal.md` 的问题背景。现有物品解析器已维护 `influences` 数组，但只覆盖部分当前尾标；查价模型尚未将六种经典势力转成查询条件。官方过滤目录将六种势力暴露为 `pseudo.pseudo_has_*_influence`，而非 `misc_filters` 三态字段；回忆束丝则暴露为数值范围 `misc_filters.memory_level`。查价模型会从渲染进程回传，因此必须以最初剪贴板模型作为可信边界。

## Goals / Non-Goals

**Goals:**

- 用单一势力定义表驱动尾标别名、展示文案与官方 pseudo ID，避免六种势力在解析、建模和清理阶段出现不一致。
- 让回忆束丝复用现有可编辑数值属性与官方过滤序列化路径。
- 使渲染层只能启停可信势力条件或编辑可信束丝属性的范围。

**Non-Goals:**

- 不为六种经典势力增加“否”语义或改造三态状态过滤。
- 不改变忆境、焚界者、灭界者的现有状态字段，不刷新或重生成完整交易目录。
- 不打包或发布应用。

## Decisions

### 势力使用 pseudo stat 而非状态过滤

为每个可信 `influences` 值构建一条无数值的 `pseudo` stat，默认 `enabled: true`，使其自然出现在现有词缀过滤区且可切换。这与官方目录契约相同，也避免为不存在的 `shaper_item`/`elder_item` 等字段伪造三态语义。备选方案是引入 `not` stat 分组实现“否”，但这会扩大查询编辑和清理契约，不在本次需求中。

### 势力条件从可信模型重建

清理渲染层回传模型时，以捕获阶段的可信势力列表决定允许存在的势力 stat，以可信模型中的 ID、类型、文案和来源覆盖渲染层值，仅接受用户对 `enabled` 的修改。单纯依赖“ID 存在于目录”无法阻止用户为无势力物品注入合法 pseudo ID，因此不采用。

### 回忆束丝作为可信物品属性

解析器将格式有效的非负整数保存为 `memoryLevel`。建模时仅在原始文本真实存在该行时创建 `misc.memoryLevel` 属性，默认启用、最小值等于解析值且最大值留空。清理阶段按可信属性白名单决定其是否允许存在，用户可修改有限非负范围。这比将束丝当作普通词缀更符合官方 `misc_filters.memory_level` 契约。

### 势力尾标使用显式别名表

在已有“某某者物品”兼容文本之外，补齐附件证实的当前“塑界之器”和“裂界之器”等对应尾标，并为六种势力保留显式映射。不从词缀名中模糊猜测势力，避免同名文案和物品描述造成误判。

## Risks / Trade-offs

- [国服尾标在不同版本存在翻译差异] → 保留旧“某某者物品”别名，并为附件和代表性样本建立回归。
- [pseudo stat 为无数值条件，现有 UI 仍显示最小/最大输入框] → 本次保持词缀列表契约，序列化时不携带数值；如需隐藏无数值输入框应作为独立样式改进。
- [用户输入束丝最小值大于最大值] → 沿用查价数值范围的可编辑行为，并在清理/构建请求时不发送非法边界。

## Migration Plan

1. 先扩展解析数据和回归语料，再接入查价模型与清理白名单。
2. 用针对性测试验证官方 query 形状，再运行完整测试、Vite 构建和开发版 Electron 交互验证。
3. 变更不需要数据迁移；回滚时恢复解析别名、势力 stat 生成和束丝属性映射即可。
