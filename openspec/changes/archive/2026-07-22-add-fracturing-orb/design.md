## Context

装备词缀状态已有 `fractured` 标志，所有常规清除、重铸和移除原语也会保护该标志；但该状态目前只能在创建破裂底材时指定，手动制作无法从普通稀有装备产生破裂结果。基础通货 Provider 能修改装备状态，但破裂后还必须同步 `session.variant`，才能让后续势力、综合等规则正确识别物品类型。

## Goals / Non-Goals

**Goals:**

- 准确实现当前破溃宝珠的随机选择、合法性和元工艺交互。
- 保留被选中词缀的完整来源语义，包括天然、精华、加密和工艺台词缀。
- 让破裂状态参与后续制作、展示、历史和撤销重做。

**Non-Goals:**

- 不实现野兽分裂、印记、综合化或破裂词缀的外部掉落生成。
- 不实现瓦尔腐化、孔色、链接或价格。
- 不推测未揭露占位被破裂后的揭露行为。

## Decisions

### 1. 破溃宝珠作为基础通货 Provider，变体同步由手动会话层负责

Provider 负责验证状态并从全部显式词缀中等概率选择一条，把其 `fractured` 设为 true；`applyManualCurrency` 在动作完成后识别破溃宝珠，将会话变体切换为 `fractured` 并记录 `fracturedTierId`。这样保留统一通货目录，同时让撤销、重做和重置使用现有 variantBefore/variantAfter 机制。

### 2. 候选包含工艺词缀并完全忽略元工艺

破溃宝珠从前后缀数组的全部已揭露词缀中等概率选择，不调用 `mutableAffixes`，因此前后缀锁、攻击/施法限制和工艺来源都不改变概率。被选中项只增加 `fractured: true`，其 `source`、`metaCraft`、阶级和数值保持不变；破裂工艺词缀继续计入工艺上限，破裂元工艺继续生效。

### 3. 使用状态事实与变体双重拒绝不兼容物品

可用性同时检查现有破裂 affix、势力数组、变体种类和综合/古灵状态。古灵隐式保存在独立状态中，因此允许携带古灵隐式的装备破裂，并在变体切换后保留两侧隐式；Split 标志同样原样保留。

### 4. 未揭露占位暂时安全禁用

未揭露占位计入显式词缀数量，但不进入可执行破裂结果。只要存在 `veiled: true`，目录显示“请先揭露”的具体原因。相比把伪 modifier 永久锁定，此边界不会伪造无法从权威资料确认的结果，后续取得可靠规则后可独立扩展。

## Risks / Trade-offs

- [通货 Provider 无法独立同步会话变体] → 在统一手动通货入口记录 variantBefore/After，并增加撤销重做测试。
- [破裂工艺词缀会形成难以清除的工艺占位] → 保留真实 `source: crafted` 和元工艺语义，在页面与帮助中明确展示。
- [古灵与破裂组合不由单一 variant 枚举表达] → 以 `fractured` 表示显式词缀状态，古灵隐式继续由 `state.eldritchImplicits` 表示，不丢失任何状态。

## Migration Plan

1. 新增 Provider 与会话变体同步。
2. 增加破裂标记、历史和 UI 说明。
3. 运行专项、完整测试、严格规格校验与生产构建。

## Open Questions

无。未揭露占位交互在获得可验证资料前明确保持禁用。
