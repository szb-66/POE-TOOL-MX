## Context

参见 `proposal.md` 的动机。当前 Electron 主进程已有从 EOF 开始的 Client.txt tailer、白名单事件服务、游戏前台监视、独立浮窗管理、受限 IPC 和随应用提供的 Python 运行时。工作区中这些区域存在用户未提交改动，实施必须原地扩展而不替换。

## Goals / Non-Goals

**Goals:**

- 用单一主进程状态机处理刷图生命周期，让首页、抽屉和浮窗共享同一事实源。
- 将自动日志观察与受限的地图生命周期输入协调起来，并保持命令白名单、前台门禁与节流。
- 保持长期记录可查询、可修复且不泄露原始日志、剪贴板或用户路径。

**Non-Goals:**

- 不支持 PoE2、云游戏客户端或云端同步。
- 不为地图跟踪器新增一级侧边栏页面或复用首页 `/` 路由创建导航项。
- 不自动发送 `/whois` 或白名单外聊天命令；启用击杀增强后，仅在地图开始及从地图返回藏身处或城镇时自动发送 `/kills`。
- 不保证未经验证的赛季对白或未校准画面特征可被识别。

## Decisions

### 主进程作为地图事实源

新增 `MapTrackerService`，直接订阅 `ClientEventsService.onEvent`、前台状态和系统空闲时间。它持有设置、单一活动局、待捕获的下一张地图物品及今日汇总，通过单一 snapshot 频道发布。不在 Pinia 中复制可持久化业务状态；Pinia store 仅缓存主进程快照和调用受限 API。

备选方案是在渲染层从最近 50 条事件组装历史；该方案在页面重载、应用退出和浮窗未打开时都会丢失数据，因此不采用。

### 先结构化日志，再交给跟踪器

`ClientEventsService` 增加每条已解析事件的主进程订阅，但不暴露原始行。解析器输出固定 union：`area-entered`、`character-level`、`player-death`、`kills-result`、`character-profile`、`map-mechanic`、`client-state`。机制解析只使用版本化且显式启用的中英文特征目录。

区域目录以静态 JSON 包含 `areaId`、中文显示名、类型和附属区域分类。未知 ID 仅在匹配受支持的 PoE1 地图/Boss 前缀时开始记录，显示名使用安全的 CamelCase 分词回退并保留 ID。

### 显式地图状态机

活动局用 `areaId:seed` 作为实例键，包含累计时长和一个可重放的上次活跃时间戳。计时每秒由门禁判定累加：未暂停、游戏前台、空闲小于 10 秒，且当前区域属于主地图或其附属区域。计时使用单调时钟，持久化仅保存已累计毫秒和壁钟时间。

初次进入主地图记一个传送门；只有从城镇/藏身处重返同实例才再加一。新实例到达前以 `next-map` 结束旧局。手动关闭跟踪只暂停并保留草稿；手动“结束并保存”和“丢弃”才清除它。正常应用关闭以 `app-exit` 结束；崩溃留下 `active-run.json` 供恢复。

### 版本化本地存储

`<userData>/map-tracker/settings.json` 保存规范化设置，`active-run.json` 保存单一草稿，`runs/<safe-league>/<YYYY-MM>.json` 保存月度记录。赛季名用安全 slug 作为目录，原始显示值留在记录内。每个文件包含 `schemaVersion: 1`，写入均使用同目录临时文件和原子重命名。

月度文件损坏时不重写：查询收集受影响的相对分片标识并继续读其他分片；编辑该分片前直接拒绝。默认不自动删除旧数据。CSV 通过保存对话框写入 UTF-8 BOM，导出当前筛选的全部结果而不只是当前页。

### 字段模型和计算规则

历史记录固定包含：`id`、`instanceKey`、`areaId`、`areaName`、`areaLevel`、`mapTier`、`startedAt`、`endedAt`、`activeDurationMs`、`experienceEfficiency`、`deaths`、`portalsUsed`、`kills`、`loot[]`、`mapModifiers[]`、`notes[]`、`deviceInputs[]`、`mechanics[]`、`character`、`league`、`endReason`。用户只能编辑 `areaName`、`notes`和标签类数组；观测计数不提供自由修改。

经验效率使用 PoE1 经验等级差公式与高级区域有效等级修正，输出 0–1 数值；任一输入未知时保存 `null`。该计算实现为纯函数并用固定样例测试，方便游戏规则变更时替换。

### 主动采集通过单一安全服务

`/kills`、`/whois`、悬停物品复制和 `Ctrl+单击` 重放都通过主进程受限服务执行，每次校验模块、功能开关、活动局、游戏前台、配置和节流。生命周期触发的 `/kills` 不抢占窗口焦点，并在游戏不处于前台时跳过；用户触发的补采可先激活游戏再执行。渲染层 IPC 只能传入枚举动作和长度受限的结构化备注，不能传入任意命令、路径或键序列。

掉落入库监听作为 Python 运行时的可停止子进程，只在所有门禁成立时使用受控的“拦截—复制—原样重放”。无论复制成功、超时还是解析失败，finally 路径均只重放一次原点击。紧急停止和模块移除立即结束该子进程。

### 浮窗与首页使用同一快照

新浮窗复用现有 BrowserWindow 管理、加载感知发布、前台策略、DPI 和位置持久化模式。显示状态直接由浮窗开关、活动局、暂停状态和游戏前台决定，不注册显隐快捷键。默认不接收鼠标；仅在用户显式进入交互模式且游戏前台时接收。首页卡片、明细抽屉和浮窗都订阅 `map-tracker:snapshot`，禁止各自计时或重新派生记录。

### 首次启用使用现有配置引导

新增 `map-tracker` 模块、`enable`、`loot`、`mechanic` 动作和 Client.txt/模板编辑器。启用跟踪时只将不可用的 Client.txt 列为阻塞项；击杀和地图采集快捷键未设置不阻塞基础统计。继续按钮重新读取主进程状态，只在成功后调用一次 `setEnabled(true)`。

## Risks / Trade-offs

- [国服日志文案或地图 ID 随版本变化] → 特征和区域目录版本化，未知项回退显示但不猜测增强数据。
- [全局鼠标拦截可能影响游戏输入] → 默认关闭掉落跟踪，多重前台/画面门禁，finally 严格重放一次，提供紧急停止。
- [月度 JSON 在超大历史上查询成本增长] → 先按赛季与月份裁剪分片，再在内存中过滤；不为首版引入原生数据库依赖。
- [用户未在进图前采集地图物品] → 保留区域日志名和阶级，词缀/投入列明确显示未采集，不阻止记录。
- [外部参考实现的授权] → 优先独立实现行为；任何实际复用的 MIT 数据、算法或素材都在第三方声明中指明来源。

## Migration Plan

1. 先扩展结构化日志事件，保持现有事件字段兼容。
2. 加入默认关闭的地图服务和仓储，再接入 IPC、store、首页和浮窗。
3. 将新模块加入首页模块管理与运行时适配器，但不加入一级导航功能目录；旧版偏好不包含其 ID 时默认展示首页卡片，内部跟踪开关仍为关闭。
4. 如发生回滚，旧代码忽略新功能 ID 和 `<userData>/map-tracker/` 数据；不删除用户历史。
