## Context

见 [proposal.md](./proposal.md)。现有物品解析器会把分隔线后的未知文本收入普通显式词缀；查价模型又会全局合并相同 stat ID，两者都无法表达佣兵凭证的分组语义。当前内置/官方目录已包含 64 种 `mercenary_warrant` 物品与 534 条 `mercenary` stat，但普通 matcher 不能直接匹配剪贴板中 `(等阶：N)` 与官方目录的 `（等阶 N）` 差异。

## Goals / Non-Goals

**Goals:**

- 以专用结构保留佣兵构建、等级和技能分组，不污染普通词缀。
- 将渲染端编辑限制为可信技能组上的启用状态。
- 精确序列化官方 `mercenary` 查询组，并保持现有普通物品查询不变。

**Non-Goals:**

- 不根据佣兵姓名、技能稀有度或装备猜测普通/恶名身份。
- 不实现跨技能组的宽松匹配、自动放宽或多查询拆分/合并。
- 不打包安装程序，不刷新云端或官方交易目录。

## Decisions

### 1. 在通用词缀解析前识别整张佣兵凭证

只有当类别为“地图碎片”且物品名为“佣兵凭证”时，解析器才启用佣兵段落状态机。先按原始分隔线切段，定位 `BD构建`/佣兵等级段，再将其后到帮助文本之前的每段解析为一个技能组。这些行标记为已消费，不再进入通用显式词缀逻辑。

替代方案是在现有逐行 `else-if` 中添加更多忽略规则；该方案仍会丢失组边界，无法从根因上解决问题。

### 2. 将构建身份与技能目录映射分开

身份解析使用完整显示文本 `佣兵凭证（${build}）` 在目录中查找唯一、`discriminator=mercenary_warrant` 的物品。查价身份对用户继续显示“佣兵凭证”与中文 BD 构建，官方查询使用目录中的内部 type 及 `mercenary_warrant` discriminator，同时保留 `map.fragment` 大类约束。匹配不存在或不唯一时阻止查询并给出可诊断错误，不降级为全部凭证。

技能映射不改变全局 matcher 规则：主动技能以原文匹配 `mercenary.skill_*`；辅助技能先从 `(等阶：N)` 提取名称和等阶，再构造目录标准形式 `名称 （等阶 N）` 匹配 `mercenary.support_*`。这避免放宽其他 stat 类型的全局文本规则。

### 3. 使用独立 `mercenarySkillGroups` 而非扩展平铺 `stats`

解析结果新增 `mercenary: { build, level, skills: [{ name, supports: [{ text, name, tier }] }] }`。查价模型新增 `mercenarySkillGroups`，每组包含稳定组键、`enabled`、一个已解析的主动技能条件及有序辅助技能条件。辅助条件各自保存 `enabled`，没有数值范围；相同辅助 ID 在不同组中保留为独立实例。

这避免现有 stat 合并逻辑破坏分组，也不受渲染模型普通词缀 24 条清理上限影响。通用词缀 UI 与综合词缀生成逻辑不需要知道佣兵分组。

### 4. 从可信模型重建渲染端状态

主进程 rerun 已拥有当前剪贴板重新解析的 trusted model。清理时按组键和辅助键从可信模型遍历，只读取渲染模型中对应的布尔 `enabled`；ID、文本、等阶、顺序、所属组与 BD 身份全部来自 trusted model。渲染端额外条目自然被忽略，无需依赖可被绕过的客户端数量上限。

### 5. 序列化严格的官方佣兵组

查询序列化器接收普通 stats 和佣兵技能组。对每个已启用组，构建：

```text
type = mercenary
filters = [skill.id, ...enabledSupportIds]
value.min = filters.length
```

技能组不进入共享 `and` 组。佣兵等级复用已有 `misc.itemLevel` 属性序列化，但在佣兵模型中使用“佣兵等级”标签并默认 `enabled=false`。

官方错误消息命中查询复杂度限制时，服务层返回稳定错误代码和中文提示；保留当前模型，不重写选择或发送宽松重试。

### 6. 浮窗分组交互与普通词缀区隔离

佣兵技能组使用专用区块位于物品属性与普通词缀之间。组标题行具有整行选中、鼠标和键盘交互；辅助技能使用可换行标签，显示名称和等阶。在未启用组内选中辅助技能会同时启用该组；关闭组只使其不参与查询，保留子选择便于恢复。

## Risks / Trade-offs

- [严格同组查询会消耗多个官方 stat group，某些会话可能拒绝] → 默认不启用技能组；拒绝时显示可操作错误并保留选择，由用户减少组数。
- [国服技能文案标点可能继续变化] → 将规范化限定在佣兵辅助格式，以三份实际凭证和目录全量匹配测试锁定。
- [目录缺少新 BD 构建或技能] → 阻止不可解释查询并显示缺失身份/技能，不猜测 ID 或降级为宽泛查询。
- [现有查价文件已有其他未提交改动] → 实现时以最小增量补丁集成，不重置、清理或改写无关差异。

## Migration Plan

1. 在现有解析结果和查价模型上添加可选佣兵字段，老模型和非佣兵物品路径继续按无该字段处理。
2. 在开发版中用普通、恶名残酷女王和恶名焰矢射手三份复制文本验证解析、模型和请求。
3. 回滚时可移除可选字段与专用 UI；不存在持久化数据迁移或服务端状态。
