## Context

参见 `proposal.md`。当前两个运行入口已经调用同一 Python 分类脚本和基础模型，但君锋镇管理器注入本机校准路径，仓库管理器显式禁用；君锋镇页面用原图加 DOM 网格，仓库页面显示 Python 烧录标注图，训练工作台又维护一套更完整的交互网格。校准仓库已经保存原始图块和标签，因此可在不破坏旧数据的前提下扩展来源元数据。

## Goals / Non-Goals

**Goals:**

- 用一个 Vue 共享组件承载三处原图网格、颜色/圆点开关、提示和逐格标签循环。
- 用一个通用 Electron 校准 API 保存、列出、删除和重置来自三种场景的素材。
- 预览事件显式输出最终候选与模糊状态，避免前端从原始三分类标签猜测自动点击决策。
- 运行时为三种场景加载同一素材池，并保持现有模型校验和 `0.995` 安全门槛。

**Non-Goals:**

- 不改变模型结构、训练算法或自动重新训练策略。
- 不把训练会话标签自动写入即时校准池；只有用户在检测预览明确保存的纠正才进入。
- 不修改仓库布局识别和自动取件点击确认算法。

## Decisions

### 1. 抽取无业务归属的共享网格组件

组件接收原图、行列、cells、可编辑状态和显示状态，向父级发出标签变更。训练页和背包页保留各自的数据加载与保存职责。相比让仓库复用训练页面或继续复制模板，这能统一交互而不耦合路由和训练会话生命周期。

### 2. 保留模型标签并新增决策状态

Python 单元结果继续返回 `label`、`probability` 和 `highlightProbability`，并新增 `decision`：`candidate`、`uncertain` 或 `classified`。运行预览以 `decision` 决定安全颜色，人工标注模式仍按人工标签决定颜色。相比前端再次实现阈值规则，后端输出决策可保证预览与取件使用同一判断。

### 3. 校准仓库升级为跨场景共享素材池

已有记录缺省迁移为 `domain: junfeng`、`columns: 12`、`rows: 11`；新记录保存明确元数据。Python 仍以当前模型重新计算所有素材 embedding，并仅对达到相似度门槛的素材投票，不按 domain 过滤。来源字段用于审计、筛选和未来调参，而不是当前匹配硬门槛。

选择共享池是因为三个场景使用完全相同的 64×64 输入契约和标签语义；保留高相似度门槛可避免仅凭来源进行宽泛覆盖。替代方案“每场景独立池”无法满足跨场景通用目标，也会继续产生体验差异。

### 4. 新增通用校准 IPC，同时兼容旧君锋镇调用

提供中性的校准保存/列表/删除/重置接口，三处预览统一调用。旧君锋镇接口暂时委托给同一实现，避免正在进行的功能和已有测试被一次性破坏；后续可在独立清理变更中移除别名。

### 5. 每次检测预览只保存用户实际修改的格子

前端记录原始标签快照和修改集合，保存时逐格发送原始 `tileDataUrl`、embedding、模型版本及来源元数据。这样不会把模型未经人工确认的整张预测批量固化为校准真值。

## Risks / Trade-offs

- [跨场景视觉相似但语义不同，可能错误覆盖] → 继续使用高相似度门槛、保留来源审计信息，并通过跨场景回归样本验证零高置信误报。
- [旧素材缺少来源字段] → 读取时兼容补全，不原地重写或删除用户文件。
- [共享组件迁移影响训练页既有复核能力] → 保持当前颜色开关、中心圆点、复核焦点与盲测行为，并增加结构测试。
- [预览与取件分别截图仍可能不同] → 本变更统一规则而不承诺复用同一帧；界面继续明确预览是当次截图结果。

## Migration Plan

1. 扩展校准记录与通用 IPC，旧记录按缺省来源兼容读取。
2. 让仓库运行配置注入共享校准路径，并输出逐格原图数据与决策状态。
3. 抽取共享网格组件，依次迁移训练页、君锋镇预览和仓库预览。
4. 增加三场景保存与跨场景应用测试；全部通过后保留旧 IPC 兼容别名。
5. 回滚时可恢复仓库不注入校准路径及旧页面模板，校准数据文件仍可被旧版本忽略，不需要删除。
