## Context

剧情技能存储在 `storyGuide:v1` 中，目前每项只有自由文本名称和红绿蓝颜色。剧情浮窗直接消费该结构。技能目录需要在构建前从 POEDB 获取，但应用运行时必须离线，且现有用户数据不能因新增目录字段失效。

## Goals / Non-Goals

**Goals:**

- 从中文主动与辅助宝石页面生成小型、可版本化的离线目录。
- 让剧情编辑器既能联想选择并补齐元数据，也能继续保存自定义名称。
- 将等级显示作为持久化的编辑偏好，不改变浮窗文本。

**Non-Goals:**

- 不解析职业任务奖励、商店解锁条件或赛季中的实际可购买性。
- 不在应用运行时访问 POEDB。
- 不为剧情浮窗增加等级、宝石类型或新的颜色。

## Decisions

1. 原始 HTML 使用现有 `synchronizeRawSnapshot` 机制，保存在独立的 `electron/assets/skill-raw/<patch>` 目录；规范化目录输出到渲染端可静态导入的位置。这样复用离线、补抓与刷新语义，同时不让运行时读取大型原始文件。
2. 目录项保存稳定来源路径、纯名称、一级需求等级、颜色和主动/辅助类型；显示标签运行时组合为 `名称(等级)`，不把括号文本写入用户数据。
3. 剧情存储版本保持 v1，规范化器只接受有效的可选目录字段。旧数据自然迁移；自由文本与目录项名称不再一致时清除关联字段。
4. 联想和选中逻辑提取为无 UI 依赖的目录工具。候选按名称子串匹配，英文使用小写比较；选择结果自动覆盖颜色。
5. `storyShowSkillRequiredLevel` 放入现有设置存储，默认开启。编辑页通过只读后缀展示等级，候选标签不受开关影响；浮窗快照仅保留名称和颜色。

## Risks / Trade-offs

- [POEDB DOM 变化导致解析失败] → 使用结构夹具、字段校验、数量及哨兵检查，失败时拒绝覆盖正式目录。
- [同名或特殊宝石产生重复候选] → 按类型和来源路径生成稳定 ID，完全相同记录去重，并在候选中显示类型与颜色。
- [目录过期] → 元数据记录赛季和抓取时间，提供显式补抓与刷新脚本；运行时仍保持确定性。
- [旧数据被误判为目录技能] → 只在用户明确选择候选时写入 `gemId`，不会按名称自动迁移。

## Migration Plan

1. 随应用发布新的静态目录和默认开启设置。
2. 旧剧情技能按原名称和颜色读取；只有重新选择候选后才获得目录字段。
3. 回滚时旧版本会忽略新增字段，名称和颜色仍然可用。
