## Context

当前帮助内容集中在 `src/domains/help/helpContent.js`，模块概览由 `moduleTopicById` 返回，页面通过 `PageHelpDrawer` 和 `HelpTopicList` 渲染段落、标题、列表与提示块。11 个正式页面已经接入抽屉；工具站明确未接入。模拟、查价和设置还会在模块概览后追加既有专题。工作区另有独立的 `merge-account-league-guide` 变更和未提交修改，本变更不得覆盖或混入这些工作。

## Goals / Non-Goals

**Goals:**

- 用一套集中式、可测试的内容结构覆盖 12 个正式侧栏模块。
- 让第一次使用助手的玩家仅阅读本页帮助即可完成一次基础流程，并能判断成功、停止或失败。
- 保留现有详细专题和单主题查询兼容性，避免复制内容或改变帮助抽屉的只读性质。

**Non-Goals:**

- 不增加截图、富媒体、交互式高亮、页面跳转或一键配置。
- 不改变任何模块功能、安全门禁、账号接口、数据模型或持久化字段。
- 不为开发训练页和独立浮窗增加帮助，也不打包或发布。

## Decisions

### 1. 以模块概览加子主题组成分层指南

每个模块保留现有 `module-*` 概览主题，并增加稳定 ID 的新手操作子主题。子主题正文只使用现有 `paragraph`、`heading`、`list` 和 `callout` 块，统一覆盖首次准备、实际步骤、结果判断、停止恢复、常见问题、安全边界和必要术语。

不把全部内容塞入一个超长概览主题：多主题折叠能让新手按当前任务阅读，也避免设置和多功能模块难以浏览。不开辟新的帮助页面，以继续满足就地帮助约束。

### 2. 新增完整集合查询并保留旧查询

新增 `moduleHelpTopicsById(id)`，返回冻结或不可变语义的有序主题数组；未知模块返回空数组。`moduleTopicById(id)` 继续只返回模块概览或 `null`，保持现有调用约定。各正式页面统一使用完整集合接口，再按原顺序追加快速开始、做装参考、查价专题或 FAQ。

不直接把所有专题写进页面组件：集中目录便于检查主题唯一性、路由覆盖和文案与界面契约。也不移除旧接口，以避免无必要的破坏性迁移。

### 3. 内容按当前可见功能分组

- 首页覆盖环境状态、模块卡片、需配置状态和首次配置顺序。
- 制作覆盖预设、物品与通货准备、制作模式、词缀目标、预检、停止和恢复。
- 存取覆盖入库、格子布局、黑名单、仓库取件、君锋镇高亮和本机校准素材。
- 地图覆盖异界地图/航海海图、洗图方式、黑白名单、收尾选项和存仓。
- 战斗覆盖公共频率保护、被动喝药、主动循环、一键回城和采样测试。
- 剧情覆盖剧情/技能预设、章节步骤、当前进度和浮窗。
- 商城覆盖商城配方与商城正则两条独立流程。
- 模拟补充创建装备、执行工艺、阅读状态及历史撤销，再衔接现有工艺专题。
- 查价覆盖账号赛季、启用快捷键、浮窗筛选、词缀、挂单和私聊边界。
- 海图覆盖校准、识别纠错、锁定、策略、方案检查和自动放置。
- 工具站覆盖打开、添加、编辑、删除、排序、自定义图片和外站安全。
- 设置按七个现有页签组织配置顺序、影响与重新校准条件。

帮助文案使用页面当前真实标签；只解释容易误解的游戏术语，不扩展为游戏玩法教程。

### 4. 工具站复用现有帮助抽屉

工具站接入与其他一级页面相同的 `PageHelpDrawer`，不为它建立特殊组件或交互。帮助主题只说明现有站点管理行为和打开第三方网站的边界，不改变站点数据或外链处理。

### 5. 用结构和关键词契约防止内容回退

测试验证 12 个路由、主题 ID 唯一性、有序集合、各模块必需内容和与界面一致的关键标签；同时保留对既有专题数量及关键公开边界的断言。组件源码契约继续验证帮助列表没有启动、保存或输入动作。

纯文本测试无法证明可读性，因此开发版还需逐页人工检查主题顺序、折叠、溢出和基础流程可完成性。

## Risks / Trade-offs

- [帮助文案与界面后续变化不同步] → 对主要页签、按钮和字段名称增加回归断言，功能改名时测试提醒同步更新。
- [多主题导致抽屉初始全部收起，新手忽略内容] → 每个主题使用明确任务型标题和摘要，保持现有多主题折叠规则，不引入额外交互状态。
- [内容过长掩盖核心步骤] → 概览保持简短，首次流程、子功能和排错拆成独立主题；详细做装规则继续放在既有专题。
- [工作区已有修改发生重叠] → 只编辑帮助目录、需要接入的页面、对应测试和本变更 OpenSpec 文件；提交或暂存前逐项核对。

## Migration Plan

无需数据迁移。开发版加载新内容后立即生效；回滚只需恢复帮助目录、工具站接入和测试，不影响用户配置或自动化状态。实现完成后执行定向测试、完整测试、开发构建、严格 OpenSpec 校验和逐页开发版验收，不执行打包。
