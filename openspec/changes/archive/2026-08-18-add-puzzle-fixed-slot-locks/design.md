## Context

海图 store 目前将两页全部识别格合并为 `allSlots`，同一集合同时驱动计数、求解、收益、来源分配和完成扣除。锁位必须跨识别内容重置长期存在，且不能破坏现有识别、IPC 和自动放置协议。

## Goals / Non-Goals

**Goals:**
- 用一个位置级持久化状态统一控制所有计算和自动来源的排除行为。
- 保留锁定格现有的识别、词缀读取和人工修正能力。
- 不改变中断续跑时已冻结的方案和来源。
- 求解期间不阻塞锁位、类型和方向编辑，且旧求解结果不得覆盖更新后的仓库状态。

**Non-Goals:**
- 不识别游戏画面自身的白色锁标记。
- 不修改 Electron IPC 或 Python 自动放置配置结构。
- 不为 3×3 海图区提供格子锁。

## Decisions

### 使用独立的锁位数组

在 `puzzleSettings` 中保存 `lockedSlots: Array<{ page, row, column }>`，加载时限制页码为 1–2、行为 0–9、列为 0–5并去重。相比把 `locked` 写入每次识别都会整体替换的 slot，独立状态可以自然跨清空和重新识别保留。

### 在 store 建立唯一可用格集合

保留 `allSlots` 供页面展示完整识别结果，新增从中排除锁位的可用集合，并让计数、求解、收益和来源分配统一读取该集合。这样现有求解器和自动放置协议无需感知锁状态，也避免在多个下游分别增加过滤条件。

### 锁按钮独立于格子编辑控件

锁按钮位于格子角落并阻止点击传播，保留现有左键下拉编辑和右键旋转。切换后持久化、重置方案序号并重新求解；执行中或 `resumeIndex > 0` 时禁用按钮。

### 完成扣除沿用方案来源

当前方案来源由可用集合产生，因此完成海图继续只按 `sourceSlots` 扣除即可；锁位数组不随扣除、识别清空或区域重选变化。启动自动化前仍保留九个来源完整性校验。

### 使用浏览器 Worker 执行最新一次求解

渲染端用模块 Worker 调用现有纯函数求解器。store 为每次重算生成递增请求编号并发送可序列化的状态快照；新请求终止旧 Worker，只有仍为最新编号的结果可以更新方案。Node 测试环境没有浏览器 Worker 时保留同步执行路径。求解期间仓库编辑保持可用，但自动放入和完成海图失败关闭，避免消费旧方案。

## Risks / Trade-offs

- [锁位使可用库存突然不足] → 立即重新求解并沿用现有库存不足反馈。
- [锁按钮与下拉触发冲突] → 使用独立按钮并阻止 click、pointer 和 contextmenu 冒泡。
- [旧配置含损坏位置] → 在唯一规范化入口过滤和去重，持久化时只写规范值。
- [同步求解阻塞连续编辑] → 在浏览器 Worker 中求解，新状态立即终止旧任务并以最新快照重启。
- [旧结果迟到覆盖新状态] → 使用单调请求编号校验提交资格；清空和重置也会使活动请求失效。
- [Worker 启动或运行失败] → 清除可执行方案并显示结构化错误，不在渲染主线程回退同步求解。

## Migration Plan

旧配置缺少 `lockedSlots` 时默认空数组，无需一次性迁移。回滚旧版本时该额外字段会被忽略；不涉及数据删除或打包迁移。
