## Context

参见 `proposal.md` 的动机。现有应用由声明为 `requireAdministrator` 的 Electron 主进程启动自动化脚本，并已经具备 Vue 一级页面、屏幕区域选择、仓库网格校准、RapidOCR 运行环境、游戏前台与 DPI 检测、自动化互斥、Python 输入脚本、结构化脚本事件和全局紧急停止等基础设施，但没有独立 Automation Host、浮士德业务领域，也没有可从物品复制文本读取的定价字段。价格窗口的数值在窄输入框内会视觉截断，因此读取必须依赖聚焦后的剪贴板，而中文通货只能从窗口文字可靠判定。

这项变更横跨渲染页面、持久配置、Electron IPC、自动化生命周期和 Python 识别/输入脚本。安全边界是：任何不确定状态都不得演变为猜测点击，且提交动作不可重试。

## Goals / Non-Goals

**Goals:**

- 把价格计算与游戏输入分离，使分段、换算和原因码可以纯函数测试。
- 用单件事务状态机保证读取、计划、写入、二次确认和单次提交的顺序不可绕过。
- 复用现有前台、DPI、区域选择、OCR、互斥和紧急停止基础设施，同时给浮士德保存独立校准。
- 让 renderer 只提交经过 schema 归一化的业务配置，实际输入操作和顺序由管理员主进程的固定 IPC 与固定脚本决定。

**Non-Goals:**

- 不把市集页建模为可离线同步的仓库，也不引入账号、市集或社区 API。
- 不自动探测 NPC、翻页、切换页签、记录上架时刻或建立后台调度器。
- 不通过图标分类通货，不支持混沌石和神圣石以外的定价单位。
- 不在本变更中改变全局 OCR 模型、自动化时序设置或其他模块的网格配置。
- 不在本变更中拆分普通权限界面与独立高权限 Automation Host，也不改变当前 Electron 的管理员执行级别。

## Decisions

### 1. 建立独立 `faustus` 领域并保持 IPC 表面最小化

渲染端新增独立路由、侧栏入口、页面、Pinia store 和纯价格规则模块；Electron 端新增浮士德 IPC 注册器与单实例 manager。preload 只公开获取状态、更新运行配置、选择网格区域、执行识别测试、开始、停止和订阅事件这些固定方法，不公开通用脚本路径、鼠标坐标点击或按键原语。

选择独立领域而不是塞进“商城”页，是因为该功能有持续配置、运行状态和安全控制，且用户明确需要一级入口。选择固定 IPC 而不是复用通用 `executePython`，是为了让 renderer 无法替换脚本或跳过预检。

### 2. 配置采用版本化快照，计算使用混沌石归一化基准

持久配置包含 `version`、`chaosPerDivine`、有序 `bands` 和独立的 `gridCalibration`。分段保存稳定 ID，拖拽排序只改变数组顺序；空白或旧版本数据经归一化后默认为“不可运行”，不会生成隐式比例或分段。开始运行时 manager 深拷贝并冻结一个配置快照，后续页面编辑只影响下一次运行。

规则模块把边界和旧价统一转换到混沌石基准，验证区间后再计算折扣和目标单位整数值。计算使用可避免二进制浮点边界漂移的有理数/整数化表示；最终只在输出单位处向下取整。替代方案是直接用浮点数逐段比较，代码较短但会在神圣石小数边界和折扣乘法上产生不可预测的临界值，因此不采用。

### 3. 浮士德网格拥有独立校准但复用现有区域与 DPI 契约

页面调用现有屏幕区域选择能力取得物理像素区域、显示器 ID、缩放和采集时间，使用共享的矩形/DPI 校验工具；浮士德配置单独保存市集网格，不借用仓库根页或文件夹页校准。脚本按校准区域和可确认的网格线/槽位结构生成候选格子，并在开始前验证当前页面锚点。

独立保存避免仓库布局调整误伤市集，同时复用公共契约避免再造坐标系统。硬编码截图中的 3840×2088 绝对坐标不具备显示器和缩放适应性，因此不采用。

### 4. 价格窗口识别采用“剪贴板数值 + 白名单文字 OCR”双通道

单件状态机依次执行：确认前台与页面、悬停复制物品、右键开窗、确认窗口锚点、双击数值框、`Ctrl+A`、`Ctrl+C`、解析正整数、OCR 当前单位、计算计划、写入、必要时展开单位选择器并按精确文字点击、重新复制数值和 OCR 单位、单击一次提交。

完整价格只来自价格框选中后的剪贴板。OCR 只负责窗口标题/页面锚点、当前单位、展开列表选项和提交后的警告状态，并将通货候选限制为“混沌石”“神圣石”。OCR 结果必须同时满足精确规范化文字、唯一候选和最低置信度；选择器命中使用文字框中心而不是列表序号。

替代方案包括读取视觉数字和按固定下拉序号选择。前者会把 1000 误读为可见的 000，后者会随列表滚动、版本和选项排序变化误点，均不采用。

### 5. Python 执行单件事务，管理员主进程掌握固定入口与生命周期

管理员 Electron 主进程先完成配置 schema、OCR 依赖、游戏前台/DPI、页面/网格和 AutomationLock 预检，再由浮士德专用 manager 启动仓库内固定路径的脚本。renderer 只能调用固定状态、校准、识别测试、开始和停止 IPC，不能传入脚本路径、权限类型、任意坐标点击或通用键鼠操作。脚本通过 stdout 发送有限的结构化事件，manager 负责校验、脱敏并转发。

停止标志在每个可中断边界检查；脚本所有输入通过统一适配器并在 `finally` 释放。manager 的 stop 是幂等的，并接入 EmergencyStopCoordinator、应用退出与窗口销毁清理。替代方案一是每件物品启动一次 Python，它会重复运行环境准备并使页面级停止和上下文验证断裂；替代方案二是在本变更内先拆分独立高权限 Host，它会显著扩大基础架构范围。两者均不采用，本变更沿用当前管理员主进程并执行单次运行、逐件事务。

### 6. 失败分为单件可恢复和页面级终止

数值无效、单位不确定、无分段、结果不可表达或二次确认不一致属于单件失败：尝试用确定的关闭动作取消窗口，然后继续下一件。前台丢失、页面锚点消失、网格结构整体失效、锁丢失、用户停止和紧急停止属于页面级失败：立即终止，不再移动到下一格。

关闭价格窗口也必须先确认价格窗口仍是当前可识别窗口；无法确认时不猜测点击关闭按钮，而是直接终止全流程并释放输入。提交后警告、冷却或未知结果记为该件失败，不重试提交。

### 7. 识别夹具与输入协议测试分层

纯 JavaScript 测试覆盖配置归一化、区间重叠、跨单位边界、折扣、向下取整和原因码。截图夹具从用户提供的国服截图裁出并脱敏保存：关闭的单位选择器、展开后含混沌石/神圣石的列表、以及视觉“000”场景；识别测试只断言允许的文字和区域，不把用户完整桌面作为仓库资产。

Python/manager 集成测试使用伪屏幕、伪剪贴板和输入记录器验证事件与严格输入顺序，特别锁定双击后 `Ctrl+A`/`Ctrl+C`、换单位后复核、单次提交、停止和输入释放。真实开发版验收先执行只读识别测试并取消，再由用户准备低价值物品进行三类改价；自动测试不会向真实游戏发送输入。

## Risks / Trade-offs

- [游戏更新改变中文窗口或列表布局] → 使用标题/文字/结构多重锚点与置信度门槛，失败时关闭或终止，不通过扩大模糊匹配继续点击。
- [剪贴板仍是旧物品或旧价格] → 每次复制前聚焦目标控件并等待剪贴板发生符合类型的变化；把指纹与价格读取限定在当前单件事务，超时即跳过。
- [多格物品被重复处理] → 用复制文本生成的运行期指纹结合已占用格子集合去重；指纹不写入持久日志。
- [换单位后数值被游戏重置或格式化] → 无论是否换单位都执行提交前的完整数值与单位二次确认。
- [单件取消窗口失败导致下一次右键落在错误上下文] → 不能确认窗口已关闭时升级为页面级终止。
- [OCR 依赖增加启动成本] → 识别测试与运行按需加载现有 RapidOCR 环境，主页面加载不启动 Python 或 UAC。
- [向下取整造成比百分比更大的实际降幅] → 页面规则明确以目标单位最小整数为表达能力；不足 1 或没有真实降低时跳过，并在日志中显示实际新旧值。

## Migration Plan

1. 先加入配置与计算模块及其测试，默认配置没有有效比例、分段和校准，因此升级后不会自动产生输入。
2. 接入路由、侧栏、页面和 preload/IPC 状态表面，再接入管理员主进程 manager、固定脚本、紧急停止和生命周期清理。
3. 加入脱敏截图夹具和输入协议集成测试；运行受影响测试、完整 `npm test`、Vite 构建与 OpenSpec 严格校验。
4. 只在开发版执行识别测试和低价值物品验收，不打包 Electron。若后续必须验证安装包资源或管理员执行级别，先另行取得用户授权。

回滚时删除页面入口和浮士德 IPC/manager/脚本注册；遗留的版本化本地配置没有其他消费者，可安全忽略而无需迁移或删除用户数据。规范归档不在实施过程中自动执行，完成后另行请用户确认。
