## Context

物品制作预设目前保存三个扁平字段，Electron 匹配器按字符串包含关系计算一组条件。制作脚本已经使用 `Alt+Ctrl+C`，解析器能够获得词缀名称、完整效果行和 T 级。做装数据仓库已有版本化 POEDB 原始快照和规范化词缀数据，但搜索接口要求具体底材，且来源清单不含药剂。

## Goals / Non-Goals

**Goals:**

- 用结构化条件表达目录词缀、自定义关键词和可选最低 T。
- 支持多组 OR 条件，并提供可诊断的逐组匹配结果。
- 提供无需底材的全库词缀联想，并加入四类药剂魔法前后缀。
- 无损迁移旧预设并维持脚本和悬浮窗兼容字段。

**Non-Goals:**

- 不把药剂加入手动做装模拟器，也不模拟药剂通货规则。
- 不收录传奇药剂、启明石/灌顶石附魔、工艺台附魔或酊剂。
- 不改变插槽制作、地图制作或做装路径优化逻辑。

## Decisions

1. `moduleTwo.affixGroups` 是唯一的新配置源。每个条件采用 `{ id, kind, keyword, displayName, effectPattern, source, profileId, applicableLabel, minTier }`；旧字段只在加载迁移入口读取，保存时不再双写，避免两套状态漂移。
2. 目录条件用解析器已经生成的数值占位效果 `name/effectKey` 匹配详细复制中的完整效果行；`#` 编译为有符号数值通配符，并要求整条多行效果匹配。自定义条件继续使用名称或效果的子串匹配。
3. 最低 T 使用详细词缀的数值阶级比较：无门槛只检查效果，有门槛时要求合法正整数且 `actualTier <= minTier`。
4. 匹配器接收组数组并返回 `groupResults`、`matchedGroupId`、`matchedGroupName`；旧的 `requiredAllMatched` 与 `matchedSelectedCount` 映射到命中组，未命中时映射到匹配条件最多的组。
5. 新增无需底材的只读联想索引。索引遍历规范化 `modifierFamilies`，按关键词搜索名称、效果、标签、来源和适用配置；完全相同的效果模板、来源与 T 阶梯合并适用配置。
6. 药剂页面只作为 modifier source 加入原始快照与规范化词缀家族，不加入 `POEDB_BASE_PAGES`。生命、魔力和功能药剂页面提供 `ModsView`；复合药剂页面没有独立 `ModsView`，其可用词缀由生命/魔力药剂池共同覆盖，因此该页只校验底材哨兵并在联想适用标签中合并“复合药剂”。这样既遵循真实来源结构，又不把药剂加入手动做装状态模型。
7. 预设规范化集中到独立工具，默认预设、新建预设、加载旧存储和更新操作共用，避免 UI 层各自补缺字段。

## Risks / Trade-offs

- [POEDB 药剂页面结构与装备页面略有差异] → 为三份词缀载荷和复合药剂底材页分别建立哨兵，验证生命/魔力词缀适用范围覆盖复合药剂。
- [自由关键词可能匹配同一词缀的局部文本] → 维持旧行为以兼容；目录选择使用严格效果模板。
- [全库索引数据量较大] → 在仓库初始化时构建轻量搜索行，IPC 限制返回数量并由前端防抖。
- [旧预设包含空字符串或包含数越界] → 迁移时清理空项、生成稳定本地 ID并收敛包含数。
- [当前内置快照缺少新增页面] → 实施时用 `--fetch-missing` 只补四个来源，再离线重建并校验，不刷新既有来源。

## Migration Plan

1. 发布时内置新 schema 兼容的数据与四页原始快照。
2. 首次加载每个物品预设时把旧扁平字段迁移为“组合 1”并立即使用规范化结构。
3. 保留读取旧字段的迁移代码至少一个版本；运行时和保存数据只使用 `affixGroups`。
4. 回滚到旧版本时旧版本会忽略新字段；已有旧字段不再更新，因此回滚仅保证应用可启动，不保证回滚后保留新组合。
