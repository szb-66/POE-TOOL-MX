## Context

客户端 fetch 与服务 openOfficial 各自使用字母数字正则；search 只检查 truthy id。开发版只读快照确认 status=ready、total=1703、shown=0，queryId 是包含 `-` 和 `_` 的长字符串，符合这两处拒绝路径。临时诊断只保存编号和数量，不采集会话或卖家信息。

## Goals / Non-Goals

**Goals:** 统一查询编号契约，消除静默失败，保留真实空结果及现有错误序列化。

**Non-Goals:** 不修改登录流程、筛选算法或挂单 ID 字符集，不增加生产诊断常驻代码。

## Decisions

- 新增主进程查询编号验证函数供客户端和服务复用：只接受非空白字符串，原样返回；可编码性失败也转为接口不兼容错误。拒绝按短编号猜测字符集或最大长度，URL 使用 encodeURIComponent。
- search 验证编号和数组/对象结果结构再缓存；fetch 保留空 ID 数组无请求行为，非法输入显式失败，不静默丢弃非法 ID。
- 页面用独立 actionError 显示跳转失败，不覆盖 ready 状态和结果；禁用重复点击，开始新查询或再次跳转时清空操作错误。
- 在开发版通过现有 IPC 读取及重放物品查询，临时采集代码在验证后撤除。测试包含真实长编号形状及 URI 保真验证。

## Risks / Trade-offs

- [官方编号格式继续变化] → 不解析内部内容，固定域名并编码整个路径段/参数。
- [测试替身绕过真实客户端] → 增加真实客户端与服务组合测试，验证请求确实发送。
- [本地工作区存在其他改动] → 仅修改本变更文件；完整测试的无关失败单独记录。

## Migration Plan

无需数据迁移；重启开发主进程使客户端修复生效，再重新搜索。回滚只撤销本变更文件中的修改。
