## Context

参见 `proposal.md`。当前 `/bag` 路由由单个 `BagView.vue` 承载入库、仓库取件、君锋镇取件和共享校准素材，相关状态与处理函数已经集中在同一页面。工作区中这些取件能力仍处于未提交开发状态，因此实现必须保留现有 store、事件处理和用户改动。

## Goals / Non-Goals

**Goals:**

- 仅调整用户可见信息架构和关联模块文案，不改变运行时业务逻辑。
- 用模板层级表达两个业务 Tab 与独立共享素材区，复用当前组件状态，切换 Tab 时不重建 store。
- 为名称与布局增加静态契约测试，覆盖后续回归。

**Non-Goals:**

- 不重命名 `/bag` 路由、文件目录、Pinia store、IPC 通道或配置字段。
- 不改变自动入库、仓库取件、君锋镇识别与校准素材的算法和持久化格式。
- 不将“背包”这一游戏对象名称机械替换为“存取”。

## Decisions

### 使用单个受控 Tab 状态组织现有模板

在 `BagView.vue` 顶部增加受控的 Element Plus Tabs，并将三块入库内容和两块取件内容分别包入对应面板。这样不需要拆分组件或迁移状态，能最大程度保护当前未提交实现。备选方案是拆成多个子组件，但会放大本次纯布局变更的影响面。

### 共享素材作为取件 Tab 内的独立同级模块

将素材表格从君锋镇卡片中原样迁移到“取件”Tab 内的独立卡片。它与“仓库自动取件”“君锋镇取出高亮”处于同一内容层级，同时共享当前 `junfengStore.corrections` 和现有操作函数，不引入重复状态。

### 只修改表示模块身份的文案

侧边栏、首页卡片、帮助主题和设置页跳转提示改称“存取”；“背包格子布局”“背包标题模板”“仓库与背包已就绪”等对象或状态称呼保持不变。备选的全局文本替换会损害游戏术语准确性，因此不采用。

## Risks / Trade-offs

- [Tab 隐藏内容导致用户误以为功能消失] → 使用清晰的“入库/取件”标签，并让默认页签为最常用的入库。
- [移动共享素材区时遗漏操作或数据绑定] → 原样迁移表格、计数和三个操作入口，并用静态测试校验其在取件 Tab 内与另外两个模块同级。
- [工作区已有未提交改动产生覆盖] → 只做局部模板包裹和精确文案替换，不还原相关文件。

## Migration Plan

开发版直接加载新页面结构；内部路由和持久化数据不变，无需数据迁移。回滚时仅恢复模板分组与用户可见文案即可。
