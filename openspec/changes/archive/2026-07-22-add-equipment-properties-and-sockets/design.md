## Context

手动做装引擎目前围绕显式词缀构建。`bases` 只有名称、类别、错误风险较高的 `requiredLevel`、标签和词缀容量；会话状态只有稀有度、显式词缀、特殊状态与少量隐式状态。POEDB 普通物品卡片其实包含基础防御/武器属性、完整需求和普通固有词缀，但解析器只取 `.requirements .colourDefault` 的第一个数字，因此无等级需求的粗铁盔会把 9 力量保存为需求等级 9。

品质、孔数、孔色和连接同时影响多个通货、黑莫里根配方、物品展示、撤销历史、分裂和希内科拉预览，是一个跨数据、规则、服务和界面的基础层。当前正式版本经官方托管 PoE Wiki 核验为 3.28.0i。

## Goals / Non-Goals

**Goals:**

- 以结构化且可校验的方式保存底材需求、基础数值、普通固有词缀、品质类型和最大孔数。
- 让会话拥有确定性可复现的基础掷值、品质、孔色和连接状态。
- 实现 3.28 核心品质/孔位/固有词缀通货及黑莫里根最大孔数、最大连接配方。
- 在装备卡和动作结果中展示每次使用后的实际变化，并让所有变化服从撤销/重做和预览契约。
- 明确区分游戏公开的硬规则与社区测得或推断的随机分布。

**Non-Goals:**

- 本变更不实现瓦尔宝珠、污秽通货、腐化工艺台额外瓦尔成本、催化剂或神圣石对基础属性以外的新语义。
- 本变更不实现神圣石不能覆盖的圣洁石基础防御百分位重掷。
- 本变更不支持传奇物品、特殊“插槽无法被修改”或由传奇词缀改变孔位上限的例外。
- 本变更不声称未公开的珠宝匠石与链接石完整分布为官方精确概率。

## Decisions

### 1. 升级快照 schema，并在底材上保存可直接执行的结构化属性

`base` 增加 `requirements`、`qualityType`、`socketLimit`、`baseStats` 和 `implicitModifiers`。范围属性同时保存文本模板与数值范围，避免运行时再次从中文文本猜测。`requiredLevel` 保留为兼容查询字段，但必须等于 `requirements.level`。

选择直接扩充当前 POEDB 解析管线，而不是引入 RePoE：当前 RePoE 镜像已归档且停留在旧版本；POEDB 是现有 3.28 中文目录的共同来源。Path of Building 自动生成数据只用于交叉验证孔位上限和字段含义，不成为运行时依赖。

### 2. 需求解析按标签语义，不按数字位置

解析 `.requirements` 的完整文本，并分别识别“等级”“力量”“敏捷”“智慧”；缺少“等级”时等级为 1。基础属性从 `.property` 节点按已知中文标签解析，固有词缀从 `.implicitMod` 解析。快照生成必须包含哨兵底材断言，至少覆盖无等级需求、混合属性、带固有词缀和六孔上限底材。

### 3. 孔位上限由底材类型硬规则与物品等级共同决定

底材保存装备类型上限：双手武器/弓/长杖/胸甲为 6，头盔/手套/鞋为 4，单手武器与盾为 3，潜能之戒为 1，普通首饰/箭袋/腰带/珠宝为 0。自然最大孔数再按物品等级限制为 ilvl 1→2、2→3、25→4、35→5、50→6，并取二者最小值；束缚石的四孔结果按游戏规则忽略 ilvl，但仍受底材类型上限约束。

选择由稳定的类型规则生成 `socketLimit`，而不是从卡片尺寸猜测，因为当前目录不保存格子尺寸，且受支持装备类型已有明确上限。

### 4. 会话以孔数组和连接边保存孔位拓扑

状态保存 `sockets: [{ id, color }]` 和 `links: [[socketId...]]`，规范化时要求每个孔只属于一个连接组、连接组连续且不引用不存在的孔。这样可以无损表示多个连接组、白孔以及珠宝匠石改变孔数时保留/重建合法拓扑。

会话创建时，能打孔的空白底材初始化为 1 个按属性需求加权的彩色孔；不能打孔的底材为空。所有随机值继续使用会话 RNG，因此相同 seed、状态和动作得到相同结果。

### 5. 基础属性与固有词缀使用统一的范围掷值结构

`baseStats` 和 `implicitModifiers` 在会话中保存模板、范围和当前值。品质通过派生显示值影响武器基础物理伤害或护甲基础防御，不覆盖原始掷值。祝福石只重掷具有范围的固有词缀，并保证至少一个受影响值变化；它可覆盖普通、忆境和古灵固有词缀，但拒绝腐化物品。

### 6. 品质遵循 3.25 起的物品等级公式

磨刀石/护甲片对非传奇装备使用 `max(1, min(30 * exp(-ilvl / 30) - 0.3, 20))`，以小数部分进行随机取整，然后把品质封顶为 20%。武器与护甲分别限制适用类型，箭袋不接受装备品质通货。品质每 1% 为基础物理伤害或基础防御提供 1% more，并提高珠宝匠/链接结果。

### 7. 随机孔位模型公开来源和边界

珠宝匠石使用公开武器样本可复现的基础权重 100/90/80/30/5/1，并在合法孔数范围内归一化；品质对更高孔数施加单调增益。孔色按力量→红、敏捷→绿、智慧→蓝的属性需求权重抽取；无属性需求时三色等权。链接石使用隔离的经验分布模块，并让品质单调提高较大连接组概率。

动作目录和帮助页必须把珠宝匠/链接分布标注为社区经验模型。测试重点验证硬规则、确定性、单调性和状态不变量，不用脆弱的单次随机结果声称概率精确。

### 8. 相关动作共享纯规则模块

新增装备属性/孔位规则模块，普通通货、束缚石、黑莫里根配方和希内科拉预览调用同一组纯函数。黑莫里根最大孔数使用当前自然最大孔数；最大连接只连接现有全部孔，不创建新孔。普通孔位通货拒绝腐化、镜像和不适用底材。

### 9. 原始来源快照与规范化数据分层

全量联网抓取只负责生成按游戏版本保存的原始来源快照。每个原始页面以稳定 URL 标识并记录内容哈希、抓取时间、HTTP 状态、补丁版本和来源类别；解析器与 schema 开发默认只读取该本地快照，不因代码修改重新访问 POEDB。

规范化的 `dataset.json` 是原始快照的可重复构建产物。生成器提供离线重建、仅补缺失来源、刷新指定来源和显式全量刷新模式；增量抓取成功后先更新对应原始页面与 manifest，再从完整本地原始集合重建候选数据。图片缓存与文字原始快照独立，文字重建不得触发全量图片下载。

原始快照按补丁目录隔离，不能用 3.28 页面静默覆盖未来版本。仓库至少提交规范化快照；体积较大的原始快照可使用压缩归档或 Git LFS，但本地开发和 CI 必须能在无网络条件下获得指定版本并完成确定性重建。

## Risks / Trade-offs

- [POEDB 中文标签或 DOM 结构变化] → 使用结构化节点、哨兵断言和原子快照激活；解析缺失时整次更新失败并保留旧快照。
- [频繁重爬导致开发慢且站点结果漂移] → 持久保存版本化原始 HTML 与 manifest；日常解析、测试和 schema 迁移全部离线，只有缺失或显式刷新来源才联网。
- [未公开孔位概率无法完全复刻服务器] → 把经验模型集中、版本化并在界面标注；硬规则与概率模型分层，未来拿到更可靠数据时可替换分布而不迁移状态。
- [schema 升级导致旧快照不可激活] → 内置快照与代码同版本发布，仓库继续拒绝不兼容 schema 并显示可操作的更新提示。
- [基础属性文本种类很多] → 首批只规范化当前受支持装备页实际出现的标签；未知 `.property` 作为可显示的结构化文本保留，但关键需求/孔位字段缺失则拒绝生成。
- [状态字段扩展影响分裂与历史] → 统一通过会话深克隆和规范化路径保存，增加分裂、撤销/重做、预览不变性集成测试。

## Migration Plan

1. 首次全量抓取并固化 3.28 原始页面快照、来源 manifest 和内容哈希。
2. 升级 parser/model 与 fixture，确保能从本地原始快照离线、确定性生成 schema 新版本数据并通过哨兵校验。
3. 增加纯装备属性/孔位规则和单元测试，再接入会话状态与历史。
4. 注册通货和黑莫里根动作，接入服务/IPC/UI。
5. 从固化的 3.28 原始快照重新生成中文内置快照，运行全量测试、严格 OpenSpec 校验和生产构建。
6. 若缺少来源，只增量抓取缺失页；若候选数据生成失败，保留当前内置快照和原始快照，不得激活半成品。

## Open Questions

- 珠宝匠石与链接石的经验概率模型未来若获得可靠 3.28 数据，应只替换版本化权重并追加统计回归，不改变公开状态结构。
