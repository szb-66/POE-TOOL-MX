## Context

现有共享帧后处理与 OCR 已独立，但 OCR 和图标共用串行请求。奖励面板以所有币种、多尺度在正文全域扫描，重复计算模板统计量。正文基准名称与实际完整弹框 OCR 不符。动机见 proposal.md。

## Goals / Non-Goals

目标为生产路径整轮减半且识别不退化；不缩短 150ms 悬停、不降低匹配阈值、不改变用户工作流，不依赖 GPU。

## Decisions

- 基准保存固定输入和结果摘要，交替测量旧版与新版；局部指标不能替代实机整轮指标。
- 图标缓存模板统计量；完整粗扫描定位候选，再在局部精匹配。不同币种使用最多四个线程并行扫描，按原词库顺序合并后统一竞争，保留阈值和稳定排序。小于八逻辑核心时上限为核心数的一半（至少一个）。
- 图像以会话、目标和帧标识引用；文字与图标共用一次解码的像素，有限容量及引用生命周期，不使用跨轮状态缓存。
- 文字和图标独立有界队列，输入自动化仍单通道。比较 1/2 工作进程及 1/2/4 推理线程，正确性通过后按整轮中位耗时选优，同速优先低占用。
- 词库预处理按内容版本失效，单次解析记忆相同查询，保持匹配平分时 ID 排序及数值约束。
- 原有证据、进度、停止、超时和部分结果规则保留；新增指标不包含用户敏感路径。

## Risks / Trade-offs

- 候选筛选漏图标 → 保守覆盖判断与全图回退，真实样本及合成边界对比旧算法。
- 多进程争用 CPU → 限制并发与线程并实测组合。
- 缓存泄漏/串帧 → 容量上限、完整身份、取消/退出统一释放。
- 游戏环境不足 → 明确保留实机验收任务，不以离线指标宣称达标。

## 实测调整

复用频域变换曾在单次对比显示约 20% 改善，但稳定生产回放收益不明显。基于投影能量上界的矩形候选筛选也因大部分透明模板不满足筛选条件而增加开销。两条试验路径及专属测试均移除，改为保持完整候选扫描并在币种之间并行；样本单线程约 3.8 秒，四线程约 1.0 秒，识别与置信度一致。避免引入颜色/缩放启发式造成漏扫。

## Migration Plan

无用户数据迁移。开发版验证后保留测量报告；回滚本变更即可恢复原实现。删除失败试验与旧重复路径。

## 前台采集第二阶段

- 基线保存本轮修改前的生产代码及 SHA256 到本地缓存；原始整轮基线仍保留。
- Python 按命令加载识别/后处理模块，独立初始化与预检并行。成功结束仅模型和静态模板可保温 60 秒；图片、输入会话立即回收。停止、故障、退出强制关闭。
- 截图容量不再由图标完成控制。原始帧沿用现有上限；后处理输出先申请 128MiB 待识别图片预算，再释放原始帧；识别交接后释放压缩图片预算，解码图片仍使用已有独立容量。
- 资源截图返回后排队识别，同时继续状态栏采集；相同有效帧可用于资源、布局、图标定位，界面切换及鼠标移动使快照失效。必要任务均完成后才能显示完成。
- 静态校准以通道配置传递，动态身份、前台与 DPI 检查不缓存。
- 记录点击到首移、每次移动间隔、截图/队列等待、状态栏采集和解析结束，以及整轮指标。各场景至少五组交替实机对照；未达标继续优化，实机条件不足标记未验收。
