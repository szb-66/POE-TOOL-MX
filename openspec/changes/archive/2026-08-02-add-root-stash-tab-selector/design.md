## Context

制作脚本由 renderer 将 Python 模板生成到用户临时目录，再由 Electron 主进程选择解释器并启动；正式动作前已有剪贴板通货预检。项目也已有跨显示器矩形框选、物理坐标/DPI 元数据和可下载校验的内置 Python 运行时。仓库列表文字为固定金色、左侧混有图标，列表可能通过鼠标滚轮滚动；提供的真实截图验证表明 PP-OCRv6 在裁剪列表上能稳定识别自定义中文名称，但图标偶尔产生伪文字。

## Goals / Non-Goals

**Goals:**
- 让设置页预览与两类制作脚本复用同一选择算法和配置格式。
- 将仓库导航限制在通货/物品动作前，并让失败进入现有结构化脚本错误链路。
- 保持关闭功能时的启动依赖和运行行为不变。

**Non-Goals:**
- 不遍历、展开或识别文件夹内部仓库。
- 不改变混沌配方取件的跨页状态机。
- 不以模糊文字结果执行点击，也不自动判断是否存在滚动条。

## Decisions

### 使用独立 Python 选择器作为单一算法实现
新增可执行脚本，接受 JSON 配置并提供 `preview` 与 `select` 模式。设置页预览由主进程直接启动；生成的物品/地图脚本把资源路径和配置传给同一脚本，并轮询子进程以响应停止状态。相比把 OCR 代码复制进两个大模板，这能避免识别和滚动规则分叉，也便于使用截图夹具独立测试。

### 配置保存在全局设置，运行时只消费通货映射
`stashTabSelection` 保存 `enabled/rootRegion/hasScrollbar/names`。区域沿用现有物理坐标元数据结构，名称由共享目录常量规范化。十一种映射全部展示，但脚本首版固定请求 `currency`，以免 UI 暗示其他类型已经接入自动化。

### OCR 使用完整列表截图并以文字颜色过滤图标伪结果
选择器使用 RapidOCR 3.9.1 的内置 PP-OCRv6 small 模型与 ONNX Runtime。OCR 后先按 Unicode NFKC、空白和大小写规范化，再以仓库金色文字像素占比、有效行框和置信度过滤图标候选。只有目标规范化文本唯一精确匹配才可点击；相似结果仅进入诊断。

### 滚动扫描先收集再重新定位
无滚动条配置只识别一帧。有滚动条配置先以区域截图指纹检测顶部，再每次滚动六格、等待至少 200ms 并识别，连续两帧不变视为到底，单方向最多三十次。扫描阶段不点击；唯一目标保存滚动步数，随后回顶、重放、重新 OCR 确认后点击。这样可以在点击前发现重复名称，并避免保存滚动后的易失屏幕坐标。

### 动态 Python 模块要求与结构化错误
主进程根据请求中的 `stashTabSelection.enabled` 选择基础模块集或基础 + OCR 模块集。选择器输出单行 JSON；父脚本转换为 `stash-tab-selection-succeeded/failed` 事件。主进程和浮层把失败事件与现有通货预检失败同样处理，但错误文案保持仓库选择根因。

制作浮层在创建后必须先完成页面加载，再允许 Python 制作进程启动；物品与地图脚本仅在仓库选择和通货预检都通过后发送 `crafting-startup-succeeded`。主进程收到该握手前不得向 renderer 返回启动成功；若进程提前退出或返回任一结构化失败事件，则清理进程与文件监听并直接返回根因，避免空浮层长期停留在“等待物品信息”。

制作父脚本不得在轮询 OCR 子进程退出时把 stdout/stderr 留在无人读取的匿名管道中；RapidOCR 初始化日志在 Windows 上可能填满管道并造成父子进程互相等待。两类模板将本次合并输出持续写入覆盖式诊断日志，结束后从独立 `RESULT` 行解析结果；无滚动列表最长等待 30 秒，有滚动列表最长等待 120 秒，超过上限时终止选择器并上报 `selector-timeout`。

### 内置运行时固定并校验全部传递依赖
运行时清单加入 RapidOCR、ONNX Runtime 及其 Python 3.13 Windows x64 传递 wheel，沿用现有 SHA-256 下载和解包流程；模型随 RapidOCR wheel 离线分发。打包前验证导入、模型文件和许可证声明，开发环境仍可选择满足本次动态模块集合的系统解释器。

## Risks / Trade-offs

- [不同分辨率或颜色校正影响文字颜色过滤] → 颜色阈值按相对主色和像素占比计算，保留 OCR 置信度与预览诊断，并要求显示环境变化后重新框选。
- [长列表扫描耗时] → 每步只截取用户区域、模型在选择器进程内只初始化一次，并设置截图稳定停止和三十步硬上限。
- [根目录文件夹与普通页重名] → 扫描要求全列表唯一名称；文案明确不支持文件夹，预览显示全部候选，运行失败后仍由通货预检兜底。
- [OCR 依赖显著增大安装体积] → 仅加入 CPU 推理包和 small 模型，复用已有 OpenCV/Numpy，并通过发布检查跟踪安装包体积。
- [工作区已有未提交改动] → 新服务和配置文件优先独立新增；对共享窗口、制作启动和浮层文件只做局部补丁，不覆盖现有差异。

## Migration Plan

1. 旧 `settings` 不含字段时由规范化函数补全默认关闭配置，不触发 OCR 依赖或自动导航。
2. 发布前准备并验证新内置运行时，再执行安装包冒烟检查；若 OCR 资源验证失败则阻止发布。
3. 回滚应用版本时旧版本忽略额外设置字段；用户原通货坐标和制作预设不受影响。
