## Why

物品制作和地图制作目前要求用户先手动切到正确的通货仓库页；仓库页可以自定义名称且列表可能滚动，切错页面只会在稍后的通货预检中报错，操作割裂且容易反复失败。项目已有跨屏框选、物理坐标和内置 Python 运行时能力，可以在不放宽现有安全门禁的前提下补齐根目录仓库页识别与导航。

## What Changes

- 新增根目录仓库列表区域框选、滚动列表标记、十一种官方仓库类型到单个用户名称的映射和 OCR 识别预览。
- 使用内置离线 OCR 在物品制作和地图制作启动时唯一、精确识别通货仓库页并点击；文件夹内仓库和混沌配方跨页不在首版范围。
- 将仓库页导航置于现有通货预检之前，并把识别失败作为结构化脚本错误同步到主界面和制作浮层。
- 扩展内置 Python 运行时、打包资源和第三方声明，使正式包离线包含 OCR 推理及其传递依赖。
- 保持功能默认关闭；关闭时沿用原制作流程和原 Python 依赖要求。

## Capabilities

### New Capabilities
- `root-stash-tab-selection`: 根目录仓库名称映射、区域校准、OCR 预览、滚动扫描、唯一匹配点击和安全失败行为。

### Modified Capabilities
- `currency-preflight`: 制作可在通货只读预检前执行一次受控仓库页导航，导航失败仍须在任何通货或物品点击前停止。
- `bundled-python-runtime`: 正式包内置并验证离线 OCR 所需的固定 Python 包、模型和许可证信息。
- `crafting-script-startup`: 制作脚本按自动切页配置动态要求 OCR 依赖，并统一上报仓库页选择失败。

## Impact

- 设置页与全局设置持久化新增仓库页识别配置和预览入口。
- Electron 主进程新增仓库列表框选、预览服务以及按需 Python 依赖探测。
- 物品和地图生成脚本在通货预检前调用共享选择器。
- 运行时清单、打包资源、第三方声明、发布验证和截图夹具增加 OCR 相关内容。
