## Context

当前配置分散在多个 Pinia store、localStorage 记录和 Electron user-data 文件中；部分保存方法还会立即同步全局快捷键、检测服务、浮窗或持续输入运行时。预设集合已经各自拥有历史迁移与 normalizer，但没有稳定的跨模块导出契约，也没有能在批量失败时恢复所有参与方的协调层。现有 `settingsReset.js` 已提供“先停止全部自动化再改配置”的安全基线，快捷键和查价设置也已有候选先注册、失败回滚的局部事务。

本变更必须与正在进行的 `fix-chart-edge-clockwise-recognition-order` 及其未提交文件隔离，不重写相关海图识别代码或测试。参见 proposal.md 和各 delta spec 了解用户可见行为。

## Goals / Non-Goals

**Goals:**

- 用稳定语义区块而非存储键描述配置，使存储迁移不会直接破坏文件格式。
- 复用各业务 normalizer，把导出、预览、应用和回滚集中到一个可测试的串行事务。
- 让单预设分享简单，同时把坐标、路径、资产、会话和运行状态默认隔离。
- 对 renderer、localStorage、主进程价格覆盖及已同步运行时提供一致的失败恢复。

**Non-Goals:**

- 不提供云端上传、分享码、加密、压缩或自动发现旧用户目录。
- 不复制背景、视频、模板、训练集、缓存、诊断、窗口状态或账号会话。
- 不改变现有预设的当前选择、默认预设保护规则或模块启动入口。
- 不在本变更中打包或发布正式安装程序。

## Decisions

### 1. 使用纯格式层、区块描述器和事务协调器三层结构

在设置领域新增配置传输模块：纯格式层负责 `ConfigBundleV1` 构建、解析、大小/版本校验和安全 JSON 克隆；区块描述器注册表负责每个稳定 ID 的分组、schema 版本、风险级别、可选择条目、字段过滤、normalize、snapshot、apply 与 rollback；事务协调器只按描述器驱动预览和串行提交。

描述器由应用启动后显式注入所需 store/API，不让纯格式层直接依赖 Pinia 或 Electron。所有区块数据必须先通过描述器 normalizer，现有 store 中只存在于加载路径的 normalizer 将提取为可复用纯函数。相比直接导出 localStorage，这能固定公开语义、统一隐私过滤，并避免遗漏历史迁移。

### 2. 固定 v1 信封，区块独立演进

顶层结构固定为：

```js
{
  kind: 'poe-cn-helper/config-bundle',
  formatVersion: 1,
  appVersion,
  exportedAt,
  sections: {
    [sectionId]: { schemaVersion: 1, data }
  }
}
```

主格式只处理信封级不兼容；每个区块自行迁移旧 schema。未知区块和未来区块版本保留在预览结果中但不可选择。导出文件上限与打开文件上限都按 UTF-8 字节计算为 5 MiB，避免 renderer 字符数与磁盘字节数不一致。

不采用校验和：本地 JSON 的完整性由严格解析和逐区块 schema 校验保证，校验和无法防止恶意修改且会增加无实际安全收益的兼容契约。

### 3. 区块只拥有明确字段

预设、便携设置和本机环境使用 proposal/spec 中的稳定 ID。单例描述器只导出和替换白名单字段；它不得透传 store 整体对象。`enabled`、`moduleEnabled`、运行任务、识别结果、当前 Tab 和当前预设 ID 不进入传输数据。

覆盖层只传输主题、透明度、模糊度、遮罩等无资产字段；当来源使用自定义背景时不输出模式和路径。界面识别只传输无路径阈值；模板及其来源/选择均不写入。通用设置可以包含合法赛季、更新模式等非认证偏好，但账号状态始终排除。

工具站点按去除首尾空白、规范协议/主机和尾斜杠后的 URL 合并；本地同 URL 项完整保留，新 URL 追加。制作价格覆盖以资源 ID 为键，导入项覆盖同 ID，其他本地项不变；主进程为此提供一次性校验并原子替换完整覆盖映射的接口。

### 4. 预设记录在文件内使用传输键，导入时统一重建身份

每个预设条目包含文件内唯一 `recordKey`、显示名称和经过 normalizer 的业务数据，不把来源 ID 当作接收方身份。导入先收集接收方现有名称，再按稳定顺序分配“（导入）”后缀和新 ID。剧情/技能预设通过专用深拷贝器重建章节、步骤、技能组和技能 ID；默认预设标记不传输。

地图与海图业务数据导出前总是移除 `grid`，导出端显式选择坐标时才在条目旁写 `deviceGrid`。导入端未单独选择坐标时把 grid 设为环境中立的未配置默认值；选择时先通过现有网格 normalizer，再附加到新预设。不会从当前本地预设暗中复制坐标。

### 5. 预览与提交分离，提交执行全选区块事务

打开文件只进行解析、兼容性分析、候选 normalize、预设名称规划和冲突计数，不访问持久化写接口。确认后重新验证选择，随后按以下固定顺序执行：

1. 为全部已选描述器读取 renderer、localStorage 和主进程快照。
2. 若任一区块标记 `requiresAutomationStop`，调用统一紧急停止；失败立即结束且不写入。
3. 生成最终候选，强制持续输入模块关闭，并先对快捷键等可预检运行时执行候选同步。
4. 按描述器固定顺序写入 store/localStorage，随后同步其余已关闭运行时和主进程文件数据。
5. 任一步失败时按相反顺序 rollback，再恢复快捷键和主进程运行时；任何 rollback 失败都再次尝试紧急停止、持久化关闭标记并返回 `rollback_failed`。

事务通过单一 Promise 队列串行执行，导入进行中禁用重复提交。描述器不得吞掉同步错误；取消文件对话框不进入事务。预设专属导入既不切换当前预设也不改变运行时，因此不需要停止自动化；包含本机环境、快捷键或持续模块设置时必须停止。

### 6. 复用快捷键和运行时现有事务，而不是绕过 store

快捷键候选调用现有完整集合注册路径，成功后才保存；失败时由既有回滚语义保留原集合。查价、背包、混沌配方、仓库取件和君锋候选均将 `enabled/moduleEnabled` 固定为 false 后同步。一次性制作、地图、战斗和九宫格只保持停止，不因导入注册后的快捷键自行启动；用户后续点击开始或主动按开始快捷键才会运行。

这比直接写 localStorage 后重启更安全，也保持设置页面“即时生效”的现有契约。若某 store 目前没有可回滚批量入口，新增 adapter 调用其纯 normalizer、保存和运行时同步，而不是复制业务校验。

### 7. Electron 只暴露专用、安全的文件能力

新增 `config-transfer:open` 与 `config-transfer:save` handler，并通过 preload/renderer API 暴露 `configTransfer.open()` 和 `configTransfer.save({ content, suggestedName })`。两者先断言调用者为主窗口，并使用主窗口作为原生对话框 owner。

打开操作只接受用户通过对话框选择的普通 `.json` 文件，先 `stat` 和读取最多 5 MiB，再返回 `{ canceled, fileName, content }`；错误只返回稳定错误码和安全文案。保存操作验证字符串字节数与建议文件名，写入目标同目录的随机临时文件，成功后 rename 替换，失败时清理临时文件。任何结果都不返回绝对路径。

不复用现有通用文件 IPC，因为那会扩大 renderer 的任意路径读写能力且难以保证文件上限和路径脱敏。

### 8. 设置页使用卡片加两阶段弹窗

“系统”分类新增全宽卡片和导入/导出按钮。导出弹窗维护分组选择、逐预设选择和坐标选择；“可分享预设”只选预设且不选坐标，“完整备份”选择允许内容后再确认本机环境。导入先选择文件，再显示只读元数据和复选树；默认只选兼容预设，本机/便携区块关闭。

最终确认显示将新增的预设名、单例更新数、站点/价格冲突数、坐标警告和将保持关闭的模块。结果使用统一 `ImportResult` 汇总每个区块的 `added/updated/skipped/conflicts/disabled`，错误码映射为中文信息。关闭弹窗不改变路由或当前 Tab。

## Risks / Trade-offs

- [跨多个 store 的事务不是数据库原子事务] → 在写入前建立全量快照、固定提交顺序并为每个描述器实现逆序 rollback；测试每个故障注入点。
- [回滚过程中主进程可能再次失败] → 再次执行紧急停止、强制持久模块关闭并明确报告 `rollback_failed`，绝不把部分恢复称为成功。
- [未来 store 新字段可能被遗漏] → 白名单遗漏默认不导出，新增可传输字段必须显式更新区块 schema、normalizer 和测试，优先安全于“自动完整”。
- [普通 JSON 可被用户编辑或泄露] → 导入视所有内容为不可信并严格 normalize；界面明确文件为明文，仍禁止会话、路径和资产进入文件。
- [5 MiB 限制可能约束超大剧情预设] → 预设不含二进制资产，当前数据量远低于限制；超限时在写入前给出可操作错误。
- [与现有未提交海图工作冲突] → 新增独立测试和配置传输模块，不修改 `chartEdgeGeometry`、`chart-mod-recognition` delta 或其现有测试；若必须碰到同一文件则精确按 hunk 处理并先报告。

## Migration Plan

1. 先添加纯格式/描述器测试和 Electron 文件 IPC，再接入各 store adapter 与设置页。
2. 新能力不自动读取任何文件，也不迁移现有数据；首次启动行为保持不变。
3. 开发版依次验证目标测试、全量测试、Vite build、严格 OpenSpec 和 Electron 手工流程。
4. 若需回退，移除设置入口、配置传输模块和专用 IPC 即可；现有持久格式未改变，已导入数据仍是正常的当前格式预设或设置。
