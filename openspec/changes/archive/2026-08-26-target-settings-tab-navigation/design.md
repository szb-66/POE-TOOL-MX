## Context

设置页当前从 `localStorage` 恢复六个合法分类之一，所有跨页入口都只导航到 `/settings`。商城与查价入口有明确的账号或快捷键语义，首页环境按钮则已经持有按展示顺序排列的健康项。参见 proposal.md 与 settings-tab-navigation delta spec。

## Goals / Non-Goals

**Goals:**

- 用一个可复用模块统一设置分类常量、路由构造、查询校验和健康项映射。
- 同时支持首次进入和设置组件复用期间的目标分类变化。
- 保持普通入口、持久化、滚动复位和 `v-show` 挂载语义不变。

**Non-Goals:**

- 不重排设置分类或移动设置字段。
- 不改变首页健康检测、异常优先级或 Electron IPC。
- 不执行安装包验证。

## Decisions

### 使用 `tab` 查询参数承载目标分类

目标以 `/settings?tab=<name>` 表达，便于 Vue Router 响应、测试和未来入口复用。与隐藏模块状态或临时 Pinia 请求相比，查询参数可以在刷新和历史返回时保持可解释状态。

### 由统一导航模块维护合法值和入口映射

设置页和调用方共同导入同一组合法分类，路由构造器仅为合法单值生成查询参数。首页选择第一个 `status !== 'ready'` 的健康项；`shortcuts` 映射到 `general`，其余当前环境项映射到 `system`。这保留现有健康列表顺序作为优先级，不另建第二套规则。

### 设置页双向同步但不增加历史记录

设置页立即监听 `route.query.tab`。合法单值调用统一激活逻辑，写入持久化状态并滚动到顶部；缺失、数组或非法值不覆盖当前持久化选择。用户手动切换时使用 `router.replace` 更新 `tab`，避免每次切换产生浏览器历史项；路由回写相同值时不得重复滚动或形成循环。

### 普通入口继续使用纯 `/settings`

侧边栏和帮助页不使用目标路由构造器，因此设置页仍按现有持久化规则初始化。只有文案和上下文明示目标的入口携带 `tab`。

## Risks / Trade-offs

- [查询参数与手动 Tab 双向监听可能形成重复导航] → 在替换路由前比较当前合法目标，且激活相同分类时不重复写入或滚动。
- [非法或重复查询值覆盖用户选择] → 仅接受合法字符串单值，其他形式全部忽略。
- [首页未来增加新的健康项] → 未显式识别为快捷键的环境项安全回退到“系统”，并用映射测试固定现有行为。

## Migration Plan

无需数据迁移。现有 `settings.activeTab` 值保持兼容；回滚时移除查询目标处理和目标入口即可恢复原行为。
