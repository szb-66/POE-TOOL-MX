## Context

见 proposal.md。现有碎片补位在填充率过滤之后执行；本次 90×109 轮廓填充率 0.28，被过滤。内存试验全局降至 0.25 得到 33 间并恢复位置，但末列误增背景房间。

## Goals / Non-Goals

**Goals:** 保留高置信候选，用独立低填充补位恢复完整几何，再统一编号。

**Non-Goals:** 不改变采集、路径定位、接口和持久化；不处理状态栏；不以固定房间数量凑网格。

## Decisions

- 填充率 0.25～0.40 仅进入弱候选列表，沿用尺寸及宽高比边界。高置信流程及已有碎片补位保留。
- 使用至少两个不同位置的同列可信房间确定列中心和中位尺寸；弱候选不能作为后续补位的锚点。
- 从可见碎片边界和同列尺寸恢复矩形，在包含该碎片的有限纵向范围内检验相邻可信列的连续路径，使用连续支持和几何残差选择框位置。恢复框必须在图内且不与已有房间重叠。
- 只接受具备连续真实路径的弱候选，排除仅交叉点或背景装饰；多阈值重复候选去重后编号。
- 同样连续的粗线候选按实际线条中心与拟定房间中心连线的偏差择优，避免选择支持率平台的第一个纵坐标。列首中尾测试曾检出此偏移，加入对齐后通过。
- 不采用全局降低填充率（已证明误增房间），不增加多帧重试（用户明确要求）。

## Risks / Trade-offs

- 弱候选误识别 → 独立可信锚点、完整框去重和连续路径验证；以背景反例回归约束。
- 框中心偏移导致连线遗漏 → 同列尺寸恢复并利用连接几何选择纵向位置，验证原图完整连线。
- 极端遮挡仍无法恢复 → 保持未知，不能放宽定位逻辑掩盖漏检。

## Migration Plan

无存档迁移；只在开发版与离线回放验证，不打包。
