## Context

海图页面目前在标题区放置识别强度、双页识别与自动放入操作，两个区域配置卡始终完整展示。Electron 服务的 `analyze` 调用再通过一个组合探测函数依次采集碎片与边缘词缀，而独立边缘识别通道已经存在并由完成当前海图流程复用。

## Goals / Non-Goals

**Goals:**

- 让页面操作跟随其业务数据归属，并减少已有配置时的首屏占用。
- 在服务边界拆除一键识别对边缘 OCR 的调用，同时保持独立边缘识别和自动化安全约束。
- 保持现有 IPC 名称及旧边缘结果兼容。

**Non-Goals:**

- 不修改碎片识别、边缘 OCR 或自动放入算法。
- 不持久化折叠状态，不新增组件、依赖或设置迁移。

## Decisions

1. **折叠状态保留在页面组件。** 使用按 `inventory`、`atlas` 索引的本地响应式对象，并复用 Element Plus 折叠过渡。初始值直接由 store 同步加载的区域元数据计算；相比写入 Pinia/localStorage，这避免新增不必要的设置和迁移。
2. **操作直接移动到现有卡片头部。** 碎片识别控件复用仓库工具栏，方案执行控件复用最优方案标题区；不拆新组件，以维持事件处理和禁用条件的单一来源。
3. **在 Electron 服务中收窄组合探测。** 将组合函数改为只采集碎片词缀，`analyze` 不再接收或消费海图区元数据，统一返回 `borderMods: null` 与已跳过的 `borderProbe`。Pinia 对空边缘字段不应用更新，因此自然保留旧结果。
4. **独立边缘识别保持原链路。** `probeBorderMods`、完成后自动识别、进度事件和自动化锁继续复用现有 `runBorderProbe`，避免复制安全校验。

## Risks / Trade-offs

- [仓库工具栏控件增多，在窄窗口可能拥挤] → 允许工具栏换行，并保留分页按钮自身不换行。
- [兼容字段被误当成新边缘结果] → 边缘字段使用 `null/已跳过`，前端仅在存在对象结果时应用。
- [边缘探测与自动放入发生并发] → 将分析与边缘探测纳入 store 的自动放入阻塞原因，同时保留主进程自动化锁作为最终保护。

## Migration Plan

无需数据迁移。开发版验证通过后随普通更新发布；回滚只需恢复页面布局与组合探测调用，现有设置和边缘结果格式不变。
