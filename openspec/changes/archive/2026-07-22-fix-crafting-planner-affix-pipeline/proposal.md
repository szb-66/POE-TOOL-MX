## Why

当前做装规划器将同一 POEDB Mod Family 下的法术、火焰、冰霜和闪电等内部结果错误拆成多个外层词缀项，破坏了编年史的分组和总权重语义。底材目录同时只显示“手套”等宽泛名称，无法区分力量、敏捷和智慧底材。

## What Changes

- 以 POEDB 词缀目录的受支持装备层级和底材专属页面为准，保存底材分类路径及词缀配置；特殊底材使用独立词缀池。
- 以 Mod Family 作为外层词缀项，在内部保存效果分支和等级记录；外层总权重由当前可生成的内部记录汇总。
- 过滤 Royale、测试和废弃底材；合法中文同名底材使用可区分的显示名称，不再出现视觉重复项。
- 将 POEDB `master` 记录与工艺台表格精确关联，保存实际数值、适用类别和成本。
- **BREAKING**：目标请求从“词缀 + 最低 T 级 + 来源策略”改为“统一目标效果 + 最低等级”；来源由规划器自动选择。
- 工艺台仅在同效果且最低数值达到目标门槛时可完成目标，规划结果使用真实工艺成本。
- 做装三个主模块改为纵向全宽排列；目标内部使用可展开父项，等级不足记录保留但置灰。
- 做装数据 schema 升级到 v3，重新生成内置快照；schema v2 活动快照安全回退到内置 v3。

## Capabilities

### New Capabilities

- `crafting-data-catalog`: 定义与 POEDB 一致的受支持装备分类、专属词缀配置、阶级元数据、工艺台关联和快照兼容行为。
- `crafting-path-optimization`: 定义来源无关的目标模型、天然/工艺台自动达成规则以及目标选择界面行为。

### Modified Capabilities

无。当前主规格目录尚未包含做装规划能力；本变更以同名能力规格补充并修正尚未归档的初版做装变更。

## Impact

- 影响做装领域模型、POEDB 来源/解析器、数据更新器、仓库查询、工艺状态与优化器，以及做装规划 Vue 页面和相关测试。
- 数据集和 IPC 词缀查询结果升级到 schema v3；规划目标继续使用 `goalId + minTierId`，现有 schema v2 用户快照不原地迁移。
- 不新增运行时依赖，不扩展药剂、地图、夺宝装备等当前规划器范围外的类别。
