## Context

见 proposal.md。现有 moveToDip 每次调用 sync，并向主窗口发送偏移；store 收到后同步写 localStorage。前端结束事件无坐标，主进程会话目前位于 IPC 模块。

## Goals / Non-Goals

Goals: 拖动热路径仅处理位置；最终落点准确且只保存一次；业务更新保持有效。
Non-Goals: 不改用原生拖动，不引入定时节流，不改其他浮窗协议。

## Decisions

- 控制浮窗自行持有拖动会话，IPC 保留发送者校验并委托处理，关闭及渲染器退出清理会话。
- moveToDip 只换算、钳制并更新位置，保存实际钳制后的相对物理偏移；相同 bounds 跳过 setBounds。sync 复用同一定位函数，避免重复位置操作。
- end 应用最终有效坐标，再清除会话并单次通知配置保存；cancel/lost capture 使用最后有效位置，关闭前提交已有移动。无移动、重复结束和旧窗口消息不提交。
- 公共指针工具增加可选最终坐标模式，仅控制浮窗启用；指针取消、失去捕获和卸载统一结束，结束先解除活动状态避免重入。
- 保留实时业务同步。拖动时 runtime 更新不得用旧持久化偏移覆盖正在使用的位置；其余业务字段继续更新。
- 不先加节流：它不能消除每次移动的业务工作且会增加等待。先以真实 Electron 开发窗口与事件计数基线验证拆分效果。

## Risks / Trade-offs

- 异常结束不能信任事件默认坐标 → 使用最后一次有效移动位置。
- DPI 往返误差 → 保留现有坐标转换及规范内容尺寸，保存钳制后的实际偏移。
- 游戏前台条件限制现场复现 → 开发窗口自动回放验证消息、耗时和位置，同时如实标明真实游戏人工验收是否完成。

## Migration Plan

配置与 IPC 通道不迁移。开发版验证后交付；回退本次代码即可恢复原行为。
