## Context

地图洗练的界面按钮与全局快捷键最终都调用 `startMapRolling()`，但触发时的前台窗口不同：点击按钮后前台是 Electron 主窗口，而在游戏内按 `Alt+2` 时前台已经是游戏。生成的 Python 脚本目前不检查前台窗口，移动鼠标后立即发送 `Ctrl+Alt+C`，因此界面入口会把复制键发给应用自身，再把没有变化的剪贴板误判为空格。

项目现有混沌配方脚本已经包含经过使用的 Windows 游戏窗口查找、恢复、激活和验证逻辑，地图脚本可以采用相同策略而不引入新依赖。

## Goals / Non-Goals

**Goals:**

- 让界面按钮和游戏内快捷键启动地图洗练时具有一致的前台游戏窗口前置条件。
- 在任何鼠标、键盘或剪贴板操作前完成游戏窗口激活验证。
- 激活失败时安全停止，避免误操作应用或把地图误判为空格。
- 用可执行的 Python 模板测试覆盖“应用在前台，游戏可激活”和“游戏无法激活”两条路径。

**Non-Goals:**

- 不改变地图词缀匹配、通货使用、连续空格阈值或坐标配置。
- 不修改 Electron 主窗口的通用最小化行为。
- 不重构所有 Python 模板的窗口操作代码。

## Decisions

1. **在生成的地图 Python 脚本中恢复游戏前台，而不是只在界面按钮中最小化 Electron。** 最小化依赖 Windows 恢复“上一个窗口”的行为，无法保证目标一定是游戏，也不能覆盖未来其他非游戏入口；脚本在发送输入的位置验证前台，安全边界更可靠。
2. **复用混沌配方脚本的 Win32 激活策略。** 脚本枚举可见的中文或英文《流放之路》窗口，必要时恢复最小化窗口，并通过 `AttachThreadInput`、`BringWindowToTop`、`SetForegroundWindow` 和 `SetFocus` 激活，随后在有限超时内验证前台标题。
3. **激活失败直接停止，不计为空格。** 失败发生在扫描循环和剪贴板判定之前，日志明确说明“无法激活游戏窗口”，从根源上区分窗口焦点失败与真实空格。
4. **测试真实模板函数调用顺序。** 回归测试从模板抽取窗口辅助函数和 `start_map_rolling()`，使用假的 Win32 API 模拟应用窗口前台及游戏窗口激活，断言激活成功后才移动鼠标；同时断言激活失败时不会移动鼠标或复制。

## Risks / Trade-offs

- [Windows 限制前台切换导致激活失败] → 使用线程输入附加和有限轮询验证；仍失败时安全停止并提供明确日志。
- [窗口标题匹配到错误版本或额外窗口] → 仅枚举可见顶层窗口并保持与项目其他自动化一致的标题规则；当前改动不扩大既有识别范围。
- [模板间存在少量重复的 Win32 逻辑] → 本次保持生成脚本独立、变更最小；若后续多个模板继续演进，再单独抽取共享模板片段。
