## Context

参见 proposal.md。当前批量扫描由主进程冻结背包网格和尺寸目录后启动 `bag_auto_stash_template.py --mode scan`，Python 按列遍历并通过剪贴板识别，Renderer 使用扫描内稳定 ID 冻结批次。当前高亮模型及 manifest 已随开发版资源提供，但训练域不包含 12×5 角色背包，因此只能作为保守预筛，不能替代剪贴板身份识别。

## Goals / Non-Goals

**Goals:**

- 在不削弱现有扫描安全门禁与身份可信度的前提下减少空格上的键鼠和剪贴板操作。
- 让逐件完成事件与原扫描预览建立稳定映射。
- 将重复确认偏好纳入现有全局设置生命周期。

**Non-Goals:**

- 不重新训练或修改当前模型，不用模型判断物品类别、底材或尺寸。
- 不改变冻结批次、制作顺序、异常后重新扫描和通货预检契约。
- 本次不执行安装包构建，也不自动同步或归档 OpenSpec。

## Decisions

### 在现有扫描脚本内执行一次整图推理

主进程根据已校准的首格中心和格子间距注入模型、manifest 与阈值路径。扫描脚本在聚焦游戏后截取精确 12×5 矩形，一次推理得到 60 格分类。相比启动第二个高亮脚本进程，这能保持同一前台会话、停止信号和输入清理路径，并避免两次窗口准备。

### 只信任高置信度 empty，其他结果继续复制

只有标签为 `empty` 且该标签概率不低于 0.995 的格子加入模型跳过集合。任何加载、契约、校验和、截图或推理错误都转为快照回退原因并使用空跳过集合。相比严格依赖模型，这一方案保留分布外背包画面的安全回退。

### 进度区分模型空格与尺寸占位

遍历仍覆盖固定 60 格，模型空格与已解析多格物品占位都会增加已处理数，但分别记入 `skippedModelEmpty` 和 `skippedOccupied`。快照加入 `scanOptimization` 摘要，现有消费者可忽略新增字段。

### 完成 ID 保存在制作运行 Store

`crafting-batch-item-completed` 已包含扫描内稳定 ID，Renderer 对 ID 做去重累积并由预览直接查询。状态不写入预设或扫描快照，避免把一次运行结果误当成可续作数据；新扫描和新批次显式清空。

### 提示偏好使用全局设置

新增布尔设置 `batchScanConfirmationSuppressed`，通过现有 `settings` localStorage 文档保存和重置。确认框使用可控复选框内容，只有确认分支提交设置，取消分支不产生副作用。

## Risks / Trade-offs

- [模型对角色背包可能出现高置信度误判] → 使用 0.995 阈值，只跳过 `empty`，并保留完整复制回退和后续整批身份预检。
- [截图边界与格子中心配置不一致] → 从现有物理像素首格中心和格子间距推导矩形，截图失败直接全量扫描。
- [模型推理增加扫描启动时间] → 单次批量推理代替逐格推理，只有一次截图和一次 ONNX 调用。
- [旧设置没有新增字段] → 加载时默认 false，不需要持久化迁移版本。

## Migration Plan

新增运行字段均可选，旧设置默认继续显示确认，旧扫描事件消费者忽略新增统计。回滚时移除模型配置与预筛、完成 ID 和提示偏好即可恢复原逐格扫描，不需要转换用户数据。
