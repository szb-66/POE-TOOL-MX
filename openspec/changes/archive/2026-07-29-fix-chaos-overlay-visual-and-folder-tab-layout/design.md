## Context

控制浮窗的 `disabled` 表达式混入空字符串，Vue 会渲染原生禁用属性，但 `pointerdown` 处理仍可能执行，造成“看似禁用但可点击”。

普通与大型仓库占用相同的整体屏幕矩形，仅网格密度分别为 12×12 和 24×24，因此区域应按“文件夹外/文件夹内”区分，不应再按仓库大小拆分。

现场验证表明，Cookie 会话访问新版 `/api/stash/{league}` 返回 403；旧版 `get-stash-items` 能读取无需 OAuth 的仓库列表与详情，但不能可靠表达文件夹关系。文件夹归属影响的是屏幕坐标选择，因此由用户显式指定比继续猜测接口结构更可靠。

## Goals / Non-Goals

**Goals:**

- 让按钮禁用语义、样式和行为一致。
- 只保留旧接口单一路径，避免双请求与 Provider 状态分裂。
- 按赛季和仓库 ID 保存手动文件夹归属，未设置时固定为文件夹外。
- 让列表标签、配方快照、预览和自动取件使用同一手动归属。
- 保留文件夹内外两套校准，普通/大型独立决定网格密度。

**Non-Goals:**

- 不申请或集成新版 Account Stashes OAuth。
- 不通过仓库名称、接口 `parent/folder` 或空物品响应猜测文件夹归属。
- 不扫描游戏网格，不允许手动覆盖接口返回的仓库名称或物品内容。

## Decisions

1. 按钮模板显式比较忙碌状态，保证 `disabled` 只产生布尔值。
2. `PoeCnStashClient` 的列表和详情都调用 `get-stash-items`；`fetchTabs` 每次先刷新列表，再按最新索引获取详情。
3. 设置使用 `tabFolderStates[league][tabId] = boolean`。旧 `tabOverrides` 仅迁移其中的 `inFolder`，名称和文件夹名称字段不再保留。
4. 应用手动状态时清空接口模型中的 `parent`、`folder` 和 `folderName`，防止 `stashCalibrationKey` 被接口字段反向覆盖。缺少状态时 `inFolder=false`。
5. 已选仓库页切换归属后立即重新刷新快照，保证主界面预览和游戏内控制使用同一状态。
6. 校准键为 `root/folder`，普通和大型分别产生 12/24 列。

## Risks / Trade-offs

- [用户选择错误] → 界面明确提示旧接口无法判断，默认使用更常见的文件夹外位置，并在每个已选页旁提供开关。
- [旧接口返回旧名称或空内容] → 禁用 HTTP 缓存并在每次详情刷新前重载列表；仍为空时显示明确诊断，不伪造物品。
- [旧设置包含名称覆盖] → 只迁移文件夹布尔值，避免过期名称继续遮蔽接口数据。
