## Context

物品制作当前在三个层级把知识卷轴视为无条件依赖：前端坐标校验、生成脚本的固定通货预检清单、Python 目标物品准备。古灵模块与显式词缀和插槽模块互斥，因此可以用古灵模块启用状态稳定地区分两种启动策略。

## Goals / Non-Goals

**Goals:**

- 让古灵隐式独占模式完全不依赖知识卷轴位置或当前仓库页可见性。
- 保持正式制作只能使用已预检通货的安全门禁。
- 保持显式词缀、插槽和地图制作的现有知识卷轴行为。

**Non-Goals:**

- 不改变仓库页识别、通货名称识别或古灵词缀命中规则。
- 不允许古灵模块与其他物品制作模块组合运行。

## Decisions

### 以古灵模块启用状态派生知识卷轴需求

在通货清单、配置校验和脚本准备分支中使用同一业务条件：`moduleEldritch.enabled` 为真时不需要知识卷轴。选择该方式是因为预设规范化和启动校验已经保证古灵模块与其他模块互斥，无需增加持久化配置或迁移。

备选方案是增加“校验知识卷轴”开关，但会把仓库布局约束暴露给用户，并可能产生不安全的组合状态，因此不采用。

### 古灵模式保留首次读取并拒绝未鉴定装备

目标物品仍需首次复制和解析，以便执行底材、腐化、势力和初始命中检查。若解析结果为未鉴定，准备阶段直接通过结构化启动失败通道停止并提示用户先鉴定装备；若已经鉴定，则继续古灵制作。这样既消除跨页依赖，也避免在信息不完整的装备上消耗古灵通货。

### 用行为测试锁定三个入口

回归测试分别覆盖清单只含所选古灵通货、缺少知识卷轴坐标仍通过配置校验、生成脚本对未鉴定古灵目标零通货消耗并返回明确失败。非古灵测试继续断言知识卷轴要求，防止条件范围扩大。

## Risks / Trade-offs

- [用户需要手动切页鉴定后重试] → 启动失败信息明确说明需要先鉴定装备，并保证停止前不消耗任何通货。
- [条件在 JavaScript 与 Python 模板之间漂移] → 通过生成脚本执行测试同时覆盖替换值与运行行为。
