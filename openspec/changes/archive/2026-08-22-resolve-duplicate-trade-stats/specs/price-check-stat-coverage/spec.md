## ADDED Requirements

### Requirement: 等价 stat 必须形成可信查询分组
系统 MUST 将一个逻辑词缀的单一有效 stat ID 序列化到普通 `and` 组，并 MUST 将两个或以上有效等价 ID 序列化到该词缀独立的 `count` 组且设置 `value.min=1`。各变体 MUST 使用同一显示边界并按其可信 matcher 的数值方向转换；渲染进程只能修改逻辑词缀的启用状态和数值边界，主进程 MUST 从当前可信目录重建变体的 ID、类型、方向和等价组。

#### Scenario: 单一有效 ID 查询
- **WHEN** 一个逻辑词缀在当前 Provider 和游戏版本只有一个有效 stat ID
- **THEN** 系统将它作为普通过滤项写入 `and` 组

#### Scenario: 多个等价 ID 查询
- **WHEN** 一个逻辑词缀具有二至四个有效等价 ID
- **THEN** 系统在该词缀的独立 `count` 组中写入全部变体并设置 `value.min=1`

#### Scenario: 多条逻辑词缀同时启用
- **WHEN** 用户同时启用多条含等价变体的逻辑词缀
- **THEN** 每条词缀生成自己的 `count` 组且不得将不同词缀的变体混合

#### Scenario: 渲染进程伪造变体
- **WHEN** 渲染进程提交额外的等价组成员、已标记不可查询的 ID 或被篡改的数值方向
- **THEN** 主进程忽略伪造字段、从当前目录重建可信变体且不得向官方提交无效 ID

#### Scenario: 反射伤害隐式词缀
- **WHEN** 3.29 腾讯国服胸甲包含“阻挡受到的 +50% 反射伤害”
- **THEN** 系统唯一使用 `implicit.stat_2510655429` 并以正向 `value.min=50` 查询

## MODIFIED Requirements

### Requirement: 通用交易语义与国服本地化分层
系统 MUST 保留国际服官方物品与词缀目录中每条结构有效的记录、词缀类型和 stat ID，并以腾讯国服官方目录按相同 ID 覆盖本地化 matcher；同一显示文本对应多个 ID 时 MUST 保留全部官方记录并参与覆盖审计。系统 SHALL 仅在 Provider 和游戏版本都精确匹配时将已实证不可查询的 ID 排除出解析候选、可信模型和官方请求，并 SHALL 按官方 stat 类型、标准化中文文案和数值占位结构构建确定性等价组，不得因无法立即唯一映射、翻译暂缺或不可查询标记而静默删除官方记录。

#### Scenario: 同文案存在多个显式 ID
- **WHEN** 官方目录返回显示文本相同、类型相同且数值占位结构相同、但 stat ID 不同的多条词缀
- **THEN** 运行时目录保留全部官方记录、为它们记录同一等价组且覆盖审计不报告记录丢失

#### Scenario: 当前版本存在不可查询记录
- **WHEN** `implicit.stat_1571797746` 出现在腾讯国服 3.29 目录中
- **THEN** 它仍保留在目录和覆盖审计中，但不进入解析候选、可信模型或官方请求

#### Scenario: 游戏版本变更
- **WHEN** 系统加载的腾讯国服游戏版本不再是 3.29
- **THEN** 3.29 的不可查询结论不会自动继承，该 ID 只在新版本存在独立实证记录时才被排除

#### Scenario: 官方目录刷新成功
- **WHEN** 应用取得结构有效的最新官方物品与词缀目录
- **THEN** 系统重新应用当前 Provider 和游戏版本的不可查询清单、重建等价组、原子切换到新目录，并向查价页面与浮窗公布版本、来源和记录数量

#### Scenario: 新赛季仅新增通用记录
- **WHEN** 国际服官方目录包含国服内置翻译快照尚未覆盖的新 stat ID
- **THEN** 系统保留该 ID 与真实类型，等待国服官方目录按 ID 补充 matcher，并将缺失计入本地化覆盖状态而不是删除记录

#### Scenario: 挂单使用内部币种 ID
- **WHEN** 腾讯搜索结果用 `chrome` 等内部 ID 表示挂牌币种
- **THEN** 系统使用腾讯官方静态交易目录显示“幻色石”等国服名称，同时保留内部 ID 参与统计与查询

### Requirement: 确定性消歧和聚合
系统 MUST 先使用词缀类型、物品类别、完整多行文本、词缀元数据、local/global 规则和明确的合并规则缩小候选，再排除当前 Provider 与游戏版本标记为不可查询的 ID。只有唯一有效候选、规则明确允许聚合，或剩余候选全部属于同一可信等价组且官方文案、类型、数值占位数和实际数值方向一致时，才能自动生成一条逻辑过滤项。

#### Scenario: 物品类别可消除歧义
- **WHEN** 同一文案的多个候选分别适用于武器和护甲且当前物品类别已知
- **THEN** 系统自动选择适用于当前类别的候选

#### Scenario: 多条来源贡献同一可合并属性
- **WHEN** 多条同类型词缀按官方语义共同贡献同一个可查询属性
- **THEN** 系统显示一个聚合过滤项并使用可追溯的合计数值

#### Scenario: 剩余候选属于同一等价组
- **WHEN** 所有上下文规则执行后仍有多个候选，但它们属于同一等价组且数值方向一致
- **THEN** 系统生成一条逻辑词缀及可信 `queryVariants`，浮窗只显示一行、一个勾选状态和一组最小/最大值

#### Scenario: 排除无效项后只剩一个候选
- **WHEN** 多个原始候选中的不可查询 ID 被排除后只剩一个有效 ID
- **THEN** 系统按普通单一 stat 处理并不再要求用户选择

#### Scenario: 上下文仍不能唯一确定
- **WHEN** 所有确定性规则执行后仍保留多个合法 stat ID，且它们的官方文案、类型、数值占位数、实际数值方向或等价组不一致
- **THEN** 系统不得猜测、不得强制合并，并将全部合法候选交给用户选择

### Requirement: 可量化的覆盖验收
系统 MUST 提供可重复执行的覆盖审计，证明结构有效的官方 stat 记录均被保留，报告国际服通用 ID 与国服本地化 ID 的差异、同文案重复组、等价组和按版本标记的不可查询记录，并 SHALL 通过涵盖装备类别、词缀类型、复合词缀和歧义词缀的当前格式及真实国服剪贴板语料回归。

#### Scenario: 官方目录覆盖审计
- **WHEN** 开发版对一份官方 stats/items 响应执行覆盖审计
- **THEN** 报告有效记录总数、保留数、自动唯一映射数、歧义候选数、重复组数、等价组数、当前版本不可查询记录数和拒绝原因，且静默丢弃数为零

#### Scenario: 固定国服目录回归
- **WHEN** 对当前固定腾讯国服数据重复执行目录生成和覆盖审计
- **THEN** 系统确定性产生相同的同文案重复组、等价组、成员顺序和当前版本不可查询记录

#### Scenario: 国服物品语料回归
- **WHEN** 回放覆盖普通、魔法、稀有、传奇、未鉴定、腐化、破裂、工艺、附魔、地图、药剂、珠宝、武器和护甲的代表性剪贴板文本
- **THEN** 每件官方可查物品都能形成有效查询，每条交易词缀均处于自动映射、自动等价分组或可选择候选状态

#### Scenario: 当前国际服参考格式回归
- **WHEN** 回放当前仍在维护的国际服查价器已覆盖的普通 `(fractured)` 与详细 `Fractured Prefix/Suffix Modifier` 格式
- **THEN** 系统自动恢复 fractured 类型且不要求用户选择词缀类型
