## Context

手动做装会话已经维护底材、物品等级、稀有度、前后缀、元工艺标志、固定随机种子和历史。内置 schema v4 快照包含 743 条显式工艺台定义，并通过各词缀目标的 `craftedOptions` 提供效果、物品等级、适用类别、成本和解锁位置；目前这些数据只被旧优化器和三级词缀目录读取。

工艺台与随机通货不同：普通工艺是确定性添加；只有一条现有工艺时，新工艺可以连同额外一枚重铸石自动替换它；多大师允许最多三条工艺且自身计数；元工艺既是实际前后缀，又改变后续随机动作。实现必须复用同一份状态，不建立第二套“页面假装备”。

## Goals / Non-Goals

**Goals:**

- 从真实快照为当前底材生成唯一、可解释的工艺台动作目录。
- 准确模拟普通工艺、五种元工艺、单工艺替换、全部移除、词缀位和 Mod Group 规则。
- 工艺结果进入与通货和精华相同的装备状态、固定种子和历史链。
- 页面在执行前展示实际效果、成本、额外替换成本、解锁位置和不可用原因。

**Non-Goals:**

- 不记录玩家是否已经解锁配方；解锁位置仅作为说明。
- 不扣减库存、不查询价格，也不计算自动制作路径。
- 不模拟插槽、连接、颜色、品质、附魔、地图装置或腐化装备的瓦尔石附加成本。
- 本阶段不扩展花园、野兽、化石、庄园或背叛工艺。

## Decisions

1. **目录以 `modifier.craftedOptions` 为权威效果映射。** `crafts` 表能给出工艺定义，但只有 `craftedOptions` 同时绑定 Mod Group、前后缀和具体数值。目录先按当前底材 profile、类别和物品等级过滤，再以 option ID 去重；五种元工艺和移除动作单独注入。相比直接展示全部 748 条 bench craft，这能排除插槽类和无法映射为显式词缀的记录。

2. **普通工艺和元工艺都通过动作提供器写入规范化 affix。** 手动服务负责替换预处理和历史封装，动作提供器负责最终合法性及写入。这样旧优化器与新手动页面共享词缀位、工艺数量和 Mod Group 约束，不复制规则。

3. **词缀容量按当前稀有度计算。** 魔法物品每侧最多一条，稀有物品使用底材的每侧上限；对普通物品添加首条工艺后变为魔法。此修正同时约束增幅石等已有动作，消除魔法物品出现两个同侧词缀的旧漏洞。

4. **替换是显式的状态转换。** 仅当物品恰有一条未破裂工艺词缀且未启用多大师时，目录在移除旧工艺后的临时状态上判断新工艺，并把额外一枚重铸石加入展示成本和历史。多条工艺、破裂工艺或不可修改状态不做隐式替换，用户必须选择移除动作。

5. **元工艺由实际词缀和派生标志双重表示。** 锁后缀是前缀，其余四项是后缀；应用时写入完整可展示 affix 并设置对应 `state.meta` 标志。移除或替换工艺后，从剩余元工艺 affix 重新计算标志，避免残留布尔状态。

6. **目录和所有会话响应一起刷新。** 创建、通货、精华、工艺台、撤销、重做和重置响应都返回 currencies、essences、benchCrafts，保证禁用原因与当前装备状态同源。

## Risks / Trade-offs

- [POEDB 类别名称与内部 itemClass 不同] → 复用当前三级目录已经验证的 `categoryPath`/`itemClass` 匹配，并对 951 个底材做未映射审计。
- [同一效果在多个 profile 重复] → 先用 modifier profile 和 spawn tag 过滤，再按 option ID 去重；重复但内容不一致视为审计错误。
- [历史状态中的旧元工艺缺少完整展示字段] → 模型继续提供默认值，新的动作只写完整结构；移除逻辑以稳定 group ID 和 `metaCraft` 标志兼容旧状态。
- [工艺数据来自 `current` 快照而非确认补丁号] → 继续显示快照时间和版本未确认警告，更新后运行真实目录审计。
