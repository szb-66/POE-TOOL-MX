## Context

自动取件的仓库归一化结果已经包含 `baseType/typeLine/width/height`，但数据仅存在于混沌配方服务快照中。自动入库 Python 脚本只能通过 Ctrl+C 得到类别和名称，逐格扫描导致多格物品入库后的剩余格被重复访问。实现必须跨 Electron 与 Python，同时保持无远程请求、旧配置兼容和失败关闭。

## Goals / Non-Goals

**Goals:**

- 在 Electron 内共享、合并并冻结可信的物品尺寸。
- 对能确定左上角的已知多格物品跳过剩余占位。
- 让未知、冲突、越界和排除格歧义自动回退逐格扫描。
- 保持连续空格提前结束、界面门禁和进度兼容。

**Non-Goals:**

- 不读取游戏进程内存或实时背包 API。
- 不根据图像边缘或剪贴板内容猜测未知尺寸。
- 不改变扫描顺序、用户配置或自动取件网络接口。

## Decisions

1. 使用 Electron 单例 `ItemFootprintRegistry` 作为共享边界。注册键由规范化类别和基底名组成；仓库 API 数据优先于内置规则，但任一键出现不同尺寸即标记冲突，快照不输出该键。相比直接让背包模块依赖混沌配方服务，这避免功能间生命周期耦合。
2. 内置目录采用带 `schemaVersion` 的 JSON，保存类别默认尺寸和少量基底例外。加载失败、版本错误或校验失败返回空目录；安装包显式携带该资源。
3. 每轮入库启动前把注册表快照放入 `inventory.itemFootprints`。Python 使用与 JS 相同的键规范化规则，不在运行中读取磁盘或网络。
4. Python 为每个扫描阶段维护 `resolvedSlots`。只有成功点击或确认黑名单，且当前格按扫描历史可安全视为左上角、矩形完全位于当前阶段并不涉及更早排除格时，才登记矩形。
5. 跳过格仍执行用户停止、前台和界面门禁，计入 `scannedSlots` 和新增 `skippedOccupiedSlots`，并清空连续空格候选；不执行鼠标、剪贴板或点击。

## Risks / Trade-offs

- [内置类别规则无法覆盖新赛季特殊物品] → 未命中时逐格扫描，后续仓库 API 快照可动态补充。
- [同名物品在不同上下文尺寸不同] → 冲突键整轮禁用优化，不选择任一尺寸。
- [排除格遮住真实左上角] → 检测所有可能更早锚点；存在排除格即不登记占位。
- [占位资源损坏导致启动失败] → 资源校验失败只记录警告并使用空目录。

## Migration Plan

- 新字段和资源均为向后兼容增量；无需迁移用户配置。
- 回滚时可移除注册表注入和 Python 跳过逻辑，旧运行配置仍有效。
