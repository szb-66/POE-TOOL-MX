## Context

当前手动制作会话一次只持有一个当前装备，但历史事件可以保存完整的附加产物快照；装备状态已经包含 `mirrored`，现有普通、特殊和污秽制作门禁也会拒绝镜像物品。卡兰德之镜不会改变原件，而是创建属性完全相同且不可再修改的副本，因此不能只把它描述成普通的原地状态变更。

## Goals / Non-Goals

**Goals:**

- 准确表达原件不变、生成镜像副本和副本不可修改。
- 复用现有单目标会话、事件、撤销/重做和预见基础设施。
- 对腐化、镜像及当前目录不支持的对象提供明确门禁。

**Non-Goals:**

- 不建立完整仓库或多装备持有系统。
- 不支持传奇、地图、药剂、技能宝石等当前底材目录之外的对象。
- 不实现镜像服务费用、Reflective Oil 或其他明确允许修改镜像物品的例外。

## Decisions

### 1. 当前目标切换为副本，事件保留原件

卡兰德之镜执行时先深克隆当前 state 与 variant 作为 `sourceItem`，再以相同内容创建 `createdItem` 并仅把副本的 `mirrored` 设为 true；会话当前 state 切换到该副本。相比增加库存系统，这能让用户立即看到并验证副本，同时事件仍能证明原件没有被改写。

### 2. 复制不消耗随机数

镜像是确定性复制，执行前后的 RNG 状态必须相同。希内科拉预见仍按“下一次通货修改”语义被消费，预览显示镜像副本结果。

### 3. 通过专用 Provider 和通用事件扩展实现

动作注册仍使用 `currency:mirror-of-kalandra`，Provider 负责门禁和把当前 state 标记为副本；手动通货执行器识别该动作并附加原件/副本快照、切换稳定物品 ID。历史记录沿用现有 state、variant 和辅助状态快照，无需新会话字段。

### 4. 门禁以当前可验证对象范围为准

目录中的底材均为可装备非传奇对象，因此运行时明确拒绝腐化和镜像状态；若未来引入 `unique` 稀有度或非装备底材，应由同一规则继续拒绝。Split、势力、破裂、综合和附魔不是镜子的禁用条件，均按原样复制。

## Risks / Trade-offs

- [单目标会话不能同时继续制作原件] → 事件保存完整原件快照并明确当前目标已切换为副本；未来库存系统可消费该结构。
- [普通事件摘要可能把复制写成“修改”] → 为镜子提供专用摘要和 `sourceItem`/`createdItem` 字段，界面单独展示。
- [部分旧动作只检查自身稀有度而未检查镜像] → 使用现有公共门禁测试覆盖全部可执行目录，发现遗漏时只修正共用门禁，不增加逐动作补丁。
