## Context

参见 proposal.md。点金石操作同时出现在 Vue 预设、启动通货清单、JavaScript 脚本生成逻辑和两套 Python 模板中；固定通货坐标又是配置引导、预检和失败恢复的共享边界。当前工作区在这些模板中已有其他未提交修改，实现必须采用局部补丁保留现有工作。

## Goals / Non-Goals

**Goals:**

- 用一个明确的有效通货选择贯穿界面、预检、正式点击和消耗统计，避免清单与实际点击分叉。
- 对旧预设和现有混沌石模式零行为变更。
- 继续使用现有通货预检和配置失败链路。

**Non-Goals:**

- 不为高阶点金石新增独立制作模式。
- 不改变做装模拟器的通货规则或成本估算。
- 不让混沌石模式使用高阶点金石。

## Decisions

1. **持久化字段与现有预设结构对齐。** 物品使用 `moduleTwo.enableBinding` 布尔字段，地图/海图使用 `binding.enabled` 对象。两个规范化器都对缺失字段补 `false`；这符合物品 `enableRegal` 和地图 `exalted.enabled` 的现有风格。
2. **通货身份使用 `binding`。** 它作为坐标键、脚本事件键和消耗账本键，中文显示名统一为“高阶点金石”。不复用 `alchemy` 坐标，因为预检需要对完整名称和实际物品做一对一校验。
3. **在生成器中求出单一有效点金通货。** 物品制作逻辑仅当 `mode === 'alchemy' && enableBinding` 时使用 `binding`；地图模板在运行配置中得到同样的有效键。清单构建使用相同判定，保证预检集合与可达点击分支一致。
4. **通货目录和图标作为完整支持的一部分。** 在共享目录中增加 `binding`，并提供本地 PNG，使消耗账本不会丢弃已成功使用的高阶点金事件。

## Risks / Trade-offs

- [高阶点金石坐标未配置导致运行中断] → 将其加入现有配置问题与启动前只读预检，在任何正式点击前失败。
- [清单使用 `binding` 但某个点金分支仍硬编码 `alchemy`] → 通过脚本生成测试和模板状态机测试覆盖初次点金、重铸、基底失败和词缀失败路径。
- [工作区的现有模板修改被覆盖] → 只对通货映射和点金调用做小范围补丁，验证最终 diff 不包含无关回退。

## Migration Plan

- 规范化器为缺失字段提供关闭默认值，无需一次性存储迁移。
- 新坐标随环境默认值添加为 `(0, 0)`，只在对应预设启用时要求用户配置。
- 回退时关闭开关即可恢复普通点金流程；保留的额外坐标不影响旧版读取。
