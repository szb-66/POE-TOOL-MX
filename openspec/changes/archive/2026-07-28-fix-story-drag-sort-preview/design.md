## Context

剧情编辑页对章节、步骤和技能组各维护一组拖拽 ID，并在放置时调用 `reorderItemsById(items, movedId, targetId)`。该函数删除源项后仍使用删除前的目标索引，导致前后移动的插入语义不对称；视图只在目标卡片底部画线，也无法预告真实落位。页面存在深度监听并自动保存，因此拖动预览不能直接修改 store。

## Goals / Non-Goals

**Goals:**

- 三类列表使用相同的最终索引语义。
- 卡片在拖动期间实时让位，成功放置只保存一次。
- 取消拖动不会污染 store 或持久化数据。
- 保持对象引用、当前选中 ID 和表单编辑行为不变。

**Non-Goals:**

- 不增加单个技能排序。
- 不引入第三方拖拽依赖或修改剧情存储结构。

## Decisions

1. **排序工具接收最终索引。** 工具先解析稳定 ID，再将目标索引限制到有效范围，删除源对象后按最终索引插入。相比目标 ID，该接口直接描述最终结果，不受移动方向影响。

2. **预览顺序只保存 ID。** 拖拽开始时复制源列表 ID；拖过卡片时通过指针与卡片垂直中点判断前后插入槽，并更新预览 ID。渲染时按 ID 映射回 store 中的原对象，因此 `v-model` 和对象身份保持不变。

3. **预览与提交分离。** `dragover` 只改变组件临时状态；`drop` 从预览顺序读取拖动项最终索引并调用 store 一次。`dragend` 未提交时仅清理临时状态，原列表自然恢复。

4. **使用统一拖拽控制器。** 控制器保存列表类型、拖动 ID、预览 ID 和是否提交，三类列表共用开始、预览、放置、清理逻辑，类型分支只负责读取列表和调用对应 store 方法。

5. **卡片指针不覆盖内部控件。** 卡片使用 `cursor: pointer`，抓手继续使用 `grab/grabbing`，Element Plus 输入框、文本域和按钮沿用自身样式。

## Risks / Trade-offs

- [实时重排后鼠标下方 DOM 节点改变，可能重复触发 dragover] → 仅在计算出的 ID 顺序变化时更新状态，并基于当前预览顺序重新计算。
- [在列表外结束拖动没有 drop] → 由抓手 `dragend` 统一清理，且预览从未修改 store。
- [页面深度监听可能保存预览] → 预览只存在组件本地 ref，store 仅在 drop 时改变一次。
