## Context

Electron 的默认 `userData` 名称在开发启动和打包启动之间可能变化，因此应用需要显式固定一个唯一目录。项目不再承担旧目录与旧格式兼容。当前剧情抓手位于已经调用 `setIgnoreMouseEvents(true)` 的内容窗口内，Windows 命中测试把鼠标交给下层游戏/桌面，DOM 的进入事件无法可靠地解除穿透。

## Goals / Non-Goals

**Goals:**

- 开发版和正式版永久使用同一个具名用户数据目录。
- 只读写 `%APPDATA%/流放助手` 下的当前格式，不识别或导入旧数据。
- 内容浮窗始终穿透，仅一个小型原生抓手窗口接收鼠标并可靠拖动。
- 数据目录选择和拖动逻辑可测试、可重复执行。

**Non-Goals:**

- 不迁移、解析、合并或删除任何旧目录数据。
- 不改变剧情数据模型和页面编辑能力。

## Decisions

1. 主进程在创建任何窗口前把 `userData` 固定到 `appData/流放助手`。不增加版本子目录、迁移标记、旧来源域快照或渲染层导入步骤。
2. 删除旧 `Electron` 目录识别、文件复制、LevelDB/Snappy 解析和 LocalStorage 兼容导入代码，只保留 Electron 当前格式的原生读写路径。
3. 内容浮窗永久保持 `setIgnoreMouseEvents(true, { forward: true })`。另建 52×20 的透明无框抓手 BrowserWindow，抓手本身不穿透并使用 `-webkit-app-region: drag`。主进程维护独立于原生窗口读数的规范尺寸（配置宽度与内容测量高度）；拖动期间根据抓手位置和规范尺寸生成完整 bounds 并一次性提交，不使用 `setPosition`，也不把 Windows 在非整数 DPI 缩放下取整后的宽高反馈为下一次状态。只有配置宽度或内容高度变化时才更新规范尺寸。
4. 抓手窗口与剧情内容窗口共同显示、隐藏和销毁；只持久化内容窗口坐标，避免两套位置状态分叉。
5. Vite 开发服务器固定监听 3000 并启用 `strictPort`。Electron 始终加载 `http://localhost:3000`；若端口被占用，开发启动器打印可操作提示并退出，禁止自动递增端口产生新的 LocalStorage origin。

## Risks / Trade-offs

- [旧数据不会自动出现] → 这是明确取舍；新版本只维护一份新格式数据，旧目录完全忽略。
- [非整数 DPI 缩放把 `setPosition` 的坐标边界取整为不同 DIP，导致每次移动增加 1 像素] → 尺寸由配置和内容测量构成唯一规范状态；拖动原子提交完整 bounds，系统返回值只用于当前位置和持久化，不再进入尺寸计算。
- [抓手在显示器边缘越界] → 根据内容窗口和当前显示器工作区限制抓手与内容的最终位置。
- [3000 端口被旧进程占用时无法启动] → 明确报错并要求关闭旧进程；这比静默打开一份空 origin 更安全。

## Migration Plan

无迁移。首次启动直接创建或使用 `%APPDATA%/流放助手` 当前格式目录。
