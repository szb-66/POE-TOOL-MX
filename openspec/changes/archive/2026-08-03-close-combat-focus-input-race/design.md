## Context

现有自动喝药循环在每轮开始检查一次前台，随后读取像素、判断阈值并发送整组按键。回城流程也只在发送开门键前检查一次，等待后直接移动鼠标和点击。Windows 前台窗口可在这些步骤之间切换，因此检查结果不能作为后续输入的长期授权。

## Goals / Non-Goals

**Goals:**

- 将前台检查放到不可再拆分的输入动作边界，并让多键序列可在中途停止。
- 让测试通过注入焦点判断与输入发送器稳定模拟切窗，不触发真实系统输入。
- 保持自动喝药失焦暂停、回焦恢复和现有状态事件语义。

**Non-Goals:**

- 不尝试锁定 Windows 前台窗口，也不向后台窗口定向发送消息。
- 不更换现有 `keybd_event`/鼠标 API，不修改窗口标题白名单。
- 不改变药剂配置、IPC 或 UI。

## Decisions

### 1. 输入函数承担最后一道前台门禁

按键序列函数在每个按键按下前调用前台判断，并返回实际发送数量。调用方仍保留扫描前门禁以避免无效像素读取，并在发送前增加一次门禁以覆盖像素读取后的切窗间隙。相比只提高扫描频率，这能直接缩短检查到输入之间的竞态窗口，并阻止序列剩余按键。

### 2. 当前按键必须成对释放

一旦某个按键已经按下，同一输入动作会立即发送对应抬起事件；下一个按键前才重新检查焦点。这样失焦不会遗留按下状态。无法消除操作系统在一次检查与紧随其后的系统调用之间的微小调度竞态，但这是全局输入 API 下可实现的最窄边界。

### 3. 回城的键盘与鼠标阶段分别授权

开门键使用相同的受保护按键函数。等待结束后再次检查前台，只有通过后才移动鼠标；鼠标按下前再检查一次，按下后始终配对抬起。任一门禁失败都返回相同的“游戏窗口当前不在前台”结果。

### 4. 用依赖注入建立无副作用回归缝

受保护的按键与点击辅助函数允许测试注入焦点序列和记录型输入发送器。生产调用使用默认 Windows 实现。相比依赖源码正则或真实切换窗口，这个测试缝能稳定覆盖检查顺序且不会向用户桌面发送输入。

## Risks / Trade-offs

- [检查后到系统调用间仍存在极小竞态] → 将检查紧邻每个输入动作，并避免其间执行任何其他业务逻辑。
- [序列部分发送后失焦，回焦可能再次从头触发] → 只要已发送至少一个键就记录本轮触发时间，遵守原冷却，避免立即重复整组输入。
- [新增测试缝扩大函数参数] → 参数仅用于内部默认依赖和测试，不穿透配置或 IPC。

## Migration Plan

无需数据迁移。开发版通过定向测试和完整测试后生效；回滚时恢复原脚本与测试即可。
