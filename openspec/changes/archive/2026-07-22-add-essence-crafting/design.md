## Context

手动做装状态机当前只接受无参数的基础通货 ID。内置 POEDB 快照已含 1,444 条 `source: essence` 词缀，但精华物品名称和资源标识仍嵌在 `tier.name` 的 HTML 片段中，`requiredLevel` 表示保证词缀自身等级，不能直接当作精华最低使用等级。精华还具有按阶级变化的普通/稀有适用范围和低阶随机词缀等级上限。

## Goals / Non-Goals

**Goals:**

- 从每条精华阶级记录提取稳定的精华资源 ID、纯文本中文名和精华阶级元数据。
- 为当前底材列出精确的一件精华对应一条保证词缀的选项。
- 精确实现普通升级、T5+ 稀有重铸、低阶随机词缀等级上限、最低装备等级、Mod Group 冲突和元工艺禁用。
- 保持固定种子、撤销、重做、历史及 Provider 说明同源。
- 覆盖 3.28 新增的哀恸精华和已有特殊精华，不把特殊精华错误映射为普通七阶前缀。

**Non-Goals:**

- 本变更不实现精华怪物、瓦尔宝珠腐化精华怪或三换一升级配方。
- 不实现化石、花园、野兽或其他特殊制作材料。
- 不模拟传奇装备，也不允许用精华近似未被 POEDB 当前快照覆盖的底材效果。

## Decisions

### 1. 精华来源信息成为阶级结构的一部分

解析器从 `record.Name` 的锚点提取 `sourceItemId` 与 `sourceItemName`，并根据稳定英文资源前缀映射 `essenceTier`、`minimumItemLevel`、`randomModifierLevelCap` 和 `canReforgeRare`。规范化模型保存这些字段，目录和执行层只消费结构化数据。相比在 UI 中解析 HTML，这能让校验、测试和显示共享同一来源，并能在 HTML 结构异常时明确拒绝生成选项。

### 2. 特殊精华使用独立的参数化动作入口

新增 `listManualEssences` 与 `applyManualEssence(session, essenceId)`，而不是为 105 种精华注册静态 Provider。目录项本身携带 Provider 风格的说明、条件、后果和可用原因；执行前再次根据同一解析结果校验，避免客户端篡改。基础 `applyManualCurrency` 保持兼容。

### 3. 先写入保证词缀，再补充天然词缀

精华应用先清除全部可变显式词缀并重置元工艺，再把选中精华的确定阶级写入对应前/后缀。随后按现有稀有词缀数量分布补充 `source: natural` 词缀；已有保证词缀的 `groupId` 会自动排除冲突 family。保证词缀不使用生成权重，随机补充词缀才使用 POEDB 权重。

### 4. 低阶上限只影响额外随机词缀

T1–T4 分别用 `min(物品等级, 35/45/60/75)` 构造天然候选池，但保证词缀始终使用所选精华对应阶级，不受该上限过滤。T5–T7 和特殊 T8 不限制额外随机词缀等级。

### 5. 元工艺是整体禁用条件

只要装备存在任一 `metaCraft` 词缀或状态中的任一元工艺标志，所有精华选项均禁用并返回同一中文原因；不会尝试执行“锁前/锁后”保留，因为游戏中的精华不允许用于带元工艺的物品。

## Risks / Trade-offs

- [POEDB 精华名称 HTML 再次变化] → 解析器 fixture 覆盖锚点、纯文本和无法识别三种情况，无法识别时不输出可应用选项。
- [特殊 T8 精华没有普通阶级表中的最低使用等级] → 按物品描述支持普通/稀有且不施加推测的等级门槛，同时在目录标为“特殊精华”。
- [稀有词缀总数的内部概率未公开] → 继续使用现有明确标注的 4/5/6 模拟分布；保证词缀和适用限制仍为精确规则。
- [重新生成快照耗时] → schema 保持向后兼容，旧快照可加载但不提供未结构化精华动作；新快照原子替换。

## Migration Plan

1. 扩展解析器和规范化模型并添加 fixture 测试。
2. 重新生成内置 POEDB 快照，审计每个精华选项均有唯一资源 ID 和保证词缀。
3. 添加精华目录和参数化手动动作服务、IPC 与渲染 API。
4. 接入页面选择器、装备卡片、历史及帮助说明。
5. 运行真实快照流程、全量测试、生产构建和 OpenSpec 校验。

回滚时可移除精华动作入口；新增阶级字段为增量字段，不影响基础通货读取。

## Open Questions

- 3.28 新增哀恸精华的获取方式属于 Mirage 赛季机制，但其装备使用规则与其他特殊精华一致；后续版本若改变最低等级，需要从权威数据新增显式字段，而非推测。
