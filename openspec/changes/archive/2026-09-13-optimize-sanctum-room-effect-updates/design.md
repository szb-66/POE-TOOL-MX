## Context

见 proposal.md。effectLedger 目前只允许相同位置缓存；liveDriver 的 observe 与 finalizeFloor 均使用该缓存。当前房间在 capture 中被排除悬停，因此增量更新必须依赖此前快照中的可信房间详情。状态栏扫描同时产生效果与奖励。

## Goals / Non-Goals

统一观察和最终采集的效果判定，保持自动化安全检查。不推算实际资源、奖励选择或未观察的路线，不新增 IPC。

## Decisions

- 扩展效果账本的纯函数，在同位置复用之外识别可信直接推进；限定相同 scope、整轮、楼层、地图，入口到 startRoomIds 或已匹配可通行边连接的下一列。未知、回退、跨列、重置均返回需扫描。
- 只使用旧快照中同地图已观察的房间类型、痛苦和效果字段。reward、treasure 为安全类型；merchant、pact、fountain 或未知类型继续扫描。房间必得痛苦必须有明确词条 ID 与 entry 触发，正文已知而仅奖励数量缺失不妨碍效果判断。
- 使用词库匹配记录构建痛苦分类条目，保留身份和来源房间证据，按 entryId 去重，不依据规划结果触发。先确认房间与新增痛苦，再统一检查已有状态和待追加状态的触发条件；机制未知时实际扫描，不以计算未知推断效果不变。
- 喷泉事件、购买事件及购买后移除、恩赐获取转换、楼层或楼层首领到期均不阻止同层普通安全房复用。获得痛苦的转换或随机追加仅在有新增痛苦时扫描；次要痛苦免疫仅检查新增次要痛苦。房间倒计时、战斗次数、复活、每房随机及未知机制仍扫描，不假设宝藏房没有战斗。
- 统一决策返回 snapshot、mode 和原因，保留旧复用函数作为兼容入口。驱动在观察和最终采集使用相同决策，进度说明重读原因，effectScan.scanReason 保留该次重读依据，不将其作为识别失败。手动请求清空基线，完整基线缺失继续扫描。
- 推导账本设置 updateMode（reuse / append）、effectBinding 与来源信息；binding 继续表示实际状态栏观测位置，奖励保持此绑定。无新截图时不伪造新状态栏目标。将账本转为展示快照的逻辑共用，最终采集更新作为下一次推进依据的房间快照。
- 手动重读清空账本沿用现有机制；扫描成功替换全部推导状态。保存仍只用于历史展示。

## Risks / Trade-offs

- 房间字段缺失或特殊效果可能在本房间触发 → 保守扫描，不把未知当无效果；仅限其他场景的条件不阻止复用。
- 旧图片与新位置混淆 → 保留原始证据绑定，为追加条目标注房间来源。
- 奖励房跳过扫描后奖励不更新 → 保留手动读取，不将旧奖励观测改绑。

## Migration Plan

无需数据迁移；旧快照缺少增量所需证据时扫描。开发版测试与验证，不打包。回退仅恢复位置变化时扫描即可。
