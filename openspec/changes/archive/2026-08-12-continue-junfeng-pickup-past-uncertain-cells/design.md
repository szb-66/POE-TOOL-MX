## Context

君锋镇 manager 当前在生成 Python 配置时强制启用“遇任意不确定格则整轮中止”。共享取件脚本已支持另一种安全路径：保留不确定格统计，但只处理高置信候选，并在每次点击前再次高置信复检。

## Goals / Non-Goals

**Goals:**

- 复用已有的“跳过不确定格”执行路径，避免个别模糊格放大为整轮失败。
- 保留现有自动操作的全部安全门禁和可观测统计。
- 将标题匹配限定为按钮显示和启动前校验，避免鼠标悬浮属性弹窗遮挡标题后误停正在执行的取件。

**Non-Goals:**

- 不调整模型、高置信门槛或本机校准相似度。
- 不改变空闲态按钮的标题检测规则、转移确认或失焦中止逻辑。

## Decisions

### 仅改变君锋镇运行配置的不确定格策略

将君锋镇写入脚本的整轮中止开关关闭，复用脚本已存在且已被普通仓库运行级测试覆盖的跳过路径。这是共享执行模型的最小根因修复，无需改写 Python 候选筛选或点击循环。

备选方案是降低模型门槛或对 `uncertain-cells` 特殊重试。前者会增加误点击风险，后者增加时序复杂度且仍可被稳定低置信格阻塞，因此不采用。

### 用运行级回归测试锁定安全边界

回归用例同时注入一个高置信候选和一个不确定格，并断言只发生一次候选点击、流程完成且事件仍报告不确定格数。同时更新 manager 配置契约，防止未来恢复整轮中止。

### 标题匹配只作为启动门禁

公共标题检测继续决定普通仓库与君锋镇按钮的空闲态显示，并由 manager 在启动前校验对应界面。自动化进入运行态后，manager 和 Python 点击循环不再消费标题匹配结果，也不再为逐件匹配标题反复移动鼠标；控制浮窗锁定当前运行模式，直到完成、用户停止或运行安全条件失败。

执行期间仍在移动、截图和点击前检查游戏前台，并保留候选逐格复检、来源清空确认和自动化互斥锁。这样修复的是标题模板被物品属性弹窗遮挡的根因，而不是放宽会产生错误输入的安全边界。

## Risks / Trade-offs

- [低置信格可能是高亮大型物品的部分占格] → 低置信格本身不会被点击；只有同物品上另一格达到高置信并通过点击前复检时才会执行一次 Ctrl+点击。
- [用户可能未取出所有视觉上高亮的物品] → 保留 `uncertainCells` 统计，不通过降低门槛换取表面完整性。

## Migration Plan

1. 更新君锋镇脚本运行配置和对应契约测试。
2. 删除正式取件与自动入库执行阶段的标题模板匹配，保留按钮检测和启动前校验。
3. 添加高置信与低置信共存、标题匹配器不得进入执行路径及运行按钮锁定的回归测试，然后在开发版运行受影响测试与全量测试。
4. 如需回滚，恢复君锋镇的整轮中止开关和执行态标题门禁；不涉及数据迁移。
