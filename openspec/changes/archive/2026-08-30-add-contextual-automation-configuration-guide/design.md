## Context

见 proposal.md。现有启动校验由多个工具函数、store、页面与 Electron 管理器分别执行：部分返回字符串，部分返回字符串数组，仪表盘还会因配置问题直接禁用启动按钮。制作与地图预检已经在 Python 事件中携带通货、期望值、实际值和坐标，但没有稳定的失败分类；制作浮窗也无法安全请求主窗口打开具体配置流程。

配置仍由现有 Pinia/localStorage 与 Electron 设置接口持久化。坐标、区域、模板和按键的抓取流程包含窗口最小化、DPI 与前台安全约束，必须复用而不能在引导中另造一套状态或输入路径。

## Goals / Non-Goals

**Goals:**

- 用一个稳定、可测试的问题模型描述全部游戏交互动作的阻塞配置，并让所有入口在产生副作用前共用门禁。
- 复用原配置组件和持久化目标，在应用级弹窗内完成配置、持续重检并显式继续原动作。
- 用结构化失败上下文连接运行错误、辅助浮窗和主窗口中的定向纠错，同时维持手动安全重试。
- 保持既有配置数据、错误字段、快捷键兼容行为和自动化安全门禁。

**Non-Goals:**

- 不制作应用启动时的强制向导，不覆盖纯资料或离线工具。
- 不把游戏前台、网络、剪贴板、服务忙、当前无识别结果等临时状态伪装成配置问题。
- 不重构自动化脚本主体、持久化格式或账号认证协议，不进行打包或发布。

## Decisions

### 1. 使用稳定问题对象并保留旧文本适配

新增 `ConfigurationIssue`，最少包含 `id`、`moduleId`、`actionId`、`kind`、`title`、`message`、`editorId`、`state` 与 `blocking`。`state` 使用 `missing | invalid | suspect`；运行纠错可强制加入已有非空值的 `suspect` 项。新增 `ConfigurationCheckResult`：`ok`、`issues` 和由问题消息派生的 `errors`，旧调用在迁移期间继续读取 `isValid/errors` 或字符串包装器。

问题 ID 使用稳定命名空间，例如 `currency.wisdom`、`inventory.grid`、`template.stash-title`、`combat.potion.life.position`。显示文字仅用于界面，不参与分派。相比继续扩展文本错误，这能避免文案变化破坏纠错；相比把 Vue 组件写进问题对象，纯数据对象也能安全测试和跨边界校验。

### 2. 按动作集中收集问题并在最外层执行安全门禁

配置注册表以 `moduleId + actionId` 选择 collector，collector 从当前 store/config 构造问题。制作和地图直接复用现有通货 preflight 清单作为唯一通货依赖来源，消除启动校验遗漏蜕变、重铸等条件通货的差异。

主渲染进程使用 `runWithConfigurationGuide` 风格的控制器保存本地待执行函数；若无问题立即执行，有问题则打开弹窗。继续按钮重新调用 collector，只有最新结果为空才以单飞锁执行一次函数。函数不进入 Pinia 持久化或 IPC，关闭弹窗即丢弃。全局快捷键、详情页和仪表盘都调用同一受保护动作，而不是只在按钮层提示。

### 3. 以共享编辑器注册表复用真实配置流程

应用壳挂载单个配置引导宿主。原设置页和模块页中的坐标、背包网格、模板区域、战斗按键、账号赛季、仓库页/网格与拼图区域交互拆成可复用编辑器，仍直接读写原 store 或调用原 Electron 抓取接口。问题只携带 `editorId` 与非敏感 props，由本地白名单注册表选择组件。

弹窗按问题卡片展示并聚焦首项或指定项；每次成功保存后重新收集问题。已在本会话完成的项保留完成标记，新增依赖立即出现。复杂编辑器可保持原模块的分组交互，但不得复制另一份持久化状态。

### 4. 明确区分配置阻塞与临时运行状态

注册表覆盖当前动作真实必需的坐标、区域、模板、按键、账号、赛季、仓库页和模式选择。当前识别结果、方案、网络、目录加载、游戏前台、自动化占用和剪贴板可靠性属于临时状态，继续沿用现有错误/禁用语义。查价快捷键保持可空，因为现有契约允许模块启用但不注册快捷键。

仪表盘与功能页只取消“因配置问题而禁用”的按钮；忙碌、冲突或运行中仍禁用。禁用入口改为点击后进入门禁，确保新用户能触发引导。

### 5. 运行纠错依赖失败码和问题 ID

制作与地图 Python 预检事件在现有字段之外增加 `failureCode` 和 `configurationIssueId`。坐标未配置、复制成功但位置为空、识别到其他通货属于可纠正失败；剪贴板序列不可用、复制失败、鼠标移动失败或游戏失焦不附配置问题 ID。其他 Electron 管理器和 store 使用相同结构返回可纠正配置错误。

主界面错误面板直接打开引导；辅助浮窗通过 preload 请求主进程。请求 `GuideRequest` 只包含白名单化的 `moduleId`、`actionId` 与 `focusIssueId`，不包含回调、凭证、配置内容或任意路由；强制显示的可疑项由主渲染进程根据受信任请求在本地构造。

### 6. 浮窗到主窗口采用白名单 IPC 和停止态交接

新增配置引导 IPC 仅接受已识别的应用浮窗 sender。主进程校验模块、动作、问题 ID 的允许组合后恢复/聚焦主窗口，并向主渲染进程发布打开请求；主界面内部请求不经过 IPC。未知 sender 或值返回通用拒绝，不回显敏感请求内容。

从制作浮窗进入纠错时，来源上下文只用于“返回浮窗”。完成配置不会调用重试；浮窗保持异常停止、账单、目标与恢复检查点。用户手动点击既有重试后才重新加载设置并执行完整启动校验和通货预检。

### 7. 保持数据与协议向后兼容

不修改现有 localStorage/Pinia 字段或模板文件位置。旧验证返回值在调用迁移期间由新问题列表派生；旧 Python 事件消费者继续使用原事件名和字段。新字段只增加信息，未知字段可忽略。账号凭证始终留在既有认证流程，不进入问题对象、IPC、日志或诊断。

## Risks / Trade-offs

- [共享编辑器拆分触及多个页面，容易产生状态双向同步差异] → 编辑器直接绑定原 store/保存函数，先为共享逻辑补单元测试，再替换原页面调用，禁止复制默认值和保存分支。
- [模块校验目前分散，迁移时可能出现入口漏接] → 建立动作清单与表驱动测试，逐一覆盖仪表盘、详情页、快捷键和浮窗入口；保留 Electron/Python 最末端安全校验作为纵深防御。
- [把临时错误误判为配置问题会误导用户] → 只有明确失败码和白名单问题 ID 才显示纠错入口，绝不解析中文 reason。
- [另一个进行中的 OpenSpec 变更正在修改海图边缘测试] → 本变更使用独立工件和新测试文件，不修改或暂存现有顺时针识别文件；最终按路径复核差异。
- [一次覆盖多个模块导致界面改动较大] → 核心控制器和问题模型先落地，模块采用统一注册表逐项接入，每完成一组即运行针对性测试。

## Migration Plan

1. 创建问题模型、注册表、控制器和兼容适配，保持现有入口行为可用。
2. 引入应用级弹窗与共享编辑器，先接入制作/地图验证，再按模块清单接入其余入口。
3. 增加结构化运行失败与受限浮窗 IPC，最后切换配置型禁用按钮为可引导动作。
4. 在开发版完成针对性、全量、构建和严格 OpenSpec 验证；不执行打包。
5. 若需回滚，移除新引导宿主与门禁调用即可恢复旧文本错误路径；持久化数据无需回滚。
