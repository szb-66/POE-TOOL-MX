## Context

覆盖层设置当前只保存 `backgroundPath`，空路径直接回退到内置背景；文件选择 IPC 会复制到 `userData/backgrounds`，但拖拽没有安全取得本地路径和复用导入逻辑的入口。设置存于 LocalStorage，背景二进制文件必须继续留在稳定 userData 中。

## Goals / Non-Goals

**Goals:**
- 用显式模式消除空路径的双重含义，并兼容旧设置。
- 让选择与拖拽经过同一主进程验证和复制边界。
- 保持个人配置、背景文件与源码仓库隔离。

**Non-Goals:**
- 不改变遮罩透明度、模糊参数或历史上限。
- 不删除已经复制但从历史中移除的背景文件。
- 不进行安装包构建或旧用户数据目录迁移。

## Decisions

1. `overlaySettings` 增加 `backgroundMode`，规范化规则为：合法显式模式优先；无模式且路径非空为 `custom`；否则为 `default`。`none` 与 `default` 不依赖路径，历史记录单独保留自定义选择。
2. 文件对话框与拖拽分别提供选择入口，但都调用主进程的同一个导入帮助函数。主进程以白名单扩展名、文件状态和真实本地路径为信任边界，成功后才复制并返回目标路径。
3. preload 使用 Electron `webUtils.getPathForFile` 将拖入的 DOM File 转成本地路径，不暴露任意文件读取能力；删除没有对应 IPC handler 的旧桥接方法。
4. 覆盖层依据模式决定渲染：`default` 使用内置资源，`custom` 使用路径并按扩展名选择图片或视频，`none` 不产生媒体背景；遮罩层始终独立渲染。
5. 设置页背景文件区域承担 drop zone，阻止浏览器默认打开文件；仅在成功导入后提交设置和历史记录。

## Risks / Trade-offs

- [同一文件重复导入会产生多个副本] → 保留现有时间戳命名，历史按目标路径去重，避免改变已有文件生命周期策略。
- [损坏但扩展名合法的媒体文件可能导入成功] → 由预览加载错误提示/隐藏处理，本次只保证类型与本地文件边界。
- [旧设置可能包含非法显式模式] → 统一规范化为根据路径推导的安全模式。

## Migration Plan

首次加载旧设置时在内存中推导模式；下一次保存会写入新字段。回滚旧版本时其仍可读取 `backgroundPath`，因此不需要破坏性迁移。
