## Context

repository 已保存 lastCapture，但 service 的 routeResult 和 overlayResult 仅存在内存；加载会撤销实时身份，页面摘要和资源又依赖该身份。见 proposal.md。

## Goals / Non-Goals

恢复展示与配套路线，复用原子存储及标题检测。不做增量续扫、多存档或自动操作，不恢复截图证据。

## Decisions

- 在现有 JSON 增加可选保存结果，独立校验快照，旧格式无需迁移。通过 service 的统一保存方法携带路线和悬浮结果，避免仅某一种保存入口覆盖数据。
- 路线快照附带计算时状态，最新采集快照单独保留。恢复标识仅用于展示；活动 floor 仍撤销身份、资源和账本撤销实时 key，历史资源保留其来源 key 供展示匹配。
- 悬浮快照仅保存 clientBounds、mapRegion 和所需环境尺寸/DPI，清除截图和证据引用；实时标题检测决定可见性。复用现有末房清除逻辑，并持久化清除结果。
- 恢复不刷新保存时间；真实新结果更新保存时间。重置清空所有结果。页面分别展示最近状态和配套路线，不使用历史结果启动计算。

## Risks / Trade-offs

- 游戏内进度可能变化 → 标注保存来源与时间，手动采集更新。
- 可选快照损坏 → 验证楼层和推荐引用，独立忽略损坏部分，不让配置加载失败。
- 显示环境改变 → 隐藏保存悬浮标记，提示重新采集，保留页面结果。

## Migration Plan

新增可选字段兼容已有 schema；不从旧决策历史猜测缺失路线。运行定向和完整测试、Vite 开发转换及开发版验收，不打包。
