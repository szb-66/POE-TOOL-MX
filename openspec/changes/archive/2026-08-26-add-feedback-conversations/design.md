## Context

参见 `proposal.md`。现有 Electron 主进程以持久化设备 ID 换取匿名会话，只能向 `app_feedback` 插入记录；渲染进程通过主窗口受限 IPC 提交内容和附件。新能力需要同时扩展 PostgreSQL、PG Storage、主进程服务、IPC 和 Vue 页面，并与私有后台共享同一数据库迁移契约。

## Goals / Non-Goals

**Goals:**
- 让安装级匿名身份只读本人反馈安全字段，并可追加受限的用户消息。
- 保持令牌、管理字段和对象 key 在主进程边界内，确保附件失败可回滚。
- 让旧反馈无需数据回填即可作为会话根消息参与新界面。

**Non-Goals:**
- 不提供跨安装身份恢复、账户体系、推送、轮询、未读回执、消息编辑或删除。
- 不改变管理员处理状态，也不把处理状态返回桌面端。
- 不在本变更中打包或验证安装程序。

## Decisions

1. **原反馈保持根记录，后续消息使用独立表。** `app_feedback_messages` 使用 UUID 主键、反馈 UUID 外键、`author_role`、正文、附件 JSON、`submitter_uid`、`client_message_id`、服务端时间和 schema 版本。相比把消息 JSON 追加到原记录，独立行便于 RLS、限流、排序和幂等唯一约束；相比回填根消息，不复制旧数据可避免迁移风险。
2. **通过列级授权与 RLS 开放最小读取。** 匿名身份只能选择本人反馈的编号、类型、标题、描述、原始附件和创建时间；状态、联系方式、环境明细和 UID 保持不可读。消息行复制父反馈的提交者 UID，并由安全函数/触发器验证父子归属，避免客户端伪造 UID 或借已知反馈 UUID 越权。
3. **用户消息直写 PG，但由数据库强制作者和配额。** RLS 只允许当前身份创建 `user` 消息；安全函数执行每身份每小时 20 条、每反馈最多 200 条、正文和附件元数据校验。`(feedback_id, client_message_id)` 唯一约束提供幂等性，写请求本身不自动重试。
4. **复用现有主进程附件选择令牌和上传回滚。** 回复附件继续在主进程读取、校验文件指纹、魔数、单个和合计大小；对象路径扩展为 `{uid}/{feedbackId}/messages/{clientMessageId}/{uuid}-{safeName}`。全部上传成功后才写消息，失败按逆序删除本次对象。
5. **主进程提供分离的列表、详情和发送 IPC。** 列表只取摘要和消息聚合，打开会话时再取完整消息并生成短期下载地址，避免每次刷新签名所有历史附件。所有新 handler 复用 `assertMainWindowSender`，preload 仅暴露结构化结果，不暴露访问令牌。
6. **反馈页内使用两级视图。** 外层“提交反馈 / 我的反馈”保留现有表单和诊断流程；提交成功后切到新反馈对话。“我的反馈”用列表加详情布局，进入时加载、按钮手动刷新，无定时器。回复提示由 `admin_message_count` 与 `last_message_author` 计算，不存未读状态。
7. **双仓库迁移保持字节一致。** `20260826090000_add_feedback_conversations.sql` 同时保存在两个仓库，私有后台 CI 是生产迁移执行源；桌面仓库副本用于客户端契约、测试与本地闭环。

## Risks / Trade-offs

- [开放本人反馈读取扩大了原只写表面] → 使用列级 GRANT、父子归属 RLS、真实匿名会话交叉身份测试，并读回策略与授权。
- [连续附件更快触达现有身份级或全局对象上限] → 保留既有限额并返回明确限制错误，不静默扩大生产存储预算。
- [附件上传后应用退出可能留下孤儿对象] → 正常失败执行回滚；对象路径和消息引用可供后续受控清理，不让孤儿对象变成可见消息。
- [当前设置页存在未提交修改] → 只编辑反馈组件和明确的 IPC/服务文件，应用前检查 staged/unstaged 差异并避免覆盖用户改动。

## Migration Plan

1. 在两仓库写入同版本、同校验和迁移，并以只读查询确认生产表、授权、策略和迁移历史没有冲突。
2. 在开发环境先应用迁移并读回表结构、唯一约束、GRANT、RLS、存储桶限制和策略；用两个匿名身份验证正反权限。
3. 实现并验证后台能力后，由后台 CI 在云函数和 Web App 发布前应用迁移；旧桌面端不读取新表，因此保持兼容。
4. 再验证开发版桌面会话与线上后台互通，不打包安装程序。
5. 若发布后需回滚应用代码，保留新增表和兼容授权；删除表或收紧授权仅通过后续显式迁移执行，避免破坏已经产生的会话数据。
