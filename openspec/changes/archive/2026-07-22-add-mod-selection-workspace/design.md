## Context

词缀目录已经按来源、前后缀、Mod Family 和具体阶级展示，并使用一个 `Set` 保存勾选 ID。该状态只驱动当前可见复选框，没有用户可见摘要；搜索会替换目录结果，因此被过滤掉的选择仍存在但不可发现。当前 45,647 个阶级 ID 经审计全局唯一，但组件仍不应把数据源的偶然唯一性当作选择模型契约。

## Goals / Non-Goals

**Goals:**

- 让所有已选具体阶级在目录筛选之外持续可见并可管理。
- 保持二级父项与三级阶级的全选、半选和单选联动。
- 让选择状态有稳定、可测试的键和快照，不依赖当前筛选结果。
- 保持手动做装定位，选中目标不触发制作或路径计算。

**Non-Goals:**

- 不计算获得目标词缀的自动制作路径、概率或成本。
- 不改变词缀目录数据结构、权重算法或制作引擎。
- 不跨底材或应用重启持久化目标选择。

## Decisions

1. 新增纯函数选择模型，用 `modifierId + tier.id` 组成稳定键。即使未来数据源的阶级 ID 规则变化，也不会让不同 Mod Family 的项互相联动。相比继续直接操作 Vue 内的裸 `Set`，该模型可以独立回归测试。
2. 组件同时保存“选择键集合”和“已选项快照 Map”。键集合负责复选框联动；快照保存来源、前后缀、Family、阶级和展示元数据，使搜索替换当前目录后仍能展示选择。相比从过滤后的目录反向推导，这不会产生不可见选择。
3. 已选目标区放在词缀目录标题与来源折叠列表之间，并明确标注“仅供手动制作对照”。每项允许移除和打开其 Family 详情，全部选择可一键清空。
4. 新建底材时清空目标；普通目录搜索不清空。底材决定合法词缀池，而搜索只是视图过滤条件。

## Risks / Trade-offs

- [已选快照在目录数据热更新后可能陈旧] → 数据更新或新建底材都会重建会话并清空选择；本变更不做跨会话持久化。
- [大量全选会占用页面空间] → 使用有限高度的滚动列表和紧凑行，顶部始终显示总数与清空动作。
- [打开已被搜索隐藏的 Family 时当前目录中没有对象] → 快照保存完整 Family 上下文，详情弹窗可直接使用快照中的 Family。
