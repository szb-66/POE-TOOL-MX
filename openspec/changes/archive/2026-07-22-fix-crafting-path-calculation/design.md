## Context

现有优化器把每个候选简化为“一次随机状态 + 固定每次成本”，并在候选内直接写入稀有度。这无法表达“首次点金，失败后才混沌”、“成功后才支付工艺台成本”等差异，也让收尾策略在没有前置状态时被伪造出来。

## Goals / Non-Goals

**Goals:**

- 用“初始成本、每次尝试成本、失败重试成本、成功收尾成本”表达循环。
- 候选模拟从真实初始状态出发，通过 Provider 完成稀有度转换。
- 工艺台元工艺真实占用后缀，并执行工艺数量、Mod Group 和槽位校验。
- 只生成数据集可证明可执行的花园候选。

**Non-Goals:**

- 本次不引入精髓、化石、爱斯林、异界崇高等新体系。
- 不在没有可验证前置状态的情况下估算崇高或元工艺收尾；这些候选暂不生成。
- 不改变用户的目标请求格式。

## Decisions

1. **扩展候选成本阶段。** 候选保存 `initialCosts`、`attemptCosts`、`retryCosts` 和 `successCosts`，期望成本为初始成本 + 尝试成本 × E[N] + 重试成本 × (E[N]-1) + 成功成本。这比在模拟中运行到成功更容易保持现有抽样与置信区间模型。
2. **基础循环的一次抽样代表一次同分布重铸。** 首次动作由蜕变/点金 Provider 执行，后续重试成本分别为改造、混沌或重铸+点金。它们的词缀分布相同，因此可共用一个成功概率。
3. **工艺台路径使用点金/重铸准备稀有底材。** 每次抽样先合法点金，只在所有目标工艺和元工艺都有槽位时才收尾；工艺成本只计入成功分支。
4. **不可证明的收尾路径宁可缺席。** 独立崇高、破裂元工艺和无数据花园路径暂停生成，避免把免费的“部分成品”当作起点。
5. **花园工艺采用严格匹配。** `effectKind`、`params.tag` 和非空成本必须同时匹配；解析器不再把插槽颜色重铸识别为显式词缀重铸。

## Risks / Trade-offs

- [候选数量短期减少] → 帮助页明确标注只显示可由当前数据执行和计价的路径。
- [旧的确定性测试数值改变] → 改为验证成本公式、排序和固定种子可复现性，更新合法的黄金值。
- [工艺台准备策略不是全局最优] → 路径名称和帮助页说明其使用点金/重铸准备，不宣称已搜索尚未实现的前置工艺。
