## Context

参见 `proposal.md`。当前物品解析器已能识别详细前后缀，但对所有 `(enchant)` 行直接跳过；无标签的星团放置说明又会在物品等级之后落入普通显式词缀。查价目录已经包含样例所需的官方 `enchant.stat_*` matcher，查询模型和浮窗也已支持 `enchant` 类型，因此不需要扩展外部接口或刷新目录。当前解析器另有势力与回忆束丝的未提交改动，实施必须保留这些内容。

## Goals / Non-Goals

**Goals:**

- 在解析边界区分有效星团附魔与纯说明文本，使后续模型只接收有查询语义的内容。
- 复用现有附魔解析、目录匹配、清理、浮窗标签和官方序列化链路。
- 用真实大型、中型样例和补充的小型样例覆盖三种尺寸与鉴定状态。

**Non-Goals:**

- 不修改交易目录、IPC、查价设置或浮窗布局。
- 不改变普通附魔、普通珠宝、星团显式词缀或物品等级的既有默认策略。
- 不打包、发布或迁移持久化数据。

## Decisions

### 在物品解析器中建立附魔与说明文本的边界

移除 `(enchant)` 后先判断正文是否为括号说明；只有非说明正文才生成独立的 `type: enchant` modifier，并保留清理后的查询文本及原始文本。星团底部放置说明使用稳定的语义模式在通用描述过滤边界排除，确保它不会进入 `explicitMods`。备选方案是在查价模型中删除未知文案，但那会让错误数据继续污染共享物品模型，只修复表象，因此不采用。

### 星团附魔使用现有 stat 管线

解析后的附魔由现有目录解析为官方 `enchant.stat_*`，不硬编码 stat ID。这样可继续使用目录 matcher、类型校验、模型清理、数值边界和浮窗“附魔”标签。备选方案是把天赋数量建模为专用物品属性，但会重复官方 stat 契约并扩大白名单，不采用。

### 自动模式启用全部星团附魔

只有确认底材为大型、中型或小型星团珠宝时，自动初选才对其有效 `enchant` modifier 全部启用；`all` 和 `none` 设置继续保持全局语义。普通物品附魔的默认选择不改变，物品等级属性仍默认关闭。

### 用底材身份限定星团专用行为

以解析后的真实底材是否属于三种星团珠宝为判断依据，而不把宽泛的“珠宝”类别都视为星团。大型、中型、小型继续使用官方物品目录中现有底材和 `jewel` 类别，未鉴定魔法星团不进入传奇候选流程。

## Risks / Trade-offs

- [国服说明文案以后调整措辞] → 使用星团放置语义的有限模式并为真实文本建立回归，不使用过宽的“珠宝槽”关键字过滤。
- [普通物品也存在 `(enchant)` 行] → 通用解析保留有效附魔，但自动全选仅限星团底材，避免改变其他物品默认查询宽度。
- [当前工作区解析器有重叠改动] → 实施前后审查局部 diff，运行势力/回忆束丝及完整测试，禁止覆盖用户现有内容。

## Migration Plan

1. 在现有解析器改动上增加附魔分类和说明过滤，再接入星团专用初选。
2. 先回放附件及针对性测试，再运行完整测试、构建和开发版 Electron 验证。
3. 无数据迁移；回滚时只需撤销本变更的解析分类、星团初选和新增测试，不影响交易目录或设置。
