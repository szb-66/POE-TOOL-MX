## Context

见 `proposal.md`。当前共享物品解析器已经识别地图阶级、地图奖励、海图区域和部分状态，但地图阶级行会进入 `baseName`，海图形状尚未解析。查价模型只有通用属性与 `map.tier`，查询构造又无条件发送地图阶级；官方物品目录转换会丢失原始分组，因而不能把 `chart` 区域记录作为可信身份使用。

腾讯国服 `/api/trade/data/filters` 当前明确提供 `map_tier`、`map_packsize`、`map_iiq`、`map_iir`、`chart_sulphur`、`chart_shape` 和 `area_level`。当前工作区有多项未提交且与查价模块重叠的用户改动，实施必须在现有状态上最小增量修改并逐项审查最终差异。

## Goals / Non-Goals

**Goals:**

- 从当前国服地图/海图详细复制文本建立不歧义、可清理、可重跑的官方查询模型。
- 让目录、解析、模型、查询和浮窗共享同一地图/海图语义，避免各层各自猜测身份。
- 保持既有装备、通货、药剂、宝石、传奇候选和价格分布行为不变。

**Non-Goals:**

- 不把第三方查价界面或代码引入项目。
- 不为官方没有字段的“更多地图/圣甲虫/通货”伪造 stat。
- 不改变海图洗练、九宫格求解或自动放置逻辑。
- 不新增打包、发布或数据迁移步骤。

## Decisions

### 1. 在共享解析结果中保留原始事实，在查价层规范化交易身份

解析器继续负责提取随机名称、传奇名称候选、物理底材、地图阶级、海图区域、区域等级、奖励值、状态、词缀和新增 `chartShape`。对地图，解析器将“地图（N阶）”只解释为阶级，并把交易底材稳定为“地图”；随机稀有名称仍可保留作诊断或展示，但查价身份构建明确忽略它。

查价层根据 `category` 建立专用身份：地图固定 `category=map`，并按官方目录将 `type` 序列化为 `{ discriminator: map, option: 地图 }`，仅已鉴定传奇使用名称；海图固定 `category=chart`，以区域目录记录的内部类型和 `chart` discriminator 构造 `type`，同时保存中文区域和物理底材供展示。这样不会把交易目录规则泄漏到通用解析器，也能从主进程可信捕获事实重建身份。

备选方案是在浮窗或查询构造阶段临时改写 `baseName`。该做法会让模型、重跑和展示看到不同身份，无法修复根因，因此不采用。

### 2. 扩充目录记录而不是维护独立运行时海图表

官方物品目录转换保留分组 ID，并为 `chart` 区域记录保存内部类型、从 `Chart（中文）` 文本提取的显示名、discriminator 与 aliases。内置目录携带当前国服详细复制所需的版本化别名；在线刷新按“内部类型 + discriminator”合并这些别名。目录校验建立规范化别名唯一索引并拒绝歧义。

首批别名至少覆盖现有真实样本的“深渊平原”“海底林地”和“海王领域”，并由固定版本输入补齐当前官方全部海图区域，而不是在查询函数中散落条件分支。

备选方案是只按官方显示名匹配。国服复制文本与交易目录已经存在“海王领域/惊海之王的领域”等差异，会使合法海图无法查询，因此不采用。

### 3. 使用带种类的白名单属性模型驱动全部过滤字段

属性记录区分数值范围与枚举选项，并由可信定义决定官方目标：

- `map.tier` → `map_tier`
- `map.quantity` → `map_iiq`
- `map.rarity` → `map_iir`
- `map.packSize` → `map_packsize`
- `chart.sulphur` → `chart_sulphur`
- `chart.shape` → `chart_shape`
- `area.level` → `area_level`
- `misc.itemLevel` → `misc_filters.ilvl`

查询构造不再从 `model.item.mapTier` 无条件写入字段，而是与其他属性一样只消费已清理且启用的属性。地图和海图身份、类别、稀有度及状态仍是独立的可信约束。普通/魔法/稀有沿用 `nonunique`；地图与海图传奇明确使用 `unique`，使无名称未鉴定传奇地图仍可安全查询。

官方不可查询奖励进入独立只读 `information` 白名单，不复用可选 `properties` 或 `stats`，避免渲染端把展示值变成请求条件。

### 4. 初始选择在模型创建时按物品域覆盖通用 T 级策略

装备继续使用现有 T1/T2 自动选择。地图与海图先完成词缀映射，再把可查询 `implicit` 基底词缀设为启用、普通显式/前缀/后缀设为关闭；用户手动修改不受影响。

地图默认启用精确阶级。海图默认启用精确区域等级、精确物品等级和存在的硫磺；形状虽能查询但按用户选择默认关闭。数量、稀有度和怪群始终初始关闭。该策略与第三方参考界面的信息层级一致，同时避免随机危险词缀把样本压缩到不可用。

### 5. 在现有浮窗组件内做条件化标签和只读信息展示

不新增第二套地图查价窗口。身份栏根据模型域显示地图名称或中文海图区域；属性网格继续使用现有整行选择和 min/max 输入，枚举形状使用受限选择控件，只读信息使用无启用交互的紧凑行。内部海图类型仅用于请求，不直接显示给用户。

## Risks / Trade-offs

- [国服海图翻译会随补丁变化] → 将别名与目录版本绑定，在线刷新保留内置别名；未知区域明确失败并可通过后续目录更新补充。
- [地图/海图专用初选可能改变现有少量地图查询结果] → 用便签七种地图和三种海图做完整查询 JSON 回归，装备自动初选另作不变性测试。
- [模型字段扩展可能被渲染进程伪造] → 主进程按捕获事实重建身份，只接受属性 ID、种类、数值和枚举白名单，忽略客户端提交的目录元数据。
- [目录 schema 扩展影响内置大文件与在线合并] → 字段采用可校验的确定性结构，生成器、加载器、在线刷新和降级路径同时测试；若实现失败可回退本变更而无需迁移用户数据。
- [工作区已有重叠改动] → 修改前后逐文件审查，禁止覆盖现有改动；若尝试失败，最终删除失败方案遗留代码再运行全量验证。

## Migration Plan

无需用户数据迁移。实现以向后兼容方式清理旧模型：旧模型缺少新属性时按现有字段重建；新字段只在本次捕获或可信模型中出现。发布回滚只需恢复代码和内置目录，持久化查价设置不变。
