## Why

S30 赛季“海图”需要玩家辨认、旋转并逐格放入九块碎片，现有“九宫格”模块只能识别仓库和展示方案，用户仍需手工完成容易出错的摆放过程。需要把识别、方案确认、自动输入和可视化验证串成一条可追踪、可停止的开发版工作流。

## What Changes

- 将所有用户可见的“九宫格”名称更新为 S30“海图”，保留内部 puzzle 路由与存储兼容。
- 增加碎片仓库 6×10 与海图区 3×3 双区域框选、持久化截图预览和显示环境有效性状态。
- 将碎片识别结果扩展为精确方向掩码和角度，并允许用户修正类型与角度。
- 增加使用当前已确认方案的自动放置：仓库内逆时针旋转、来源/目标点击、逐格截图验证、动态刷新来源和终检。
- 增加与区域对齐的鼠标穿透网格遮罩、结构化执行状态、停止入口和自动化互斥。

## Capabilities

### New Capabilities
- `atlas-auto-placement`: 海图双区域配置、自动摆放、逐格验证、实时遮罩和停止/失败行为。

### Modified Capabilities
- `nine-grid-puzzle-solver`: 将用户领域名称改为“海图”，并把仓库识别扩展为可执行所需的精确方向与人工角度修正。
- `screen-region-template-picker`: 区域选取器增加海图 3×3/仓库 6×10 实时网格提示与选区预览持久化。
- `captured-key-input`: 全局结束快捷键在海图自动摆放运行时提供紧急停止。

## Impact

- 影响海图页面、Pinia 状态、求解/来源分配、快捷键分发和用户可见文案。
- 扩展 Electron IPC/preload API、海图主进程服务、窗口管理和 Python 视觉/输入脚本。
- 复用现有 Python 运行时、自动化锁、操作延迟和透明覆盖层能力，不引入新的运行时依赖。
- 新增开发版识别、几何、自动化与遮罩测试；安装包验证不在本次范围。
