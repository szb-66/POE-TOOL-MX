## Context

现有 puzzle 领域已经包含 6×10 仓库区域、Python 截图识别、确定性 3×3 求解器、来源格分配和方案页面。识别角度主要来自绿色连通块包围盒，主进程服务只执行一次分析；项目另有自动化锁、Python 鼠标输入、透明置顶窗口和物理像素/DPI 坐标工具可复用。

## Goals / Non-Goals

**Goals:**
- 在不破坏旧仓库配置和内部 puzzle 标识的前提下形成可验证的自动放置闭环。
- 让主进程拥有区域、预览、执行计划和运行状态的可信边界，渲染层不直接传坐标。
- 在任何识别或前台异常后停止新增输入，并让用户看见确切进度。

**Non-Goals:**
- 不自动选择同分方案，不自动放宽必选出口。
- 不承诺在缺少真实 S30 多角度样本时完成视觉准确率验收。
- 不在本次执行安装包构建或发布验证。

## Decisions

### 保留 puzzle 内部名称并仅迁移用户语言
路由 `/puzzle`、Pinia id、IPC 命名和旧 localStorage 键保持不变，侧栏、页面、提示和设置统一显示“海图”。这样避免纯命名造成持久化和深链兼容风险。

### 双区域元数据在渲染层兼容持久化，预览由主进程保存
旧 `regionMetadata` 读取为 `inventoryRegionMetadata`；新增 `atlasRegionMetadata`。选取结果中的 PNG 由海图服务写入 `app.getPath('userData')/puzzle-regions` 固定文件，页面通过 IPC 取得 data URL，避免把大体积 base64 放进 localStorage。

页面预览使用选区物理宽高计算独立的等比例舞台，截图与网格共同填充该舞台。外部卡片只负责居中和留白，不能让图片使用 `contain` 后再把网格铺满整个卡片，否则纵向仓库的网格会被横向压缩并偏离图片。

### 使用方向掩码作为识别、显示、旋转和验证的统一真相
仓库视觉层先定位绿色图标，但直接在格内原始比例坐标中提取图标内部的黑色航线，并在预期交点附近对 N/E/S/W 四个方向取样、比较 15 个非空拓扑模板；禁止再把绿色发光连通块的紧包围盒非等比拉伸后用于方向判断。识别结果先产出 `mask`，再由 mask 派生类型和绝对角度；原有绿色尺寸特征只作为小权重候选先验。海图区继续从原始格内黑色航线识别拓扑，两类区域使用各自 ROI 参数。

### 主进程编排，Python 进程执行完整会话
海图服务验证区域和方案、获取 AutomationLock、管理状态和覆盖层，并启动专用 Python 自动放置脚本。脚本只接收区域元数据、九格目标、操作延迟和模板路径，自行聚焦游戏、识别当前来源、计算逆时针右键次数、输入和逐格复核，通过 EVENT 行回报状态。这样截图和鼠标输入位于同一物理坐标/DPI 上下文，停止时可直接终止子进程。

### 每步动态选择来源而不依赖初始来源坐标
方案只规定九格目标类型和 mask。每格前重新识别仓库，从当前同类型候选中稳定选择置信度最高、行列最前者；低置信度候选保留警告但仍可参与执行，放置后的海图区逐格验证作为最终安全门。

### 全新执行前要求海图为空
游戏把新碎片放入已有海图格时，会将旧碎片顶替到鼠标手上，而不是完成无状态覆盖；后续仓库点击将因此失去确定性。全新执行在任何输入前识别完整海图区，只要存在一个已占用格就以结构化错误停止并提示用户点击游戏内“清空面板”。显式续跑仍允许读取已有正确格恢复进度，因为它处理的是已知的部分执行状态。

### 新识别会话先清空旧状态
用户主动点击开始识别时，渲染层和主进程先把旧方案、格子、执行进度、错误和续跑状态恢复为初始值，再启动新截图分析。这样旧的部分完成状态不会污染一次明确的新识别操作。

### 两个区域窗口共享一个遮罩管理器
主进程为仓库和海图区分别创建无边框、透明、置顶、鼠标穿透 BrowserWindow。窗口边界使用 `screenToDipRect` 将完整物理矩形一次转换为整数 DIP 矩形，并在页面加载后再次应用；每个窗口的区域类型由自身路由固定，避免快照状态让仓库和海图互换。快照通过事件更新；识别前只隐藏当前截图区域对应的窗口，连续三次只读验证共用一次隐藏/恢复区间，捕获后 showInactive 恢复，关闭与异常路径统一清理。

### 失败重试只重读画面，不重放输入
单格输入后最多进行三次带短间隔的截图识别；失败立即结束。自动重复右键或左键可能把一次瞬态问题放大成不可恢复状态，因此禁止输入重试。

低置信度只表示保留警告；只要识别结果已经给出与目标一致的类型和方向掩码，逐格验证和终检均视为匹配。全新执行要求当前海图为空；只有显式续跑才读取当前海图恢复已完成格，避免已有内容和顶替到手上的碎片污染新一轮执行。

### 鼠标移动与点击使用统一的可靠输入时序
Windows `SetCursorPos` 成功只代表系统光标位置已更新，不代表游戏已经处理新的悬停格。真实失败现场中，来源左键后碎片仍留在仓库，随后目标格三次识别均为空，说明移动后立即发送按下和抬起会概率性漏掉来源点击。所有旋转、来源和目标点击统一执行“移动、至少 80ms 稳定等待、重新检查游戏前台、按下、至少 20ms 保持、抬起”；异常路径必须尝试抬起已按下的按键。来源点击后的 160ms 和目标点击后的 200ms 游戏状态等待继续保留，且不得用重复输入掩盖失败。

### 验证前移出目标格并隔离海图外框
游戏会对鼠标所在的海图格增加悬停高亮；真实第九格失败事件中，目标三岔被高亮稳定误识别为十字，而鼠标移开后的同一画面可正确识别。目标左键后必须先把鼠标移动到仓库和海图区之外、当前显示器以内的安全点，再执行原有稳定等待和三次只读验证；续跑时把手上碎片放回目标格后遵守同一规则。海图拓扑识别同时在形态学处理后清空每格外围保护带，避免右下角航线通过外框或角落装饰引入额外方向。两项修复都不增加点击、不重放输入，也不跳过第九格或终检。

## Risks / Trade-offs

- [真实海图区图形与仓库图形存在尺度或装饰差异] → 分离 ROI 配置、保存置信度，并以真实 S30 素材作为最终验收门槛。
- [覆盖层污染截图] → 截图入口统一经过遮罩 hide/restore 包装，并增加调用顺序测试。
- [Python 进程被强制停止时正处于点击序列] → 每个离散输入前检查停止和游戏前台，主进程终止后统一释放自动化锁；无法回滚已经成功的游戏输入。
- [Electron 物理坐标与 DIP 窗口边界不同] → 鼠标和截图始终使用保存的物理坐标，窗口显示通过 `screenToDipRect` 对完整矩形一次转换为整数边界，并测试高 DPI/负坐标，禁止拆成两个点换算后把小数边界传给 BrowserWindow。
- [方向拓扑仍可能受发光底纹、文字和动画干扰] → 仓库只在绿色图标内部检测黑色航线、保留原始比例并小范围搜索交点；使用逐格真实方向真值、显式待确认、置信度优先来源选择和放入后的三次只读验证。低置信度来源允许执行，但验证失败立即停止。
- [鼠标悬停与海图外框改变黑色连通结构] → 放置后移到显示器内的安全悬停点，海图识别清空每格外围保护带，并以真实失败数据和九格边框干扰回归固定行为。
- [游戏尚未处理新鼠标位置就收到点击] → 点击原语统一加入落点稳定等待和按键保持，并在按下前复查游戏前台；逐格失败仍只重读画面，不自动补点。

## Migration Plan

- 首次加载新版本时把旧 `regionMetadata` 作为仓库区域使用并按新字段重新保存；海图区保持未配置。
- 旧仓库截图不存在时显示坐标有效但预览不可用，用户重新框选后生成预览。
- 回滚时旧 `regionMetadata` 和内部 puzzle 路由仍可读取；新增区域与预览文件可被旧版本忽略。
