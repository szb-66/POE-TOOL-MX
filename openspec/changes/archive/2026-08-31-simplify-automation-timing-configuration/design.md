> **实施结论（2026-08-30）**：下述单字段设计已在开发版验收中失败并撤销。当前设置、持久化、跨进程载荷和 Python 时序协议均恢复 v1.2.2 模型；除非用户重新确认新方案，不再继续实施本设计。

## Context

当前时序模型横跨 Vue 设置/store、Electron IPC、自动化宿主、Python 参数、设置迁移与导入导出。用户可见配置同时包含悬停等待、自适应开关、统一超时和八项固定时序，但多个自动化消费者仍存在不受这些开关控制的等待，形成了两套并行责任。制作事务的点击后确认性能由 `rebuild-crafting-transaction-flow` 负责，本变更只定义全局配置和跨进程协议的收敛方式。

## Goals / Non-Goals

**Goals:**

- 建立唯一用户时序模型 `{ operationDelayMs }`，让所有模块共享相同含义。
- 把物理输入、结果轮询与失败超时收回到内部命名协议并接受测试约束。
- 迁移旧数据且不丢失用户已有的有效 `operationDelayMs`。
- 将自动检测输入、输出、应用和撤销都收敛为一个数值。

**Non-Goals:**

- 不移除内部安全等待、失败超时或自动化安全门禁。
- 不为不同模块建立独立延时，也不增加快稳预设或隐藏高级配置。
- 不在本变更重复设计制作通货点击后的事务证据规则。
- 不打包、安装或发布。

## Decisions

### 1. 用户时序协议采用封闭的单字段结构

持久化、导入导出、渲染到主进程以及主进程到自动化宿主的用户时序结构统一为 `{ operationDelayMs }`；Python 命令边界只接收 `operation_delay_ms`。消费者不得以透传剩余属性的方式保留旧字段。

选择封闭投影而不是仅隐藏界面，是因为只隐藏界面仍会让旧字段在保存、导出和跨进程载荷中持续成为事实契约，未来消费者也可能再次依赖它们。

### 2. 可观察结果使用内部事件驱动等待

剪贴板、画面、页签、存仓及其他具有可靠信号的动作，通过内部轮询在成功时立即继续；轮询间隔与最大失败时间为语义命名的内部常量。没有可靠信号的动作使用与动作语义绑定的内部安全边界。

未选择统一固定睡眠，因为它会把最坏情况成本施加到每次成功路径；也未保留用户自适应开关，因为结果确认是正确性责任，不应由用户决定是否启用。

### 3. 物理输入参数归属自动化协议实现

修饰键稳定、按键保持、按钮保持和释放稳定由共享输入协议的内部常量负责，消费者只调用完整输入动作，不接受这些数值作为运行时用户载荷。常量名称、用途和边界由定向测试覆盖。

未将常量删除或全部设为零，因为 Windows 输入注入和游戏消费事件仍需要安全边界；本变更删除的是用户配置责任，而不是底层可靠性措施。

### 4. 迁移在读取时容错、保存时净化

提升 `operationTimingVersion`。读取现有设置或导入旧配置时，优先保留有效 `operationDelayMs`；缺失时继续支持既有三字段与背包等待迁移路径。高级字段被忽略且不进入规范化后的内存模型，下一次保存或导出自然只写回当前字段。

选择规范化投影而不是对每个旧键逐项删除，可同时覆盖未来遇到的旧备份文件，并防止对象展开把废弃字段重新写回。

### 5. 自动检测只搜索并推荐悬停等待

保留现有无副作用五格复制、前台门禁、互斥、紧急停止和剪贴板恢复。搜索仅针对 `operationDelayMs`，结果契约返回旧值、推荐值、样本、耗时、置信度和非敏感证据摘要；应用与撤销都调用同一单字段原子更新入口。

未保留完整推荐表，因为其余数值已成为内部协议，继续展示会重新制造两套用户模型。

### 6. 按消费者清单进行封闭式审计

以制作、地图、海图、背包入库、普通/君锋/商城配方取件、仓库页签选择、海图自动放置和战斗辅助为固定清单，逐一检查设置读取、IPC 载荷和 Python 参数。测试同时断言旧字段不会重新出现，而不只断言新字段存在。

## Risks / Trade-offs

- [内部常量过于保守，仍可能拖慢无信号动作] → 对有信号动作优先轮询；为无信号边界保留语义化指标和定向测试，后续调整不改变用户契约。
- [旧字段通过对象展开重新写回] → 所有读取、保存、导入、导出和 IPC 边界使用白名单投影，并增加负向断言。
- [部分较少使用的消费者漏改] → 使用明确模块清单搜索全部字段名和 Python 参数，并对运行时载荷做仓库级回归检查。
- [自动检测精简后历史结果类型不兼容] → 在同一提交组同步主进程、preload、store、组件和测试，旧结果只用于迁移读取，不作为新输出。
- [与制作事务性能变更产生重叠] → 本变更只负责全局单字段协议；点击后快照与确认逻辑留在 `rebuild-crafting-transaction-flow`，共同验收但分别校验。

## Migration Plan

1. 先建立单字段规范化、版本迁移和旧配置导入测试，确认有效 `operationDelayMs` 被保留且高级字段被剥离。
2. 收敛 TypeScript/IPC/Python 协议，并逐项迁移所有自动化消费者到单字段载荷和内部输入协议。
3. 精简自动检测服务与结果类型，再精简设置界面，避免界面先于运行时契约产生半迁移状态。
4. 运行定向测试、完整测试、开发构建和仓库字段审计；与制作事务变更一起进行开发版手工验收。
5. 回滚时必须同时恢复设置结构、IPC/Python 协议和全部消费者；不能只恢复界面。旧设置仍可从备份读取，但新版本保存后已清除的高级字段不会被重建。
