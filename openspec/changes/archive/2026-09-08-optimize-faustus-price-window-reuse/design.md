## Context

参见 proposal.md。GameAdapter 当前只缓存单件上下文，open_price_at 每次清空并调用大区域 OCR；read_full_price 已双击、全选、复制，后续计算和通货读取不改变焦点。

## Goals / Non-Goals

**Goals:** 缩小后续识别范围并删除冗余输入，保留当前失败关闭与单次提交。

**Non-Goals:** 不修改其他等待，不增加设置、接口或跨运行持久化。

## Decisions

- 保存独立布局（标题、通货、提交按钮边框及识别区域），不保存旧价和可复用通货代码。单件上下文仍在打开、关闭、提交时清空。
- 后续分别裁剪标题与通货区域，按文字高度留边；标题边框和通货左边、垂直中心及高度须与布局基本一致。区域变化、文字缺失、歧义、低置信度或几何变化均清除布局并完整识别。不能仅凭标题存在就使用过期按钮坐标。
- 全部交易先粘贴新价，再选择所需单位，最后提交。读取旧价与粘贴之间不得新增任何改变焦点或选区的输入。
- 用可选开发环境变量启用 stderr 耗时诊断，仅记录阶段、耗时、识别路径和像素面积，不包含物品或剪贴板内容，不修改事件协议。

## Risks / Trade-offs

- 小区域 OCR 仍有固定调用开销 → 不承诺面积与速度成比例，开发版实测首次及后续耗时。
- 窗口移动或缩放导致旧坐标失效 → 检查区域和锚点几何，不匹配时回退完整识别。
- 保留选区依赖游戏行为 → 用不同位数数字和双向通货切换验证，用户已确认切换不重置数字。

## Migration Plan

无数据迁移。回滚仅恢复 Python 实现及对应测试。开发版验收，不打包。
