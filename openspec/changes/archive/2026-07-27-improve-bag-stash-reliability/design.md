## Context

全局设置当前保存 `delays.mouseMove/action/clipboardRead`，脚本生成时分别乘 0.05 或 0.2，默认显示值实际只产生约 13–20ms 等待。背包另存 `bagSettings.transferDelayMs`。这让用户无法知道哪个值控制“鼠标到位后再操作”，也造成相同行为在不同模块中配置不一致。

## Goals / Non-Goals

**Goals:**

- 用一个真实毫秒值覆盖制作、地图洗练和背包的通用输入等待。
- 保留必要的复制可靠性，删除被根因分析证明多余的点击后确认链路。
- 自动迁移旧设置且保存后不再输出废弃字段。

**Non-Goals:**

- 不开放重试次数、按键组合内部间隔或秒级业务等待。
- 不改变战斗辅助扫描周期和回城等待。

## Decisions

- `settings.operationDelayMs` 为唯一用户配置，默认 80ms并钳制到 20–500ms。脚本将它直接换算为秒，不再乘隐藏系数。
- 迁移依次采用已有 `operationDelayMs`、`bagSettings.transferDelayMs`、旧三字段原实际等待的最大值且最低 80ms，最后回退 80ms；保存时移除旧字段。
- 制作和地图内部仍可保留固定安全下限与组合键短间隔，但所有用户可调的鼠标稳定、点击及剪贴板等待均来自同一个值。
- 背包主进程继续接受运行时延迟同步，但字段改为 `operation_delay_ms`；子进程启动时读取快照，修改不影响当前轮次。
- 背包在识别并通过黑名单后只发送一次 Ctrl+点击并计入成功。Ctrl+C 无响应重试与待确认空格逻辑保留，`failedSlots` 全链路删除。

## Risks / Trade-offs

- [统一 80ms 会让部分制作流程比旧默认慢] → 可靠性优先，用户仍可在 20–500ms内微调。
- [旧自定义三字段无法一一保留] → 按旧隐藏倍率还原实际等待并取最保守值，避免迁移后变快。
- [不再确认点击结果] → 根因是点击前稳定不足；保持单击可避免额外复制与误重试，并允许手动补扫处理极端输入丢失。
