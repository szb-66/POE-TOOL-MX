## Context

商城路由和侧栏入口已经存在，但 `ShopView.vue` 仅显示占位内容。项目已有 Vue 3、Element Plus、Pinia、Electron IPC 和一套物品/地图预设机制，因此本变更需要横跨商城 UI、纯函数正则逻辑、预设持久化及安全剪贴板写入。目标数据为实施时最新国服 PoE 1 正式服简体中文文本，且应用应继续离线工作。

## Goals / Non-Goals

**Goals:**

- 在现有商城页完成完整 Vendor 条件选择、实时正则生成、长度反馈和手动复制。
- 生成适用于国服中文客户端的短正则，并保持组合筛选语义正确。
- 提供与物品、地图预设隔离的商城预设，并兼容已有 localStorage 数据。
- 保持正则核心为可单元测试的纯 JavaScript，不依赖 Vue 或 Electron。

**Non-Goals:**

- 不整合 poe.re 的地图、物品、远征、劫盗等非 Vendor 页面。
- 不嵌入 poe.re、不复用其 React 组件，也不在运行时请求远端数据。
- 不提供自动复制、配置导入导出、在线数据更新或游戏窗口自动粘贴。

## Decisions

### 1. 使用领域内静态数据快照

在商城领域内维护带 `locale`、`gameVersion` 和 `updatedAt` 元数据的中文 Vendor 数据。选项使用稳定 ID、中文标签和语义类型。这样可离线运行，并能在游戏更新时通过替换快照和重跑测试完成升级。

备选方案是启动时抓取远端数据，但会引入网络失败、来源漂移和 Electron 安全面，因此不采用。

### 2. 配置、表达式和优化分层

商城配置只保存结构化选择：连接/孔色布尔项、指定颜色数量、移速、法杖与伤害选项及武器基底 ID。生成器先把配置转换为原始表达式列表，再执行去空、去重、孔色等价合并和必要的整体引号处理，最终返回：

```js
{ regex, length, overLimit, warnings }
```

生成结果不进入预设，以确保数据或优化逻辑升级后自动得到新结果。`overLimit` 以 50 字符为阈值；超长只警告，不阻止复制。

### 3. 商城 UI 沿用现有组件体系

`ShopView` 使用响应式卡片分组展示连接/孔色、移动速度、法杖与伤害、武器基底。顶部放置 `PresetSelector type="shop"` 与重置操作，结果卡固定展示正则、字符数、警告和复制按钮。所有标签、提示和错误均使用中文。

### 4. 扩展统一预设 Store，但隔离存储键

`preset.js` 新增 `shopPresets`、`currentShopPresetId`、`currentShopPreset` 和对应 CRUD/切换/更新函数；`PresetSelector` 的类型校验扩展为 `item | map | shop`。商城使用独立的 `shopPresets` 与 `currentShopPresetId` 键。新商城预设从空白默认配置创建，当前预设内的变化通过深度监听自动保存；默认预设不可删除。

读取数据时用默认结构补齐缺失字段，非法 ID 回退默认预设，解析失败只重置商城预设，不触碰物品和地图预设。

### 5. 通过 Electron IPC 写入剪贴板

主进程注册文本剪贴板写入 handler，preload 仅暴露 `writeClipboardText(text)`，前端 API 封装为 `electronApi.clipboard.writeText(text)`。Vite 浏览器开发环境回退到 `navigator.clipboard.writeText`。复制只在用户点击时发生，成功与失败均给出明确反馈。

### 6. 独立实现并保留来源说明

poe.re 及其公开仓库只作为功能行为和优化思路参考。由于上游仓库未展示明确许可证，本项目不直接复制其源码或英文生成数据；商城帮助区提供参考链接和非官方工具声明。

## Risks / Trade-offs

- [国服译名或商店内容随赛季变化] → 数据快照记录明确版本，更新时重跑生成器回归测试。
- [选择大量条件导致正则超过 50 字符] → 实时显示字符数和超长警告，但按已确认需求仍允许复制。
- [扩展旧预设 Store 增加回归风险] → 使用独立键、商城专属默认值和测试，避免修改现有 item/map 数据结构。
- [浏览器模式剪贴板权限被拒绝] → 捕获失败并提示用户，不显示成功状态；Electron 生产环境走受控 IPC。

## Migration Plan

1. 新增商城数据、生成器、预设字段和剪贴板接口，不修改现有 localStorage 键。
2. 首次加载时若无商城数据则创建默认商城预设；已有用户无需迁移操作。
3. 发布前运行生成器、持久化、剪贴板相关测试及完整构建。
4. 如需回滚，恢复商城占位页并移除新增 IPC；遗留的商城 localStorage 键不会影响旧版本。
