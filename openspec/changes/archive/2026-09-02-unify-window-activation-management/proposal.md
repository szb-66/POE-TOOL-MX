## Why

游戏窗口激活与助手主窗口恢复目前分散在 Electron 模块和多个 Python 业务脚本中，导致匹配规则与失败行为发生漂移；浮士德价格识别已经出现仅凭标题把浏览器误认成游戏的实际缺陷。需要把两个前台目标的激活机制收敛到主进程的单一服务，并继续以现有窗口名称和客户端进程名配置作为唯一匹配来源。

## What Changes

- 新增主进程窗口激活服务，统一提供激活游戏窗口与恢复助手主窗口的内部接口、稳定结果码和前台复核。
- 游戏窗口选择统一要求标题与客户端进程名同时匹配，并按标题优先级、非最小化、当前前台和可见面积排序。
- 将制作、地图、背包、配方、君锋镇、海图、浮士德、查价和屏幕选取等入口迁移到统一游戏激活接口；失败时在创建输入进程或截图前安全终止。
- 移除业务 Python 脚本中的游戏窗口查找与激活实现；脚本继续保留每次输入前的游戏前台安全校验，运行中失焦不得自动抢回前台。
- 将业务模块中的助手主窗口直接聚焦迁移到统一恢复接口；登录窗、查价浮窗和识别反馈层等辅助窗口不纳入本次统一范围。
- 保持各业务现有的焦点归还时机与非 Windows 行为，不新增 renderer 可控制的窗口句柄或任意激活能力。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `game-foreground-runtime-policy`: 明确主进程统一窗口激活边界、游戏候选选择规则、业务迁移约束和助手主窗口恢复契约。

## Impact

- Electron 主进程窗口管理、自动化管理器与 IPC 组合关系。
- 依赖游戏激活的固定及生成型 Python 自动化脚本。
- 游戏窗口名称/客户端进程名注册表、Windows 原生前台切换辅助逻辑及其测试。
- 不改变现有 renderer 公共 API，不引入第三方依赖，不在本变更中执行安装包构建。
