## Context

价格分段列表直接绑定持久化配置，现有 `moveBand` 每次调用都会立即保存；这适合按钮式单步移动，但不适合拖动经过多行时的连续预览。页面还使用固定网格列，在可用宽度不足时允许区间关系文字换行。参见 proposal.md 与增量规格。

## Goals / Non-Goals

**Goals:**

- 使用序号前的单一抓手完成鼠标拖拽与键盘排序。
- 在拖动过程中即时移动整行并更新序号，同时确保只有成功放下才保存。
- 保持分段标识和字段值不变，排序只改变数组顺序。
- 在现有桌面断点内保证区间关系文字单行显示。
- 让百分比输入无需依赖上下文即可识别为降价幅度。

**Non-Goals:**

- 不引入通用拖拽框架或第三方依赖。
- 不支持跨列表拖动、复制分段或移动到列表外。
- 不改变价格区间的业务含义、自动排序或验证规则。
- 不为触摸设备设计单独的手势系统。

## Decisions

### 1. 使用浏览器原生拖拽事件与 Element Plus 线性抓手图标

抓手是唯一可开始拖动的元素，使用原生 `dragstart`、`dragenter`、`dragover`、`drop` 和 `dragend` 生命周期。拖动图像取整行，当前被拖行使用半透明和强调边框表达状态；进入其他行时立刻移动数据项，因此页面本身就是最终位置预览。

选择原生能力可以避免为单列表排序增加依赖，并适配 Electron 当前 Chromium 环境。备选方案是引入 SortableJS，但会扩大依赖、打包和测试范围，因此不采用。

### 2. 在领域 store 中区分预览重排与最终提交

store 增加一次拖拽事务：开始时保存分段原始顺序；预览时只更新内存中的数组顺序，不调用配置仓库；成功放下时对当前顺序执行一次规范化与持久化；未成功放下的 `dragend` 恢复原始数组。事务按稳定分段 ID 定位源项和目标项，避免连续预览后索引过期。

选择把事务放在 store 是为了让持久化边界可单测，并避免页面直接接触 repository。备选方案是在页面维护一份临时列表，但会形成表单编辑值与预览列表两套状态，容易丢失拖动期间的字段更新，因此不采用。

### 3. 键盘排序复用立即持久化的单步移动

抓手使用可聚焦按钮语义和明确的 `aria-label`。上、下方向键调用既有单步移动能力，边界位置不移动；运行期间同时设置禁用态。鼠标用户不再看到“上移/下移”文字按钮，删除仍保留在行末。

### 4. 将区间关系设为不可换行的独立网格列

为“≤ 旧价 <”增加语义类并设置 `white-space: nowrap`，同时把抓手、序号和关系文字列定义为内容宽度，把主要输入列设为可收缩的 `minmax`。宽度不足时沿用页面横向滚动，而不是把关系文字拆成多行。

### 5. 使用带文字前缀和单位后缀的降价输入组

降价字段使用同一个输入组显示“降价 | 数值 | %”，并设置 `aria-label="降价百分比"`。该方案在不增加独立表头的情况下直接说明字段用途，仍保持每行紧凑的横向编辑动线。备选方案是只使用 placeholder，但输入值存在时提示会消失，因此不采用。

## Risks / Trade-offs

- [高频 `dragenter` 导致重复重排] → 仅当源项与目标项的当前索引不同时更新数组。
- [成功 drop 后仍触发 dragend 回滚] → 提交先结束 store 内的拖拽事务，后续 dragend 对非活动事务保持幂等。
- [拖动时表单控件误触] → 只有抓手可拖动，输入框和选择器不设置 draggable。
- [列表重排后 Vue 复用错误行] → 继续使用稳定 `band.id` 作为 key，并用 ID 而非旧索引跟踪拖动项。
- [窄宽度产生横向滚动] → 保持现有卡片滚动策略，以单行可读性优先于强行压缩字段。

## Migration Plan

1. 扩展 store 的可预览重排事务并补齐成功、取消和边界测试。
2. 替换页面按钮为抓手，接入拖拽生命周期、键盘操作和视觉状态。
3. 调整分段行网格、区间关系与降价输入组样式，删除不再使用的上移/下移按钮样式和断言。
4. 运行受影响测试、完整测试、Vite 构建和开发版浏览器拖拽验证。
5. 回滚时恢复按钮式 `moveBand` UI；原有配置数据无需迁移。
