## Context
见 proposal.md。现有自动入库发送逐物品事件，但 IPC 冻结地图身份，服务拒绝无地图事件；今日数量从地图 loot 汇总。
## Goals / Non-Goals
目标：保持现有 snapshot.summary 接口，独立、幂等、可恢复的入库落盘。非目标：手动点击采集、完整物品词缀、入库独立导出。
## Decisions
- 在 map-tracker/stash-events/YYYY-MM.json 保存 schemaVersion 与 events，事件含 id、recordedAt、name、baseType、rarity、quantity。复用目标文件队列和原子写，替代追加地图记录。
- 每个 Python 批次在主进程生成 UUID，成功事件序号组成 id。服务调用时冻结设置资格、时间与白名单字段，再排队写入；跨地图与开关切换不改变已收到事件。
- IPC 追踪全部写入 Promise，完成/中止通知等待结算；保存失败报告并携带 statisticsError，物品已转移不得重试点击。
- 汇总从独立 events 输入取入库，历史地图只提供地图统计；读取近 24 小时及今日所需月份。历史入库字段在初始化逐文件原子清理，直接删除字段，不规范化重写其他数据。
- 删除地图专用入库补写代码和仅为入库采集设置的模板校准。经验依赖的地图状态保持。
## Risks / Trade-offs
- 文件占用 → 已有串行写与有界重试，错误暴露，旧文件保留。
- 成功事件可能在进程结束前等待落盘 → 完成通知及关闭等待任务，不另启键鼠操作。
- 旧入库数据清理不可逆 → 用户已选择去除；不清理独立新记录，失败按文件重试。
## Migration Plan
初始化清除草稿和历史的 loot 字段，错误报告但不阻塞应用启动；新地图模型不再携带 loot。开发版验证，不打包，不自动归档。
