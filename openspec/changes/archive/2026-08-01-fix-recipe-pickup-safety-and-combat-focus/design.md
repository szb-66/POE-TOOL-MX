## Context

商城配方自动取件脚本当前在剪贴板校验后直接 Ctrl+点击并发送 `item-picked`，没有验证源仓库格是否真正变化。已有仓库网格计划包含每件物品的屏幕范围，脚本也已经依赖 `mss`、OpenCV 和 NumPy；仓库自动取件脚本已有相同的点击后画面变化确认模式可供参考。

取件管理器已经按仓库页维护 `plan`、`tabIndex` 和 `itemOffset`，但脚本的背包满事件会进入不可恢复的失败路径。控制浮窗和商城页面已经支持 `paused` 状态与继续动作。战斗辅助脚本按游戏标题判断前台，但失焦分支目前只是等待并继续运行；首页选择器由 dashboard 组合层从商城 Store 派生。

## Goals / Non-Goals

**Goals:**

- 用源仓库格的保守视觉变化确认替代无条件成功上报，覆盖七种商店配方。
- 将确认失败区分为背包满暂停和前台/界面安全错误，并保持可恢复任务的自动化锁。
- 让刷新、手动停止、错误和应用退出具有明确的断点清理边界。
- 让战斗辅助在非游戏前台时暂停检测与输入，恢复游戏前台后自动继续，并保留快捷键与按钮的显式停止控制。
- 让首页选项数量直接响应商城 Store 快照。

**Non-Goals:**

- 不新增背包空位模板、校准入口或本地断点持久化。
- 不在恢复取件时重新请求国服接口或重新规划剩余物品。
- 不改变配方识别、套装优化、插槽校验、回城流程或其他脚本的前台策略。

## Decisions

### 1. 使用源仓库画面变化确认取件结果

每次点击前使用计划中物品的 `screen` 范围截取源格快照；Ctrl+点击后在有限等待窗口内重复截取并比较像素差异。未变化时只重试一次点击和等待。只有源格变化才发送 `item-picked`，因此当前物品不会在背包满时被错误消费。

相比扫描背包空位，这个方案不需要新的用户配置，直接复用当前配方计划的物理坐标；相比读取音效或游戏提示，画面变化更可测试且不依赖系统音频。检测期间若前台或界面门禁丢失，优先报告对应安全错误而不是 `INVENTORY_FULL`。

### 2. 背包满使用可恢复暂停，其他停止清除断点

取件管理器新增 `INVENTORY_FULL` 错误码和暂停处理路径。收到该事件后先使当前子进程失效，再停止它；管理器保留计划游标、锁和高亮，状态中公开 `reason`/`code`，恢复时直接从现有 `itemOffset` 生成当前页剩余配置。

手动停止和非满包错误沿用不可恢复停止语义并清除计划游标。服务刷新在获取新仓库数据前调用自动化重置，避免旧计划与新快照混用。应用重启天然丢失内存状态，不写入用户数据。

### 3. 非游戏前台只暂停战斗辅助工作循环

战斗 Python 循环每轮检测前台标题；非游戏前台时保持进程运行，仅休眠并跳过像素读取与按键发送。游戏恢复前台后沿用原配置自动继续检测。进程只响应页面按钮、配置快捷键或应用退出发出的显式停止操作。

前端通过现有 `focus` 事件显示“等待游戏窗口”，不把失焦记录为错误。保留现有“流放之路”/“Path of Exile”标题白名单和回城入口的前台校验，不引入进程枚举或额外系统依赖。

### 4. 首页数量按配方语义格式化

dashboard 的商城控制选项从 `snapshot.recipes[id]`读取数量：套装使用 `fullSetCount`，单件使用 `candidateCount`，没有快照时统一回退 0。选项值和当前配方持久化逻辑不变，只扩展展示标签。

## Risks / Trade-offs

- [游戏渲染延迟可能使成功点击暂时看不到变化] → 使用操作延迟相关的等待窗口并允许一次重试；无法确认时保守暂停，避免继续误点。
- [源格变化阈值受主题、DPI或鼠标位置影响] → 截取计划提供的完整物品范围，复用现有物理 DPI 感知和仓库校准，并覆盖模拟画面的回归测试。
- [暂停时保留自动化锁可能阻塞其他自动化] → 这是有意的安全行为；用户必须继续或紧急停止，后者释放锁并清除断点。
- [刷新期间旧子进程可能迟到输出] → 在处理刷新重置时先清空管理器对子进程的引用，使迟到事件被忽略。

## Migration Plan

1. 先扩展 OpenSpec delta、错误码和纯状态处理，再加入 Python 点击后视觉确认。
2. 接入服务刷新重置、控制浮窗/商城页面提示和首页数量标签。
3. 更新战斗脚本与 IPC 状态转发，补充定向测试。
4. 运行定向测试、完整测试和生产构建；检查所有停止路径的锁、输入按键和计划清理。
5. 如需回滚，移除新错误码和确认逻辑即可；既有仓库快照和用户设置格式无需迁移。
