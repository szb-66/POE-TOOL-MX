## Why

商店配方取件目前在 Ctrl+点击后无条件认为物品已取走，背包满时会继续点击并错误推进进度；战斗辅助必须确保只在游戏前台时读取状态和发送输入，同时由用户显式控制进程退出。首页配方选择器还缺少当前快照的可取数量，无法快速判断要处理的规模。

## What Changes

- 在所有商店配方取件中增加源仓库格画面变化确认；背包满时暂停并保留当前取件游标。
- 增加可恢复的背包满状态、原因和错误码；清空背包后从当前物品继续，不重新请求仓库接口或生成计划。
- 手动停止、非背包满错误、刷新仓库和应用重启清除取件断点；刷新前结束旧任务。
- 战斗辅助检测到前台不是游戏窗口时暂停检测与输入，游戏恢复前台后自动继续；仅由快捷键或页面按钮停止脚本。
- 首页“自动取件配方”选项显示当前可取数量，例如“工匠石(20)”。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `vendor-recipe-automation`: 增加取件成功确认、背包满暂停、任务游标恢复和刷新重置规则。
- `combat-assist`: 明确非游戏前台暂停、恢复游戏前台继续和显式停止的生命周期。
- `dashboard-home`: 商店配方选择器显示当前配方可取数量。

## Impact

- 影响商店配方 Python 自动化脚本、Electron 取件状态机、服务刷新生命周期、共享错误码和游戏内控制浮窗。
- 影响战斗辅助 Python 脚本、战斗 IPC 状态转发和前端运行状态同步。
- 影响首页 dashboard 控件模型及相关自动化、服务、战斗和 UI 回归测试。
- 不新增用户校准配置；继续使用现有仓库网格坐标、`mss` 截图和游戏窗口标题白名单。
