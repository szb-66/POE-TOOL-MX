## Context

商城页当前默认进入正则 Tab，首页商城状态也由正则是否为空派生。七种商城配方已经共用 `useChaosRecipeStore` 管理账号、配置、快照、当前配方和自动取件状态，但账号恢复目前由商城页挂载触发，导致首页不能独立获得完整状态。

## Goals / Non-Goals

**Goals:**

- 让商城配方成为商城页和首页的主能力。
- 首页直接复用配方 Store，支持摘要、切换、刷新和控制启停。
- 统一应用级账号恢复，避免页面挂载顺序影响状态。
- 保持正则数据和全部后端接口兼容。

**Non-Goals:**

- 不在首页执行、暂停或恢复自动取件计划。
- 不在首页提供登录、仓库选择、校准或正则编辑。
- 不改变配方计算、快照、IPC 和正则预设格式。

## Decisions

1. 首页商城状态仅从 `useChaosRecipeStore` 派生，不维护新的持久化副本。当前配方选择继续调用 `setActiveRecipe`，因此自动获得保存和运行时同步行为。
2. 通用模块卡片增加可选的内联选择器视图模型。选择器由首页组合层注入，纯状态计算函数仍只负责状态、说明和指标。
3. 商城卡片的异常来源为 Store 或自动化错误；控制开启或自动化处于运行/暂停状态时显示运行中；未登录、缺少赛季/仓库或无快照时显示需配置。
4. “刷新仓库”只在已登录且已选赛季和仓库页时启用；“启停控制”始终调用现有 `setEnabled`，由该服务继续执行界面模板校验。
5. 应用初始化调用可复用的账号恢复流程并加载赛季、仓库元数据，商城页不再重复恢复。初始化失败仍由 Store 保存错误并关闭不安全的已启用状态。
6. 商城 Tab 仅在没有合法历史值时默认配方；合法的 `vendor` 或 `chaos` 历史选择继续保留。

## Risks / Trade-offs

- [账号恢复会在应用启动时发起额外请求] → 复用已有单次恢复与元数据加载流程，不新增轮询。
- [通用卡片接口扩大] → 选择器保持可选，未配置的六个模块不改变渲染和行为。
- [旧用户最后停留在正则页] → 按“记忆最后选择”的产品决定保留其选择；只有新用户默认配方。
- [无快照时首页信息有限] → 明确显示“待刷新”，并在配置满足后提供刷新操作。
