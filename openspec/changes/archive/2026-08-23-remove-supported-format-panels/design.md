## Context

制作页面和地图页面目前都渲染同一个支持格式公共面板。面板数据同时被解析器回归、查价和航海海图测试导入，因此“移除界面”不能简单等同于删除全部格式数据。参见 `proposal.md` 和本变更的规格差异。

## Goals / Non-Goals

**Goals:**

- 让制作、异界地图和航海海图页面不再渲染顶部支持格式面板。
- 清理页面层不再使用的组件、导入、计算属性和样式。
- 保持测试所依赖的代表性剪贴板样例以及全部解析行为不变。

**Non-Goals:**

- 不调整制作、洗图、预设或查价交互。
- 不修改物品、地图或航海海图解析规则。
- 不打包、不安装、不发布。

## Decisions

### 页面展示与回归样例解耦

从页面模板和脚本中移除公共面板依赖，但保留测试仍在使用的格式样例导出。这样既消除用户可见冗余，也避免失去真实解析器的回归覆盖。

备选方案是删除整个格式数据模块并将样例复制进各测试；这会造成样例散落和重复，且扩大无关改动，因此不采用。

### 删除无剩余调用者的展示组件

在确认仓库内没有其他调用者后，删除只用于这三处面板的公共组件。若仍有调用者，则仅移除页面引用并保留组件。

备选方案是保留未使用组件，虽然风险较低，但会留下无法触达的界面代码，不利于后续维护。

## Risks / Trade-offs

- [回归样例与界面文案不再共享数据] → 样例已不再承担界面职责，改以解析器测试作为唯一约束并保持集中导出。
- [误删测试依赖的样例导出] → 先检索全部引用，再运行受影响的支持格式、查价和航海海图测试。
- [页面顶部残留空白或无用间距] → 对两个页面执行开发版 Vite 转换，并检查相邻布局样式。

## Migration Plan

1. 移除三个页面的面板渲染及页面脚本依赖。
2. 删除无调用者的展示组件，保留测试需要的样例数据。
3. 运行定向测试、Vite 开发构建和 OpenSpec 严格校验。
4. 如需回滚，恢复页面引用与展示组件即可；数据和解析路径未迁移。
