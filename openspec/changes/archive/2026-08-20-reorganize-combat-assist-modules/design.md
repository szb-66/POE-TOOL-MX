## Context

战斗辅助页面的所有配置、运行状态和操作目前都集中在 `CombatView.vue`，并通过现有 settings store、combat store 和 combat service 完成自动保存与启停。页面已有未提交的 Element Plus 响应式栅格迁移，本次实现必须在该版本上重排模板，不能恢复旧的局部网格实现。

## Goals / Non-Goals

**Goals:**

- 用四个同级卡片表达配置、被动喝药、主动喝药和一键回城的功能边界。
- 让模块标题、问号说明、状态标签和右侧操作形成一致且可响应换行的标题栏。
- 复用现有状态、处理函数和配置监听，确保本次变更只影响呈现和入口位置。

**Non-Goals:**

- 不抽取跨页面通用标题组件，不调整 store、service、IPC 或 Python 自动化。
- 不改变默认配置、校验规则、保存防抖、进程并行关系或失焦安全策略。
- 不增加一键回城的短生命周期状态模型。

## Decisions

### 在现有页面内重组四个卡片

直接在 `CombatView.vue` 中使用统一的模块标题栏结构，并保留生命/魔力配置已有的 Element Plus 响应式双列。相比新增通用组件，这能避免为单页视觉模式扩大公共接口，同时完整保留工作区当前的栅格改动。

### 通过现有运行状态条件渲染单个按钮

被动喝药继续读取 `combatStore.running` 和 `combatStore.focused`，主动喝药继续读取 `loopRunning` 和 `loopFocused`。停止状态渲染主要“开始”按钮，运行状态渲染危险“停止”按钮；按钮仍调用现有 service 方法，因此不会改变运行协议或幂等语义。

### 将说明收进可访问的问号提示

四个标题都使用 `QuestionFilled` 图标和提示组件，并为图标提供键盘聚焦能力及可理解的无障碍名称。说明分别覆盖快捷键与频率保护、像素检测和前台限制、主动循环规则、一键回城执行流程。

### 将添加入口纳入主动喝药列表流

“添加按键”按钮放在循环条目循环之后，使用默认按钮样式；空列表不再提示用户点击“右上角”，而是直接显示该按钮。现有 `addLoopItem` 默认值和深度监听保存流程保持不变。

## Risks / Trade-offs

- [窄窗口标题内容可能拥挤] → 标题左侧信息允许换行，右侧操作保持独立，并在开发版验证窄屏布局。
- [重排模板可能误删当前未提交栅格改动] → 基于当前工作树做最小范围修改，并通过布局测试确认仍使用 `app-grid` 与响应式列。
- [静态结构测试可能对无关文案过于敏感] → 测试聚焦模块顺序、标题栏关键语义、条件按钮和列表末尾入口，不锁定完整模板快照。
