## Context

装备生成逻辑和地图模板都已有“首次读取失败后补读一次”的局部实现，但装备的插槽等路径仍会在读取失败后进入下一轮并再次使用通货，地图主扫描与单格处理也分别维护重试。停止浮窗只能从结构化日志和进程关闭事件推断状态，地图结果文件保存统计但没有失败格检查点。现有完成态“重新开始”已经具备加载最新配置并走标准启动链的基础，可复用于异常恢复。

## Goals / Non-Goals

**Goals:**

- 用同一套三次读取语义覆盖装备、地图和海图的所有当前目标读取路径。
- 让异常停止和用户主动停止在内部事件中可判定，并让浮窗只为异常停止提供恢复。
- 让地图和海图从失败格继续，同时只恢复已经提交的统计。
- 保留前台窗口、坐标、DPI、通货、模板、仓库页和停止门禁。

**Non-Goals:**

- 不保存或恢复 Python 进程内存、按键按下状态或未完成的通货操作。
- 不改变制作目标判断、地图换格顺序、空格阈值或预设持久化格式。
- 不增加跨应用重启的长期断点，也不包含打包和发布。

## Decisions

### 1. 用统一的“复制并解析当前目标”助手承载三级读取

每次调用先执行当前动作所需的一次通货操作，再由读取助手最多串行读取三次。第 2、3 次只重新移动到同一目标、复制并等待对应请求 ID 的解析结果；同文本只能在剪贴板序列号变化时接受。助手耗尽后返回结构化错误，由调用方进入统一安全停止。

选择这一方式而不是在每个制作循环外围重试，是因为外围重试会再次执行通货操作；也不采用固定延时后直接读取，因为无法证明剪贴板属于本次复制。

### 2. 恢复是新任务，不复用已退出进程

装备恢复重新加载最新预设与设置，生成仅在本次生效的预设副本并强制首次判断，不写回用户的“首次识别”选项。地图和海图恢复同样走标准启动校验，但向生成脚本传入经过边界和目标类型校验的恢复检查点。

选择新任务是为了重新执行全部安全门禁；精确恢复 Python 内存断点会持有过期的窗口、坐标和按键状态，风险更高。

### 3. 地图检查点只保存已提交状态

检查点包含目标类型、当前失败格列行、已处理数、合格数以及累计黑白名单统计。每张目标的词缀统计先保存在局部变量，只有单格进入完成终态后才合并到累计统计并把检查点推进到下一格。失败事件携带尚未推进的当前格和此前已提交统计。

选择在脚本结构化事件中传递检查点，而不是依赖可能被解析响应覆盖的结果文件，可让浮窗在进程异常结束前保留最新可恢复状态；结果文件仍用于现有统计展示。

### 4. 显式传递终止类型

`script-stopped` 使用 `mode`、`termination`、`error` 和可选 `recovery` 描述停止。主进程主动停止发出 `manual`；脚本结构化失败或非主动异常退出发出 `abnormal`；已经由浮窗确认完成的流程不提供异常重试。Python 内部停止快捷键也发出主动停止事件，避免与自然异常退出混淆。

## Risks / Trade-offs

- [用户在停止后修改地图配置，历史统计与后续规则可能不同] → 统计明确表示同一恢复会话的累计结果，失败格及后续格使用点击重试时的最新有效配置。
- [结构化失败事件与进程关闭事件先后到达造成状态覆盖] → 以运行实例和终止优先级合并，`manual` 与已记录的具体异常不得被后续通用关闭事件降级。
- [检查点损坏或旧网格尺寸变化] → 启动前校验目标类型、整数范围和统计字段；失败时不启动输入并保留停止画面。
- [三级等待增加最坏停止时间] → 只增加一次现有有界读取等待，不改变单次超时和全局停止快捷键的即时取消能力。

## Migration Plan

该变更不迁移持久化用户数据。开发版更新后，新检查点只存在于当前浮窗运行期；回滚代码即可恢复旧行为。实施时先补充回归测试，再修改读取与恢复链，最后执行完整测试、构建和 OpenSpec 严格校验。
