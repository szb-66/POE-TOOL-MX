## Context

当前 `src/views/Help.vue` 同时保存全部文案、布局和样式，共 15 个一级区块、80 个列表项。测试直接读取该 Vue 文件验证做装公开契约。应用已经使用 Vue Router、Element Plus 和全局主题变量，不需要引入新的界面或搜索依赖。

## Goals / Non-Goals

**Goals:**

- 将帮助内容与页面交互分离，使内容可检索、可测试并便于后续维护。
- 在现有 1280×720 桌面窗口内提供清晰首屏和单一滚动体验。
- 保持做装规则文本及所有现有业务路由不变。

**Non-Goals:**

- 不提供在线文档、远程内容更新、运行状态或帮助页内业务操作。
- 不改变做装模拟规则、Electron IPC 或侧栏结构。

## Decisions

1. 使用普通 JavaScript 内容目录定义 `HelpTopic` 结构，字段包含 `id`、`category`、`title`、`summary`、`keywords`、可选 `route` 和结构化 `blocks`。相比在 Vue 模板中保留长文，这允许搜索和 Node 测试复用同一数据源。
2. 使用通用富文本块渲染段落、小标题、列表和提示，不使用 `v-html`，避免内容转义与安全问题。做装正文按现有章节迁移，测试改为读取结构化内容的扁平文本。
3. 帮助页维持一个正文滚动容器。桌面显示固定分类栏，窄窗口使用横向分类按钮；折叠状态由页面本地状态管理。
4. `topic` 查询参数是唯一可持久化导航状态。目录、搜索结果和专题标题更新该参数；搜索词保持本地，避免路由历史被每次输入污染。
5. 搜索使用规范化小写后的同步包含匹配。当前内容量有限，不引入模糊搜索、索引库或防抖。
6. 版本直接从 `package.json` 导入，项目地址使用当前仓库远端。外链沿用 Electron 已有外部链接策略。

## Risks / Trade-offs

- [结构化正文迁移时遗漏既有契约文本] → 迁移后让现有关键词测试读取内容目录，并增加完整扁平文本断言。
- [深链接滚动发生在折叠内容渲染前] → 先切换分类和展开专题，再在下一个 Vue tick 后滚动及聚焦。
- [工作区已有未提交改动] → 仅修改帮助相关新文件、`Help.vue` 和对应测试，不覆盖其他业务文件。
- [富文本数据比手写模板更啰嗦] → 限定少量 block 类型并保持渲染组件无业务逻辑。

## Migration Plan

先建立内容目录和搜索工具，再替换帮助页渲染，最后迁移契约测试并在开发版验证。回滚时恢复原 `Help.vue` 与测试即可，不涉及用户数据迁移。
