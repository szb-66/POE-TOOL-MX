## Context

参见 `proposal.md` 的 Why。现有链路使用集中状态定义创建 `stateFilters`，并在创建模型、清理渲染进程回传模型以及兼容旧模型时复用同一默认函数。已实施版本把“已鉴定”始终设为“任意”，但解析器在文本明确出现“未鉴定”时会产生 `identified=false`，该明确否定事实不应被丢失。

当前工作树含有其他查价 OpenSpec 变更的未提交实现，本变更必须仅增量修改共享状态默认逻辑和相关测试。

## Goals / Non-Goals

**Goals:**

- 使新捕获、非法值回退和旧模型迁移共享同一套“明确肯定、明确否定或任意”默认规则。
- 保留用户明确提交的合法 `false` 三态值。
- 保持物品事实展示与查询意图独立。

**Non-Goals:**

- 不更改状态项列表、官方键名、浮窗布局或其他过滤器的默认启用逻辑。
- 不重构物品解析器或改变 `facts` 字段语义。

## Decisions

### 1. 在集中默认函数修复根因

状态默认函数对除 `identified` 外的白名单状态使用“事实为真则 `true`，否则 `any`”；`identified` 在事实为 `false` 时设为 `false`，在事实为 `true` 或缺失时设为 `any`。这利用解析器对“未鉴定”独立行的明确识别，但不把未出现该行解释为用户必须搜索已鉴定物品。

不选择只在 Vue 浮窗中替换显示值，因为即时查询、主进程清理和旧调用路径仍会提交隐式否定条件。

### 2. 区分默认回退与用户合法选择

清理函数继续保留输入 `stateFilters` 中已通过白名单的 `any | true | false`；只有缺失或非法值才使用新默认。因此用户手动选择“否”的查询契约不变。

### 3. 旧布尔模型使用同一默认规则

没有 `stateFilters` 的模型先按现有信任边界重建物品事实，再交由集中默认函数生成状态条件。旧 `unidentified=true` 代表明确的未鉴定状态，因此迁移为“已鉴定=否”；其他旧 `false` 仅表示未观测到肯定状态，不被解释为否定搜索意图。

## Risks / Trade-offs

- [默认查询比旧版宽泛，挂单数可能增加] → 这是所需语义；保留手动“否”供用户收窄结果。
- [工作树其他查价变更与相同测试文件重叠] → 实施时仅添加状态默认断言，通过定向 diff 检查不覆盖既有修改。

## Migration Plan

1. 更新集中状态默认函数和相关回归断言。
2. 运行定向测试、完整测试、Vite 开发转换与 OpenSpec 严格校验。
3. 若需回滚，恢复原默认映射和相关断言；不涉及持久化数据迁移。
