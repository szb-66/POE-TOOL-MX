## Context

通用制作浮窗由 Electron 创建为无边框、置顶、不可聚焦窗口，并默认调用 `setIgnoreMouseEvents(true, { forward: true })`。渲染层目前把标题当作拖动区域，但窗口移动 API 并未实际暴露，且整块内容的 hover 会关闭穿透，交互范围和用户预期不一致。背包检测由 Electron 生成临时配置并启动 Python；IPC 在 `spawn` 返回后立即报告成功，实际子进程若因脚本路径、依赖、配置或运行时异常退出，页面随后只看到停止状态。

## Goals / Non-Goals

**Goals:**

- 保持浮窗主体穿透，只让一个小抓手成为稳定可拖动区域。
- 使用 Electron 原生拖动区域完成移动，避免自行计算窗口坐标。
- 让背包检测“启动成功”代表进程已进入可运行状态，并准确区分主动停止和异常退出。
- 保留 stderr、退出码与结构化检测错误，方便后续诊断。

**Non-Goals:**

- 不重做浮窗视觉内容、尺寸或制作流程。
- 不修改背包图像匹配算法和自动入库策略。
- 不引入新的运行时依赖。

## Decisions

1. 在浮窗顶边增加独立抓手，使用 `-webkit-app-region: drag` 交给 Electron 原生窗口拖动。抓手通过转发的鼠标移动事件临时关闭忽略鼠标，离开后恢复穿透。相比渲染层手算坐标，此方案不依赖缺失的 IPC、异步窗口坐标或缩放换算。
2. 浮窗内容不再因普通 hover 关闭整窗穿透；只有抓手以及原本需要完成确认/关闭的终态交互改变穿透状态。抓手尺寸保持小且视觉明确。
3. 背包检测启动前枚举可用 Python 解释器并探测 `cv2`、`mss`、`numpy`、`pyperclip`、`pynput`，优先选择依赖完整的解释器；若所有解释器都缺依赖，则仍启动默认解释器以返回明确的缺失模块诊断。
4. 背包检测启动增加短暂的启动确认门槛：监听 `spawn`、结构化就绪/状态事件和早期 `error/close`，只有未发生早退时才向渲染层返回成功。正常长期退出仍由统一生命周期监听发布状态。
5. 主动停止前记录停止意图，进程关闭时不再发送“进程异常退出”；Python 发出的 `detection-error` 优先作为最终原因，stderr/退出码仅作为没有结构化原因时的回退。
6. 将子进程启动与退出原因归一逻辑提取为可单测的辅助函数，以行为测试替代仅匹配源代码字符串的测试。

## Risks / Trade-offs

- [抓手 hover 依赖 Electron 的 `forward` 鼠标移动转发] → 保留窗口创建时的 `forward: true`，并用组件测试/源契约验证抓手是唯一主动取消穿透的普通区域。
- [启动确认时间过短可能漏掉稍晚的导入错误] → 以 Python 首个结构化状态事件为优先确认，并设置有限超时作为兼容回退；早期退出直接返回失败。
- [已有未提交改动与本修复交叠] → 只增量调整背包和浮窗相关代码，验证后检查并删除被替代的旧手动拖动代码与脆弱测试。

## Migration Plan

无需数据迁移。变更可通过回退相关 Electron、Vue 和测试文件撤销；持久化背包配置保持兼容。
