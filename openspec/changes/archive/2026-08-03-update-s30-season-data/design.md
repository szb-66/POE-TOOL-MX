## Context

当前数据维护分为三套版本化 POEDB 原始快照（做装、技能、传奇）、规范化内置目录、少量静态规则与说明，以及运行时腾讯国服交易/仓库接口。生成器默认补丁均为 3.28，做装规则还包含 Mirage 专属常量和固定数量哨兵；直接全局替换版本号既无法刷新数据，也会掩盖规则变化。参见 `proposal.md`。

## Goals / Non-Goals

**Goals:**

- 以可重复的刷新命令采集 3.29 来源，保留 3.28 原始数据并原子生成新目录。
- 从生成结果和 3.29 更新内容反向审计解析器、固定规则、UI 说明和测试哨兵。
- 对在线国服接口做无账号的 schema/赛季检查，并对需要登录的路径用现有契约测试覆盖。
- 提供一个快速的一致性测试，阻止旧赛季标识再次混入当前运行基线。

**Non-Goals:**

- 不实现 S30 赛季玩法模拟、佣兵或海底航行系统。
- 不在应用运行时增加 POEDB 请求。
- 不执行安装包构建；所有运行与验证均使用开发版。

## Decisions

### 1. 原始来源按补丁隔离后再生成正式目录

继续使用现有 `crafting-raw/<patch>`、`skill-raw/<patch>`、`unique-items-raw/<patch>` 机制，并先抓取到 3.29 目录。相比覆盖 3.28 或直接修改规范化 JSON，这能保留来源证据、支持离线重建和失败回滚。

### 2. 用数据驱动哨兵替代脆弱的 3.28 固定数量

长期稳定哨兵继续检查；与 Mirage 页面数量绑定的断言改为验证结构、最低覆盖量和 3.29 当前关键记录。固定数量能快速发现页面变化，但每赛季必然制造假故障，且无法区分正常新增与解析丢失。

### 3. 当前赛季元数据集中导出

新增单一赛季基线常量供生成器、规则集和一致性测试复用；用户说明中的详细统计从实际目录计算或更新。相比散落字符串替换，可由测试枚举所有运行入口并阻止版本漂移。

### 4. 在线国服能力与离线快照分别验证

交易物品和词缀接口使用公开无状态请求验证 schema；赛季列表、仓库页与实际搜索需要登录信息，因此沿用 mock/契约测试并验证 S30 ID 透明传递。这样既不要求开发环境持有用户凭据，也不把赛季列表返回 401 的“未登录”误判成接口不兼容。

## Risks / Trade-offs

- [POEDB 在赛季初仍持续更新，抓取结果可能短期变化] → 保存抓取时间和哈希，使用关键记录与最低覆盖校验，并允许之后显式刷新。
- [3.29 页面结构或中文翻译未稳定] → 生成失败时保留正式目录；只对确认的数据启用执行规则。
- [传奇图片数量大、刷新耗时] → 复用同 URL 的已验证本地图片，仅下载新增或内容变化的 3.29 资源。
- [腾讯仓库接口必须登录才能端到端访问] → 将公开接口烟测与认证路径契约测试分开，最终说明认证边界。

## Migration Plan

1. 增加 3.29 基线与审计测试，使旧默认值先产生明确失败。
2. 刷新三套 3.29 原始来源并生成候选目录；任何失败不替换正式输出。
3. 根据 3.29 数据差异更新解析器、规则和说明，重新生成并通过快照测试。
4. 验证腾讯公开接口和开发版核心流程，运行全量测试。
5. 保留 3.28 原始目录作为回滚依据；若 3.29 候选存在缺口，恢复上一正式规范化目录而不删除新原始来源。
