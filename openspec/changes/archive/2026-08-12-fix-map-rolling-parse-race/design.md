## Context

参见 [proposal.md](proposal.md) 的问题说明。装备制作与地图/海图洗练目前分别由两个 Python 模板写入 `item_info.txt`，Electron 的共享文件监听器解析剪贴板并写入 `item_info_result.json`，Python 再轮询结果文件。两个模板的等待函数都在请求已经发出后删除结果文件，因此快速响应可能被当作旧结果删除；地图/海图模板中 `process_single_map` 的失败返回值还不会阻止外层网格递增。

该通道也服务于其他制作流程，因此协议扩展必须向后兼容。实现不得改变前台门禁、停止快捷键、通货预检、地图条件或预设结构。

## Goals / Non-Goals

**Goals:**

- 让装备、地图和海图的每次解析请求和响应具备相同且可验证的一一对应关系。
- 消除“响应已返回却被等待方删除”的时间窗口。
- 将单张地图的“完成终态”和“内部处理失败”建模为不同结果，防止失败后换格。
- 用无需启动游戏或 Electron 窗口的确定性测试覆盖竞态和外层控制流。

**Non-Goals:**

- 不调整六项地图基底、黑白名单或必选/挑选语义。
- 不改变点金、混沌、重铸、瓦尔和自动存仓的正常状态机顺序。
- 不把该变更扩展到不使用物品解析文件通道的其他自动化脚本，也不引入数据库、套接字或新依赖。
- 不执行打包验证；仅在开发版和自动化测试中验证。

## Decisions

### 1. 为共享解析请求增加关联标识，并保持旧调用兼容

装备模板和地图/海图共用模板都为每次解析请求生成当前进程内单调递增的 `requestId`，随剪贴板文本写入输入 JSON。Electron 文件监听和解析处理器在输入包含 `requestId` 时将其原样写回结果；旧调用不提供该字段时继续沿用现有格式。

Python 等待方只接受 `requestId` 与当前请求相同的结果。这样既能隔离旧请求的迟到响应，也能明确测试每次判断使用的是哪张地图。

备选方案是只比较文件修改时间或剪贴板序列号。修改时间受 Windows 时间精度、调度和同毫秒写入影响，剪贴板序列号只能证明复制文本变化，不能证明 Electron 返回结果属于哪次请求，因此不采用。

### 2. 在发布请求之前清空结果内容，等待阶段只读不删

两个 Python 模板都在写入当前请求前将结果文件截断为空，保留文件本身，随后写入携带 `requestId` 的输入；`wait_for_parse_result` 不再删除结果文件。即使 Electron 同步或极快写回，等待方也只能看到空内容或当前响应，不会删除新响应。

保留结果文件而不是删除再创建，可避免 Windows `fs.watch` 绑定文件时因删除和重建产生额外失效风险。关联标识仍是正确性的主要保证，清空仅用于减少无关轮询和保持现有文件协议直观。

备选方案是继续删除文件但把删除提前。该方案能关闭已发现的快速响应窗口，却无法可靠隔离上一请求延迟写回，因此不单独采用。

### 3. 解析重试只重复读取，不重复制作动作

抽取单一的“请求当前格解析结果”操作，负责移动/确认当前格、复制、发布请求、等待并校验响应。调用方在首次失败时最多重新执行一次该读取操作；已执行的通货动作不回滚，也不再次执行。两次均失败后设置致命停止原因、释放输入状态并结束主循环。

重试次数固定为一次，避免短暂文件监听抖动直接终止，同时限制失焦或异常环境下的等待时间。用户停止和前台失效在每次重试前仍优先终止。

备选方案是无限重试或直接跳格。无限重试可能把自动化卡死，跳格会保留未知状态地图并继续消耗后续物品，因此均不采用。

### 4. 单张处理返回结构化终态

将单张处理结果区分为至少三类：`completed-qualified`、`completed-unqualified` 和 `failed`。前两类表示当前格已经进入既有明确终态，外层可按既有语义更新统计并换格；`failed` 携带稳定原因，外层必须停止且不递增当前行列。

实现可使用 Python 字典、枚举字符串或等价的小型结构，但不得继续依赖 `True`、`False` 与元组混用所产生的隐式真值。这样可从根本上消除外层无条件换格，而不是只在某一个超时分支打补丁。

备选方案是在每个失败分支设置全局布尔值。该方式容易漏掉新增分支，且继续保留返回值语义不清的问题，因此不采用。

### 5. 测试直接驱动协议和状态机边界

新增测试从两个真实模板提取相关函数或生成可执行测试脚本，通过受控临时文件和桩函数构造以下顺序：响应在等待前写回、旧响应在新请求后迟到、装备制作读取当前响应、地图/海图首次读取失败后恢复、连续失败、未达标目标继续使用当前格。外层测试至少使用两个网格位置，断言失败时没有第二格移动或输入事件。

解析器与六项基底现有测试继续作为条件语义保护；新测试不得只匹配源码字符串作为核心行为证明。

## Risks / Trade-offs

- [协议字段传递遗漏导致所有响应被视为陈旧] → 在 Electron 文件监听、成功结果和错误结果路径统一回传 `requestId`，并加入错误响应测试。
- [结果文件截断触发覆盖层读取空内容] → 现有监听器已忽略空内容；增加测试确认空内容不产生业务结果。
- [一次读取重试增加失败停止时间] → 复用现有固定剪贴板响应窗口，只重试一次，并允许停止快捷键和前台门禁随时中断。
- [结构化终态迁移漏掉传奇、腐化或不可改变分支] → 表驱动覆盖所有既有返回路径，并保持它们原有的处理/合格统计语义。
- [共享文件协议影响物品制作] → `requestId` 设为可选，旧输入和旧响应格式保持可用；运行相关物品制作回归测试。

## Migration Plan

1. 先添加失败复现测试，证明快速响应会被当前等待逻辑删除且失败后会换格。
2. 向共享文件协议添加可选 `requestId` 回传，并验证旧格式兼容。
3. 调整两个模板的请求顺序与等待校验，并为地图/海图加入一次只读重试。
4. 将单张处理返回迁移为结构化终态，收紧外层统计与换格条件。
5. 运行地图模板、文件监听、物品制作相关定向测试及全量 `npm test`，再在 `npm run electron:dev` 中进行开发版手工验证。

回滚时可整体撤销协议字段、等待流程和结构化终态改动；该变更不迁移持久数据或用户预设。
