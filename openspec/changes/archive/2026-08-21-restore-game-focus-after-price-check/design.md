## Context

参见 `proposal.md`。当前查价浮窗通过 Electron `BrowserWindow` 取得焦点，主动收起时只隐藏窗口；Ctrl+D 捕获则继续通过 Windows 前台窗口标题与进程双重门禁。关闭入口分散在鼠标离开监视、窗口 `blur`、关闭 IPC、外部市集跳转以及禁用/退出清理中，因此需要在窗口生命周期、服务编排和 Windows 输入辅助之间传递关闭意图。

## Goals / Non-Goals

**Goals:**

- 让主动结束查价操作可靠触发一次最佳努力的游戏焦点恢复。
- 保证普通失焦、外部浏览器跳转和系统清理不会抢夺用户当前焦点。
- 复用现有游戏标题、进程与权限安全边界，并为关闭原因建立可执行测试缝隙。

**Non-Goals:**

- 不允许在查价浮窗或其他应用位于前台时直接执行 Ctrl+D 捕获。
- 不修改查价查询、持久化设置、窗口尺寸/位置或公开 IPC 协议。
- 不引入原生 Node 扩展、安装包验证或通用窗口管理架构。

## Decisions

### 1. 使用显式关闭原因驱动焦点策略

浮窗关闭接收内部原因，至少区分 `user-dismiss`、`pointer-leave`、`blur`、`external-action` 和 `system`。仅前两类允许请求恢复游戏焦点；关闭 IPC 映射为用户主动关闭，服务禁用和生命周期清理保留系统默认值。这样可在调用点表达真实意图，而不是根据窗口当前可见性猜测。

备选方案是所有 `close()` 都恢复游戏焦点，但会在 Alt+Tab、点击浏览器和应用退出时产生抢焦点；仅依赖 `blur`/`hide` 的系统默认焦点转移又无法保证回到游戏，均不采用。

### 2. 外部跳转对当前浮窗会话抑制焦点恢复

打开官方市集前在浮窗会话上记录外部动作状态，调用系统浏览器后立即以 `external-action` 原因收起浮窗。该关闭原因不得恢复游戏焦点，浏览器继续保持前台；隐藏引发的迟到 `blur` 由会话去重处理。新物品创建浮窗状态时重置外部动作标记。

### 3. 通过注入的 Windows 聚焦函数执行最佳努力恢复

在现有 Windows/Python 输入辅助附近提供游戏聚焦函数，并由主进程构造查价浮窗时注入。脚本枚举顶级窗口，只选择标题包含当前配置且进程名属于允许列表的候选，必要时恢复窗口、使用线程输入附加配合 `SetForegroundWindow`，最后再次验证前台窗口仍满足双重匹配。聚焦函数返回成功/失败，不把失败升级为关闭错误。

直接在浮窗模块导入 Python 检测器会增加窗口组件与运行时定位耦合；新增原生 Node 扩展会带来打包和 ABI 维护成本，因此均不采用。

### 4. 隐藏先于聚焦，并对每次会话去重

主动关闭先同步停止监视、清理状态并隐藏窗口，再异步请求游戏焦点。每次显示会话记录是否已请求恢复，`hide()` 引发的迟到 `blur`、重复 IPC 或计时器回调不得重复执行。失败被捕获并归一为 `false`，不得产生未处理 Promise rejection。

### 5. 测试策略采用纯策略测试与调用点集成断言

将“关闭原因是否允许恢复”的判断保留为可直接执行的纯逻辑，覆盖全部原因、外部动作抑制和重复关闭；对 Windows 脚本验证标题/进程双重匹配、目标枚举、`SetForegroundWindow` 与最终验证。现有集成测试继续锁定各关闭入口的原因映射，真实 Windows 焦点切换只在开发版配合游戏人工验收。

## Risks / Trade-offs

- [Windows 可能拒绝 `SetForegroundWindow`] → 使用与项目既有自动化一致的线程输入附加/恢复策略并最终验证；失败保持安静且不激活其他应用。
- [存在多个合法游戏客户端窗口] → 按 Windows 顶级窗口顺序选择最靠前的匹配候选；始终要求标题和进程同时匹配。
- [前台监视器最多约 250ms 后重新注册游戏范围快捷键] → 开发版验收连续 Ctrl+D；不绕过前台监视器或提前声明游戏已在前台，以保留安全边界。
- [隐藏触发 `blur` 造成重复关闭] → 会话级去重使焦点恢复最多执行一次，重复关闭保持幂等。
- [当前相关文件已有未提交改动] → 仅做局部增量修改，实施前后审查相关 diff，不重置或覆盖现有尺寸、预热与主题工作。

## Migration Plan

无需数据迁移。按回归测试、开发版真实交互、完整测试和构建顺序验证；若焦点恢复产生回归，可回退关闭原因传递和聚焦注入而不影响既有查价数据或设置。实现阶段不执行安装包构建。
