## Context

剧情模块当前把章节、步骤和技能组保存在同一份 v1 localStorage 数据中，浮层快照也直接从当前章节读取技能。浮层内容窗口始终鼠标穿透，仅顶部独立原生抓手接收输入。技能目录解析器只接受带红绿蓝 CSS 类的链接，因此白色技能石被过滤。

## Goals / Non-Goals

**Goals:**

- 无损拆分并组合剧情路线与技能方案预设。
- 保持浮层主体穿透的同时提供可靠的栏宽拖拽。
- 让白色技能、等级和透明度贯穿生成、存储、快照与显示。

**Non-Goals:**

- 不把预设同步到云端，也不增加导入导出格式。
- 不让技能预设按章节名称或 ID 自动匹配。
- 不改变现有剧情前后步骤快捷键和浮层位置语义。

## Decisions

1. **使用统一 v2 剧情存储，但保留两套独立预设集合。** 剧情预设保存章节、步骤与进度；技能预设保存按章节序号排列的技能槽。相比把技能继续嵌入章节，这允许任意组合；相比按章节 ID 关联，不会把技能预设绑定到某一条剧情路线。

2. **v1 在读取时原地迁移为两个默认预设。** 章节和步骤进入默认剧情预设，各章节的技能组进入默认技能预设；写回只使用 v2。新建复制预设时深拷贝并重新生成章节、步骤、技能组和技能 ID，避免跨预设共享或碰撞。

3. **浮层快照由当前两类预设和等级设置组合。** 技能槽通过当前章节下标选取，额外技能槽保留但不显示。等级关闭时从快照中省略 `requiredLevel`，使浮层渲染保持简单且不会泄漏关闭的显示信息。

4. **白色技能以缺少 RGB 类的有效 gem 链接识别。** 解析器要求有效路径、非空名称、图片和等级；同一稳定来源重复时校验名称/类型/颜色一致并保留最低等级。这样处理标准与特殊白色宝石，同时避免为“号召”硬编码。

5. **分割线使用第二个原生透明 BrowserWindow。** 内容窗口继续全域穿透；渲染进程上报双栏区域，主进程把窄的原生拖柄对齐到分割线。拖柄移动事件计算并限制比例，再同步内容和窗口状态。窄宽度上下布局、透明度为 0 或浮层关闭时隐藏/销毁拖柄。

6. **透明度使用 Electron 窗口 opacity。** 内容、顶部抓手和分割抓手使用相同的 0–1 opacity，满足“整个浮层”透明；0 时隐藏两个交互窗口以消除不可见拦截区域。数值和宽度一样由设置 store 全局持久化。

## Risks / Trade-offs

- [技能按序号组合可能与差异很大的剧情路线错位] → UI 明确显示两套当前预设，额外槽位不删除，用户可为不同路线建立技能预设。
- [原生分割抓手在 DPI 取整下漂移] → 始终从内容窗口规范尺寸和最新布局指标计算，不把取整后的原生尺寸反馈为下一次基准。
- [白色判定可能收录特殊但有效的技能] → 仅收录完整有效 gem 行，并继续使用生成校验与哨兵技能测试。
- [0 透明度导致用户找不到浮层] → 主页面数值控件始终可恢复；0 时主动隐藏交互抓手。

## Migration Plan

1. 读取 `storyGuide:v1` 时生成 v2 内存模型并保留全部有效字段。
2. 首次保存、切换或编辑后写回同一存储键的 v2 结构。
3. 若 v2 结构损坏，回退到包含两个默认空预设的安全状态。
4. 回滚旧版本时旧程序无法理解 v2；实现不删除 v2 数据，但旧版本会回退空数据，因此发布前以迁移测试保证升级路径。
