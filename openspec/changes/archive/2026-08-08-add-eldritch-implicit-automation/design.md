## Context

现有物品自动化由预设、启动校验、通货预检、剪贴板文件监听和生成的 Python 脚本组成。项目已经包含 schema v5 古灵隐式家族、T1–T6 阶级和八种 T1–T4 直接通货定义，但自动制作目录查询只覆盖显式词缀，解析结果也没有向脚本公开隐式匹配状态。

## Goals / Non-Goals

**Goals:**
- 在原自动化链路内增加可安全停止的古灵直接通货循环。
- 复用同一古灵快照、坐标选取、通货预检和外链防护。
- 让预设迁移与互斥规则在界面和启动校验两层一致。

**Non-Goals:**
- 不实现冲突石、T5/T6、双侧阶级编排或古灵支配显式通货。
- 不允许自由文本古灵目标，不嵌入远程网页。

## Decisions

1. 使用语义字段 `moduleEldritch`，而不是继续增加 `moduleFour`。配置保存来源、直接通货阶级和稳定目标记录；归一化层负责旧预设默认值和异常互斥数据收敛。
2. 目录查询直接遍历活动快照的 `eldritchImplicitFamilies`，按来源、阶级和正权重筛选，并以家族 `effectKey` 生成跨随机数值的稳定匹配模式。相比复用显式目录，这能保留古灵来源和适用护甲类别。
3. 新增专用隐式 matcher，只读取 `implicitMods`。文件监听器把匹配布尔值、命中名称、隐式与势力信息写入结果，Python 不复制目录算法。
4. Python 在首次正式输入前完成物品读取与合法性检查；先检查已有目标，再循环应用所选且已预检的唯一通货。循环沿用现有输入释放、前台门禁、剪贴板等待和 1000 次上限。
5. 互斥操作在三个模块的启用处理器中即时落盘，归一化与启动校验作为防御层。显式与插槽仍可同时启用。
6. 词缀参考使用带 `target="_blank"` 和 `rel="noopener noreferrer"` 的 HTTPS 链接，交由主窗口现有 `setWindowOpenHandler` 转发至系统浏览器，不新增 IPC。

## Risks / Trade-offs

- [游戏中文词缀格式改变] → 使用已有效果模式归一化与剪贴板解析测试覆盖多行、数值和范围格式。
- [旧预设出现三个模块同时启用] → 加载归一化时古灵启用优先，确定性关闭另外两个模块。
- [错误坐标导致误点] → 所选通货必须通过启动只读名称预检，非法装备必须在正式点击前结束。
- [目录目标不适用当前具体底材] → 候选展示适用类别，运行时由游戏文本类别门禁并保留明确失败反馈。

## Migration Plan

加载现有物品预设时注入默认关闭的 `moduleEldritch`，不删除或改写原模块配置。新增坐标以默认零值进入设置，只有启用对应古灵模式时才要求配置。回滚时旧版本忽略新增预设字段和坐标字段。
