## Context

项目使用 Vue 3、Pinia 和 Electron。现有制作/洗图覆盖层共用一个 `overlayWindow`；全局快捷键由主进程注册，但配置分散在 settings 与 bag store，触发监听也分散在页面生命周期中。剧情功能需要长期保存可编辑的层级数据、在独立窗口中实时展示，并在游戏前台通过全局快捷键推进，因此会同时影响渲染状态、IPC、窗口管理和快捷键生命周期。

## Goals / Non-Goals

**Goals:**

- 提供可持久化的章节、步骤和章内技能组编辑模型。
- 提供与制作/洗图覆盖层互不干扰的剧情浮窗和连续跨章导航。
- 让所有全局快捷键和战斗动作键通过按键捕获配置。
- 集中处理全局快捷键注册、冲突校验、触发分发和旧背包配置迁移。

**Non-Goals:**

- 不自动识别游戏章节或自动推进步骤。
- 不提供云同步、导入导出、步骤循环或技能组跨章节共享。
- 不捕获鼠标按键，也不改变战斗动作键实际发送逻辑。

## Decisions

### 剧情状态使用独立、版本化的 Pinia 持久化模型

剧情数据保存为 `{ version, chapters, currentChapterId, currentStepId }`。章节包含稳定 ID、名称、步骤数组和技能组数组；技能颜色仅允许 `red`、`green`、`blue`。加载函数负责补齐 ID、过滤非法数据并修复失效进度。浮窗可见性是会话状态，不写入持久化数据。

选择独立 story store，而不是扩展 settings store，是为了隔离大量、频繁编辑的攻略内容和全局应用设置。相比按章节拆分多个存储键，单一版本化文档更容易原子保存、迁移和测试。

### 导航由纯函数生成连续步骤序列

导航层按章节数组顺序和章内步骤顺序生成线性索引，空章节不进入可导航序列。前后移动在全局首尾处保持不动，不循环。点击章节定位其第一步，点击步骤定位指定项；删除当前项时优先选择后继，否则选择前驱。

将导航逻辑从 Vue 组件中分离，便于覆盖跨章、空章节和删除等边界测试，也让面板操作与快捷键触发使用同一规则。

### 使用独立剧情 BrowserWindow 和快照式 IPC

窗口管理新增 `storyOverlayWindow`，加载独立 `/story-overlay` 路由。主渲染进程是剧情数据与当前进度的唯一写入方，每次打开、编辑或导航后发送一个可序列化展示快照；浮窗只负责渲染，不直接读写攻略存储。

剧情窗口默认顶部居中，保存移动后的 bounds，并在恢复时约束到当前显示器工作区。高度由内容测量结果驱动，设置上下限；窗口主体保持穿透，拖动区域和需要滚动时临时接收鼠标。

独立窗口避免与制作/洗图状态互相覆盖。未选择复用现有覆盖层，因为两种功能需要同时显示并拥有不同生命周期。

### 全局快捷键使用单一清单和单一分发器

`globalShortcuts` 增加 `stashStart`、`storyPrevious`、`storyNext`，默认分别沿用旧背包值、`PageUp`、`PageDown`。应用启动或任一快捷键提交时，用完整清单一次性校验和重新注册；主渲染进程只安装一个触发监听器，再按功能 ID 分发。

旧 `bagSettings.stashShortcut` 仅在新字段不存在时迁移，之后以 settings 为唯一来源。此方案避免进入特定页面才注册、重复监听以及重新初始化时遗漏背包快捷键。

### 捕获控件分为组合快捷键、单动作键和按键序列

组合快捷键组件从 `keydown` 生成规范化 accelerator：修饰键单独按下不提交，Esc 取消，Backspace/Delete 清空。校验器对完整快捷键集合做大小写无关比较，并拒绝不支持格式、F12、Ctrl+Shift+I。注册失败时不提交新配置，并恢复之前成功注册的清单。

战斗传送门动作键使用只允许单个非修饰键的捕获控件。喝药序列使用按键标签，每次捕获追加一个单键，支持删除和拖动重排，继续按数组顺序交给现有战斗脚本。

捕获组合快捷键期间，主进程临时挂起当前全局快捷键，避免已注册的 `Alt+1` 等组合先被 Electron 截获；捕获提交、取消或失焦后恢复原注册清单。控件同时跟踪按下中的修饰键，使 Alt 引发焦点变化时仍能组成完整 accelerator。

### 章节与步骤使用稳定 ID 拖动排序

章节列表与章内步骤列表通过原生拖放交互重排，store 按稳定 ID 移动数组项并立即持久化。排序只改变展示和连续导航顺序，不更换当前章节或步骤 ID；浮窗打开时同步更新三步上下文。

## Risks / Trade-offs

- [剧情数据频繁编辑造成过多写入] → 在 store 中对文本编辑采用短延迟保存，结构操作和进度切换立即保存。
- [浮窗内容过多遮挡游戏] → 固定宽度、限制为可用屏幕高度并在超限时启用内部滚动。
- [全量重新注册时部分按键失败] → 先校验候选清单；注册失败后恢复上一份已知可用清单并向用户显示失败按键。
- [旧页面遗留独立监听器导致重复执行] → 移除页面级注册和触发监听，统一由应用级快捷键服务管理。
- [按键名称在 DOM 与 Electron/Python 间不同] → 维护显式键名映射，并分别输出 Electron accelerator 与战斗动作键格式。

## Migration Plan

1. 加载 settings 时补齐新增剧情快捷键，并从旧 `bagSettings.stashShortcut` 迁移背包快捷键。
2. 保留其他现有设置和值不变；剧情存储不存在时初始化为空数据和空进度。
3. 切换所有页面到新捕获控件和统一注册服务后，停止读取 bag store 中的快捷键字段。
4. 如需回滚，旧版本会忽略 settings 中未知的新字段；旧 `bagSettings` 数据不主动删除，以便回滚后仍可使用。
