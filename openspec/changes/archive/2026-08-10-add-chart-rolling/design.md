## Context

现有地图预设是扁平 `map` 配置，页面、首页、验证器和 Python 模板都直接读取该对象；解析器只把“异界地图”和“地图”视为地图类别。侧栏已有名为“海图”的九宫格玩法，航海海图洗练必须留在地图模块内部。

## Goals / Non-Goals

**Goals:**
- 以最小迁移面保留现有异界地图配置路径和行为。
- 让前后端解析、匹配和 Python 运行时使用同一目标与数值语义。
- 对混装背包实行使用通货前的类别门禁。

**Non-Goals:**
- 不处理海图形状、纪念币或已测绘资源。
- 不新增侧栏路由，不执行发行包验证。

## Decisions

1. 预设仓库分别维护 `mapPresets/currentMapPresetId` 与 `chartPresets/currentChartPresetId`；活动目标使用独立的 `mapRollingKind` 持久化，不隶属于任一预设。
2. 页面抽取可复用配置面板，由 Tab 绑定对应预设集合、当前预设和数值定义；两个 Tab 的新建、删除、重命名、切换及配置均互不影响。
3. 启动时根据 `mapRollingKind` 读取对应当前预设，规范化为带 `targetKind` 的运行时配置。验证、通货预检、JavaScript 匹配器和 Python 模板都只消费该运行时对象。
4. 解析器新增航海海图专用身份规则：分隔线前以“海图”结尾的行是基底，前一身份行才是稀有名称；区域名称只作为展示信息处理。
5. 航海海图四项键使用 `quantity`、`rarity`、`packSize`、`deadmanSulphur`，前三项与地图共用解析字段，第四项映射到独立顶层字段。

## Risks / Trade-offs

- [旧版本曾把海图嵌入地图预设] → 首次加载时把每个 `map.chart` 拆入独立海图预设集合，并从地图配置删除 `chart/activeKind`；没有嵌套数据时创建默认海图预设。
- [说明文字混入词缀导致误判] → 同步更新主进程和浏览器解析器的忽略规则，并使用完整样本回归。
- [页面显示通过但脚本继续重洗] → JavaScript 与 Python 共用相同有效键、冲突处理和缺失值规则的测试向量。
- [混装时误耗通货] → 在进入单件状态机前及每次重新解析后验证目标类别。

## Migration Plan

加载旧预设时原有异界地图预设继续写入 `mapPresets`；若检测到嵌套 `map.chart`，按原预设名称和 ID 拆分到 `chartPresets`。活动目标迁移到独立键，后续保存不再把两类配置写进同一个预设对象。
