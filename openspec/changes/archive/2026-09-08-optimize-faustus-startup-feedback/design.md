## Context

参见 proposal.md。运行时检测已有异步 API 与缓存；当前 manager 在显示反馈前同步调用检测。Python 已有价格布局缓存和格子身份缓存，但主循环仍重复复制候选格。

## Goals / Non-Goals

**Goals:** 及时反馈、可取消启动、消除重复扫描工作、提供分段耗时证据。

**Non-Goals:** 不调整输入等待，不削弱提交警告检查，不修改价格算法或持久化数据。

## Decisions

- 取得锁后立即设置 preparing 并开始统一反馈，异步解析运行时；按启动对象身份检查每个 await 的结果，避免停止后旧请求污染新运行。运行时直接传给 spawn。
- 内部 state 增加 stage，Python 使用白名单阶段事件；页面与浮窗由同一状态更新，完成或失败清空阶段。
- 缓存本轮原始复制文本与规范化身份分别用于下一格处理与占格判定；只在内存保留，不写入日志。失败空文本允许主循环重试。
- 首轮由 main 的只读预检负责，循环保留每 12 个候选格的复检。直接调用 run_repricing 的测试保留默认预检语义，通过参数标明已预检。
- 沿用 FAUSTUS_TIMING 开关，仅开发版向进程传递诊断开关；记录运行时、提交、占格、页面复检和窗口打开/物品切换耗时。

## Risks / Trade-offs

- 停止与新启动竞态 → 每个异步边界核对启动身份，旧结果无副作用。
- 提交 OCR 可能仍占主要时间 → 保留完整检查并明确显示阶段，真实游戏计时单独记录。
- 缓存假设当前页物品位置稳定 → 仅本轮有效，保留前台与周期网格检查。

## Migration Plan

无数据迁移。开发版验证，无打包；回滚本变更文件即可，保留原有价格布局优化。
