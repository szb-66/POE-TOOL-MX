## Context

当前 `ManualSession` 的前后缀数组只容纳已确定 modifier/tier 的词缀；加密制作则先生成一个占用前缀或后缀位置但没有效果的未揭露占位，随后才从三个候选中选择实际 modifier。快照中已有 1,274 条按底材配置展开的 `source: veiled` 记录，对应 109 种唯一效果，均为通用“天选的/秩序之”池，不包含密教成员签名词缀。

现有引擎已具备位置锁、无法骰出攻击/施法、ModGroup、固定随机种子、加权选择和撤销历史。新能力应复用这些原语，同时区分三个不同阶段：通货移除/重铸、放置无标签的加密占位、用户揭露真实词缀。

## Goals / Non-Goals

**Goals:**

- 准确实现当前版本加密崇高石与加密混沌石。
- 把未揭露词缀作为真正占用词缀槽的装备状态，而不是只存在于界面的临时标记。
- 从真实加密池按权重生成稳定的三选一选项，并允许工艺台 ModGroup 阻断改变候选。
- 所有随机选择、数值与历史在相同种子下可重复，并支持撤销、重做、重置。

**Non-Goals:**

- 不模拟密教成员签名加密词缀、密教棋盘、解锁经验或账号工艺解锁进度。
- 不模拟腐化/镜像加密物品的掉落来源。
- 不获取加密通货价格。

## Decisions

### 1. 未揭露词缀沿用 affix 结构并增加 `veiled` 标志

占位词缀使用稳定的伪 modifier/tier ID、`source: veiled-pending`、`veiled: true`，并进入 `prefixes` 或 `suffixes` 数组。它因此自然占用容量、能被后续重铸或剥离移除，也能被历史快照和装备预览展示。普通词缀读取时默认 `veiled: false`，无需提升数据快照 schema。

不增加独立 `pendingVeil` 顶层字段，因为那会让容量、移除和历史系统维护两份事实来源。

### 2. 加密崇高石拆成“移除”与“放置占位”两次随机

先从 `mutableAffixes(..., respectMeta: true)` 随机移除一条，因此前缀/后缀无法改变会保护对应侧；选择时明确忽略无法骰出攻击/施法。移除后，从仍有容量且至少能提供三个合法揭露选项的前缀/后缀位置中等概率选择一侧并放入占位。

动作前拒绝已有未揭露词缀、已揭露加密词缀，或已有加密词缀工艺台版本的装备，匹配当前通货限制。校验与状态变化原子执行。

### 3. 加密混沌石通过保证伪 affix 复用 `rollItem`

先根据位置锁计算重铸后保留词缀，并选择一个有容量且有完整揭露池的位置。把该位置的占位描述成只在本次调用存在的 guaranteed pseudo-affix，再交给 `rollItem` 生成稀有词缀数量；最终标准化为 `veiled: true`。

重铸阶段保留操作开始时的“无法骰出攻击/施法”限制来过滤普通随机词缀，即使对应元工艺随后被消耗。揭露候选阶段不使用这些标签限制。若位置锁会保留另一条未揭露或已揭露加密词缀，则拒绝动作，避免生成多个加密词缀。

### 4. 揭露选项由当前状态即时、确定性生成

按占位位置调用现有底材匹配与物品等级规则，读取 `source: veiled` 的正权重阶级，并排除装备上已占用的 ModGroup。无法骰出攻击/施法不参与过滤。候选按 modifier family 权重进行不放回抽样，最多返回三个不同 modifier；候选池不足三个时占位通货不可生成。

目录查询用 `session.rngState` 的副本，不推进会话随机数，因此页面重复刷新保持稳定。用户选择时用同一算法重新验证三个选项，再用正式 RNG 重骰所选 tier 数值并推进状态。

### 5. 揭露是独立的可撤销动作

选择后用真实 `rolledAffix(..., source: veiled)` 替换占位。它不计为 crafted affix，但同样占用 ModGroup；事件记录三个候选、所选结果和具体数值。撤销恢复占位，重做恢复同一揭露结果。

## Risks / Trade-offs

- [快照按多个 modifier profile 展开同一效果] → 先按当前底材过滤，再按稳定 modifier/family ID 去重，测试唯一效果数量与候选重复。
- [阻断工艺会改变三选一结果] → 候选基于当前完整装备即时计算；历史只在真正选择后固化结果。
- [加密混沌与元工艺的阶段语义容易混淆] → 分别保存“操作开始时的生成标签限制”和“清理后的保留词缀”，用专门测试覆盖。
- [旧会话 affix 缺少 `veiled`] → 状态规范化默认 false，回滚时删除新增入口即可。
