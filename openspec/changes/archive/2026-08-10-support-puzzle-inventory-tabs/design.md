## Context

海图模块当前以单个 60 格数组作为识别、编辑、求解和自动放入的共同来源。新版仓库的两个页签共享同一 6×10 网格区域，但自动化必须在每次截图与取件前确认正确页面。现有区域和坐标均使用 Windows 物理坐标，并已有通用全屏坐标取点器。

## Goals / Non-Goals

**Goals:**
- 在不改变求解算法输入语义的前提下，用带页码的聚合库存扩展来源分配。
- 使用已标定页签完成一次操作内的双页自动识别，取消玩家手动同步游戏页与助手页的要求。
- 自动化在错误页、过期坐标或库存变化时先失败，绝不对未验证来源发送旋转或取件输入。
- 保持旧区域和识别强度设置可读取，保持单页识别可用。

**Non-Goals:**
- 不识别或推断游戏当前激活页签；每次识别都显式点击目标页签。
- 不支持两个以上仓库页，不自动发现页签数量。
- 不改变 3×3 海图求解规则或目标格验证方式。

## Decisions

### 每页保存完整识别快照，求解时生成聚合视图
状态层保存 `inventoryPages[1|2]`，每页包含 `recognized`、`slots`、`warnings` 和 `gridConfidence`。聚合计算为格子附加页码后复用现有计数与求解器。相比维护一个 120 格可变数组，这能让页面替换、清空、修正和 UI 切换保持局部且明确。

### 页签点绑定仓库区域并使用安全带校验
设置保存两个物理坐标；合法范围限定在网格横向范围内，以及网格顶部向上一格高度的带状区域内。重新框选或清空仓库区域会使坐标和页面快照失效。相比按比例猜测页签位置，显式取点适应不同分辨率和 UI 缩放，同时安全带可阻止明显误点。

### 计划来源显式携带页码
来源身份使用 `(page,row,column)`，候选排序保持“手动修正优先、置信度优先”，再按页、行、列稳定排序。自动化不尝试动态跨页寻找替代来源，确保实际点击与用户确认过的方案一致。

### 每个来源先切页再截图校验
自动化配置携带页签坐标。脚本在每个未完成来源前点击对应页签、等待稳定、截图目标网格并验证计划格；只有校验通过才进入旋转和取件。即使页码绑定错误或游戏内容变化，失败也发生在危险输入之前。

### 双页识别由主进程编排并原子提交
单次 `puzzle-analyze` 请求携带两个页签坐标。主进程校验两个坐标后依次调用识别器切页、等待和截图，最终返回带页码的两页结果。渲染状态先验证整批结果与重复页保护，再一次性替换两页快照；任一页失败都保留旧库存，避免新旧页面混用。

### 分页后将鼠标移出识别区域
识别器和自动放入脚本在页签点击完成并释放鼠标按键后，统一把指针移动到物理坐标 `(0,0)`，随后才等待稳定和截图，避免页签悬停效果或鼠标指针遮挡识别区域。

### 用执行事件增量同步，再以最后页重识别兜底
`step-completed` 携带来源页和坐标，渲染状态立即清空对应格。错误或停止时只重识别最后操作页，用于处理“来源已拿起但目标验证未完成”等不确定状态；其他已完成来源已由事件同步，无需逐页自动扫描。

## Risks / Trade-offs

- [两页内容恰好完全一致会触发重复保护] → 明确提示用户；可先只保留一页，或通过手动修正形成可区分状态后重新识别。
- [用户把助手页与游戏页对应反了] → 自动放入切到标定页后会在来源校验阶段安全停止，并给出页码相关提示。
- [空页降低原有“框错区域”检测能力] → 仅在网格置信度足以证明 6×10 边界存在时接受空页，否则仍返回框选错误。

## Migration Plan

旧设置迁移为第 1 页默认选中，两个页签点为空且页面快照不持久化。用户可继续单页识别与求解；自动放入会按方案引用页提示完成相应页签标定。回滚时新增设置字段会被旧版本忽略。
