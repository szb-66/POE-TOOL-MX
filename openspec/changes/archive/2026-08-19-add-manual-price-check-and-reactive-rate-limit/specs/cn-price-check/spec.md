## ADDED Requirements

### Requirement: 用户选择立即或手动查价
系统 SHALL 在查价页面提供持久化的“立即查价”开关且默认关闭，并 MUST 在两种模式下都保留 `Ctrl+D` 捕获物品和打开浮窗的能力。

#### Scenario: 默认使用手动查价
- **WHEN** 用户首次使用或旧版本设置中没有“立即查价”字段，并在游戏前台对物品按下 `Ctrl+D`
- **THEN** 系统捕获并解析物品、打开浮窗、展示可编辑查询条件，但不访问官方交易搜索或挂单接口

#### Scenario: 用户主动搜索
- **WHEN** 浮窗已展示捕获物品且用户点击“搜索”
- **THEN** 系统使用浮窗当前物品模型和查询条件请求官方交易接口并展示结果

#### Scenario: 开启立即查价
- **WHEN** 用户开启“立即查价”后在游戏前台对物品按下 `Ctrl+D`
- **THEN** 系统捕获并解析物品后立即请求官方交易接口并展示结果

#### Scenario: 模式跨重启保留
- **WHEN** 用户修改“立即查价”开关并重启应用
- **THEN** 系统恢复用户最后保存的模式

#### Scenario: 手动模式解析候选
- **WHEN** 手动模式下用户选择未鉴定传奇身份或未识别词缀候选
- **THEN** 系统更新浮窗中的待查询模型且不访问官方交易接口，直到用户点击“搜索”

## MODIFIED Requirements

### Requirement: 查询国服官方挂单
系统 MUST 通过已认证国服 Session 请求腾讯官方交易搜索和结果接口，SHALL 对相同短期搜索使用缓存，且 MUST NOT 在官方未返回限流错误时施加固定请求间隔。

#### Scenario: 查询成功
- **WHEN** 官方搜索返回 query ID 和结果 ID
- **THEN** 系统按官方排序获取首批挂单并返回总数、查询 ID 和标准化挂单，且不因软件预设的搜索或 Fetch 间隔延后请求

#### Scenario: 官方明确限流
- **WHEN** 官方接口返回 429 和有效 `Retry-After`
- **THEN** 系统展示官方限制和剩余重试时间，并在该官方冷却期内立即拒绝同组重复请求而不是静默等待

#### Scenario: 官方限流未提供恢复时间
- **WHEN** 官方接口返回 429 但没有有效 `Retry-After`
- **THEN** 系统展示官方限流错误但不得自行设置固定冷却时长

#### Scenario: 会话过期
- **WHEN** 官方接口返回 401 或登录 HTML
- **THEN** 系统返回 `SESSION_EXPIRED`、清理查价缓存并同步未登录状态

#### Scenario: 接口结构变化
- **WHEN** 响应缺少必要字段或不是预期 JSON
- **THEN** 系统返回 `API_INCOMPATIBLE` 且不展示旧结果为新结果

#### Scenario: 后台目录正在刷新
- **WHEN** 官方词缀或物品目录请求尚未完成且用户发起查价
- **THEN** 交互搜索不等待目录请求队列，并继续使用当前已加载的可信目录构造查询
