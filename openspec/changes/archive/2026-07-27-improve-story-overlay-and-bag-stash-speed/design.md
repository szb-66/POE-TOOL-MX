## Context

剧情浮窗窗口默认开启鼠标穿透并转发鼠标移动事件。当前 Vue 根节点在任意 hover 时关闭穿透，标题行整体被标为原生拖动区，但没有三点或其他抓手图形，因此用户既看不出哪里可拖，也可能因穿透切换范围过大而难以稳定操作。背包扫描每格都执行界面校验、移动鼠标、复制读取和可选 Ctrl+点击；历史全局延迟最高会给鼠标移动增加 260–500ms，使一格远超期望。扫描循环固定遍历 60 格，不识别背包尾部已经连续为空的情况。

## Goals / Non-Goals

**Goals:**

- 让剧情浮窗的拖动入口始终清晰可见且可稳定命中。
- 抓手之外继续保持鼠标穿透，不扩大对游戏输入的拦截范围。
- 把背包单格内置等待预算压到 120ms 以内，为正常情况下低于 0.2 秒/格留出截图和系统调用时间。
- 连续确认三个空格后，把本轮视为正常提前完成并释放输入状态。

**Non-Goals:**

- 不改变剧情浮窗内容布局、宽度设置或位置持久化格式。
- 不移除逐格前台检查和仓库/背包界面检查。
- 不把无法读取、模板失败或物品文本解析失败误判为空格。

## Decisions

1. 剧情浮窗新增独立三点胶囊抓手，抓手使用 `-webkit-app-region: drag`。只有抓手监听 `mouseenter`/`mouseleave` 来切换 `setIgnoreMouseEvents`；移除根容器的整窗交互切换。相比继续用标题行，此设计既可发现又保持最小交互面积。
2. 背包脚本在运行边界再次限制延迟，而不只修改 UI 默认值。鼠标移动最多 15ms、动作后等待最多 15ms、空剪贴板确认最多 50ms，键盘/鼠标按下等待各 10ms；最坏内置等待合计 120ms，即使旧配置保存了 500ms，也不会继续拖慢背包入库。
3. 同步在运行配置生成层应用相同上限，使写入临时配置的值与脚本实际行为一致，并保留全局延迟对其他自动化功能的原语义。
4. 扫描循环维护 `consecutive_empty_slots`。只有复制结果明确为 `empty` 才递增；任何已复制、无法读取或移动失败都会清零。达到 3 后发布带 `reason: three-consecutive-empty` 的 `stash-completed`，避免被 UI 当作异常停止。
5. 性能测试验证内置最坏等待预算，而连续空格测试验证计数/重置和第三个空格后不再扫描。真实游戏响应和截图耗时属于外部变量，仍通过保留 80ms 以上余量满足正常 0.2 秒目标。

## Risks / Trade-offs

- [延迟过短可能使极慢游戏客户端来不及更新剪贴板] → 空格仍等待最多 60ms，逐格安全校验保留；无法读取不会计入连续空格。
- [用户故意在扫描中间留三个连续空格] → 按用户要求将其视为背包有效内容结束；黑名单物品、无效文本和读取失败都会中断空格连续计数。
- [拖动期间鼠标离开抓手导致穿透恢复] → 使用 Electron 原生拖动区接管按住拖动，抓手 hover 仅负责让首次按下可到达原生拖动区。

## Migration Plan

无需数据迁移。旧延迟配置继续保留，只有背包模块在运行时采用新的上限。回退相关 Vue、配置生成和 Python 扫描代码即可恢复旧行为。
