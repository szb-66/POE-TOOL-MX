## Context

国服复制的魔法药剂头部只有一行完整名称，例如“预兆的自由之不朽魔力药剂”。通用解析器因此只能得到 `name`，无法得到独立的 `baseName`。查价模型当前回退到 `name` 作为 `type`，最终把词缀名一并发送给官方接口。

运行时交易目录已从腾讯官方物品目录加载所有普通底材，因此可以在查询模型层利用目录补全身份，而不需要在通用文本解析器中维护易过期的药剂名称表。

## Goals / Non-Goals

**Goals:**

- 从官方目录中可靠恢复魔法药剂的真实底材。
- 保持普通、稀有、传奇和已有独立底材行的查询行为不变。
- 候选不可靠时不猜测底材。

**Non-Goals:**

- 不新增硬编码药剂底材列表。
- 不改变通货兑换流程。
- 不尝试解析或翻译官方目录中不存在的底材。

## Decisions

1. 在 `createPriceCheckModel` 中解析非传奇物品的底材。该层同时拥有解析结果和运行时官方目录，比通用剪贴板解析器更适合处理交易身份。
2. 优先使用复制文本明确给出的 `baseName`；否则先精确匹配目录底材，再从完整名称的后缀候选中选择最长底材。最长匹配可区分“不朽魔力药剂”和更短的“魔力药剂”。
3. 只考虑目录中 `unique !== true` 的普通底材记录，并要求最长候选唯一；无候选或同长度歧义时保留原身份，不臆造请求条件。
4. 查询模型中的 `item.baseType` 与 `identity.type` 使用同一解析结果，确保界面展示和实际请求一致。
5. 词缀映射先尝试完整文本，以兼容目录中可能存在的复合 matcher；完整文本无法匹配时，再按高级复制文本的效果行逐条匹配官方 stat。这样不会把同一词缀的多行效果错误拼成目录中不存在的单条 stat。
6. “— 数值不可调整”是客户端对掷值的展示注记，不是官方 stat 文本。只在匹配输入中移除该注记，界面仍保留原始效果文本，避免丢失用户可见信息。
7. 每条成功映射的效果行生成一个现有 stat 筛选项，继续使用 `initialSelection`、最小值和最大值语义；未匹配行单独进入 `unknownStats`，不得猜测 ID。

## Risks / Trade-offs

- [官方物品目录未成功加载时无法补全底材] → 保持现有回退行为，并由既有目录降级状态提示用户。
- [完整名称可能同时以后缀形式匹配多个层级底材] → 选择最长候选，并对同长度歧义拒绝替换。
- [通用修复影响其他魔法物品] → 仅在缺少明确 `baseName` 时运行，并增加现有普通/稀有查询回归测试。
- [拆分多行词缀可能改变已有复合 matcher] → 始终优先匹配完整文本，仅在完整匹配失败时才逐行回退。
