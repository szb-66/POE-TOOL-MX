## Context

参见 `proposal.md`。当前模型只保存 `identity.name` 与 `identity.type`，官方请求序列化也只写名称和底材；原始 `item.category` 虽已由解析器保留，却既未规范化为官方类别，也未进入查询。浮窗身份栏直接展示原始物品名称和底材，手动模式说明位于身份栏外。

本变更横跨共享元数据、模型创建/清理、未鉴定传奇解析、查询序列化、服务降级和 Vue 浮窗，因此需要统一身份契约，避免仅在界面隐藏名称而后端仍继续提交名称或底材。

## Goals / Non-Goals

**Goals:**

- 让模型、界面和实际官方请求共享同一份“名称是否启用”状态。
- 把国服中文类别收敛为可显示标签与官方代码，并让合法官方类别成为名称关闭查询的强制边界。
- 保持旧模型、未鉴定候选和 `Unknown item base type` 降级路径安全兼容。
- 复用现有词缀行的可访问选择语义，并把手动说明整合进身份栏。

**Non-Goals:**

- 不新增全局“默认搜索名称”设置；每件新物品仍默认精确查询。
- 不提供任意类别下拉或允许用户切换到另一大类。
- 不改变属性、状态、词缀初选策略、官方结果分页或自动/手动查价模式。
- 不执行打包或发布验证。

## Decisions

### 1. 在共享查价元数据中集中维护类别白名单

`shared/priceCheckMetadata.js` 导出规范化类别解析器，输入只接受清理后的国服复制类别，输出 `{ category, categoryLabel }`。白名单按官方过滤目录代码组织，覆盖当前解析范围内的武器、防具、饰品、珠宝、药剂和地图，并显式收录国服同义词，例如：

- `头盔`、`头部` → `armour.helmet` / `头盔`
- `胸甲` → `armour.chest` / `胸甲`
- `盾` → `armour.shield` / `盾`
- `弓` → `weapon.bow` / `弓`
- `戒指`、`项链`、`腰带` → 对应 `accessory.*`
- `珠宝`、药剂类别、地图类别 → 对应官方 `jewel`、`flask`、`map` 家族

实现时以官方过滤目录中存在的代码为闭集，并为当前解析器支持的单/双手武器、爪、匕首、法杖、权杖、长杖、手套、鞋子等类别补齐表驱动测试。未知输入返回空结果，不做包含匹配或猜测。

备选方案是在 Vue 与 Electron 各维护一份映射，或直接把中文类别发给官方；前者容易漂移，后者不是官方协议且无法形成后端白名单，因此不采用。

### 2. 扩展身份模型，并让名称开关默认向后兼容

规范身份为：

```js
identity: {
  name,
  type,
  category,
  categoryLabel,
  nameEnabled
}
```

模型创建时从解析器给出的可信 `item.category` 解析大类，`nameEnabled` 对具有合法具体名称的模型初始化为 `true`。清理旧模型时，缺少该字段按 `true` 处理；只有明确的布尔 `false` 且类别合法时才允许关闭。

重新查询时，服务以主进程保存的当前模型为信任锚：类别由原始中文类别重新解析或沿用主进程已规范化身份，不信任渲染进程任意提交的官方代码。未鉴定传奇候选解析只替换名称和具体底材，并保留类别，同时把 `nameEnabled` 重置为 `true`。

备选方案是只在 Vue 层保存局部开关；这会导致打开官方市集、重新查询和清理后的模型状态不一致，因此不采用。

### 3. 在序列化前计算“有效身份”，官方大类始终写入 type_filters

查询构造先规范化类别，再根据 `nameEnabled` 计算有效身份：

- 启用：发送 `query.name`、`query.type` 和 `query.filters.type_filters.filters.category.option`。
- 关闭：不传名称和底材，只发送同一 category 以及其余属性、状态和 stat 过滤器。

`createAwakenedTradeRequest` 接收规范化 category，并在类别合法时通过现有安全路径写入 `type_filters.filters.category.option`。当名称启用但旧类别无法映射时，保留名称和底材执行精确查询；当名称关闭且类别缺失/非法时，查询构造直接抛出清理后的无效请求错误，不能退化为无身份搜索。

关闭名称时同时删除底材，是为了实现“所有头盔”而非“所有黄金之面”。保留底材的备选方案与用户目标不符。

### 4. 底材拒绝重试基于实际请求，而不是原始模型

服务仅在首次实际请求同时包含已启用名称与具体底材、且官方明确返回 `Unknown item base type` 时，构造移除底材的单次重试；重试体保留名称、category 和所有其他条件。名称关闭路径首次请求没有底材，自然不会进入该分支。

这避免用原始模型中仍保存的 `identity.type` 误判关闭名称路径，也保持现有无名称普通物品的失败诊断。

### 5. 身份栏左侧负责身份，右侧负责状态与说明

身份栏左侧包含可聚焦的名称筛选行和常驻元数据。名称行复用 `.filter-row` 的 enabled/hover/focus 视觉语言、`role="checkbox"`、`aria-checked`、Enter/Space 键盘切换；点击范围只覆盖名称行。类别非法时设置禁用语义和说明，保持名称选中。

右侧容器包含现有 flags 与仅在 `ready-to-query` 状态出现的手动说明，使用可换行 flex 布局。删除身份栏下方原 `ready-to-query` 说明节点，加载、错误和限流信息仍保留原位置。元数据顺序固定为“稀有度 · 大类 · 具体底材 · 赛季”。

## Risks / Trade-offs

- [国服复制类别出现新文案或别名时无法放宽名称] → 安全保持精确查询，并通过表驱动白名单扩展；绝不猜测类别。
- [旧模型携带的类别字段不可信] → 缺少开关默认启用名称，类别只由共享白名单和主进程当前模型重建。
- [某些物品没有具体名称或底材] → 名称行只在存在合法名称时可切换，类别仍作为查询边界；现有固定物品和未鉴定候选流程保持各自约束。
- [身份栏右侧内容拥挤] → 左右区域允许收缩与换行，并用开发版常见长名称、多个状态标签验证。
- [官方过滤代码变动] → 以当前官方目录代码为白名单与测试契约；非法/缺失代码失败关闭，不放宽查询。

## Migration Plan

1. 先加入共享类别解析与模型/序列化测试，再扩展模型和服务路径。
2. 更新浮窗结构与交互测试，修正“意志交锋”样本类别。
3. 运行查价测试、Vite 开发转换、完整测试与 OpenSpec strict，并在开发版核对两种请求体。
4. 若需回滚，恢复旧身份模型和序列化；旧数据无持久迁移，`nameEnabled` 缺失本来就按启用处理。
