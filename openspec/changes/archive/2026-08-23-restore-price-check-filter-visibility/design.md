## Context

名称筛选的数据和查询逻辑仍然有效，回归来自名称按钮在共享过滤行、通用按钮与身份栏样式叠加后缺少稳定、明显的专属状态。状态过滤目前只用组件局部布尔值初始化为折叠，且浮窗窗口会复用；Electron 展示层已经为每次新展示提供递增的 generation，同一次展示的后续状态更新沿用该 generation。

## Goals / Non-Goals

**Goals:**

- 让名称筛选的两种状态在默认、悬浮和键盘焦点下都能立即辨认。
- 只在新展示 generation 开始时恢复状态过滤默认展开。
- 保留同 generation 内用户手动选择的展开状态。

**Non-Goals:**

- 不改变名称筛选模型、官方查询结构或 IPC 契约。
- 不新增全局展开偏好，不恢复独立复选框。
- 不改动总过滤器、查询设置或其他面板的默认折叠行为。

## Decisions

### 使用名称按钮专属的高特异性状态规则

在通用按钮和过滤行规则之后定义名称按钮的中性未选中状态与品牌色选中状态，同时分别覆盖文字颜色。这样既保留整行交互，也避免依赖共享规则的声明顺序。未选择恢复复选框，因为现有契约要求整行状态且用户已确认强化整行选中态。

### 以展示 generation 作为默认状态重置边界

组件初始值设为展开，并记录最近一次有效 presentation generation。收到不同 generation 的快照时恢复展开；相同 generation 的加载、搜索和结果快照不修改局部展开状态。预览模式没有 presentation generation，使用组件初始展开状态并由重置预览重新挂载。

### 保留三态值与查询时机

展开状态仍只控制渲染，不写入模型；generation 切换只重置展开布尔值，不触碰 `stateFilters`，也不调用搜索。

## Risks / Trade-offs

- [旧或异常快照缺少有效 generation 时无法识别新的展示边界] → 保持当前局部状态，不把普通状态更新误判为新查价；正常 Electron 流程已有有效 generation。
- [更明显边框可能引起尺寸跳动] → 选中与未选中均使用相同边框宽度，只改变颜色、背景和文字。
- [工作区已有同组件样式修改] → 仅追加名称专属规则并精确修改状态逻辑，合并而不覆盖现有满高与单滚动改动。
