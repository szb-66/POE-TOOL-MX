## Context

现有共享更新状态已经携带规范化发布说明和真实下载进度，标题栏却直接触发下载。安装服务调用 `quitAndInstall(true, true)` 后 Electron 先关闭窗口，NSIS 静默替换文件，渲染进程无法再接收安装进度。项目使用 assisted NSIS，并保留首次安装时选择安装范围和目录的能力。

## Goals / Non-Goals

**Goals:**

- 在不增加 IPC 的情况下复用共享更新状态完成版本确认和下载进度展示。
- 让退出后的安装阶段使用 NSIS 原生进度值显示数字百分比。
- 仅改变更新路径，保持全新安装和既有安全清理边界。

**Non-Goals:**

- 不在 Vue 中估算安装百分比，也不保持主 Electron 进程跨安装存活。
- 不改变更新源、发布元数据、差分下载或升级记录格式。
- 本次不执行正式打包或发布。

## Decisions

### 标题栏使用版本级、运行期确认记录

更新 store 保存当前运行周期已确认的目标版本。标题栏在 `available` 时展示纯文本确认弹窗，确认后记录版本并下载；在 `downloaded` 时，仅当目标版本尚未确认才补充弹窗。版本变化时旧确认自然失效。该记录不持久化，避免重启后把旧授权扩展到新的安装动作。

备选方案是每次点击都弹窗，但会让手动流程在下载前后重复展示同一内容；持久化确认则会扩大授权时效，均不采用。

### 安装百分比由非静默 NSIS 更新页提供

更新服务在严格清理成功后以非静默、完成后强制运行方式启动安装器。自定义 NSIS include 在 `--updated` 场景强制沿用已检测到的安装范围、跳过 assisted 安装选项，进入原生 InstFiles 页面；定时读取该页面进度条的当前位置并更新中文百分比文本，同时禁用取消按钮。全新安装不命中这些条件。

备选方案是在主应用退出前显示估算进度，但它不能反映文件替换；另建常驻 Electron helper 会增加签名、锁文件和生命周期复杂度，均不采用。

### 安装错误由安装器原生路径负责

主应用退出后不再声明安装完成。NSIS 仅在真实进度到达对应位置时更新数值，失败沿用安装器错误展示；新版本成功启动仍由现有升级记录弹窗确认最终结果。

## Risks / Trade-offs

- [NSIS 控件标识随构建工具升级变化] → 用契约测试锁定 include、更新条件、进度读取和当前 electron-builder 主版本，依赖升级时重新验证。
- [真实体验无法在未打包开发版中端到端验证] → 先完成 Node、Vite 和 OpenSpec 验证；相邻正式安装包验收必须另行获得打包授权。
- [更新进度窗口可能短暂出现 UAC 或系统切换] → 沿用现有安装权限模型，不新增后台提权方式。

## Migration Plan

代码和规范先在开发版完成验证。获得打包授权后，以旧版安装包安装，再从更新元数据升级到新包，确认更新说明、下载百分比、独立安装百分比和自动重启。若安装器定制异常，回滚 include 配置与非静默调用即可恢复现有静默更新路径。
