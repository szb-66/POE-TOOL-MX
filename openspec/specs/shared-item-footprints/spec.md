# shared-item-footprints Specification

## Purpose
为自动入库提供版本化、可审计且运行时离线的物品占位目录，让做装基底与可靠关联的装备外物品获得精确尺寸，并在未知身份或尺寸来源冲突时保持逐格扫描等安全回退行为。
## Requirements
### Requirement: 生成版本化精确占位目录
系统 SHALL 在开发期从同版本的本地做装快照、RePoE 基底数据与腾讯官方中文物品目录生成 `schemaVersion: 1` 的基底级占位目录，并保留来源版本、生成时间、来源哈希和覆盖审计。

#### Scenario: 做装基底精确关联
- **WHEN** 生成目标为当前 POE1 版本
- **THEN** 生成器 MUST 通过本地稳定 `sourceId` 与物品类别关联 RePoE 基底身份，并且全部 995 个做装基底都具有唯一尺寸

#### Scenario: 补充装备外官方物品
- **WHEN** RePoE 繁体中文名称转换为简体后与腾讯官方 `type` 精确相同
- **THEN** 生成器 SHALL 收录该名称，且同名记录只有在尺寸完全一致时才能合并

#### Scenario: 同名异尺寸
- **WHEN** 同一简体名称对应多个尺寸
- **THEN** 生成器 MUST 剔除该身份；若该身份属于 995 个做装基底则整个生成失败

#### Scenario: 类别尺寸不统一
- **WHEN** 一个当前物品类别包含多个尺寸
- **THEN** 生成器 MUST NOT 为该类别输出兜底规则

#### Scenario: 生成门禁失败
- **WHEN** 目标版本、做装快照或 RePoE 版本不一致，或做装覆盖不足，或最终目录含冲突身份
- **THEN** 生成器 MUST 拒绝替换现有内置目录

### Requirement: 共享可信物品占位
系统 SHALL 以规范化物品类别和基底身份共享宽高，并合并内置目录与仓库 API 物品尺寸。

#### Scenario: 仓库物品登记尺寸
- **WHEN** 自动取件归一化一个具有合法 `w/h` 和基底名称的仓库物品
- **THEN** 系统登记该物品身份的宽高供后续自动入库快照使用

#### Scenario: 冲突尺寸
- **WHEN** 同一规范化身份登记了不同宽高
- **THEN** 系统 MUST 将该身份标记为冲突且不得输出到自动入库快照

#### Scenario: 内置目录不可用
- **WHEN** 内置占位目录缺失、版本错误或内容无效
- **THEN** 系统 MUST 使用空内置目录继续运行并允许仓库 API 数据登记

#### Scenario: 未知物品
- **WHEN** 内置目录与仓库 API 学到的尺寸都不能解析物品身份
- **THEN** 系统 MUST 保持尺寸未知并由自动入库执行逐格扫描

### Requirement: 冻结自动入库占位快照
系统 MUST 在每轮自动入库启动时冻结当前可信占位映射，并且运行中不得请求远程尺寸数据。

#### Scenario: 入库启动
- **WHEN** 自动或手动入口启动一轮自动入库
- **THEN** Python 运行配置包含该时刻的可信 `inventory.itemFootprints` 快照

#### Scenario: 入库期间登记新尺寸
- **WHEN** 当前入库运行期间其他功能登记新的仓库物品尺寸
- **THEN** 新尺寸仅作用于后续轮次
