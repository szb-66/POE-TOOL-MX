# enabled-feature-runtime-configuration Specification

## Purpose

为已开启的持续运行功能定义一致的配置热切换、修订顺序、失败回滚和输入动作快照边界，避免界面配置与实际运行状态分叉。

## Requirements

### Requirement: 配置事务提交
系统 MUST 在持续运行功能开启时先规范化并校验候选配置，只有运行时同步成功后才持久化并展示为已生效配置；失败时 MUST 保留并恢复上一份有效配置，同时展示明确错误。

#### Scenario: 有效配置同步成功
- **WHEN** 用户在功能开启期间提交有效详细配置且运行时接受更新
- **THEN** 系统持久化规范化后的配置并将其标记为最新已生效修订

#### Scenario: 配置同步失败
- **WHEN** 候选配置无效、运行时拒绝更新或同步过程失败
- **THEN** 系统继续使用并恢复显示上一份有效配置
- **AND** 功能保持开启且页面显示失败原因

### Requirement: 修订顺序一致
系统 SHALL 为同一功能的运行时配置更新分配单调递增修订，并按提交顺序串行处理；旧修订的迟到结果 MUST NOT 覆盖更新修订。

#### Scenario: 快速连续修改
- **WHEN** 用户在前一次配置同步完成前再次提交配置
- **THEN** 系统按提交顺序处理更新并最终使用最后一次成功修订

### Requirement: 输入动作冻结配置快照
系统 MUST 让已经开始的一轮鼠标键盘输入继续使用启动时配置快照，并让成功提交的新修订从下一轮操作开始生效。

#### Scenario: 执行中修改配置
- **WHEN** 自动入库、仓库取件或商店配方自动化正在执行且用户保存新配置
- **THEN** 当前轮次不改变坐标、规则或动作顺序
- **AND** 下一轮操作使用最新成功修订

### Requirement: 现有持续功能保持热同步
系统 SHALL 让仓库取件、商店配方和国服查价在开启状态下继续同步有效详细配置，并采用相同的失败回滚语义。

#### Scenario: 已开启但没有执行动作
- **WHEN** 用户修改仓库取件、商店配方或查价配置且当前没有输入动作执行
- **THEN** 主进程接收最新配置且功能无需关闭或重新开启

#### Scenario: 查价设置更新
- **WHEN** 用户在查价开启期间成功修改查询设置
- **THEN** 下一次捕获、重查或加载结果使用最新设置
