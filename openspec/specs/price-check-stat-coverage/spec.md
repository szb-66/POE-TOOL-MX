# price-check-stat-coverage Specification

## Purpose

保证国服游戏内可通过官方市集查询的物品与词缀都能被查价器解析并形成有效查询。游戏语义、词缀类型和 stat ID 以国际服官方交易数据为通用层，国服仅覆盖翻译与接口差异；同时为歧义、目录降级和非交易文本提供明确且可恢复的处理路径。

## Requirements

### Requirement: 通用交易语义与国服本地化分层
系统 MUST 保留国际服官方物品与词缀目录中每条结构有效的记录、词缀类型和 stat ID，并以腾讯国服官方目录按相同 ID 覆盖本地化 matcher；同一显示文本对应多个 ID 时 MUST 保留全部候选，不得因无法立即唯一映射或翻译暂缺而静默丢弃。

#### Scenario: 同文案存在多个显式 ID
- **WHEN** 官方目录返回显示文本相同、类型相同但 stat ID 不同的多条词缀
- **THEN** 运行时目录保留所有候选且覆盖审计不报告记录丢失

#### Scenario: 官方目录刷新成功
- **WHEN** 应用取得结构有效的最新官方物品与词缀目录
- **THEN** 系统原子切换到新目录并向查价页面与浮窗公布版本、来源和记录数量

#### Scenario: 新赛季仅新增通用记录
- **WHEN** 国际服官方目录包含国服内置翻译快照尚未覆盖的新 stat ID
- **THEN** 系统保留该 ID 与真实类型，等待国服官方目录按 ID 补充 matcher，并将缺失计入本地化覆盖状态而不是删除记录

#### Scenario: 挂单使用内部币种 ID
- **WHEN** 腾讯搜索结果用 `chrome` 等内部 ID 表示挂牌币种
- **THEN** 系统使用腾讯官方静态交易目录显示“幻色石”等国服名称，同时保留内部 ID 参与统计与查询

### Requirement: 词缀严格按语义解析和映射
系统 SHALL 解析普通复制与详细复制文本中的单行、多行和带数值范围词缀，并 MUST 按真实词缀类型选择同类型 stat ID，不得将缺少对应类型 ID 的词缀回退为其他类型。

#### Scenario: 普通复制中的破碎标记
- **WHEN** 词缀行以游戏提供的 `(fractured)` 类型标记结尾
- **THEN** 系统自动移除该元标记、将词缀分类为 fractured，并只匹配 fractured stat ID

#### Scenario: 详细复制中的破碎前后缀
- **WHEN** 详细复制元数据同时包含破碎标记和 Prefix/Suffix Modifier 或对应国服翻译
- **THEN** 破碎类型优先于前后缀位置，系统自动分类为 fractured，同时可保留前缀或后缀位置作为辅助元数据

#### Scenario: 多行复合词缀
- **WHEN** 一条游戏词缀由多行效果共同对应一个官方 stat
- **THEN** 系统优先把完整多行内容映射为一个查询过滤项且保留全部数值

#### Scenario: 数字文本存在多种占位组合
- **WHEN** 词缀文本中的部分数字是固定语义、其余数字是可查询掷值
- **THEN** 系统尝试受控的占位组合并选择与官方目录及当前上下文一致的映射

#### Scenario: 类型不匹配
- **WHEN** 当前词缀是隐式或工艺词缀但候选仅提供显式 stat ID
- **THEN** 系统不得生成错误类型的过滤项，并将其送入消歧或不可映射处理

#### Scenario: 类型已由游戏文本明确
- **WHEN** 普通复制尾标或详细复制元数据已经明确词缀类型
- **THEN** 系统直接采用该类型，用户无需在 explicit、fractured、implicit、crafted 或 enchant 之间手动判断

### Requirement: 确定性消歧和聚合
系统 MUST 使用词缀类型、物品类别、完整多行文本、词缀元数据和明确的合并规则缩小候选；只有唯一候选或规则明确允许合并时才能自动生成过滤项。

#### Scenario: 物品类别可消除歧义
- **WHEN** 同一文案的多个候选分别适用于武器和护甲且当前物品类别已知
- **THEN** 系统自动选择适用于当前类别的候选

#### Scenario: 多条来源贡献同一可合并属性
- **WHEN** 多条同类型词缀按官方语义共同贡献同一个可查询属性
- **THEN** 系统显示一个聚合过滤项并使用可追溯的合计数值

#### Scenario: 上下文仍不能唯一确定
- **WHEN** 所有确定性规则执行后仍保留多个合法 stat ID
- **THEN** 系统不得猜测其中一个 ID并将全部合法候选交给用户选择

### Requirement: 无法自动映射时仍可完成查价
系统 SHALL 为每条未自动映射的交易词缀显示原因和候选，并 MUST 允许用户选择候选、暂不使用该词缀继续查询或打开官方市集；无法映射的单条词缀不得阻止物品身份及其他已映射条件查价。

#### Scenario: 用户选择词缀候选
- **WHEN** 用户为歧义词缀选择一个候选 stat
- **THEN** 浮窗立即将其变为可勾选过滤项并使用该 stat 重新查询

#### Scenario: 用户跳过歧义词缀
- **WHEN** 用户不选择候选并执行查价
- **THEN** 系统使用物品身份、属性和其他已映射词缀完成查询，并明确标记被排除的条件

#### Scenario: 文本不是官方可交易 stat
- **WHEN** 剪贴板行属于说明、提醒、局部机制或官方目录没有对应 stat
- **THEN** 系统说明其不作为交易过滤项且不伪造候选

### Requirement: 本地展示补丁不得污染交易身份
系统 SHALL 在形成官方查询前移除物品名称末尾、格式明确的本地价格方括号标注，并 MUST 保留不符合价格格式的正式名称内容。

#### Scenario: 名称带本地价格尾标
- **WHEN** 游戏复制文本中的物品名称为 `活木之刃[5c]`、`深海魔甲[50c]` 或同格式的复合通货价格尾标
- **THEN** 系统使用去除尾标后的正式名称与底材形成官方身份查询

#### Scenario: 方括号不是价格尾标
- **WHEN** 名称中的方括号内容不符合数字加受支持通货缩写的尾标格式
- **THEN** 系统不得删除该名称内容

### Requirement: 目录降级期间保持可用
系统 MUST 随开发版提供覆盖常用物品和词缀的完整内置目录；官方目录正在加载或刷新失败时 SHALL 继续使用最近可用目录，并明确显示当前来源、降级原因和重试入口。

#### Scenario: 应用刚启动且官方目录尚未完成
- **WHEN** 用户在官方目录后台刷新完成前触发查价
- **THEN** 系统使用内置目录完成解析和查询且显示正在刷新状态

#### Scenario: 官方目录请求失败
- **WHEN** 官方 stats 或 items 目录因网络、登录或 schema 问题不可用
- **THEN** 系统保留最近可用目录、显示具体失败原因并允许重试，不得退化为仅支持少量手写词缀

### Requirement: 可量化的覆盖验收
系统 MUST 提供可重复执行的覆盖审计，证明结构有效的官方 stat 记录均被保留，报告国际服通用 ID 与国服本地化 ID 的差异，并 SHALL 通过涵盖装备类别、词缀类型、复合词缀和歧义词缀的当前格式及真实国服剪贴板语料回归。

#### Scenario: 官方目录覆盖审计
- **WHEN** 开发版对一份官方 stats/items 响应执行覆盖审计
- **THEN** 报告有效记录总数、保留数、自动唯一映射数、歧义候选数和拒绝原因，且静默丢弃数为零

#### Scenario: 国服物品语料回归
- **WHEN** 回放覆盖普通、魔法、稀有、传奇、未鉴定、腐化、破裂、工艺、附魔、地图、药剂、珠宝、武器和护甲的代表性剪贴板文本
- **THEN** 每件官方可查物品都能形成有效查询，每条交易词缀均处于自动映射或可选择候选状态

#### Scenario: 当前国际服参考格式回归
- **WHEN** 回放当前仍在维护的国际服查价器已覆盖的普通 `(fractured)` 与详细 `Fractured Prefix/Suffix Modifier` 格式
- **THEN** 系统自动恢复 fractured 类型且不要求用户选择词缀类型

### Requirement: 所有受支持官方 stat 类型具有一致来源身份
系统 SHALL 保留并展示官方交易目录中受支持的 `pseudo`、`explicit`、`implicit`、`enchant`、`fractured`、`crafted`、`veiled`、`scourge`、`imbued`、`delve`、`sanctum`、`mercenary`、`crucible` 和 `ultimatum` 类型，且 MUST 在解析、模型清理和查询提交过程中保持类型与 ID namespace 一致。

#### Scenario: 详细文本包含特殊来源
- **WHEN** 当前游戏详细复制文本明确标记任一受支持特殊来源
- **THEN** 系统使用同类型官方 ID、显示对应来源标签且不回退为 `explicit`

#### Scenario: 渲染进程伪造类型
- **WHEN** 渲染进程提交的类型与 stat ID namespace 不一致
- **THEN** 主进程从模型中移除该条件且不得发送官方请求

### Requirement: 综合覆盖可量化且可查询
系统 MUST 对固定综合规则集执行可重复覆盖审计，报告规则总数、可用目标、可用来源、缺失项和被安全省略项，并 SHALL 通过真实物品语料证明生成的综合条件可由腾讯国服官方市集接受。

#### Scenario: 综合规则覆盖审计
- **WHEN** 开发版对内置或刷新后的目录执行综合覆盖审计
- **THEN** 每个启用规则都具有唯一合法 `pseudo.*` 目标和至少一个合法来源，所有缺失均被显式报告

#### Scenario: 跨来源综合回归
- **WHEN** 回放包含单抗、双抗、全抗、属性、生命和法术伤害的详细物品文本
- **THEN** 系统生成预期合计值、保留贡献来源并把启用的 `pseudo.*` 条件写入官方查询 JSON

#### Scenario: 官方查询等价性
- **WHEN** 综合条件查询成功并生成官方 query ID
- **THEN** 打开的腾讯国服官方市集查询包含等价的综合 stat 过滤，不得只在本地浮窗显示

### Requirement: 正负别名保持相同 stat 的符号语义
系统 MUST 使用固定上游数据声明的 matcher 数值方向解析所有官方 stat，SHALL 将负向别名的捕获值转换为负数，并 MUST 保持剪贴板原文、正数显示边界、官方 stat ID 与转换后数值可追溯。系统不得依赖“减慢”“降低”或“减少”等中文词语白名单推断符号。

#### Scenario: 同一 stat 的正负别名
- **WHEN** 一个正向官方 stat 同时具有“加快 #”和带负向元数据的“减慢 #”matcher
- **THEN** 两个文案映射到相同 stat ID，前者产生正值，后者产生绝对值相同的负值

#### Scenario: 非药剂负向词条
- **WHEN** 装备、珠宝、地图或其他受支持物品出现上游标记的负向 matcher
- **THEN** 系统应用与药剂相同的数据驱动符号转换，不需要物品类别专用规则

#### Scenario: 原文与查询语义分离
- **WHEN** 国服市集只显示正向 stat 名称而剪贴板使用其负向文案
- **THEN** 浮窗保留负向原文并以正数编辑边界，官方请求使用可查询的 stat ID 和经过反向、交换后的负数边界

#### Scenario: 负向覆盖审计
- **WHEN** 开发版回放固定上游数据中的全部负向 matcher
- **THEN** 每条记录均命中预期官方 stat ID、产生负值且不存在负向元数据静默丢弃
