# feedback-conversations Specification

## Purpose

让当前安装在不建立公开账号、不接触管理凭据的情况下查看本人反馈、识别开发者是否已经答复，并通过受限文字和私有附件持续完成多轮问答。

## Requirements

### Requirement: 当前安装可查看自己的反馈历史
系统 SHALL 在“问题反馈”中提供“提交反馈”和“我的反馈”视图，并 MUST 只返回当前稳定匿名身份提交的反馈安全字段。

#### Scenario: 进入我的反馈
- **WHEN** 用户进入“我的反馈”且匿名身份有效
- **THEN** 系统按最近活动时间从新到旧展示当前安装提交的反馈
- **AND** 不展示处理状态、提交者 UID、管理备注或服务端凭据

#### Scenario: 其他安装尝试读取反馈
- **WHEN** 当前匿名身份请求不属于自己的反馈或消息
- **THEN** 云端拒绝读取且不返回反馈是否存在的信息

#### Scenario: 手动刷新
- **WHEN** 用户点击刷新
- **THEN** 系统重新读取反馈列表以及当前打开的对话
- **AND** 系统不启动定时轮询

### Requirement: 会话按时间线展示原始问题和双方消息
系统 SHALL 将原始反馈作为会话首条问题，并按创建时间正序展示后续用户和开发者消息及其附件。

#### Scenario: 查看既有反馈
- **WHEN** 用户打开一条在消息表创建前已经存在的反馈
- **THEN** 系统展示原始反馈内容和附件，并显示空的后续消息时间线
- **AND** 不要求复制或回填原始反馈

#### Scenario: 查看多轮问答
- **WHEN** 一条反馈包含多个用户和管理员消息
- **THEN** 系统按服务端创建时间依次展示发送方、正文、时间和附件

### Requirement: 列表明确表示回复进度而不暴露处理状态
系统 SHALL 根据管理员消息是否存在以及最后发送方显示回复进度，且 MUST NOT 将后台处理状态映射给用户。

#### Scenario: 尚无管理员回复
- **WHEN** 对话没有管理员消息
- **THEN** 列表显示“等待回复”

#### Scenario: 管理员最后回复
- **WHEN** 对话最后一条后续消息由管理员发送
- **THEN** 列表显示“已回复”

#### Scenario: 用户在管理员回复后追问
- **WHEN** 对话已有管理员消息且最后一条消息由用户发送
- **THEN** 列表显示“已追问，等待回复”

### Requirement: 用户可向自己的反馈追加幂等回复
系统 SHALL 允许当前匿名身份向自己的反馈追加 1 至 2000 个字符的文字消息，并 MUST 以反馈和客户端消息 ID 的唯一组合防止重复写入。

#### Scenario: 发送文字回复
- **WHEN** 用户向自己的反馈提交合法正文和新的客户端消息 ID
- **THEN** 系统保存一条 `user` 消息并返回服务端消息标识和创建时间
- **AND** 不改变反馈处理状态

#### Scenario: 重复客户端消息 ID
- **WHEN** 同一反馈再次提交已经成功保存的客户端消息 ID
- **THEN** 系统返回既有消息而不新增重复记录

#### Scenario: 回复越权或超过限制
- **WHEN** 用户回复其他身份的反馈、正文无效、每小时超过 20 条或对话已有 200 条后续消息
- **THEN** 系统拒绝写入并返回稳定的安全错误

### Requirement: 后续双方消息支持私有附件
系统 SHALL 允许每条后续消息包含最多 5 个受支持附件，单个不超过 10MB、合计不超过 30MB，并 MUST 只允许反馈参与方通过短期授权访问。

#### Scenario: 用户回复并附带文件
- **WHEN** 用户选择合法附件并发送回复
- **THEN** 系统先上传全部附件再保存消息，并在时间线中提供短期下载地址

#### Scenario: 开发者回复包含附件
- **WHEN** 管理员已向该反馈发送合法附件消息
- **THEN** 当前反馈所属匿名身份可以下载该附件，其他匿名身份不能读取

#### Scenario: 上传或消息保存失败
- **WHEN** 任一附件上传失败或附件已上传但消息写入失败
- **THEN** 系统将发送结果标记为失败并清理本次已上传对象
- **AND** 不显示成功消息或遗留可见的半成品记录
