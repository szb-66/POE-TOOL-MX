# dashboard-home Specification

## Purpose

Define the dashboard home, unified module status, safe common actions, system health summary, and responsive presentation.

## Requirements

### Requirement: 数据看板作为应用首页
系统 SHALL 在根路由展示数据看板，并在侧栏首项提供首页入口，同时保留所有现有业务路由。

#### Scenario: 启动应用
- **WHEN** 用户打开主窗口或访问根路由
- **THEN** 系统显示数据看板而不是重定向到物品模块

#### Scenario: 低高度窗口导航
- **WHEN** 侧栏项目高度超过可用窗口高度
- **THEN** 侧栏允许纵向滚动且所有导航项仍可访问

### Requirement: 七模块统一状态汇总
系统 SHALL 展示物品、背包、地图、战斗、剧情、商城和做装七个模块，并将每个模块归入异常、运行中、需配置或可用中的唯一一种主状态。

#### Scenario: 汇总互斥状态
- **WHEN** 看板计算模块状态
- **THEN** 每个模块只计入一个汇总类别
- **AND** 状态判定优先级为异常、运行中、需配置、可用

#### Scenario: 模块缺少配置
- **WHEN** 模块的关键配置校验失败
- **THEN** 卡片显示首要问题和缺失项数量
- **AND** 用户可以展开查看全部问题
- **AND** 启动操作被禁用

### Requirement: 模块状态反映现有业务事实
系统 MUST 从现有模块状态、当前预设、运行时查询和验证规则派生看板状态，不得维护独立的持久化业务状态副本。

#### Scenario: 运行状态变化
- **WHEN** 模块通过看板、模块页、快捷键或后台生命周期事件改变状态
- **THEN** 看板使用同一业务状态源显示最新结果

#### Scenario: 非运行型模块
- **WHEN** 商城生成有效正则或做装数据目录可用
- **THEN** 对应模块显示为可用
- **AND** 不显示虚假的启停控制

### Requirement: 安全的常用操作
系统 SHALL 在看板提供物品和地图脚本启停、背包检测启停与停止入库、战斗自动喝药启停、剧情浮窗显隐、商城正则复制以及业务页跳转。

#### Scenario: 执行模块操作
- **WHEN** 用户点击可用的常用操作
- **THEN** 系统调用与模块页或快捷键相同的公共业务服务
- **AND** 操作完成前阻止该卡片重复提交

#### Scenario: 高影响操作
- **WHEN** 用户查看战斗、做装或配置型卡片
- **THEN** 首页不提供一键回城、数据更新、重置或详细参数编辑

#### Scenario: 共享脚本被占用
- **WHEN** 物品脚本正在运行且用户查看地图卡片，或反之
- **THEN** 未运行模块的启动操作被禁用
- **AND** 卡片说明共享脚本正被哪个模块占用

### Requirement: 简要系统健康状态
系统 SHALL 展示 Python 可用性、全局快捷键注册结果和游戏窗口 DPI 状态；健康项不计入业务模块汇总。

#### Scenario: 系统环境正常
- **WHEN** 三项系统健康检查均正常
- **THEN** 系统以收起的简要状态呈现

#### Scenario: 系统环境异常
- **WHEN** 任一健康检查失败或需要用户处理
- **THEN** 系统突出显示具体问题并提供设置入口

#### Scenario: 手动刷新
- **WHEN** 用户点击刷新
- **THEN** 系统重新查询运行时和环境状态
- **AND** 系统不启动持续高频轮询

### Requirement: 响应式模块卡片
系统 SHALL 使用现有主题和组件体系展示汇总、健康信息和模块卡片，并适应主窗口宽度。

#### Scenario: 窄窗口
- **WHEN** 可用内容宽度不足以容纳多列卡片
- **THEN** 模块卡片自动降为单列且操作仍可访问
