# crafting-script-startup Specification

## Purpose
统一物品与地图制作的配置校验、脚本生成、后台进程启动及运行状态同步，在仓库选择和通货预检完成前阻止正式制作输入，确保启动结果真实可追踪。

## Requirements
### Requirement: 制作脚本可靠启动
系统 SHALL 在物品制作或地图制作被触发时，完成配置校验、脚本生成、后台进程启动、可选仓库页自动选择和启动通货预检，并且仅在后台进程已确认成功启动后报告进程创建成功。系统 MUST 在共享进程状态中保存对应运行类型，并在进程完整生命周期内同步 renderer 状态；正式制作输入 MUST 等待仓库页选择和启动通货预检全部通过。

#### Scenario: 启动物品制作
- **WHEN** 用户通过页面或已注册快捷键触发物品制作且配置有效、运行环境满足要求
- **THEN** 系统生成物品制作脚本并启动对应 Python 进程
- **AND** 返回真实进程标识、`items` 运行类型并将前端状态同步为运行中
- **AND** Python 进程按配置选择通货仓库页并在正式制作前完成固定通货预检

#### Scenario: 启动地图制作
- **WHEN** 用户通过页面或已注册快捷键触发地图制作且配置有效、运行环境满足要求
- **THEN** 系统生成地图制作脚本并启动对应 Python 进程
- **AND** 返回真实进程标识、`map` 运行类型并将前端状态同步为运行中
- **AND** Python 进程按配置选择通货仓库页并在正式洗图前完成固定通货预检

#### Scenario: 启动阶段立即失败
- **WHEN** Python 解释器、必需模块、脚本文件或进程创建在启动阶段失败
- **THEN** 系统返回包含根因的失败结果
- **AND** 系统停止文件监听并清除进程引用与运行类型
- **AND** 前端不得进入运行中状态

#### Scenario: 启动门禁完成前退出
- **WHEN** 制作进程在仓库页选择或通货预检完成前报告失败或提前退出
- **THEN** 主进程不得返回启动成功，也不得随后用运行中状态覆盖失败状态
- **AND** 已加载的制作浮层显示同一失败原因，而不是持续等待物品信息

#### Scenario: OCR 输出量超过匿名管道容量
- **WHEN** 仓库页识别器初始化期间输出大量模型日志或警告
- **THEN** 制作父进程持续接收该输出且不得等待一个因输出阻塞而无法退出的子进程
- **AND** 识别成功时继续通货预检，识别超时时终止子进程并显示明确原因

#### Scenario: 仓库页选择失败
- **WHEN** 后台进程已启动但通货仓库页自动选择失败
- **THEN** 系统阻止通货预检和正式制作输入并以结构化错误状态结束运行
- **AND** 主界面和置顶浮窗显示相同失败原因

#### Scenario: 通货预检失败
- **WHEN** 后台进程已启动但任一固定通货未通过只读预检
- **THEN** 系统阻止正式制作输入并以结构化错误状态结束运行
- **AND** 主界面和置顶浮窗显示相同失败原因

#### Scenario: 查询当前状态
- **WHEN** renderer 在应用加载或手动刷新时查询共享脚本状态
- **THEN** 系统返回运行状态、真实进程标识以及 `items`、`map` 或空运行类型

#### Scenario: 进程结束
- **WHEN** 共享脚本被手动停止、正常退出或异常退出
- **THEN** 主进程清除进程引用和运行类型
- **AND** 向主窗口发布包含退出状态、运行类型、进程标识、退出码和可用错误信息的结构化事件
- **AND** 前端停止显示对应模块为运行中

### Requirement: 共享启动入口行为一致
系统 MUST 让看板操作、模块页面操作与全局快捷键通过同一个物品制作或地图制作启动函数执行，避免入口之间出现配置、状态或错误处理差异。

#### Scenario: 快捷键分发制作动作
- **WHEN** Electron 发送制作开始或地图开始快捷键事件
- **THEN** 系统分别调用物品制作或地图制作的公共启动函数
- **AND** 每次触发只发起一次后台启动请求

#### Scenario: 看板分发制作动作
- **WHEN** 用户在看板点击物品或地图启动按钮
- **THEN** 系统调用对应公共启动函数
- **AND** 执行与快捷键入口相同的配置校验、启动和状态同步

### Requirement: 制作脚本运行环境校验
系统 SHALL 在写入并启动制作脚本前确认所选 Python 解释器能够导入本次配置实际需要的模块；自动切页关闭时只要求原制作依赖，开启时额外要求离线 OCR、截图和图像处理依赖。

#### Scenario: 自动切页关闭且基础依赖齐全
- **WHEN** Python 具备 `pynput` 和 `pyperclip` 但不具备 OCR 模块，且仓库页自动选择关闭
- **THEN** 系统允许启动原制作流程

#### Scenario: 自动切页开启但 OCR 依赖缺失
- **WHEN** 仓库页自动选择开启且所选 Python 缺少任一 OCR 必需模块
- **THEN** 系统拒绝启动并明确报告仓库页识别依赖缺失
- **AND** 不创建虚假的运行中状态

### Requirement: 物品准备属于制作启动门禁
系统 MUST 在仓库页选择、当前制作模式的全部固定通货预检和目标物品准备均成功后才报告物品制作启动成功。系统 SHALL 为显式词缀或插槽制作加入知识卷轴启动校验，但古灵隐式独占制作 MUST 只校验所选直接余烬或溶液，不得要求知识卷轴坐标或预检结果。

#### Scenario: 非古灵物品制作启动成功
- **WHEN** 仓库页选择、知识卷轴及其他固定通货预检、目标物品读取和必要鉴定均成功
- **THEN** 系统报告 `items` 制作启动成功并允许正式制作输入

#### Scenario: 非古灵制作的知识卷轴不可用
- **WHEN** 显式词缀或插槽制作所需的知识卷轴坐标未配置，或启动预检无法确认该位置为知识卷轴
- **THEN** 系统在点击目标物品前停止启动
- **AND** 不报告运行中状态

#### Scenario: 古灵制作的知识卷轴不可用
- **WHEN** 用户仅启用古灵隐式制作且所选余烬或溶液通过预检，但知识卷轴坐标未配置或不在当前仓库页
- **THEN** 系统继续目标物品准备
- **AND** 不读取、不校验也不点击知识卷轴位置

#### Scenario: 古灵制作目标未鉴定
- **WHEN** 用户仅启用古灵隐式制作且目标物品准备确认装备未鉴定
- **THEN** 系统以“请先鉴定装备”的明确原因停止启动
- **AND** 不报告运行中状态且不使用任何通货

#### Scenario: 物品准备失败
- **WHEN** 当前模式固定通货预检成功但目标物品准备失败
- **THEN** 系统通过现有结构化启动失败通道发布根因
- **AND** 不得随后以运行中状态覆盖失败状态

### Requirement: 地图洗练目标选择
系统 SHALL 在地图洗练公共启动入口读取独立持久化的最后目标，并从对应的地图或海图预设集合读取当前预设来生成和校验脚本。

#### Scenario: 启动航海海图洗练
- **WHEN** 最后选中的目标为航海海图且用户从页面、首页或快捷键启动地图洗练
- **THEN** 三个入口均使用航海海图配置、类别门禁和所需通货清单
### Requirement: 批量物品制作具有独立启动门禁顺序
系统 MUST 在批量模式下依次完成本地扫描快照与候选兼容校验、游戏内全部所选候选身份预检、按全局设置执行的可选通货仓库页选择和固定通货预检，并且只有全部成功后才报告物品制作启动成功。任何阶段失败 MUST 通过结构化启动失败通道结束，且不得随后被运行中状态覆盖。

#### Scenario: 批量制作启动成功
- **WHEN** 本地扫描、候选兼容、全部所选候选身份、通货页选择和固定通货预检全部成功
- **THEN** 系统报告 `items` 制作启动成功并允许第一个候选正式制作

#### Scenario: 背包身份预检失败
- **WHEN** 后台进程已启动但任一冻结候选与游戏内背包不一致
- **THEN** 系统阻止通货页选择、固定通货预检和正式制作输入并发布具体失败原因
- **AND** 主界面和制作浮层不得显示虚假的运行中状态

#### Scenario: 全局自动选页关闭
- **WHEN** 全局仓库页自动选择关闭且候选身份预检成功
- **THEN** 系统不切换仓库页并在当前页面执行固定通货预检

### Requirement: 共享物品制作入口按批量开关一致分发
系统 MUST 让制作页面、首页和已注册制作快捷键调用同一个公共物品制作启动函数，并由该函数读取最新当前预设的批量开关来选择固定坐标单件流程或本地扫描批量流程。

#### Scenario: 批量开关开启
- **WHEN** 当前预设开启批量制作、存在有效本地扫描且用户从任一共享入口启动
- **THEN** 系统只发起一次背包批量制作请求并执行相同门禁

#### Scenario: 批量开关开启但没有扫描
- **WHEN** 当前预设开启批量制作但没有有效本地扫描
- **THEN** 系统阻止启动并引导用户返回制作页打开背包和通货页面后扫描

#### Scenario: 批量开关关闭
- **WHEN** 当前物品预设关闭批量制作且用户从任一共享入口启动
- **THEN** 系统继续执行固定坐标单件制作且不要求本地扫描快照

### Requirement: 批量恢复启动隔离原成员与最新配置
系统 MUST 让批量恢复启动使用原批次目标集合、原顺序、批次标识、已完成目标集合和通货会话标识，同时读取点击当下最新的物品制作预设与设置。恢复启动 MUST 绕过悬浮窗本地扫描 Store，但不得绕过配置、DPI、进程互斥、剩余目标身份、仓库页或通货预检。

#### Scenario: 从失败目标恢复
- **WHEN** 原批次已完成第一项并在第二项异常停止后发起恢复
- **THEN** 恢复配置保留原批次标识和通货会话，只包含第二项及其后的未完成工作
- **AND** 第一项保持计入总完成数但不进入身份预检或制作循环

#### Scenario: 类别选择在失败后变化
- **WHEN** 用户在恢复前修改批量类别选择
- **THEN** 系统不得向原批次增加新目标或移除原批次未完成目标
- **AND** 仍使用最新制作模块和设置处理原批次剩余目标

#### Scenario: 剩余目标核验失败
- **WHEN** 任一未完成目标缺失、身份变化、重复或无法唯一核验
- **THEN** 系统在任何通货输入前停止恢复并返回具体原因
- **AND** 恢复检查点保持可用于用户修正现场后再次尝试或主动重新扫描

#### Scenario: 单件重试不继承批量模式
- **WHEN** 不存在有效批量恢复检查点且单件物品制作异常停止
- **THEN** 系统执行固定坐标单件重试
- **AND** 不得因最新预设中的批量开关而要求背包扫描
