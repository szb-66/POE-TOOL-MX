## Requirements
### Requirement: 制作脚本可靠启动
系统 SHALL 在物品制作或地图制作被触发时，完成配置校验、脚本生成、后台进程启动、可选仓库页自动选择和启动通货预检，并且仅在后台进程已确认成功启动后报告进程创建成功。系统 MUST 在共享进程状态中保存对应运行类型，并在进程完整生命周期内同步 renderer 状态；正式制作输入 MUST 等待仓库页选择和启动通货预检全部通过。

#### Scenario: 启动物品制作
- **WHEN** 用户通过页面或已注册快捷键触发物品制作且配置有效、运行环境满足要求
- **THEN** 系统生成物品制作脚本并启动对应 Python 进程
- **AND** 返回真实进程标识、`items` 运行类型并将前端状态同步为运行中
- **AND** Python 进程按配置选择通货仓库页并在正式制作前完成固定通货预检

#### Scenario: 启动地图制作
- **WHEN** 用户通过页面或已注册快捷键触发地图制作且配置有效、运行环境满足要求
- **THEN** 系统生成地图制作脚本并启动对应 Python 进程
- **AND** 返回真实进程标识、`map` 运行类型并将前端状态同步为运行中
- **AND** Python 进程按配置选择通货仓库页并在正式洗图前完成固定通货预检

#### Scenario: 启动阶段立即失败
- **WHEN** Python 解释器、必需模块、脚本文件或进程创建在启动阶段失败
- **THEN** 系统返回包含根因的失败结果
- **AND** 系统停止文件监听并清除进程引用与运行类型
- **AND** 前端不得进入运行中状态

#### Scenario: 启动门禁完成前退出
- **WHEN** 制作进程在仓库页选择或通货预检完成前报告失败或提前退出
- **THEN** 主进程不得返回启动成功，也不得随后用运行中状态覆盖失败状态
- **AND** 已加载的制作浮层显示同一失败原因，而不是持续等待物品信息

#### Scenario: OCR 输出量超过匿名管道容量
- **WHEN** 仓库页识别器初始化期间输出大量模型日志或警告
- **THEN** 制作父进程持续接收该输出且不得等待一个因输出阻塞而无法退出的子进程
- **AND** 识别成功时继续通货预检，识别超时时终止子进程并显示明确原因

#### Scenario: 仓库页选择失败
- **WHEN** 后台进程已启动但通货仓库页自动选择失败
- **THEN** 系统阻止通货预检和正式制作输入并以结构化错误状态结束运行
- **AND** 主界面和置顶浮窗显示相同失败原因

#### Scenario: 通货预检失败
- **WHEN** 后台进程已启动但任一固定通货未通过只读预检
- **THEN** 系统阻止正式制作输入并以结构化错误状态结束运行
- **AND** 主界面和置顶浮窗显示相同失败原因

#### Scenario: 查询当前状态
- **WHEN** renderer 在应用加载或手动刷新时查询共享脚本状态
- **THEN** 系统返回运行状态、真实进程标识以及 `items`、`map` 或空运行类型

#### Scenario: 进程结束
- **WHEN** 共享脚本被手动停止、正常退出或异常退出
- **THEN** 主进程清除进程引用和运行类型
- **AND** 向主窗口发布包含退出状态、运行类型、进程标识、退出码和可用错误信息的结构化事件
- **AND** 前端停止显示对应模块为运行中

### Requirement: 共享启动入口行为一致
系统 MUST 让看板操作、模块页面操作与全局快捷键通过同一个物品制作或地图制作启动函数执行，避免入口之间出现配置、状态或错误处理差异。

#### Scenario: 快捷键分发制作动作
- **WHEN** Electron 发送物品开始或地图开始快捷键事件
- **THEN** 系统分别调用物品制作或地图制作的公共启动函数
- **AND** 每次触发只发起一次后台启动请求

#### Scenario: 看板分发制作动作
- **WHEN** 用户在看板点击物品或地图启动按钮
- **THEN** 系统调用对应公共启动函数
- **AND** 执行与快捷键入口相同的配置校验、启动和状态同步

### Requirement: 制作脚本运行环境校验
系统 SHALL 在写入并启动制作脚本前确认所选 Python 解释器能够导入本次配置实际需要的模块；自动切页关闭时只要求原制作依赖，开启时额外要求离线 OCR、截图和图像处理依赖。

#### Scenario: 自动切页关闭且基础依赖齐全
- **WHEN** Python 具备 `pynput` 和 `pyperclip` 但不具备 OCR 模块，且仓库页自动选择关闭
- **THEN** 系统允许启动原制作流程

#### Scenario: 自动切页开启但 OCR 依赖缺失
- **WHEN** 仓库页自动选择开启且所选 Python 缺少任一 OCR 必需模块
- **THEN** 系统拒绝启动并明确报告仓库页识别依赖缺失
- **AND** 不创建虚假的运行中状态

### Requirement: 物品准备属于制作启动门禁
系统 SHALL 将知识卷轴加入物品制作启动通货清单与坐标校验，并 MUST 在仓库页选择、全部固定通货预检和目标物品准备均成功后才报告物品制作启动成功。

#### Scenario: 物品制作启动成功
- **WHEN** 仓库页选择、知识卷轴及其他固定通货预检、目标物品读取和必要鉴定均成功
- **THEN** 系统报告 `items` 制作启动成功并允许正式制作输入

#### Scenario: 知识卷轴不可用
- **WHEN** 知识卷轴坐标未配置或启动预检无法确认该位置为知识卷轴
- **THEN** 系统在点击目标物品前停止启动
- **AND** 不报告运行中状态

#### Scenario: 物品准备失败
- **WHEN** 固定通货预检成功但目标物品准备失败
- **THEN** 系统通过现有结构化启动失败通道发布根因
- **AND** 不得随后以运行中状态覆盖失败状态
