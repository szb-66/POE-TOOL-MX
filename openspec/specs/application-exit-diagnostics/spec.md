# application-exit-diagnostics Specification

## Purpose

为偶发应用退出提供可关联的本地现场证据，区分退出请求、清理过程以及检测子进程终止，帮助后续依据真实运行时序定位根因，同时保持现有退出和自动操作行为。

## Requirements

### Requirement: 退出来源和会话关联
系统 SHALL 记录退出请求来源、清理开始和结束、退出生命周期及最终退出码，并通过会话标识和主进程 ID 关联。来源覆盖窗口 IPC、原生窗口关闭、关闭选择、托盘、全部窗口关闭、更新、重启、诊断退出及致命异常，未知来源 MUST 明确标记。

#### Scenario: 清理后二次退出
- **WHEN** 已标记来源的退出在清理完成后再次请求退出
- **THEN** 记录保留最初来源并包含最终退出事件

#### Scenario: 托盘或关闭提示拦截
- **WHEN** 关闭窗口被转为隐藏托盘或等待关闭选择
- **THEN** 可以记录关闭候选，但不得将其标记为已请求应用退出

### Requirement: 检测子进程生命周期
系统 SHALL 记录每个检测实例的标识、PID、启动、最后事件时间、消费者、停止原因以及 error、exit、close 的退出码和信号，区分正常停止、配置重启与意外退出，并启用 Python 故障堆栈输出。

#### Scenario: 旧进程延迟结束
- **WHEN** 配置重启后的旧检测实例才触发 close
- **THEN** 旧实例的结束仍可追踪且不覆盖新实例状态

#### Scenario: 无堆栈异常退出
- **WHEN** 检测实例异常退出且没有 stderr
- **THEN** 保存退出码和信号及异常分类，保留既有失败通知，不主动关闭应用或增加恢复策略

### Requirement: 有界安全诊断
系统 SHALL 复用现有日志轮转及脱敏，限制错误输出长度，仅增加进程和生命周期信息；诊断失败 MUST 不干扰业务流程。

#### Scenario: 日志不可写
- **WHEN** 诊断记录抛错或本地日志无法写入
- **THEN** 检测和退出逻辑继续按既有行为运行
