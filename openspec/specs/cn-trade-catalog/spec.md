# cn-trade-catalog Specification

## Purpose

定义国服交易目录的版本元数据、结构校验、腾讯官方数据加载、内置目录安全降级、陈旧状态提示以及离线目录可重复生成和失败处理行为。

## Requirements

### Requirement: 使用版本化国服交易目录
系统 SHALL 随应用提供包含 schema 版本、游戏版本、locale、生成时间、物品名称、底材、传奇标记和词缀映射的国服交易目录。

#### Scenario: 加载有效目录
- **WHEN** 目录结构有效且每个 ID 与 matcher 唯一
- **THEN** 系统加载目录并向查价页报告版本和物品、词缀记录数

#### Scenario: 目录损坏
- **WHEN** 目录缺少元数据、存在重复 ID 或记录结构无效
- **THEN** 系统禁用依赖损坏数据的查询并返回可诊断的目录错误

#### Scenario: 获取腾讯官方交易元数据
- **WHEN** 应用启动且腾讯官方 `/api/trade/data/stats` 与 `/api/trade/data/items` 返回有效目录
- **THEN** 系统使用官方中文 matcher、stat ID、传奇名称和底材构建运行时目录并报告记录数量

#### Scenario: 官方交易元数据不可用
- **WHEN** 任一官方目录请求失败或响应结构无效
- **THEN** 系统回退版本化内置目录并明确报告降级状态

### Requirement: 目录陈旧时安全降级
系统 SHALL 根据目录游戏版本与时间报告陈旧状态，并 MUST 禁止使用不能可靠映射的词缀。

#### Scenario: 陈旧目录中的已知名称
- **WHEN** 目录陈旧但固定物品名称仍能唯一匹配
- **THEN** 系统允许名称查询并展示陈旧警告

#### Scenario: 陈旧目录中的未知词缀
- **WHEN** 词缀不在活动目录中
- **THEN** 系统将其标为未识别且不构造近似 stat ID

### Requirement: 可重复生成与校验目录
系统 SHALL 提供从受支持 NDJSON 输入生成目录的脚本，并 SHALL 在重复映射、空 stat ID 或无效 matcher 时失败。

#### Scenario: 相同输入重复生成
- **WHEN** 使用相同输入与版本参数执行生成器
- **THEN** 除显式生成时间外目录内容和排序保持一致

### Requirement: S30 官方交易目录兼容验证
系统 SHALL 在开发版通过认证契约验证腾讯国服官方赛季列表可返回并透明传递 S30 正式赛季 ID，并通过公开请求验证物品目录、词缀目录仍符合客户端 schema。内置交易目录 SHALL 明确报告自身版本和降级状态，不得冒充最新在线目录。

#### Scenario: S30 在线元数据可用
- **WHEN** 已认证的腾讯官方赛季接口返回 S30 ID，且公开物品和词缀接口返回有效数据
- **THEN** 系统使用官方赛季 ID 构造目录与查询并报告非降级状态

#### Scenario: S30 在线元数据不可用
- **WHEN** 官方接口不可用或响应结构不兼容
- **THEN** 系统使用已校验的内置目录安全降级
- **AND** 向用户报告降级而不构造未知词缀映射

#### Scenario: 已认证账号选择 S30
- **WHEN** 认证赛季列表返回 S30 赛季 ID
- **THEN** 查价与仓库请求使用同一 ID 且不改写中文或空格

#### Scenario: 未登录开发环境
- **WHEN** 未携带认证访问赛季列表并收到 401
- **THEN** 系统保留内置目录降级能力并通过契约测试验证请求结构

#### Scenario: 未登录访问赛季列表
- **WHEN** 开发环境未携带账号认证访问赛季列表并收到 401
- **THEN** 系统将其报告为认证边界而不是 schema 不兼容
- **AND** 使用契约测试验证赛季 ID 在查价与仓库请求中不被改写

### Requirement: 交易目录携带稳定 stat 引用和综合规则
版本化国服交易目录 SHALL 为可参与综合计算的官方 stat 保留稳定引用，并 SHALL 携带固定来源版本、目标引用、来源引用、倍率、必需性、替代组和默认启用语义明确的综合规则。

#### Scenario: 生成带引用的目录
- **WHEN** 目录生成器把当前游戏描述与国际服、腾讯国服官方 stat 目录合并
- **THEN** 系统按官方 ID 关联稳定引用，同时保留国服 matcher、真实 namespace 和来源版本

#### Scenario: 加载有效综合规则
- **WHEN** 每条综合规则的目标可唯一解析为 `pseudo.*` 且每个来源引用结构有效
- **THEN** 目录通过 schema 校验并允许运行时生成综合条件

#### Scenario: 拒绝损坏综合规则
- **WHEN** 规则包含重复身份、空引用、非法倍率、未知目标类型或不完整来源定义
- **THEN** 目录校验失败并返回可诊断错误，不得加载部分规则继续计算

### Requirement: 在线与内置目录保持综合规则一致
系统 SHALL 在官方目录刷新时保留并重新关联版本化综合规则，且 MUST 仅使用刷新后仍存在的官方 stat ID生成综合条件。

#### Scenario: 在线刷新成功
- **WHEN** 腾讯国服官方 stats/items/static 响应通过校验
- **THEN** 系统用最新官方 ID和中文 matcher重建引用索引，并报告综合规则目标、来源和缺失数量

#### Scenario: 在线规则目标已移除
- **WHEN** 最新官方目录移除某个综合目标或必要来源
- **THEN** 覆盖审计明确报告该规则不可用，运行时不生成对应条件且不得回退到陈旧 ID

#### Scenario: 官方刷新失败
- **WHEN** 官方目录不可用而系统回退内置目录
- **THEN** 系统使用与该内置目录同版本且已校验的综合规则继续生成可查询条件

### Requirement: 传奇快照携带真实属性匹配数据
系统 SHALL 在当前补丁的版本化传奇快照中按“传奇名称 + 底材”保存从可信数据页提取并规范化的真实传奇属性 matcher，MUST 排除属性解释节点，并 MUST 对快照 schema 与 matcher 结构进行完整校验。

#### Scenario: 生成传奇真实属性
- **WHEN** 数据页中的传奇物品包含带固定文本、数值或数值范围的真实属性
- **THEN** 系统为该物品生成稳定 matcher，将属性数值位置规范化为占位符并保留其他固定数字与文字

#### Scenario: 排除解释节点
- **WHEN** 传奇属性区域包含仅用于解释机制的说明节点
- **THEN** 该节点不写入真实属性 matcher

#### Scenario: 拒绝损坏的传奇快照
- **WHEN** 传奇快照 schema 不兼容，或任一当前补丁物品缺少合法 matcher 数组
- **THEN** 系统拒绝把该快照作为完整传奇属性覆盖加载，并报告可诊断的降级状态

### Requirement: 本地传奇属性元数据增强运行时目录
系统 MUST 在首次查价前用有效本地传奇快照增强内置物品目录，并 SHALL 在腾讯官方物品目录刷新后按相同身份重新关联传奇属性 matcher。系统 MUST NOT 因官方目录刷新失败而丢失已经加载的本地传奇属性元数据。

#### Scenario: 官方目录刷新成功
- **WHEN** 官方物品目录中的传奇名称和底材能匹配当前补丁传奇快照
- **THEN** 运行时物品记录携带该身份的真实属性 matcher 和完整覆盖标记

#### Scenario: 官方目录刷新失败
- **WHEN** 本地传奇快照有效但腾讯官方目录不可用
- **THEN** 系统继续使用已增强的内置目录识别传奇属性，并将交易目录报告为降级状态

#### Scenario: 本地传奇快照不可用
- **WHEN** 本地传奇快照缺失、损坏或 schema 不兼容
- **THEN** 系统保留未增强目录与既有查价行为，显示本地快照降级警告且不得猜测传奇属性集合

### Requirement: 交易目录保留 matcher 数值方向
系统 MUST 为上游声明为负向的词缀 matcher 保存可校验的数值变换元数据，并 MUST 在固定目录生成、简繁转换、官方目录刷新、内置降级和运行时匹配期间保持该元数据。负向 matcher MUST 属于同一 stat 的 matcher 集合，且不带负向标记的 matcher SHALL 使用原始捕获值。

#### Scenario: 固定英文数据包含负向 matcher
- **WHEN** 固定 Awakened PoE Trade 定义为同一 stat 提供正向 matcher 和带 `negate` 的负向 matcher
- **THEN** 生成目录同时保存两个 matcher，并只为负向 matcher记录数值乘以 `-1` 的变换

#### Scenario: 简繁中文负向 matcher
- **WHEN** 固定中文游戏描述中的 matcher 带有负向标记并转换为简体中文
- **THEN** 转换后的 matcher 继续携带相同负向数值变换并映射到原官方 stat ID

#### Scenario: 官方刷新合并 matcher
- **WHEN** 在线官方目录刷新并合并内置 matcher
- **THEN** 系统保留已有负向变换且不会因去重、别名扩展或原子替换而丢失

#### Scenario: 拒绝损坏的负向元数据
- **WHEN** 目录中的负向 matcher 不属于对应 stat、重复冲突或使用不受支持的数值变换
- **THEN** 目录校验失败且运行时继续使用最近可信目录

### Requirement: 交易目录保留航海海图区域身份
版本化内置目录与在线刷新后的运行时目录 SHALL 为每个航海海图区域保留官方 `chart` 大类、内部区域类型、官方中文显示名、discriminator 和版本化国服复制文本别名。每个规范化显示名或别名 MUST 最多解析到一个区域身份。

#### Scenario: 从官方目录生成海图记录
- **WHEN** 腾讯官方物品目录在 `chart` 分组返回带 `disc=chart` 的区域记录
- **THEN** 运行时目录保留分组、大类、内部类型和从官方文本取得的中文显示名

#### Scenario: 在线刷新合并版本化别名
- **WHEN** 官方海图区域记录与内置目录具有相同内部类型和 discriminator
- **THEN** 系统把内置的国服复制文本别名重新关联到在线记录，不因刷新丢失当前游戏文本解析能力

#### Scenario: 内置目录安全降级
- **WHEN** 官方物品目录刷新失败
- **THEN** 系统使用已校验内置海图区域记录和别名继续解析，并报告既有目录降级状态

#### Scenario: 拒绝歧义海图别名
- **WHEN** 目录中的同一规范化海图显示名或别名指向多个内部区域类型
- **THEN** 目录校验失败并返回可诊断错误，不得加载部分歧义映射

### Requirement: 海图身份元数据可重复生成
离线目录生成流程 SHALL 从固定版本的官方物品数据与国服复制文本别名输入生成确定性的海图身份元数据，并 MUST 覆盖当前官方海图区域集合。

#### Scenario: 相同海图输入重复生成
- **WHEN** 使用相同官方目录快照、别名表和版本参数重复生成目录
- **THEN** 海图区域记录、别名排序和内部类型保持一致

#### Scenario: 海图区域缺少身份字段
- **WHEN** 任一声明的海图区域缺少内部类型、官方显示名或合法国服别名集合
- **THEN** 生成或目录校验失败，不得产出声称完整的海图目录
