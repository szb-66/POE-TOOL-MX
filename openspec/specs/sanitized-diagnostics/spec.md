# sanitized-diagnostics Specification

## Purpose

为公开发布后的远程排错提供稳定、可保存的环境信息，同时在诊断生成阶段排除登录凭据、账号内容和可识别用户身份的本地路径。

## Requirements

### Requirement: 生成稳定诊断快照
系统 SHALL 生成 schema v2 JSON 快照，包含随机诊断标识、生成时间、应用版本与运行环境、操作系统、CPU 架构、管理员状态、显示器布局、DPI、游戏窗口、运行时、白名单健康状态、带稳定原因码的模块状态以及最近结构化故障事件，不得生成持久设备标识。

#### Scenario: 生成成功
- **WHEN** 用户请求生成诊断信息
- **THEN** 系统返回带有 schema 版本、随机诊断标识与生成时间的结构化快照

#### Scenario: 部分探测失败
- **WHEN** 某项系统、游戏或事件存储探测不可用
- **THEN** 快照保留其他项目，并以安全状态或原因码表示失败而不是整体失败

#### Scenario: 渲染进程提供状态
- **WHEN** 首页提交模块和渲染进程健康状态
- **THEN** 主进程只接受允许的标识、状态和原因码且丢弃所有自由文本与额外字段

### Requirement: 诊断数据脱敏
系统 MUST 在主进程生成诊断内容时排除 Cookie、POESESSID、Authorization、Bearer 或会话令牌、账号标识、邮件、IP 地址、仓库内容、预设内容、剪贴板文本、完整本地路径和 UNC 路径，并在最终序列化前对所有字符串再次执行防御性脱敏。

#### Scenario: 本地路径包含用户名
- **WHEN** 任意诊断文本包含大小写不同的用户目录、正反斜杠绝对路径或 UNC 路径
- **THEN** 诊断不包含用户名或完整绝对路径

#### Scenario: 账号已登录
- **WHEN** 用户已经登录国服账号并生成诊断
- **THEN** 诊断中不存在 Cookie、会话值、账号 ID、邮件、IP 地址或仓库数据

#### Scenario: 凭据采用常见文本格式
- **WHEN** 错误文本包含带引号、空格、URL 参数或 Bearer 前缀的凭据
- **THEN** 最终诊断不包含凭据原值

### Requirement: 用户主动导出
系统 SHALL 只在用户主动操作时显示保存位置并写出格式化单个 JSON，不得自动上传诊断；取消和写入失败不得泄露目标路径。

#### Scenario: 保存诊断
- **WHEN** 用户选择导出并确认目标文件
- **THEN** 系统将当前脱敏快照保存到该文件并仅反馈文件名

#### Scenario: 取消保存
- **WHEN** 用户取消保存对话框
- **THEN** 系统不执行诊断探测、不创建文件且首页不显示失败消息

#### Scenario: 写入失败
- **WHEN** 目标文件不可写
- **THEN** 系统返回稳定错误码和安全中文提示且不包含完整目标路径
