# application-update Specification

## Purpose

定义 Windows 客户端在应用内安全地获取稳定版本信息、下载更新并在用户明确确认后安装的可观测行为，同时保证网络或清理失败不影响主要功能。

## Requirements

### Requirement: 应用内更新信息
系统 SHALL 在设置页展示当前版本、检查状态，并在发现稳定新版本时展示版本号、发布时间和安全 Markdown 发布说明。

#### Scenario: 发现新版本
- **WHEN** 更新源返回高于当前版本的稳定版本
- **THEN** 设置页展示可用版本、发布时间、安全 Markdown 发布说明和下载操作

#### Scenario: 已是最新版本
- **WHEN** 手动检查未发现更高的稳定版本
- **THEN** 系统明确显示当前已是最新版本

### Requirement: 安全的更新说明 Markdown 展示
系统 MUST 使用同一安全规则在各更新说明入口展示 Markdown，并 MUST NOT 将发布说明作为原始 HTML 注入界面。系统 SHALL 识别一至六级标题、段落、有序与无序列表、粗体、斜体、行内代码和 HTTP(S) 链接。

#### Scenario: 展示常用 Markdown
- **WHEN** 发布说明包含受支持的标题、列表和行内标记
- **THEN** 系统在升级后弹窗、下载前确认弹窗和设置页中呈现一致的语义层级

#### Scenario: 原始 HTML 不执行
- **WHEN** 发布说明包含 HTML 标签、脚本或事件属性
- **THEN** 系统将它们显示为可读文字且不创建可执行 HTML

#### Scenario: 链接协议受限
- **WHEN** 发布说明包含 HTTP(S) 链接以外的协议或无效链接
- **THEN** 系统仅以普通文字显示该链接内容且不发起导航

#### Scenario: 无效语法可读降级
- **WHEN** 发布说明包含不支持或未闭合的 Markdown 语法
- **THEN** 系统保留可读原文而不静默丢失内容

### Requirement: 可配置的检查与下载
系统 SHALL 默认使用手动更新模式，并 SHALL 持久化用户选择的手动或自动模式。每次主窗口启动 MUST 在同步已保存的更新模式和来源后立即发起一次后台检查，且 MUST NOT 因等待检查而阻塞主窗口或离线功能。

#### Scenario: 手动模式
- **WHEN** 应用以手动更新模式启动并完成所保存来源的配置
- **THEN** 系统立即后台检查一次，发现新版本时只显示提示且不自动下载

#### Scenario: 自动模式
- **WHEN** 应用以自动更新模式启动并完成所保存来源的配置
- **THEN** 系统立即后台检查一次，之后每六小时检查，并在发现更新后自动下载

#### Scenario: 防止并发检查
- **WHEN** 检查、下载或安装已在进行且又收到重复更新操作
- **THEN** 系统拒绝重复操作并保持当前任务

### Requirement: 可观测的下载状态
系统 SHALL 在下载期间向共享更新状态发布进度、传输量和下载完成状态，并 SHALL 让标题栏与设置页观测同一份状态。

#### Scenario: 下载进行中
- **WHEN** 更新包正在下载
- **THEN** 标题栏持续显示百分比，设置页同时显示百分比和已传输数据量

#### Scenario: 下载完成
- **WHEN** 更新包验证并下载完成
- **THEN** 系统在标题栏和设置页显示安装操作且 MUST NOT 自行重启

### Requirement: 可见的安装进度
系统 SHALL 在主应用退出后立即显示独立的 Windows 更新安装窗口，以真实安装进度控件展示数字百分比，并 SHALL 在安装成功后自动重新运行应用。

#### Scenario: 安装正在进行
- **WHEN** 已下载更新完成资源清理并开始替换应用文件
- **THEN** 独立安装窗口持续显示“正在安装更新：<百分比>%”，且百分比来自安装器真实进度而非时间估算

#### Scenario: 安装完成
- **WHEN** 安装器成功完成文件替换和安装登记
- **THEN** 安装窗口完成并自动启动已安装的新版本

#### Scenario: 安装失败
- **WHEN** 安装器无法完成更新
- **THEN** 安装器显示真实错误且不得虚假显示安装成功或完成百分比

### Requirement: 安全的确认安装
系统 MUST 在目标版本更新内容已向用户显示且用户明确选择更新后才下载或安装该版本。手动下载完成后，系统 MUST 只在用户再次点击已就绪的安装入口后安装；自动下载完成但本次运行尚未确认的版本 MUST 在安装前补充展示更新内容并请求确认。系统 MUST 在安装前完成受管资源清理，并 SHALL 在安装完成后重新运行应用。

#### Scenario: 手动模式确认下载
- **WHEN** 用户点击标题栏的新版本入口
- **THEN** 系统以安全 Markdown 展示版本号、发布时间和更新内容，并仅在用户选择下载更新后开始下载

#### Scenario: 用户暂不更新
- **WHEN** 用户关闭更新内容或选择暂不更新
- **THEN** 系统不下载、不安装，并保持该版本仍可由标题栏再次打开

#### Scenario: 手动下载后安装
- **WHEN** 用户已确认当前目标版本、下载完成并再次点击安装入口
- **THEN** 系统保存升级记录、完成受管资源清理、退出当前实例并启动可见安装流程

#### Scenario: 自动下载后补充确认
- **WHEN** 自动模式已下载目标版本但本次运行尚未向用户确认该版本
- **THEN** 用户点击安装入口时先看到更新内容，且仅在确认后进入安装流程

#### Scenario: 清理成功
- **WHEN** 用户已授权安装且受管资源全部清理成功
- **THEN** 系统退出当前实例、打开可见更新安装窗口并在安装完成后重新运行应用

#### Scenario: 清理失败或超时
- **WHEN** 用户已授权安装但资源清理失败或超时
- **THEN** 系统不得调用更新安装，并通过共享退出流程受控结束当前实例

### Requirement: 标题栏更新入口
系统 SHALL 在主窗口标题文字右侧显示与设置页共享的更新状态入口，并 MUST 使两个入口的操作使用同一并发门禁。标题栏入口 SHALL 负责更新内容确认，而设置页继续展示同一版本信息和操作状态。

#### Scenario: 发现新版本
- **WHEN** 已检查到稳定新版本且尚未开始下载
- **THEN** 标题栏显示“发现新版本 v<版本>”，点击后先展示更新内容和下载选择而不直接下载

#### Scenario: 下载进行中
- **WHEN** 更新包正在下载
- **THEN** 标题栏同一位置显示“下载中 <百分比>%”且不接受重复下载操作

#### Scenario: 更新已就绪
- **WHEN** 更新包已验证并下载完成
- **THEN** 标题栏同一位置显示“更新已就绪，点击安装”并继续允许用户使用当前实例

#### Scenario: 已确认版本不重复弹窗
- **WHEN** 用户在当前运行周期已确认目标版本并在下载完成后点击安装
- **THEN** 系统直接进入单次安装授权流程而不重复展示更新内容

#### Scenario: 目标版本发生变化
- **WHEN** 共享更新状态切换到另一个目标版本
- **THEN** 先前确认不适用于新版本，新版本入口再次展示对应更新内容

#### Scenario: 无更新相关状态
- **WHEN** 未发现新版本或检查失败
- **THEN** 标题栏不显示更新入口，检查错误仍可在设置页查看和重试

### Requirement: 升级后更新内容
系统 MUST 在安装前持久化目标版本和原始 Markdown 更新内容，并 SHALL 在该目标版本首次成功打开主窗口后以样式完整的安全 Markdown 弹窗展示一次。

#### Scenario: 目标版本首次启动
- **WHEN** 当前应用版本与待展示记录的目标版本一致且主窗口已成功加载
- **THEN** 系统以具有正常宽度、间距、居中布局、关闭和确认操作的安全 Markdown 弹窗展示版本号和更新内容

#### Scenario: 更新内容已展示
- **WHEN** 升级后弹窗已向用户显示
- **THEN** 系统确认该记录已读并不在后续启动中重复展示

#### Scenario: 待展示版本不匹配
- **WHEN** 待展示记录的目标版本与当前应用版本不一致
- **THEN** 系统不弹出错误版本的更新内容且不影响应用启动

### Requirement: 发布元数据包含更新内容
每个可供应用内更新的正式版本 MUST 在两个正式更新源共用的 `latest.yml` 中包含与该版本匹配的非空 Markdown 发布说明。

#### Scenario: 发布元数据完整
- **WHEN** 正式版本进入发布资产校验
- **THEN** 校验同时确认元数据版本、安装包、摘要和非空 Markdown 发布说明一致

#### Scenario: 发布说明缺失
- **WHEN** 对应版本的发布说明文件缺失或内容为空
- **THEN** 发布流程失败且不发布不完整的更新元数据

### Requirement: 更新失败隔离
网络、元数据或下载失败 MUST NOT 阻止应用启动或影响离线功能，并 SHALL 仅对界面暴露脱敏错误。

#### Scenario: 自动检查失败
- **WHEN** 自动检查因网络不可用而失败
- **THEN** 应用继续正常运行，更新状态记录可重试错误且不泄露本地路径或凭据

#### Scenario: 预发布或降级版本
- **WHEN** 更新源出现预发布版本或低于当前版本的版本
- **THEN** 系统不下载且不安装该版本

### Requirement: 用户可选正式更新源
正式 Windows 客户端 SHALL 默认使用 CNB 仓库 `Auto-Tool-MX/POE-TOOL-MX` 的 Latest Release，并 SHALL 允许用户手动切换到同版本 GitHub Release；所选来源 MUST 持久化并统一用于更新元数据、安装包和差分块映射。

#### Scenario: 首次使用默认来源
- **WHEN** 用户没有保存过更新来源设置
- **THEN** 客户端选择 CNB 作为更新来源并在设置中标记为国内推荐

#### Scenario: 手动切换来源
- **WHEN** 当前没有进行检查或下载且用户选择 CNB 或 GitHub
- **THEN** 客户端持久化所选来源，并让之后的检查和下载使用对应 Latest Release

#### Scenario: 更新操作进行中
- **WHEN** 客户端正在检查或下载更新
- **THEN** 设置界面禁止切换来源，避免同一次更新跨来源混用资产

#### Scenario: 检查并下载稳定更新
- **WHEN** 已安装客户端从所选来源的 `latest.yml` 检查到高于当前版本的稳定版本并开始下载
- **THEN** 客户端从同一来源获取安装包及 `.blockmap`，并继续执行现有摘要校验、进度展示和确认安装流程

#### Scenario: 所选更新源不可用
- **WHEN** 所选来源的元数据或更新资产请求失败、超时或返回无效内容
- **THEN** 客户端按既有更新失败隔离规则继续运行，显示当前来源并允许用户手动切换后重试，不自动改用另一来源且不影响离线功能
