# game-display-dpi Specification

## Purpose

定义 Windows 环境下游戏窗口 DPI 的自动识别、手动覆盖、失败回退、运行时刷新和旧配置迁移行为。

## Requirements

### Requirement: 自动检测游戏窗口 DPI
系统 MUST 在 Windows 上识别中文或英文《流放之路》顶层窗口，并读取所选游戏窗口的实际 DPI 倍率。

#### Scenario: 前台游戏窗口存在
- **WHEN** 前台窗口标题匹配《流放之路》且存在其他匹配候选
- **THEN** 系统返回前台游戏窗口的 DPI、倍率和标题

#### Scenario: 多个非前台候选
- **WHEN** 存在多个可见匹配窗口且均非前台
- **THEN** 系统选择可见面积最大的非最小化窗口

#### Scenario: 未找到游戏窗口
- **WHEN** 没有可用的匹配窗口或检测环境不可用
- **THEN** 系统返回结构化失败结果而不阻断应用启动

### Requirement: 自动与手动模式
系统 MUST 默认使用自动 DPI 模式，并允许用户切换到持久化的手动倍率。

#### Scenario: 自动模式检测成功
- **WHEN** 自动检测返回有效倍率
- **THEN** 系统立即采用该倍率并保存为最近成功值

#### Scenario: 手动模式
- **WHEN** 用户切换到手动模式并设置有效倍率
- **THEN** 系统持续使用该值且不被自动检测覆盖

#### Scenario: 切回自动模式
- **WHEN** 用户从手动模式切回自动模式
- **THEN** 系统立即发起一次游戏 DPI 检测

### Requirement: 可解释的自动回退
自动模式检测失败时，系统 MUST 继续提供有效倍率并向用户展示其来源。

#### Scenario: 存在历史检测值
- **WHEN** 当前检测失败且存在最近成功倍率
- **THEN** 系统使用最近成功倍率并提示正在使用上次识别值

#### Scenario: 不存在历史检测值
- **WHEN** 当前检测失败且不存在最近成功倍率
- **THEN** 系统使用主显示器倍率并提示正在使用主屏倍率

### Requirement: 运行时刷新与坐标语义
系统 MUST 在主界面启动后及每次做装或洗图自动化开始前刷新自动 DPI，保持 Windows API 坐标为物理像素，并在 Windows 多显示器虚拟桌面中保留显示器标识、缩放倍率与负坐标。

#### Scenario: 应用启动
- **WHEN** 主界面完成挂载且处于自动模式
- **THEN** 系统异步检测 DPI，不阻塞其他初始化

#### Scenario: 自动化运行前
- **WHEN** 用户在自动模式下开始做装或地图洗练
- **THEN** 系统在生成脚本前重新检测并解析有效倍率

#### Scenario: Python 鼠标控制
- **WHEN** 生成的脚本使用 Windows API 移动鼠标
- **THEN** 坐标不进行 DPI 乘除；仅 `pynput` 回退路径使用有效倍率换算

#### Scenario: 副屏位于主屏左侧或上方
- **WHEN** 游戏窗口位于带负原点的副显示器
- **THEN** 系统保留负物理坐标并使用该显示器的实际倍率进行校准和自动化

#### Scenario: 常见缩放倍率
- **WHEN** 游戏位于 100%、125%、150% 或 200% 缩放的显示器
- **THEN** 浮窗、区域选择和自动化坐标均引用同一显示器上下文且不重复缩放

### Requirement: 旧设置迁移
系统 MUST 将旧版单一 `dpiScale` 设置迁移到新版状态而不丢失其数值。

#### Scenario: 读取旧设置
- **WHEN** 已保存设置包含 `dpiScale` 但不包含新版模式字段
- **THEN** 系统进入自动模式，并将旧值作为手动初值和最近成功回退值
