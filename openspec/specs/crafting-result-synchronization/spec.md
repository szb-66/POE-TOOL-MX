# crafting-result-synchronization Specification

## Purpose

定义装备制作、地图洗练和航海海图洗练取得当前目标最新解析结果、隔离陈旧响应，并在地图或海图读取链路失败时保持当前格和安全停止的统一可验证行为。

## Requirements

### Requirement: 所有制作目标只使用当前请求的解析结果

系统 MUST 对装备、插槽、古灵、地图和航海海图使用同一带 requestId 的解析请求/响应协议，在发出新请求前使上一份结果失效，并 MUST 只接受可确认属于当前目标、当前请求的完整解析结果。文件解析请求 SHALL 支持可选的 `publish` 字段；字段缺省时按 `true` 处理以保持兼容。确认事务用于动作验证的解析请求 MUST 指定 `publish: false`，其候选解析结果 MUST 携带 `publish: false`，主进程即时解析路径和结果文件监听路径均不得用候选结果更新面板。

Python 确认候选属于当前目标且满足动作后置条件后，SHALL 以同一 requestId 将同一结构化结果提交为 `publish: true`。发布入口 MUST 再次验证 requestId 仍为当前有效请求，并保证同一 requestId 至多发布一次；陈旧、候选或不完整结果 MUST 被忽略。发布确认的交付 MUST 独立于全局 `operationDelayMs`，不得以提高自动操作等待下限掩盖文件事件丢失或合并。外部 UI、持久化设置与公开 Electron API 保持不变。

#### Scenario: 当前候选结果不提前显示

- **WHEN** 当前目标的 `publish: false` 解析结果已生成，但 Python 尚未完成目标身份与动作后置条件验证
- **THEN** Python 可以读取该候选用于验证
- **AND** 主进程即时解析路径和结果文件监听器均不更新制作面板

#### Scenario: 验证通过后提交同一请求结果

- **WHEN** Python 验证当前候选属于当前目标并满足本次动作确认条件
- **THEN** 系统以同一 requestId 将该结构化结果标记为 `publish: true`
- **AND** 面板至多更新一次并显示该已确认结果

#### Scenario: 提交文件事件被合并或遗漏

- **WHEN** Windows 文件监听只报告候选写入，随后同一 requestId 的 `publish: true` 提交已完整落盘但没有产生可见文件事件
- **THEN** 系统通过独立于全局自动操作等待的当前请求轮询发现该完整提交
- **AND** 面板至多发布一次，实际发送成功后写入 `publicationAcknowledged: true`

#### Scenario: 结果文件处于写入中间态

- **WHEN** 监听或轮询读取到空文件、未完成写入或损坏 JSON
- **THEN** 系统等待下一次读取，不发布、不确认且不推进当前事务
- **AND** 后续完整内容仍可被读取并按当前 requestId 正常处理

#### Scenario: 旧监听会话回调晚到

- **WHEN** 结果监听停止或重启后，旧会话的延迟文件事件或轮询回调才执行
- **THEN** 系统按监听会话标识拒绝该回调
- **AND** 该回调不得发布、确认或污染新会话的当前 requestId

#### Scenario: 陈旧 requestId 不提交

- **WHEN** 某候选完成验证时，其 requestId 已不再是当前有效请求
- **THEN** 发布入口拒绝提交该结果
- **AND** 不用该结果覆盖当前目标的面板状态

#### Scenario: 缺省发布字段保持兼容

- **WHEN** 既有调用方发送不含 `publish` 字段的解析请求
- **THEN** 解析与发布协议按 `publish: true` 处理
- **AND** 既有非确认事务调用不需要修改公开接口

#### Scenario: 当前结果快速返回

- **WHEN** 当前装备、地图或航海海图的候选解析结果在 Python 开始轮询等待之前已经写回
- **THEN** Python 接受该结果用于当前确认事务
- **AND** 不因清理结果或等待时序而删除、忽略或错误切换目标

#### Scenario: 装备解析结果快速返回

- **WHEN** 当前装备的候选解析结果在 Python 开始轮询等待之前已经写回
- **THEN** Python 接受匹配 requestId 的候选用于身份与动作后置条件验证
- **AND** 候选在验证提交前不更新面板

#### Scenario: 地图或海图解析结果快速返回

- **WHEN** 当前地图或海图格位的候选解析结果在 Python 开始轮询等待之前已经写回
- **THEN** Python 接受匹配 requestId 的候选并保持当前格
- **AND** 不因等待时序错误换格或提前提交统计

#### Scenario: 陈旧结果晚到

- **WHEN** 上一次解析请求的结果在当前请求发出后才到达
- **THEN** 系统忽略该陈旧 requestId，并继续等待当前请求结果
- **AND** 即使陈旧结果带有 `publish: true` 也不得覆盖当前面板

#### Scenario: 序列号变化但内容未更新

- **WHEN** 剪贴板序列号发生变化，但提交宽限后的非空文本仍与复制前相同
- **THEN** 系统把它记录为同文本复制证据，而不消耗完整 `adaptiveTimeoutMs`
- **AND** `initial` 可按首次读取语义接受，`post-action` 必须按动作确认策略复核且不得提前发布

#### Scenario: 复制到旧剪贴板内容

- **WHEN** 通货后第一次复制取得动作前旧文本
- **THEN** 系统不得把该文本作为已确认结果发布或用于推进制作
- **AND** 在动作确认窗口内继续当前事务的剩余复制观察

#### Scenario: 重试复制到相同物品文本

- **WHEN** 同一目标的允许无变化动作在确认窗口后的第二次复制取得相同非空文本，且两次均有序列号证据
- **THEN** 系统可选择最终候选进行解析和合法稳定验证
- **AND** 若已有候选只是解析传输失败，则改为重放候选而不再次复制

#### Scenario: 完整的当前结果返回

- **WHEN** 当前 requestId 返回可识别类别和完整结构化候选，且 Python 验证目标身份与动作后置条件通过
- **THEN** 系统以同一 requestId 提交 `publish: true` 的结果
- **AND** 只有该已确认结果用于继续当前制作目标的条件判断和面板更新

### Requirement: 装备、地图或海图解析失败时保持当前目标并安全停止

系统 SHALL 在装备、插槽、古灵、地图或航海海图的复制观察失败时，对同一通货动作最多执行三次串行复制观察；在某次观察已捕获候选但解析传输失败时，最多对该候选执行三次解析重放。复制观察与解析重放为两层互斥恢复手段：解析重放不得增加复制次数，新的复制观察仅在没有可验证候选时发生。任何恢复尝试都不得重复使用通货、移动到下一格、报告制作完成或提交当前目标统计。动作结果仍未确认时，系统 MUST 异常停止、保留当前目标及既有恢复上下文，并给出不含物品内容的可区分失败原因。

#### Scenario: 装备动作最多三次复制观察

- **WHEN** 通货已经作用于当前装备，前两次复制观察未取得可验证候选
- **THEN** 系统保持当前装备并执行第三次复制观察
- **AND** 三次观察期间不得再次使用任何制作通货

#### Scenario: 地图或海图动作最多三次复制观察

- **WHEN** 通货已经作用于当前地图或海图，前两次复制观察未取得可验证候选
- **THEN** 系统保持鼠标目标为当前格并执行第三次复制观察
- **AND** 不得移动到下一格或提交当前格统计

#### Scenario: 候选解析超时只重放解析

- **WHEN** 当前动作已经捕获候选文本，但解析结果等待超时
- **THEN** 系统最多三次重新分发同一候选并等待对应 requestId
- **AND** 不发送额外 Ctrl+C、不重复使用通货且不移动目标

#### Scenario: 第三次观察仍无法确认

- **WHEN** 当前动作的三次复制观察均未取得可通过目标身份与动作条件验证的结果
- **THEN** 系统异常停止并保留当前目标及恢复上下文
- **AND** 不继续消耗通货、不换格且不提交当前目标统计

#### Scenario: 第三次解析重放仍失败

- **WHEN** 同一候选的第三次解析传输仍超时、requestId 不匹配或返回无法解析结果
- **THEN** 系统异常停止并报告对应传输失败原因
- **AND** 不通过重新复制或继续制作掩盖失败

#### Scenario: 装备首次失败后恢复

- **WHEN** 通货已经作用于当前装备，前两次复制观察均未取得可验证候选
- **THEN** 系统保持当前装备并执行第三次复制观察
- **AND** 补读期间不得再次使用改造石、混沌石、点金石、重铸石、增幅石或其他制作通货

#### Scenario: 地图或海图首次失败后恢复

- **WHEN** 通货已经作用于当前地图或海图，前两次复制观察均未取得可验证候选
- **THEN** 系统保持当前格并执行第三次复制观察
- **AND** 补读期间不得再次使用通货、移动到下一格或提交当前格统计

#### Scenario: 装备重试后仍然超时

- **WHEN** 当前装备在三次复制观察或同一候选的三次解析重放后仍未确认结果
- **THEN** 系统停止本次装备制作并报告对应的复制或解析超时
- **AND** 不继续应用通货，面板保持最近已确认结果并显示失败原因

#### Scenario: 地图或海图重试后仍然超时

- **WHEN** 当前地图或海图在三次复制观察或同一候选的三次解析重放后仍未确认结果
- **THEN** 系统停止整次洗练并报告对应超时
- **AND** 当前格不计入完成统计，且不得移动或对下一格发送输入

#### Scenario: 装备重试后返回解析错误

- **WHEN** 当前装备候选在第三次解析重放后仍无法解析、身份不符或缺少动作后置条件所需字段
- **THEN** 系统停止本次装备制作并报告对应失败原因
- **AND** 不得继续应用制作通货

#### Scenario: 地图或海图重试后返回解析错误

- **WHEN** 当前地图或海图候选在第三次解析重放后仍无法解析、类别不符或缺少动作验证字段
- **THEN** 系统停止整次洗练并报告对应失败原因
- **AND** 当前格不得计入完成统计且不得移动到下一格

### Requirement: 地图或海图仅在单张目标进入明确终态后换格
系统 MUST 仅在当前地图或航海海图完成既有成功收尾，或进入已定义的不可继续制作终态后，才更新相应统计并移动到下一格；内部读取、解析或状态同步失败不得视为单张目标完成。

#### Scenario: 可修改目标尚未满足条件
- **WHEN** 当前地图或海图可继续修改且最新解析结果不满足已启用的基底或词缀条件
- **THEN** 系统按照所选洗练方式继续处理当前格
- **AND** 不移动到下一格

#### Scenario: 当前目标满足条件
- **WHEN** 当前地图或海图满足全部有效条件并完成既有瓦尔或存仓配置要求
- **THEN** 系统将其计入已处理及符合条件数量
- **AND** 随后移动到下一格

#### Scenario: 已定义的不可继续制作终态
- **WHEN** 当前地图或海图属于传奇、不可改变、已腐化后不满足，或其他既有明确终态
- **THEN** 系统按照该终态的既有统计语义结束当前格
- **AND** 可以移动到下一格

### Requirement: 异常停止后从当前目标安全恢复
系统 MUST 为非用户主动停止的装备、地图和海图制作保留安全恢复上下文。装备恢复 SHALL 使用最新有效配置并在使用任何通货前判断当前物品；地图和海图恢复 SHALL 从失败格开始，保留此前已完成格位的累计统计，且不得重复处理此前格位。

#### Scenario: 装备失败后当前物品已经达标
- **WHEN** 装备异常停止后用户重试，重新读取的当前物品已经满足最新有效配置
- **THEN** 系统直接完成对应制作目标
- **AND** 不再使用制作通货

#### Scenario: 地图或海图从失败格恢复
- **WHEN** 地图或海图在处理中异常停止且存在有效失败格检查点
- **THEN** 系统从失败格重新读取并继续后续格位
- **AND** 保留停止前已经提交的处理数量、合格数量和词缀统计
- **AND** 不重复处理失败格之前的格位

#### Scenario: 地图或海图启动阶段失败
- **WHEN** 地图或海图在建立首个格位检查点前异常停止
- **THEN** 重试从第一格按最新有效配置安全启动

#### Scenario: 恢复检查点无效
- **WHEN** 保存的地图或海图恢复检查点超出当前网格边界、目标类型不匹配或字段无效
- **THEN** 系统拒绝启动恢复任务并保留停止状态
- **AND** 不产生键鼠输入

### Requirement: 地图或海图统计仅提交完成格位
系统 MUST 只在当前地图或海图进入既有完成终态后提交该格的处理数量、合格数量和黑白名单统计；失败格产生的临时统计不得写入恢复检查点。

#### Scenario: 当前格读取失败
- **WHEN** 当前地图或海图在处理过程中读取或解析失败并停止
- **THEN** 恢复检查点中的累计统计只包含此前已经完成的格位
- **AND** 重试当前格成功后每项统计只累计一次

### Requirement: 通货选择在目标左键前通过安全门禁

装备制作、地图和海图洗练的通货动作 MUST 共用同一选择门禁。系统 SHALL 在通货坐标上将右键保持至少 `max(buttonHoldMs, 50ms)`，完整释放后以可中断方式等待至少 `max(100ms, operationDelayMs × 2, releaseSettleMs)`，并在移动到目标前重新验证游戏前台、右键释放状态和鼠标仍位于通货坐标。移动到目标后 MUST 再次验证前台与目标坐标，全部通过才可发送唯一一次目标左键。内部下限不得被自动时序校准降低。

#### Scenario: 通货选择门禁正常通过

- **WHEN** 游戏持续在前台、鼠标位置正确、右键完整按住并释放且安全等待完成
- **THEN** 系统移动到当前装备或地图/海图格位并发送恰好一次左键
- **AND** 正常动作仍只记录一次通货使用并进入既有结果确认事务

#### Scenario: 等待期间停止或失去前台

- **WHEN** 用户停止、触发紧急停止或游戏在右键保持及释放后的等待期间失去前台
- **THEN** 系统释放右键并以 `CURRENCY_SELECTION_UNSAFE` 停止
- **AND** 不移动到目标、不发送目标左键且不记录通货使用

#### Scenario: 鼠标位置或右键状态不安全

- **WHEN** 释放等待后鼠标已离开通货坐标、右键仍处于按下状态，或移动目标后的坐标复核失败
- **THEN** 系统以 `CURRENCY_SELECTION_UNSAFE` 停止
- **AND** 门禁失败发生在目标移动前时不得移动目标，所有门禁失败均不得发送目标左键

#### Scenario: 结果证据失败不自动补点

- **WHEN** 目标左键已经发送但通货后的剪贴板或解析证据仍无法确认
- **THEN** 系统沿用异常停止和恢复上下文，不使用下一颗通货
- **AND** 不自动左键目标尝试放回物品，也不发送任何鼠标恢复输入

### Requirement: 通货动作与结果确认构成不可拆分事务

装备词缀、插槽、古灵、地图和海图的每条通货路径 MUST 以“记录动作前已提交结果、使用一次通货、观察并解析当前目标、验证目标身份与动作后置条件、提交已确认结果”为一个不可拆分事务。只有提交成功后，系统才可报告该动作完成、使用下一颗通货、执行后续收尾、更新统计或移动目标。事务约束 MUST 覆盖预处理、主循环、增幅补读、富豪石与崇高石收尾、工匠石/链接石/幻色石、古灵直接通货、地图和海图洗练及瓦尔收尾。

#### Scenario: 富豪石收尾后确认最终面板

- **WHEN** 词缀目标命中后需要使用富豪石完成收尾
- **THEN** 系统在富豪石动作后重新观察、解析并验证稀有度与词缀增加
- **AND** 只有最终结果提交到面板后才报告制作完成

#### Scenario: 崇高石收尾后确认最终面板

- **WHEN** 词缀目标命中后需要使用一颗或多颗崇高石完成收尾
- **THEN** 每颗崇高石分别建立并完成结果确认事务
- **AND** 任一颗结果未确认时不使用下一颗，也不报告制作完成

#### Scenario: 插槽与古灵路径接入事务

- **WHEN** 工匠石、链接石、幻色石或古灵直接通货作用于当前装备
- **THEN** 系统确认并提交该次动作结果后才判断是否继续
- **AND** 不通过首次读取的同文本放行绕过动作确认

#### Scenario: 地图或海图未确认不换格

- **WHEN** 当前格的洗练或瓦尔动作尚未完成结果确认事务
- **THEN** 系统不更新该格统计且不移动到下一格
- **AND** 不对当前格或下一格使用下一颗通货

### Requirement: 动作后置条件按通货策略验证

确认事务 MUST 按通货语义选择后置条件，并同时验证候选仍属于当前目标。知识卷轴结果 MUST 已鉴定；蜕变石结果 MUST 为魔法；点金石结果 MUST 为稀有；重铸石结果 MUST 为普通且不含显式词缀；增幅石结果 MUST 比动作前增加词缀；富豪石结果 MUST 变为稀有且增加词缀；崇高石结果 MUST 增加词缀；瓦尔宝珠结果 MUST 已腐化。这些确定变化未被观察到时不得确认事务。

改造石、混沌石、工匠石、链接石、幻色石和古灵直接通货 MAY 合法地产生与动作前相同的可见结果，但只有当前目标的两次非空复制均具备剪贴板序列号证据、相隔动作确认窗口且文本稳定一致，并且选定的最终候选解析为当前目标时，系统才可确认合法无变化；若任一次观察取得满足该通货语义的新结果，则提交新结果而无需额外稳定等待。

#### Scenario: 稀有度类通货验证目标稀有度

- **WHEN** 蜕变石、点金石、重铸石或富豪石已经使用
- **THEN** 系统分别验证魔法、稀有、普通无显式词缀，或稀有且词缀增加的结果
- **AND** 不满足对应条件的候选不被提交

#### Scenario: 词缀增加类通货验证计数变化

- **WHEN** 增幅石、富豪石或崇高石已经使用
- **THEN** 当前候选的可验证词缀数量必须高于动作前已提交结果
- **AND** 目标身份不一致或词缀未增加时事务不完成

#### Scenario: 知识与瓦尔验证确定标记

- **WHEN** 知识卷轴或瓦尔宝珠已经使用
- **THEN** 系统分别验证当前目标已鉴定或已腐化
- **AND** 未观察到对应标记时不提交结果

#### Scenario: 允许无变化通货确认稳定结果

- **WHEN** 改造石、混沌石、工匠石、链接石、幻色石或古灵直接通货的两次相隔确认窗口复制取得稳定同文本，且最终候选解析为当前目标
- **THEN** 系统可将最终候选作为本次动作的合法稳定结果提交
- **AND** 两次观察中的任一次缺少序列号证据时不得确认

### Requirement: 开发读取指标必须脱敏且生产关闭

系统 SHALL 仅在开发版输出结果确认读取指标，字段限于动作类型、复制观察次数、解析重放次数、枚举化结果类型和总耗时。指标 MUST NOT 包含物品文本、文本哈希、文件路径、账号信息或可还原这些内容的字段；生产构建 MUST 关闭该指标输出。

#### Scenario: 开发版记录脱敏指标

- **WHEN** 开发版中的一次结果确认事务完成或异常停止
- **THEN** 系统记录动作类型、复制次数、解析次数、结果类型和耗时
- **AND** 输出中不含文本、哈希、路径或账号信息

#### Scenario: 生产构建不输出读取指标

- **WHEN** 应用以生产构建运行制作流程
- **THEN** 结果确认读取指标不产生任何输出
